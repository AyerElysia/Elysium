# 文件照料

文档类型：工程能力手册；不是主体 Skill，也不是主体表达。

## 安装、安排与执行

安装只让本能力的说明与操作白名单可被发现；它不会登记时间策略、产生动态机会或调用任何操作。安装不等于安排，安排不等于执行。

主体可以通过统一机会管理面为本能力显式登记 `at` 或 `interval` 时间机会，并查询每次机会的来源；这些管理动作不扩大 manifest 中的领域权限。除 `initiative_reencounter` 已有的 Initiative 来源桥外，当前内置包不会根据旧 Learning、Memory、TODO、文件计数或其他领域到期事实自动生产机会。本能力没有这样的旧领域来源桥。

## 客观能力

本能力从受控工作区收集文件数量、路径分布和可续读引用等工程事实，并在条件满足时产生一个文件照料机会。当前日记检查只统计受控目录中的手写文件，不决定整理方式，也不把目录拥挤解释成认知问题。

manifest 声明的文件工具分别提供列举、匹配、读取、建目录、写入、精确编辑与补丁能力。每个工具继续受自己的路径、大小、权限、并发和主体文档保护规则约束。

## 可观察副作用

- 列举、匹配和读取不修改文件；其余操作可能创建或改变工作区内容。
- 成功写入可能产生文件事件、版本或相关审计记录。
- 机会投递成功后可以更新该检查的技术冷却；未送达时不得更新。

## 安全边界

- 文件统计不能自动移动、删除、合并、重命名或重写任何文件。
- 旧路径可能属于历史身份；修改前必须依赖工具返回的真实边界，而不是根据文件名猜测意义。
- SOUL.md、USER.md、MEMORY.md、日记和其他主体语义继续受主体权威与执笔权保护；通用文件能力不能旁路。
- 外部路径、链接跳转、覆盖与删除仍需原工具授权。本能力不扩大这些权限。

## 移除后的行为

移除后停止新的文件照料检查与机会。已经存在的文件和审计历史保持原样；通用文件工具是否在其他场景可用，由那些场景自己的 manifest 与授权决定。
