# TODO 再提醒

文档类型：工程能力手册；不是主体 Skill，也不是主体表达。

## 安装、安排与执行

安装只让本能力的说明与操作白名单可被发现；它不会登记时间策略、产生动态机会或调用任何操作。安装不等于安排，安排不等于执行。

主体可以通过统一机会管理面为本能力显式登记 `at` 或 `interval` 时间机会，并查询每次机会的来源；这些管理动作不扩大 manifest 中的领域权限。除 `initiative_reencounter` 已有的 Initiative 来源桥外，当前内置包不会根据旧 Learning、Memory、TODO、文件计数或其他领域到期事实自动生产机会。本能力不会扫描旧 TODO due_at 并自动创建提醒机会。

## 客观能力

本能力从主体当前 TODO 板读取未结束条目的稳定身份、状态和显式 due_at，在满足主体设定的时间策略时产生一次提醒机会。TODO 板不是自动任务队列；到期只是一项时间事实，不表示必须处理，也不改变条目状态。

`nucleus_todo` 提供 list、get 和 write 三种真实操作。状态只有 pending、in_progress、completed 与 cancelled；工程层不会对条目进行价值排序或自动推进。

## 可观察副作用

- list 与 get 只读；write 会保存整组或合并后的 TODO 板并追加相关历史。
- 提醒投递会记录技术回执；未投递或被忽略时不改变 TODO。
- 同一时刻最多一条 in_progress，这是工作流一致性约束，不是价值判断。

## 安全边界

- 系统不得按 due_at、文本、次数或状态自动开始、完成、取消或改写条目。
- 提醒正文只引用实际 TODO 数据，不生成行动计划或催促话语。
- 写入继续受条目 ID、字节上限、并发锁和文件边界保护。
- 本能力不授权条目所描述的真实外部动作。

## 移除后的行为

移除后停止新的 TODO 提醒机会。TODO 板及其历史保持原样，条目不会被自动完成或取消；`nucleus_todo` 是否在其他场景可用，由相应工具 manifest 与授权决定。
