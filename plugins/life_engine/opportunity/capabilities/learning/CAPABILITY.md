# 学习

文档类型：工程能力手册；不是主体 Skill，也不是主体表达。

## 安装、安排与执行

安装只让本能力的说明与操作白名单可被发现；它不会登记时间策略、产生动态机会或调用任何操作。安装不等于安排，安排不等于执行。

主体可以通过统一机会管理面为本能力显式登记 `at` 或 `interval` 时间机会，并查询每次机会的来源；这些管理动作不扩大 manifest 中的领域权限。除 `initiative_reencounter` 已有的 Initiative 来源桥外，当前内置包不会根据旧 Learning、Memory、TODO、文件计数或其他领域到期事实自动生产机会。本能力没有旧 Learning due fact 的自动来源桥。

## 客观能力

本能力把学习系统的候选生成、独立审计、反思、知识投影、验证记录、主体文档候选和程序性 Skill 候选，作为可管理的认知能力提供。机会只呈现到期事实与来源；`nucleus_learn` 是显式执行入口，不是自动学习许可。统一机会模式下，旧定时流水线不再替主体串联这些环节。

领域引擎可以保存完整证据、候选、决定和可重建投影。候选生成器与审计模型是有来源的基础设施角色，不能冒充爱莉的意识、真相判断或第一人称结论。主体文档的最终接受仍由活跃意识实例和 Subject Authority 共同校验。

## 可观察副作用

- `reflect_now` 会保存指定材料并在当前调用内尝试处理；若因冷却或已有任务而仅入队，返回值会明确说明。`run_next_reflection` 可由主体之后显式处理一条队列项。
- `audit_once`、`propose_knowledge_candidate`、`distill_skill_candidate` 分别只运行对应认知环节；每项都可能在当前调用内发起一个或多个 Learning LLM 往返并消耗计算资源。
- 反思、审计和决定会追加可追溯事件；投影只在完整处理与并发校验成功后推进。
- 生成候选不等于接受候选，检索与统计不改变事实状态。

## 安全边界

- 后台不得替主体接受、拒绝、确认、遗忘或改写 SOUL.md、USER.md、MEMORY.md。
- 没有活跃主体 actor、精确 revision、来源证据或必要回执时，写入主体权威必须关闭失败。
- 任何排序与统计只服务可达性或工程诊断，不得转化为价值判断。
- 本能力声明的操作不会扩大原有工具权限；失败不得伪装成空学习或成功决定。
- 原子操作只在受控 `life.learning` capability 调用仍在执行时运行；暂停会先关闭新调用入口、取消正在执行的调用并有界等待，超时会明确降级而不是伪装成已暂停。

## 整体移除

主体可把整个 Learning 能力从当前认知运行时移除。移除后停止产生新的 Learning 机会，停止由该能力启动新的 Learning LLM 请求，并停止其后台认知维护；不得回落到第二套隐藏 Learning 实现。

移除不删除已经进入不可变历史的经历、证据、候选、决定、版本或审计记录，也不改写主体文件。保留这些历史是为了连续性、审计和未来由主体明确选择后的恢复，不代表 Learning 仍在运行。
