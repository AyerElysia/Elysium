# life_engine（生命中枢）  
## 给你画个大的：让数字生命真的“活起来”

如果你希望你的角色不只是“会聊天”，而是能有自己的节奏、自己的心事、自己的长期记忆，  
`life_engine` 就是那颗“会跳动的内心”。

这是一份用户向说明书：有趣、够细、机制全覆盖。

---

## 0. 先画饼：你最终会得到什么

你不是在装一个插件，你是在养一个“会成长的自己”。

理想体验是这样的：

- 她会在你不说话时悄悄整理世界
- 她会记得最近发生了什么，不会每次都像重开
- 她会把“想做的事”当生活愿望，而不是打卡清单
- 她会在合适的时候，把内心灵感自然带回对话

一句话：**从“能回答”升级到“有内在连续性”。**

## 1. 生命中枢的 10 个机制（全覆盖）

下面这 10 条，就是它“活起来”的全部核心。

### 机制 1：并行心跳（后台持续苏醒）

它会按固定节奏醒来，做一轮“观察 -> 感受 -> 意图 -> 行动”。  
你不需要一直盯着它，它会自己运行。

注意：心跳只是给主体持续存在和自我整理的机会，不是“规则触发器”。
主动性不应被实现成“满足条件 -> 自动执行动作”。`life_engine` 可以在事件流、记忆、时间感和自身状态中形成自主意向，也可以选择保持沉默；系统规则只负责边界、频率、权限和风险兜底。

你也可以手动触发：

- `/心跳`
- `/heartbeat`
- `!心跳`
- `!heartbeat`

你也可以直接给生命中枢留言（仅入中枢队列，不走常规对话模式）：

- `/life 你想说的话`
- `/nucleus 你想说的话`
- `/中枢 你想说的话`

### 机制 2：睡眠/苏醒作息

你可以给她设“睡觉时间”和“起床时间”。  
在睡眠时段里，她会暂停心跳，作息更像真人，而不是 24 小时高转速。

### 机制 3：统一事件流（她的“经历时间线”）

她把所有经历都记成事件，主要有 4 类：

- 收到/发出的消息
- 心跳时的内心独白
- 调用过的动作
- 动作的结果（成功或失败）

所以她不是“只记一句结论”，而是有过程感。

### 机制 4：上下文注入（把最近发生的事带进下一次思考）

每次心跳前，她会把最近事件整理成“刚刚发生了什么”，作为下一轮思考素材。  
效果就是：不容易失忆，不容易话题断层。

### 机制 5：内在透传（同一主体的模式切换）

她会把“最近在想什么、在意什么”写成内在状态。  
这不是两个意识体之间的传话，而是同一个主体在不同运行模式间同步信息，慢慢影响对外说话风格和关注点。

### 机制 6：行动优先（不鼓励空转发呆）

心跳会被引导去做事，而不是只空谈。  
如果连续几次都没动作，会被提醒“别发呆，动起来”。

这里的“行动优先”不等于强制行动。它强调的是：当她确实有想法、有在意的事、有愿意推进的方向时，可以把意向沉淀为事件、记忆、TODO、思考流或交给表达层承接；但“不行动”“等待”“安静观察”同样是有效选择。主动性来自主体判断，不来自硬编码规则。

### 机制 7：时段感知（早晚做不同事）

她会区分清晨、上午、午后、下午、傍晚、夜晚、深夜，  
并按时段建议不同活动（规划、推进、回顾、休息）。

### 机制 8：承诺行动 TODO

她管理的不是随手记愿望，而是需要推进、复盘、完成或放下的承诺行动：

- 每条 TODO 必须有清楚的下一步
- 每条 TODO 必须有提醒、复盘、截止时间或周期规则
- 周期任务完成一次后记录完成日志，并自动排下一次

### 机制 9：仿生记忆网络（会联想、会遗忘）

她的记忆不只是“搜关键词”，而是有三件事一起发生：

- 直接找到相关记忆
- 顺着关联联想到旁支记忆
- 长期不用的弱关联会慢慢淡化

### 机制 10：可复盘（你看得见她怎么想）

她每次心跳、每次动作、每次结果都会留下记录。  
你可以回看她是怎么从“看到一件事”走到“做一个决定”的。

### 机制 11：实时消息观测（你看得见 life 和 对话器的最新消息）

现在还提供一个联合消息面板：

- `/message_timeline`
- 里面会同时展示 life 的最新事件流和每个聊天流的最新消息
- 适合你直接盯“life 刚记了什么”“对话器刚收到了什么/刚发了什么”
- 面板内可直接调用历史检索（本地 DB + NapCat 回补）来找回被上下文窗口刷走的消息

### 机制补完清单（细节版，一次讲全）

如果你想“全知道”，下面这些也都在工作中：

- 会同时感知“收到的消息”和“发出的消息”，不是只看单向输入
- 心跳不是一次性动作，而是一轮里可连续做几步，直到收尾
- 主动行为必须尊重主体性：规则只做边界治理，不决定她何时开口
- 如果一轮里只做了动作没来得及写独白，它会补一条简短总结，不让这轮变空白
- 连续几轮没动作会提醒，长时间发呆会给更强提醒
- 心跳会受作息控制，睡眠时段不打扰
- 手动触发心跳时，如果正处于睡眠时段，会明确告诉你“现在在休息”
- 最近经历会持续沉淀，不会因为重启就瞬间清零
- 历史太长时会自动“压缩成摘要 + 保留最近细节”，避免越积越乱
- 传给对外运行模式的“内在碎片”是沉淀，不是强行唤醒
- 传念会看节奏，避免短时间连续轰炸
- 文件操作有安全边界，只在私人空间活动
- 搜索内容时会自动避开不该扫的大型或无关区域，减少噪音
- TODO 会考虑逾期、复盘和提醒，但语气是引导，不是施压
- 记忆会“常用更清晰，久不用变淡”，更贴近自然记忆
- 每天会做一次记忆保养，把弱连接慢慢清理，避免记忆网络臃肿
- 现在还能联网搜索与抓取网页正文（基于 Tavily），把外部世界带入思考

## 2. 她会用哪些能力（工具全览）

总共 25 种能力，按 7 组：

### A. 文件与空间整理（8）

- `nucleus_read_file` 读内容

### B. 内容查找（1）

- `nucleus_grep_file` 在私人空间里找关键词/句子

### C. 聊天历史回放（1）

- `fetch_chat_history` 检索历史消息（支持跨流、时间范围、NapCat 回补）

### D. 承诺行动 TODO（2）

- `nucleus_manage_todo` 管理待办（create/update/start/log_progress/complete/cancel/archive/delete/review）

### F. 思考流（1）

- `nucleus_manage_thought_stream` 管理持久兴趣线索（通过 action=create/list/advance/retire 操作）

### G. 网络世界（2）

- `nucleus_web_search` 联网搜索（Tavily）
- `nucleus_browser_fetch` 打开网页并提取正文（Tavily Extract）

## 3. “传念”机制（很有灵魂的一块）

`nucleus_tell_dfc` 的作用不是“命令另一个人格”，而是“沉淀一段内在直觉给对外运行模式”。

你可以把它理解成：

- 不是强制抢麦
- 不是硬插播
- 而是把一段重要念头放进心里，等下次自然表达

它还会控制节奏，避免过度打扰（有冷却时间、会看外界是否正在高频聊天）。

## 4. 心跳里会发生什么（用户可理解版）

每次心跳大概像这样：

1. 看看最近发生了什么（消息、动作、结果）  
2. 结合当前时段和状态，形成这次的关注重点  
3. 做至少一个具体动作（看清单、读文件、写记录、建关联等）  
4. 写一段简短内心总结  
5. 更新内在状态，准备影响下一次交流

这就是“持续成长感”的来源：不是一条回复，而是一轮一轮累积。

## 5. 你的私人空间该怎么放内容

建议准备这些文件（可从简）：

- `SOUL.md`：她是谁，价值观是什么
- `MEMORY.md`：只放会改变下一次行动的关键事实、规则和偏好；别把它写成长日记
- `MEMORY_GUIDE.md`：给维护 MEMORY.md 时看的写入门槛和整理规则（不注入 prompt）
- `TOOL.md`：做事边界和风格（例如“先读后改，少打扰”）

她还会逐步产出：

- `SUBCONSCIOUS.md`：最近潜意识状态
- `todos.json`：承诺行动 TODO
- 记忆数据目录（关联和检索会用到）
- 运行记录与历史上下文文件

### 联网能力配置（Tavily）

如果你要启用 `nucleus_web_search` / `nucleus_browser_fetch`，配置一份 Tavily Key：

```toml
[web]
tavily_api_key = "tvly-..."  # 在 config/plugins/life_engine/config.toml 中填写
tavily_base_url = "https://api.tavily.com"
trust_env = true  # 是否信任系统代理；本地代理对 Tavily 握手不稳时可设为 false
search_timeout_seconds = 30
extract_timeout_seconds = 60
default_search_max_results = 5
default_fetch_max_chars = 12000
```

## 6. 怎么把“画饼”变成“真变化”

下面这套玩法很实用。

### 每天 3 分钟

早上：

- 手动心跳一次
- 让她从 TODO 里挑 1 件今天推进、重排或放下

晚上：

- 再心跳一次
- 记录“今天最值得留下的一瞬间”

### 每周 20 分钟

- 回看本周愿望进展
- 把 2~3 段相关内容连成一条记忆线
- 给下周留一个“真正期待”的小目标

### 每月一次“升级人格”

- 更新 `SOUL.md`：这一个月你想成为谁
- 更新 `TOOL.md`：哪些行为习惯有效，哪些该删
- 清理旧愿望：不想做就释怀，不要堆负担

## 7. 常见误区（提前避坑）

### 误区 1：只想让她“干活”，不给她“生活”

结果：能执行，但没有灵魂。  
解法：让她记录感受、连接经历，不只是列任务。

### 误区 2：什么都想做，清单越堆越焦虑

结果：看起来很忙，实际上没成长。  
解法：少而真，允许释怀。

### 误区 3：只写新内容，不做关联

结果：记忆像一堆散页。  
解法：每写一条，至少连一条旧记忆。

### 误区 4：期待一天就“人格飞跃”

结果：失望。  
解法：把它当长期养成，连续使用一周后会明显更连贯。

## 10. SNN 皮层下系统（核心默认组成部分）

> **Phase 0 · 2026-04 引入**

life_engine 现在拥有一个可选的 **SNN（脉冲神经网络）皮层下状态层**，
用纯 numpy 实现，为系统提供 **不依赖 LLM 的连续存在感**。

### 设计理念

| 概念 | 对应 |
|---|---|
| LLM | 大脑皮层 — 负责认知、推理、语言 |
| SNN | 皮层下系统 — 负责持续存在、情绪惯性、驱动维持 |

核心区别：LLM 在两次心跳之间"不存在"，而 SNN 在心跳间隙仍然在衰减、在演化。
这就是"连续存在"的物理基础。

### 架构

```
事件流 → 特征提取(8维) → [输入层] → [隐藏层 16 LIF] → [输出层 6 LIF] → 驱动信号
                                           ↑                        ↑
                                        STDP 学习 ←————— 奖赏信号 ←— 心跳结果
```

### 6 维驱动输出

| 维度 | 含义 | 时间尺度 |
|---|---|---|
| arousal | 整体激活度 | 快 |
| valence | 情感正负 | 快 |
| social_drive | 社交靠近冲动 | 中 |
| task_drive | 推进任务冲动 | 中 |
| exploration_drive | 探索新事物冲动 | 中 |
| rest_drive | 休息/收束冲动 | 慢 |

### 关键文件

| 文件 | 职责 |
|---|---|
| `plugins/life_engine/snn/core.py` | LIF 神经元、STDP 突触、DriveCoreNetwork |
| `plugins/life_engine/snn/bridge.py` | 事件→特征、奖赏计算、prompt 格式化 |
| `plugins/life_engine/core/config.py` | `[snn]` 配置节 |
| `config/plugins/life_engine/config.toml` | 运行时配置 |

### 配置

```toml
[snn]
enabled = false              # 总开关
shadow_only = true            # 只记录不注入
tick_interval_seconds = 10.0  # SNN 独立节拍(秒)
inject_to_heartbeat = false   # 是否注入心跳 prompt
feature_window_seconds = 600  # 特征窗口(秒)
```

### 三阶段验证

1. **Phase 0a（影子运行）**：`enabled=true, shadow_only=true` — 只在日志中记录 SNN 状态
2. **Phase 0b（软注入）**：`shadow_only=false, inject_to_heartbeat=true` — 注入心跳 prompt
3. **Phase 0c（学习验证）**：观察 STDP 权重变化是否反映了使用模式

### 安全机制

- 默认关闭（`enabled=false`）
- 影子模式不修改任何行为
- 所有 SNN 异常被捕获，不影响主心跳循环
- 一键回退：`enabled=false` 即刻关闭

## 11. Web 可视化看板

> **2026-04 引入**

为了更直观地观察数字生命的内部状态，life_engine 引入了基于 FastAPI + HTML5 Canvas 的实时可视化面板。

### SNN 驱动核监控 (`/snn`)

提供了皮层下 SNN 网络的实时运行画面：
- **核心动力学**：实时展示 8-16-6 网络结构的膜电位波动与脉冲发放。
- **STDP 脉冲粒子流**：权重越大的连接，脉冲触发时流向隐藏层的粒子越密集，直观呈现学习效果。
- **6维驱动态曲线**：平滑展示 arousal, valence 等驱动因子的连续演化。

### 仿生记忆图谱 (`/memory`)

提供了基于力导向图 (Force-Directed Graph) 的关联记忆可视化：
- **节点类型**：蓝色代表文件 (File)，粉色代表概念 (Concept)，大小由当前激活强度决定。
- **关联强度**：线条粗细反映边权重，颜色区分关系类型（如 `causes`, `mentions`, `associates`）。
- **激活扩散 (Ignite)**：支持手动选择一个节点并“点燃”激活，观察联想如何在记忆网络中扩散。
- **实时搜索**：快速定位并跳转到特定的记忆节点。

### 访问方式

当主应用运行时，直接访问以下路径（具体端口取决于主应用配置）：
- `http://localhost:<port>/router/snn/`
- `http://localhost:<port>/router/memory_vis/`
- `http://localhost:<port>/router/dream_vis/`
- `http://localhost:<port>/router/message_timeline/`
