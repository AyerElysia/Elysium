# 最小记忆连续性：手动验证步骤

本流程验证[最小闭环实现](../architecture/记忆连续性最小闭环.md)，不自动启动或停止 Elysium，不代写主体记忆。长期目标与阶段出口见[计划](../plans/记忆连续性减法重构计划.md)。

## 1. 启动门槛

工程修改已整合到主仓库工作目录，不是正在运行的旧进程自动加载了新代码。由用户自行决定合适时间，手动停止旧实例，并以前台入口手动启动。开发 agent 不发送自动启动命令、不创建守护任务，不擅自占用第二个服务端口。

启动前确认旧 PID 已退出、端口 owner 正确、storage authority 没有第二个 writer。保留现有 backend、generation、凭据和数据目录，不为实验切换到另一套正式记忆库。Witness 退役设置保持原样，机会系统也不因本实验被自动启用。

记录：Git HEAD、工作树改动摘要、启动时间、实际 backend、generation、实例身份和启动结果。报告只保留内容脱敏的状态与引用；不要把凭据或完整私聊写入工程仓库。

启动失败时停止验收并报告真实错误；不得把“原始事件可检索”当作插件初始化全部通过。未经真实手动启动及关键链路日志验收，不推送本轮运行时变更。

## 2. 最小真实场景

用普通聊天或已授权活动积累一小段经历。测试者自己保存事件时间和正确答案，不把待考题预先塞给负责压缩的爱莉。

观察以下链路，不强制她采用测试者替她写的摘要：

1. 确认一条实际消息进入 Life Event。再次读同 occurrence 时正文一致；检索节选能通过现有 read_event 继续读取。
2. 她自主决定是否通过现有文件工具留下理解或线索。若写了 MEMORY.md，随后工具读和下一轮固定 prompt 应看到同一权威版本。
3. 经历第一次由她亲自提交的有效检查点；核对 actor、manifest、revision 与归档引用，不评价摘要是否符合开发者偏好的措辞。
4. 继续交流和活动，经历第二次自主压缩。检查新的检查点保留对原始经历的可达路径。
5. 用户手动重启。已提交检查点、实例身份与精确归档应该能够恢复，没有静默空链。
6. 提问普通、未预先标成重点的近期细节。允许她自主检索，不重新注入答案。
7. 在不同表述的后续情境观察此前反馈是否影响选择；没有变化时记录失败，不用再一次“我会记住”判成功。

如果没有出现两次有效的自主压缩，就记录“该场景尚未完成”，不由开发者代写检查点。必要时另行讨论安全的测试会话与预算，不能直接改正式主体内容凑出结果。

## 3. 证据如何记录

每个问题只需保留问题编号、相关 occurrence/文件 version/group ref、实际回答或行动引用和结果。区分：

- 不借助检索直接想起；
- 沿线索找到原文；
- 明确表达未知并继续查找；
- 未找到、错归因或编造。

事实发生变化的场景，要求区分“当时”与“现在”；不要把更新当前记忆等同于删除旧历史。反馈迁移、技能效果和承诺结局在本轮只是基线观察，失败可转入后续阶段，不自动新增后台 reviewer 或大量工具。

承诺实验只能使用安全、范围明确的小任务；任何外部发送、购买、删除或扩大权限都须另有相应授权。缺少完成证据不自动等于失约，口头保证和工具返回成功也不自动等于承诺完成。

## 4. 故障时先保护什么

心跳压缩维护的专项验收：

- 若模型只返回普通文字，应能看到“未收到检查点工具调用”的技术反馈续轮；续轮不能突破既有轮数、停滞和整拍时间预算。
- 主体实际提交检查点后，必须先出现“已耐久安装”，再核对本拍实际消费回执；`count`、`drained`、`high_water` 分别是准备数量、新搬入数量和快照上界，不是已消费证据。
- 若仍未完成，应报告“准备了 N 条事件，本拍未消费”，不能同时显示“已消费 N 条”。旧原文、待处理事件和既有游标必须保持可恢复。
- 没有压缩压力时，安静结束无需额外工具或强制续轮。模型是否能稳定自主完成压缩仍须在用户手动重启新代码后观察，不能由脚本替身的成功代替。

发现恢复错误、归档缺失、CAS 冲突或未知提交结果时：

1. 保留现有快照、归档、Life Event 与主体版本，不删除、不清空游标。
2. 只读检查实际 backend 与精确版本，记录内容脱敏的 error type 和引用。
3. 不把磁盘投影直接导入成新主体意见；不重写 SOUL、USER、MEMORY 来“修好表现”。
4. 仅在可信版本与来源可证明时逐字恢复；无法证明则停在受影响路径，请用户决定。
5. 由用户手动重建/重启受影响 runtime 后重新验证，不让旧内存继续覆盖可能已经提交的新状态。

提交前崩溃可能只恢复旧快照；旧主体决定的源活动仍可审计，但本轮不自动重建未提交 pending。不要把这种情况记录成“最新检查点已恢复”。

## 5. 回退与对照

本轮没有删除旧经历、主体版本或 Experience/Witness 历史。回退只撤销本轮明确拥有的工程 hunks，并由用户手动重启；共享工作区禁止宽范围 reset/restore。快照 v3 使用 canonical digest，回退到只识别 v1/v2 的代码前须先核对兼容性；保留新快照，不手工改版本号伪装兼容。

基础链路稳定前不要同时打开多个可选模块。后续一次只加入一个组件，用同一输入、模型和预算比较收益及成本。组件故障若导致原始回忆或主体文件读取一起不可用，应优先缩短依赖，不通过假成功隐藏故障。
