# 实时通话意识（Voice Live）

> 文档状态：权威架构文档，与代码同步至 2026-08-18。
> 代码位置：`plugins/voice_live/`。
> 验收证据：`docs/report/voice_live-commercial-rebuild-2026-08-02.md` 与 `docs/report/voice-live-elysia-seedvc-integration-2026-08-02.md`。

## 1. 定位与不变量

Voice Live 是爱莉在实时语音场景中的独立意识实例，不是“语音输入 + 普通聊天 + TTS”的外壳。每次通话都拥有独立的 `ConsciousnessInstance`、场景、上下文、工具边界、事件账本和恢复检查点；稳定连续性来自统一 SOUL+USER+MEMORY 投影，近期跨实例衔接只消费 Life Engine 已持久化的潜意识因果组，不复制其他意识实例的私有滚动上下文，也不再把 `WorldState` 当作跨意识同步通道。

实现必须满足以下不变量：

- Provider 由配置显式选择；连接失败时直接报告失败，不得静默改用另一个模型或另一套认知架构。
- 浏览器永远拿不到上游 API Key；云端凭证只从服务端环境变量读取。
- 模型不能决定运行时身份。`scene_id`、`consciousness_instance_id` 和 `episode_id` 由可信运行时覆盖注入。
- `SOUL.md`、`USER.md`、`MEMORY.md` 共同构成统一主体权威；Voice 只能消费带逐源哈希和版本的只读投影，禁止从 `core.toml [personality]` 拼装第二套人格。
- 通话事件追加写入；默认不保存原始音频。
- 打断、断线、重复控制消息与资源清理必须幂等。
- OBS 只读观察会话，不能获得控制权。
- Elysium 进程只由用户手动启动；测试和插件不得自动拉起、重启或接管主进程生命周期。

## 2. 端到端架构

```text
浏览器麦克风（通常 48 kHz）
  -> AudioWorklet 采集、单声道重采样、20 ms PCM16 帧
  -> 同源短期一次性 ticket
  -> /voice-live/ws
  -> CallSession
       |- VoiceLiveConsciousnessManager
       |- ContextBridge
       |- VoiceToolBroker
       |- VoiceEpisodeStore
       `- 显式 Realtime Provider
            |- Qwen-Audio Realtime（当前云端生产路径）
            |- Qwen-Omni Realtime（获得模型权限后的升级路径）
            |- OpenAI Realtime（协议适配路径）
            `- MiniCPM-o 4.5（本地可控路径）
       `- 可选 VoiceConverter（当前为独立 Seed-VC CUDA 服务）
            |- 24 kHz Provider PCM -> 300 ms 有界块
            |- 爱莉参考音色 + 10 步扩散 + SOLA
            `- 22.05 kHz 输出 -> 24 kHz 浏览器 PCM
  <- 24 kHz PCM16 增量音频 + 转写 + 状态 + 指标
  <- 浏览器时钟调度播放、排队、清空与重连

/voice-live/observe
  -> 只读复制状态、转写和音频
  -> /voice-live/overlay
  -> OBS Browser Source
```

每个浏览器 WebSocket 对应一个 `CallSession`。`CallSession` 独占 Provider 和意识实例，负责连接、收发、打断、工具回写、持久化以及最终清理，不共享可变会话状态。

## 3. 会话与协议

### 3.1 生命周期

```text
CREATED -> CONNECTING -> ACTIVE -> STOPPING -> ENDED
                     \-> FAILED  -> STOPPING -> FAILED
```

启动顺序是：创建 episode，激活 `voice_live` 意识，读取已经预热的主体投影并生成工具 schema，记录配置尺寸，同时执行 Provider 握手与潜意识近期上下文准备；该只读投影成功送入 Provider 后才向浏览器发送 `ready`。Voice 路由启动时会在后台预热 SOUL/USER/MEMORY 的 `voice_live` 派生投影，只保存 revision、哈希与尺寸状态，不复制正文，也不阻塞 Elysium 主启动。

Provider 状态向 WorldState 的观察写入使用单消费者、容量为 1 的合并队列，不再阻塞音频接收回调、Provider 握手或浏览器 `ready`。episode 的 `provider.state` 仍同步追加，最终 `suspend` 仍是生命周期权威边界；这里只把可合并的运行状态投影移出了媒体关键路径。

失败路径会断开已经创建的 Provider、挂起意识实例、写入失败原因，并把会话置为 `FAILED`。停止操作可以重复调用，不会重复释放资源。

### 3.2 二进制音频协议

浏览器和 Elysium 之间使用 Voice Live protocol v1：二进制帧包含魔数、版本、方向、序列号、时间戳、采样率和 PCM16 payload。服务端拒绝旧序列号、非法方向、错误版本、声道或采样格式，必要时做单声道 PCM16 重采样。

- 上行：16 kHz、16-bit、mono PCM。
- 下行：24 kHz、16-bit、mono PCM。
- 浏览器采集帧：默认 20 ms。
- MiniCPM-o 上游聚合：默认 1000 ms，和官方全双工路径的输入节奏一致。

浏览器通过 Web Audio 时钟逐段预约播放，避免把每个小片段当成独立播放器造成爆音和间隙。下行帧按 Promise 链保持到达顺序；首个可听片段使用 80 ms 小型预缓冲，中途欠载后使用 60 ms 恢复缓冲，既不等待整段 `response.done`，也不以 12 ms 的脆弱余量直接开播。播放前会恢复被浏览器挂起的 `AudioContext`，页面同时显示实际 PCM 输出电平、音频时钟速率和欠载次数。每个响应开头低于 -66 dBFS 的纯算法预卷会按 10 ms 窗口从首包内部裁去，而不是只能整包丢弃；响应已经出现可听音频后，正常停顿仍原样保留。收到 `playback.clear` 时清空尚未播放的队列。

### 3.3 打断

“现在听我说”和本地 barge-in 都先立即清空客户端播放，再通知 Provider。自动抢话在播放开始 360 ms 后才武装，并要求至少 10 个连续 20 ms 高置信语音帧；门限同时受 0.015 RMS 硬下限和 4.5 倍本地噪声底约束，用来降低扬声器回声导致的误打断。Qwen 适配器跟踪 `response.created` / `response.done`：

- 有活动响应时在第一次异步发送前先原子占用该响应，重叠的本地/服务端打断最多只发送一次 `response.cancel`；
- Qwen-Audio 只使用其正式协议提供的 `response.cancel`；支持 truncate 的 Omni 路径才会在已知音频 item 上补发 `conversation.item.truncate`；
- 没有活动响应时不向上游发送非法 cancel；`response.done` 与 cancel 交错产生的 `Conversation has no active response` 被记录为可恢复竞态，不终止会话；
- Qwen 对普通用户开口也会发送 `speech_started`；只有存在活动 assistant response 时，该事件才是 `server_vad` 打断。空闲倾听阶段只更新状态，不清空播放或重置 SeedVC；
- 浏览器发起的打断只清空一次播放和转换队列；Provider 的 client interruption 回调是确认事件，不重复计数或重复清空。
- 本地 barge-in 计数只在“可听播放已经开始”后建立，不能继承上一轮用户说话的累计帧；首声有 360 ms 防尾音窗口，之后必须连续 10 个 20 ms 语音帧才触发。手动“现在听我说”不受该窗口限制。

这避免 Qwen 在“当前没有活动响应”时因 `response.cancel` 返回 `invalid_value`，也避免旧响应在取消途中到达的尾部音频重新进入播放队列。

### 3.4 爱莉实时音色转换

`voice_conversion.enabled=true` 时，Provider 下行音频不会直接送到浏览器，而是进入 `CallSession` 独占的有界转换队列。当前实现通过带 bearer token 的本地 HTTP/PCM 协议连接 Seed-VC 辅助进程；Elysium 为 AGPLv3、Seed-VC 为 GPLv3，许可证兼容。独立进程的目的不是规避许可证，而是隔离 CUDA/模型故障，并允许模型继续运行在专用 Windows Python 环境中。

关键生命周期语义：

- 会话只有在音色 profile 校验并成功分配远端转换 session 后才连接 Realtime Provider；
- profile 不是一个名字，而是 checkpoint、preset、参考 WAV 与全部实时参数的 SHA-256 revision；health 与 session revision 必须一致，旧协议或切换中途发生 revision 漂移时显式拒绝连接；
- 转换服务不可用、profile 不一致、请求超时或队列溢出时显式终止通话，不把 Qwen 原声伪装成爱莉声音；
- Elysium 客户端先在内存中聚合完整模型块，再发起一次本地 HTTP 请求；不足一块的尾音只在 flush 时提交，避免为每个 20 ms Provider delta 产生一次空 HTTP 往返；
- 每个打断都会增加转换 generation、丢弃尚未转换的旧音频并 reset SOLA/上下文；已在推理中的旧 generation 即使稍后返回，也不会播放；
- Provider 回到 `LISTENING` 时 flush 最后不足一个模型块的尾音；停止时删除远端 session 并关闭 HTTP 连接；
- 当前只允许一个活跃 Seed-VC session，与 Voice Live 默认单通话容量一致；
- Seed-VC 服务壳启动时只校验配置、资产与鉴权，不加载 CUDA 模型；首个 Voice session 通过单航班加载和预热取得模型租约，冷启动使用独立的 `activation_timeout_seconds`，不挤占普通音频块超时；
- session 持有模型租约，每个在途 audio/flush/reset 请求再持有短租约。最后一个 session 删除后，只有等所有在途请求退出才立即清除参考条件缓存、模型引用和 CUDA allocator 缓存，因此不会在 Voice 未开启时长期占用模型显存；
- 客户端在冷启动期间断开时，服务端必须回收尚未交付的 session，禁止留下无人拥有却持续占用显存的孤儿模型。

启动器的低延迟候选为 `seed-uvit-tat-xlsr-tiny`、8 diffusion steps、240 ms block、40 ms crossfade、CFG 0、输出增益 -3 dB、固定 seed 42。参考音频必须来自经过 VAD、响度归一化和峰值限制的可追溯 reference pool；Seed-VC 实际只消费 `max_prompt_length`（当前 3 秒）以内的开头片段，不能用“参考文件总时长”冒充有效提示时长。20 步在本机旧基线的模型实时系数约为 1.04，且 CAM++ 相似度没有提升，因此不得作为实时默认。固定 seed 让相同输入跨会话得到相同 PCM，便于回归和直播一致性。

协议 v3 的服务 health 暴露 content-free 的 profile revision、逐资产 SHA-256、运行参数、算法延迟下限，以及 `unloaded/loading/loaded/unloading/failed` 模型驻留状态、租约数、代次、加载/卸载耗时和 CUDA 已分配/保留字节。`unloaded` 是服务健康且 Voice 空闲的预期状态，不是故障。推理侧继续暴露有界滚动窗口中的平均/EWMA/P95/最大块耗时、模型 RTF 和实时余量；P95 达到块时长时标记 `overloaded`，达到 85% 时标记 `degraded`。这些状态只描述工程容量，不判断音色或表达质量。

## 4. 实时通话意识

### 4.1 局部实例，共享同一主体

每次通话创建 `voice_live_{episode_id}` 实例和同名场景流。它们是爱莉在当前通话场景中的运行态，不是另一个人格。激活、续租、恢复与挂起只调用 Life Engine 的异步 Presence 服务边界，并等待权威 backend 提交成功后才继续；Voice 不直接保存 registry，也不在可选存储失败时双写或回落旧 SQLite。生产配置默认要求 Life Engine 已运行，不能悄悄退化成无意识的语音机器人。

`ContextBridge` 不再读取 `core.toml [personality]`。它通过 Life Engine 的
`get_subject_context_projection_snapshot()` 取得 `voice_live` 专用投影；共享层保证
`SOUL.md`、`USER.md`、`MEMORY.md` 三个来源分别覆盖，并返回逐源 `sha256`、
`source_digest`、投影算法/版本、`projection_sha256` 和字节预算。该文本明确标记为
`derived_non_authoritative`，既不能反向写回主体文件，也不能成为平行人格。

Provider 启动 instructions 由以下有序层组成：

- 固定语音运行契约：声明统一主体、投影身份和各层优先级；
- 统一主体投影：默认不超过 24 KiB，三个权威来源各自有结构化覆盖；
- episode 续接投影：默认不超过 12 KiB，只交付最近完整轮次；
- 语音交互覆盖层：默认不超过 4 KiB，只能描述语音交互或传输场景，不能覆盖身份。

总启动上下文默认硬限制为 48 KiB。任何一层或总量越界都会显式失败，不通过隐藏截断
伪造完整性。被省略的 episode 原文仍完整保存在 episode 账本和统一 Life Event 链；
最终用户和助手转写进入统一生命事件流，临时 delta 只用于实时显示，不冒充最终记忆。

### 4.2 episode 身份绑定与重连

新 episode 首次启动时把主体投影的 `source_digest`、profile、预算、算法版本和
`projection_sha256` 追加为 `subject_context.bound`。同一 episode 重连只允许按这些字段
读取不可变历史投影；如果同一版本无法逐字节重现，或配置预算/profile 已变化，启动会
显式失败并要求建立新 episode，绝不悄悄切换身份。

主体文件发生变化时，新 episode 会获取新的投影 revision。已经进行中的 episode 保持
原 revision，直到通话边界结束；这既避免半句话之间身份前缀改变，也保留跨场景可追溯性。

### 4.3 潜意识近期上下文

`WorldState` / Perception Gateway 不进入稳定身份前缀，也不再承担 Voice 的默认跨意识同步。
每个实时响应 frontier 通过
`LifeEngineService.get_recent_subconscious_context(max_bytes=...)` 读取同一份已提交 Life Event
历史投影：只包含最近的 CONSCIOUS_ACTIVITY、HEARTBEAT、TOOL_CALL、TOOL_RESULT 与
AGENT_RESULT 因果组，明确排除 MESSAGE 和任何意识实例的私有 rolling payload。这里的
CONSCIOUS_ACTIVITY 包括已经落入统一账本的模型生成、最终 assistant 转写、完成/取消和打断；
该调用纯只读，不 drain pending、不推进 heartbeat/chatter/Perception 游标，也不产生新事件。

Voice 把现有 `session.perception_context_max_bytes` 作为兼容字节预算传给 producer；预算先扣除
固定 `<recent_subconscious_context>` 包装，producer 在剩余 UTF-8 预算内按完整因果组从新到旧
选择。`ContextBridge` 不二次摘要或裁剪，只校验 delivered_bytes、SHA-256、event ids、sequence
范围、因果组统计与算法版本。正文仅作为当前 Provider 的瞬态 turn 前缀；episode 审计只保存
哈希、字节数、sequence、group/event 数与截断状态。

Qwen/OpenAI 适配器仍以完整上游回显校验逐字节接收。每个 `response.done` 后 Provider 会删除
旧临时 item，`CallSession` 随即打开下一 frontier 并重新读取最新投影；同一 frontier 的重复
LISTENING 回调不会重复注入。缺少精确回显时只记录 content-free 的 unverified 状态，不伪造
已接收、不推进任何 Life Engine 状态；运行中刷新失败保持会话可用并留下明确 error_type，启动
阶段首次注入失败则显式拒绝 ready。

### 4.4 工具边界

`voice_live` 当前仅暴露：

```text
action-report_state
tool-inner_query
tool-conversation_evidence
```

工具清单是上下文预算和权限边界，不是关键词路由规则。`VoiceToolBroker` 从全局组件注册表解析真实工具 schema，执行前加载对应插件，并把运行时身份参数覆盖为当前会话的可信值。模型即使伪造 `scene_id` 也不能改写其他场景。

`action-report_state(kind="scene")` 会定位精确场景并更新、持久化 `WorldState`；场景不存在时显式失败，不做模糊 kind/platform 回退。

工具结果在送入 Provider 前使用默认 8 KiB 的确定性有界投影，完整工具来源不会被该
传输视图替代。Qwen/OpenAI 适配器为临时 world item 和工具结果记录“响应代次 TTL”：
普通瞬态上下文在下一次 `response.done` 删除；若工具结果是在响应 N 的回调中创建，
它会先跨过 N 的尾部事件，供后续推理使用，再在响应 N+1 完成后删除。这样既不会提前
删除工具结果，也不会让频繁工具调用无限污染长时上游上下文。

Realtime Provider 发出工具选择时，episode 先保存原始参数，随后统一 Life Event 在任何
副作用前保存同一 call 的完整参数；工具执行后的原始成功/失败结果也先进入权威活动链，
再生成 8 KiB Provider 传输视图。最终 assistant 转写另写为该 Voice instance 的模型活动并与
对外发送事实并列；`response.done`、cancel 和 barge-in interruption 保存为有来源的状态活动。
这些记录让潜意识能看见通话中实际发生的选择和打断，但不会把音频缓冲、系统 Prompt 或
Provider 协议日志伪装成第一人称思考。超大参数/结果在潜意识 Prompt 中仅给明确 excerpt/ref，
权威原文可通过稳定 occurrence 分页读取。

### 4.5 可恢复事件账本

每个 episode 写入：

```text
runtime/consciousness/{instance_id}/episodes/{episode_id}/events.jsonl
runtime/consciousness/{instance_id}/episodes/{episode_id}/checkpoint.json
```

事件包括连接、主体投影绑定/恢复、每层无正文预算统计、Provider 配置尺寸、意识激活、最终转写、工具投影、错误、打断、指标和会话结束。检查点记录当前状态、Provider、主体 revision、结束原因和累计指标。主体投影正文不会复制进事件审计；审计只保存来源哈希、版本和字节统计。原始音频默认不持久化，只有显式打开 `observability.persist_audio` 才允许保存。

### 4.6 面向未来后训练的语音归档

打开 `observability.persist_audio` 后，每个 episode 在同一目录新增独立的 `audio/`：

```text
audio/user_input.wav           # 浏览器音频重采样后的 Provider 实际输入
audio/assistant_source.wav     # Realtime Provider 原始输出，进入 SeedVC 之前
audio/assistant_converted.wav  # SeedVC 后实际发给浏览器的音频；仅启用变声时存在
audio/manifest.json            # 轨道格式、模型/音色/主体版本、字节数、缺口和哈希
```

三条轨道均为标准单声道 PCM16 WAV，采样率写入文件头和 manifest。`events.jsonl` 继续保存最终转写，并增加 `audio.transcript_anchor`，记录转写到达时每条轨道的 sample cursor；打断事件同样携带 cursor。这样未来可以按 episode、Provider 事件和时间位置对齐音频、文字、模型原声与 SeedVC 结果，又不把二进制正文塞入 Life Event。

这些文件是不可变的 **L0 episode 源素材**，不直接冒充已对齐的训练样本。manifest 显式标记 `archive_layer=L0_episode_source`、`canonicalization=not_applied` 和 `training_eligibility=unreviewed`。后续独立的 L1 构建器再按事件 cursor 完成双轨时间轴补零/裁剪、重采样、脱敏和质量筛选，且不得反向改写 L0 音频。是否进入正式后训练是之后的显式审核结果，不由录音过程自动决定。

实时回调不直接写磁盘，只向有界队列提交不可变音频块；单一后台 writer 负责顺序追加、周期 `fsync`、WAV 头修复和 manifest 原子替换。正常结束后记录每条轨道 PCM 的 SHA-256。进程异常退出时，下一次恢复同一 episode 会按实际完整 sample 数修复 WAV 头并继续追加；队列溢出或运行期磁盘故障不会卡住通话，但会在 `dropped_bytes`、`unwritten_bytes` / `writer_error` 中留下显式缺口。归档初始化失败则会阻止会话就绪，避免系统声称正在采集、实际却没有数据。

音频目录权限为 `0700`，文件与 manifest 为 `0600`。当前不自动清理这些训练候选数据；删除、脱敏、筛选和训练集发布必须是之后独立、可审计的流程，不能反向修改原始 episode。

## 5. Provider 策略

### 5.1 当前默认：Qwen-Audio Realtime

当前百炼工作空间已实测可访问 `qwen-audio-3.0-realtime-plus`。低延迟生产配置使用 Qwen 提供的 `server_vad`，阈值 0.5、连续静音 400 ms；这是官方建议会话区间的低端。`smart_turn` 仍保留为显式可选模式，但它的阈值与静音时长不可调，不能冒充确定性低延迟端点。适配器支持 16 kHz PCM 输入、24 kHz PCM 输出、流式转写、语音回复和 Function Calling。Qwen 的嵌套 function schema、函数名字符集和工具结果二轮推理均在适配层完成。

适配器显式声明输入/输出格式为 `pcm`。它会响应服务端发来的 WebSocket Ping，但不会自行要求 Qwen 返回 Pong：Qwen-Audio 的应用协议已经用事件和 `response_idle_timeout` 表达会话健康，客户端主动心跳曾把“未返回 Pong”误判成断线。浏览器到 Elysium 的短链路仍保留独立 RTT Ping，不与上游模型的 WebSocket 存活策略混用。

它是当前最适合上线的默认路径：云端延迟稳定、中文语音自然、工具调用可用，且无需在本机长期占用 GPU。

Qwen-Audio Realtime 官方目前最多保留 50 个问答轮次，并在累计音频上下文达到 300 秒
后自动丢弃更早历史。Voice Live 显式设置 `max_history_turns = 8`，把上游缓存用于最近的
声学/对话连续性，而把身份、完整 episode、Life Event 和按需回忆留在 Elysium 自己的
权威链路中。降低该值可以控制长通话延迟；提高时不得超过官方 50 轮上限。

### 5.2 升级目标：Qwen3.5-Omni Realtime

Qwen3.5-Omni Realtime 提供语义打断、多语种、语音控制、Function Calling 以及 WebRTC 路径。当前工作空间对该模型返回权限拒绝，因此不能把它伪装成已交付能力。获得 entitlement 后，只需显式修改 Provider 的 `model_name` 并重新做协议与实机验收。

生产阶段建议增加 WebRTC transport：浏览器到供应商的 RTP 音频可利用浏览器回声消除、降噪和抖动处理，同时把短期凭证、工具调用和意识上下文继续留在 Elysium 控制面。WebSocket 路径仍保留为服务端、录制和诊断通道。

### 5.3 本地路径：MiniCPM-o 4.5

本地路径使用 `llama.cpp-omni` 的 `llama-omni-server` 和 MiniCPM-o 4.5 GGUF。它提供端到端语音理解与语音生成，并保留未来连续音视频输入的空间。当前 Windows CUDA 实机已经跑通完整音频输入与有效 WAV 输出。

本地模型冷启动和首轮延迟显著高于云端，因此当前定位是：隐私模式、断网模式、供应商灾备、后续本地优化基线，而不是默认线上路径。严禁在云端失败时静默切换到本地模型；切换必须是用户或运维的显式配置决策。

### 5.4 社区方案结论

- Moshi 的双音频流和低延迟设计值得借鉴，但裸客户端缺少完整回声消除，官方 Windows 支持也不是当前主路径；不作为本项目默认 Provider。
- MoshiRAG 证明“交互前台持续说听、检索后台异步完成并回注”是降低工具等待感的正确方向。后续可把耗时工具分成异步结果事件，但不能用固定关键词替爱莉决定何时检索。
- Freeze-Omni 的 chunk-level 状态预测说明打断判断应是模型语义能力，而不是只靠固定能量阈值。
- MiniCPM-o 4.5 的连续音视频全双工能力适合作为未来本地多模态通话底座。

## 6. 安全边界

浏览器先从 `POST /voice-live/ticket` 获取 HMAC 签名 ticket，再连接 `/voice-live/ws` 或 `/voice-live/observe`。ticket 有短 TTL、随机 nonce、签名校验且只能消费一次；接口同时校验同源 Host 或显式 Origin 白名单。

其他边界：

- API Key 配置只保存环境变量名，不保存凭证值。
- ticket secret 未配置时使用进程级随机值；生产多实例部署应显式配置共享 secret。
- 默认最多一个并发通话，并设置最大通话时长和空闲超时。
- 健康接口只输出 Provider 类型、模型名、会话摘要和观察者数量，不输出密钥或转写正文。
- OBS observer 使用同样的一次性 ticket 与 Origin 校验，只能接收广播。
- 插件树的测试会扫描并拒绝内联 `sk-` 和 `api_key="..."`。

用户曾在对话中发送过真实 API Key；它不在仓库和报告中。该凭证应在本轮结束后轮换。

## 7. 浏览器与 OBS

### 7.1 通话页

地址：`http://127.0.0.1:18000/voice-live/`

页面提供开始/结束、麦克风静音、主动打断、实时状态、上下行字节、RTT、转写和错误提示。启用音色转换后还显示 `voice_profile` 与最近一个 SVC 块的推理延迟；OBS overlay 同样标记当前音色 profile。浏览器断线时采用有界退避重连；恢复时携带 episode 标识，以延续持久化上下文而不是伪造一个新 episode。

麦克风采集使用 AudioWorklet。输入存在多个声道时先选择当前能量最高的有效声道，再做保持跨渲染块相位连续的 16 kHz 重采样；Worklet 明确请求单声道，避免部分麦克风阵列把人声放在非首声道时上传全静音。Worklet 自己的 20 ms 音频时钟直接驱动 WebSocket 发送，不再经过会被浏览器节流的主线程 `setInterval`。未播放的采集图连接到 `MediaStreamAudioDestinationNode`，防止 Chromium 把零增益图降速；现场原先 48 kHz 上下文每 3.02 秒只前进 2.00 秒、上传约 33 帧/秒，改造后恢复为 3.02/3.02 秒和 50 帧/秒。WebSocket 待发送字节仍有 64 KiB 硬上限，拥塞时显式计数丢帧，不允许延迟无界增长。

“上行字节增长”只证明浏览器在发包，不证明麦克风里有人声。页面同时显示麦克风信号、实际采集帧率、AudioContext 时钟比、Qwen 停句/首声延迟与播放欠载；通话就绪后连续 5 秒未收到有效信号时会明确提示检查 Windows 输入设备或浏览器权限，而不是继续显示看似健康的“正在听”。原始音频是否落盘仍只受 `observability.persist_audio` 控制，健康判断本身只使用瞬时 RMS 和计数。

麦克风必须由用户手势授权。部署到非 localhost 时，应使用 HTTPS，否则浏览器可能拒绝 `getUserMedia`。

### 7.2 OBS 透明叠加层

Browser Source 推荐配置：

```text
URL: http://127.0.0.1:18000/voice-live/overlay
Width: 1920
Height: 1080
Custom CSS: body { background-color: rgba(0, 0, 0, 0); overflow: hidden; }
Shutdown source when not visible: off
Refresh browser when scene becomes active: off
```

叠加层没有麦克风权限和控制按钮，仅显示连接状态、爱莉/用户转写及必要的视觉状态。没有通话时透明是正常行为。OBS 捕获游戏仍应使用 Game Capture；Voice Live overlay 作为独立 Browser Source 叠加，这样语音 UI 不依赖游戏窗口标题或渲染后端。

## 8. 配置示例

配置文件只写环境变量名或本地密钥文件路径，不写密钥值：

```toml
[full_duplex]
provider_type = "qwen_realtime"
upstream_url = "wss://<workspace-host>/api-ws/v1/realtime"
api_key_env = "VOICE_LIVE_API_KEY"
api_key_file = "/root/.config/elysium/voice-live/qwen.key"
model_name = "qwen-audio-3.0-realtime-plus"
voice = "longanqian"
qwen_max_history_turns = 8
qwen_turn_detection = "server_vad"
qwen_vad_threshold = 0.5
qwen_vad_silence_duration_ms = 400

[session]
require_life_engine = true
record_to_life = true
cross_scene_awareness = true
subject_context_max_bytes = 24576
episode_context_max_bytes = 12288
voice_instructions_max_bytes = 4096
tool_result_context_max_bytes = 8192
startup_context_max_bytes = 49152
perception_context_max_bytes = 8192

[voice_conversion]
enabled = false
service_url = "http://wsl-host:17861"
token_env = "SEEDVC_STREAM_TOKEN"
token_file = "/root/.config/elysium/voice-live/seedvc.token"
profile_id = "elysia"
connect_timeout_seconds = 10.0
request_timeout_seconds = 10.0
queue_max_chunks = 64

[observability]
persist_audio = false
```

Qwen 适配器设置了 256 KiB 的本地单事件安全上限；这是 Elysium 的防御性保护，不冒充
供应商对所有模型都承诺的固定协议上限。潜意识近期上下文由 producer 先按 Voice 预算投影，
适配器仍会按 UTF-8 字符边界把大段上下文拆成不超过 192 KiB 的有序临时项；
所有出站事件都会在发送前检查大小。可观测指标只记录字节数与分块数，不记录上下文正文。Qwen 还会把 `audio_start_ms` / `audio_end_ms` 与本地已发送采样游标对齐，记录 content-free 的说话时长、判停尾随音频、`speech_stopped` 到首包以及 `response.created` 到首包耗时；浏览器只显示本轮汇总，不把转写正文混入性能轨迹。

实时语音还使用独立的确定性投影预算：`session.perception_context_max_bytes`
默认是 8 KiB；字段名为兼容旧配置保留，当前语义是潜意识近期上下文的单次传输硬上限。
完整 Life Event 历史、事件来源和因果关系不被修改，长内容仍可通过已授权历史工具按需追溯。
对话证据工具在 `voice_live` 中另受 8 KiB UTF-8 硬上限约束，超大消息通过稳定引用分块续读；
episode 只记录投影哈希、字节数、sequence 与 group/event 统计，不记录潜意识正文。

Qwen 对 `conversation.item.create` 的成功事件可能不回显正文，因此“创建成功”不能直接作为
精确交付证明。适配器会紧接着发送 `conversation.item.retrieve`，只在服务端返回的完整
`input_text` 与待交付前缀字节数和 SHA-256 都一致时记录 delivered；否则记录 unverified，
不伪造成功，也不修改任何 Life Engine 游标。

SeedVC 是显式可选后处理，当前生产配置保持关闭。关闭时不会连接 SeedVC 服务、不会加载模型或占用其显存，Provider 原始 24 kHz PCM 直接进入浏览器；未来重新启用必须单独完成音质与实时性验收。

凭证解析顺序是“环境变量优先，owner-only 本地文件兜底”。本地文件必须是当前用户拥有的普通文件，权限不得向 group/other 开放；Linux 推荐 `0600`。不得把真实值写进 TOML、脚本、命令历史示例、前端代码或 Git。文件式凭证只解决安全持久化，不改变 Elysium 必须由用户手动启动的规则。

`voice_conversion.service_url` 支持稳定语义主机名 `wsl-host`。Linux/WSL 客户端在每次创建转换器时从 `/proc/net/route` 解析当前默认网关，避免把会随 WSL/Windows 重启变化的 vEthernet 地址写死；原始 IP/域名 URL 仍按原样使用。

`/health` 的 `configured` 代表本地启动前提已经齐备，而不再只表示写了 provider URL。缺少凭证时接口返回 `status = degraded`，并在 `readiness.degraded_reasons` 中给出脱敏原因；它不会输出密钥、token 或密钥文件内容。

本地模型启动脚本为 `plugins/voice_live/scripts/start_minicpm_omni.ps1`；它只启动本地 Omni 推理服务，不启动、不终止也不重启 Elysium。

Seed-VC 辅助服务由 `plugins/voice_live/scripts/start_seedvc_stream.ps1` 启动。需要提供 Windows Python、Seed-VC 根目录、checkpoint、preset config、爱莉参考 WAV，以及环境变量 `SEEDVC_STREAM_TOKEN` 或 `ELYSIA_SEEDVC_TOKEN_FILE`。token 文件路径只进入进程参数，token 值不会进入命令行。脚本动态发现当前 WSL vEthernet 地址；端口已有服务时，必须逐项匹配协议版本、profile、checkpoint/config/reference SHA-256 和全部实时参数，再通过不会加载模型的鉴权探针确认 token 后才可复用。任何差异都只给出脱敏诊断，不会误用或停止未知端口 owner；Elysium 本身仍遵守用户手动启动边界。服务入口为 `plugins/voice_live/scripts/seedvc_stream_service.py`。
