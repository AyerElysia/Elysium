# Life Engine 派生上下文的协议闭合与事件副本

本文说明 Life Engine 对模型请求上下文的技术规范化边界。原始 Life Event、意识轨迹和主体文件仍是独立的历史事实；下面的处理只作用于可重建的上下文投影，不改写这些权威来源。

## 相邻 assistant 的协议闭合

`LifeTrajectory.to_payloads()` 导出独立的内容列表。摘要与保留的续轮 assistant 因压缩而相邻时，导出视图合并内容，防止产生不合法的 `assistant → assistant` 链。请求端追加内容不能反向修改轨迹中的内容列表。

旧工具调用退出当前工具集时，`LifeChatter._without_retired_tool_history()` 只在派生模型上下文中移除退役的调用及回执。移除回执后相邻的 assistant 合并；前帧调用若仍有保留的匹配回执，必须一起保留，只有失去回执的前帧调用可以在此技术闭合中移除。工具配对以调用 ID 为依据，不根据正文猜测。

该过程不向历史追加虚构用户消息或工具执行，也不表示消息已投递。平台发送仍由原有执行与回执链处理。

## 同一事件的精确副本

`without_exact_identity_copies()` 比较事件 ID 与完整事件字段；只有 `heartbeat_context_consumed` 不参与事实比较。完全相同的副本保留原来位置，若任一副本已经确认消费，则选择已确认的对象，无论副本顺序如何。比较与选择不修改输入对象。

已确认状态沿用既有确认，不因去重产生新确认。同一 ID 对应不同事实的事件必须同时保留，visible prepare 继续明确拒绝身份歧义，不能用字典覆盖或选择“最新”事实。

上述规则用于历史追加、当前心跳输出并入历史、visible prepare 及确认后的历史压缩。完整事实还包括原始内容、引用、因果与重投来源；不同重投来源不会被当作同一副本丢弃。原始账本的发布路径仍接收原事件，不由上下文去重替代历史写入协议。

预算针对实际可见文本计算，包括时间、来源和 ledger 标识。因果组仍须整体准入；去重不会授权跨过未确认的事件缺口，也不会代替精确投递证明和消费状态持久化。

提交失败时，只恢复本次实际从未确认改成确认的事件对象；不能按事件 ID 清除另一个副本先前已有的确认。恢复历史也使用完整事实去重，保留期间到达的新事件和同 ID 的不同事实，不以字典覆盖冲突。

## 定向契约

- `test_chatter_prompt.py` 验证退役工具清理后的协议有效性，并保留仍有真实回执的调用。
- `test_trajectory.py` 验证压缩后的请求协议，以及导出列表与轨迹列表的隔离。
- `test_heartbeat_visible_projection.py` 验证精确副本、确认顺序、冲突保留、整组预算、精确回执和提交失败回滚。
- `test_subconscious_context.py` 与 `test_subconscious_interleaved_frontier.py` 验证摘要和跨组未确认缺口。

这些测试使用合成事件、临时目录或 mock 边界，不需要启动服务或访问正式主体历史。
