# 主体持续关注线索

## 目的

`AttentionThread` 表示同一主体明确选择跨意识实例保留的关注线索。它回答的是“我愿意让未来的自己继续知道我在意什么”，不是后台替她维护的任务队列，也不是隐藏思维或推理过程的存档。

旧 `ThoughtStream` 同时保存兴趣分数、最近思考、自动衰减、容量淘汰与按时间休眠，混合了主体决定、实例瞬时状态和基础设施策略。该模型进入只读兼容与迁移阶段，不再作为新的主体权威。

## 权威边界

一个持久决定只能来自活跃意识实例，并通过 `AttentionThreadCommand` 表达：

- `occurrence_id`：决定的幂等身份；相同身份与相同字节重放返回原提交，相同身份与不同内容显式冲突。
- `thread_id`：主体线索身份。
- `action`：仅允许 `open`、`note`、`pause`、`resume`、`close`。
- `actor_consciousness_instance_id` 与 `source_instance_id`：决定者和来源实例，永久进入不可变事件。
- `source_occurrence_ids` 与 `causation_occurrence_id`：决定所依据的可追溯发生项与直接因果项。
- `expected_revision`：主体实际读取的线索版本；过期决定拒绝，不自动合并或重定基线。
- `public_statement`：主体愿意让未来意识实例读取的公开表述；不是 raw CoT。`open`、`note`、`close` 必须提供，`pause`、`resume` 不需要正文。
- `occurred_at`：决定发生时间。时间只作证据，不决定线索状态。

数据库事务按以下顺序执行：先识别幂等重放，再使用数据库时间校验 actor 的 Presence 为 `active` 且租约未过期，锁定当前 head，追加不可变事件，最后以 revision CAS 更新可重建 head。任一步失败，事件和 head 一起回滚。

关闭是终态。系统、调度器、审计器、时间阈值、分数、容量和访问频率均无权执行 open/note/pause/resume/close。后台最多产生 `attention_opportunity`，是否把它变成主体线索仍由活跃意识实例决定。

## 持久线索与瞬时焦点

`AttentionThread` 属于统一主体；`InstanceFocus` 只属于一个运行中的意识实例。

- Focus 有明确进入时间、到期时间、revision、来源 occurrence，可选择引用一个 thread。
- Focus 到期、实例暂停或结束只清除瞬时焦点，不会暂停、关闭或删除主体线索。
- 不同意识实例可以同时感知同一组主体线索，并各自拥有不同的瞬时 focus。
- Focus 不是主体价值、重要性或优先级，不能被用来排序或淘汰线程。

## 有界读取

默认投影算法为 `attention-thread-ref-v1`。投影只提供稳定 thread/event ref、状态、revision、位置、正文哈希/字节数和 UTF-8 安全短摘录：

- 单页预算必须在 4–256 KiB；默认 32 KiB。
- 每页最多 100 条 ref；不会先拼接全部正文再裁剪。
- 大正文通过 `read_statement_chunk(event_id, offset_bytes, max_bytes)` 逐字节续读，offset 与 chunk 都必须落在 UTF-8 边界。
- continuation 绑定 source frontier、排序游标、筛选条件、预算和 projection kind；来源变化、token 篡改或换查询参数都会显式失败。
- metadata 记录 algorithm、kind、source frontier、projection revision/hash、original/delivered bytes、omitted count 和 continuation。
- 投影正文对结构字符转义，不能用主体表述伪造新的投影边界。

权威事件始终完整保留；提示词、UI 和其他意识实例看到的是有界投影，需要时再按 ref 读取精确内容。

## 存储与生命周期

AttentionThread 使用 Life Engine 已选中的同一个 `StorageBackendRuntime`：

- `LifeEngineService` 是唯一 open/owner/close 方；AttentionThread 只消费注入的 runtime，不独立打开、关闭或切换 backend。
- local 与 MySQL 共享同一领域合同、CAS、数据库时间 actor gate 和有界读取语义。
- `attention_thread_events` 只追加；local/MySQL 生产 schema 都用数据库 trigger 禁止 UPDATE/DELETE。
- `attention_thread_heads` 是事件可重建投影；`attention_instance_focus` 是可过期技术状态。
- `storage.enabled=true` 时 schema 未迁移、runtime 未注入或 Presence 不可验证均 fail closed，禁止回落旧 `streams.json` 或双写。
- `storage.enabled=false` 期间旧 `streams.json` 仅供只读兼容和迁移审计；新的主体决定不会伪装成已持久化。启用正式 writer 前必须通过既有 generation/authority 迁移与激活流程，业务启动使用 `initialize_schema=false`。
- health 只返回事件数、frontier、各状态计数、focus 计数和 schema version，不返回主体表述、凭据或私有内容。

## 旧 ThoughtStream 迁移

旧数据不能自动变成主体决定：

- `title`、`reason` 可以成为供主体审阅的迁移候选，但不是已打开的 AttentionThread。
- `last_thought` 可能包含内部独白，禁止自动复制到 `public_statement`。
- `curiosity_score`、`advance_count`、衰减值、自动 dormant/completed 状态不进入新权威。
- 只有活跃意识实例在看到候选和当前主体上下文后显式 open/note/pause/close，才会产生正式事件。
- legacy facade 只负责旧调用的明确映射或拒绝，不得另建平行 AttentionThread 类型、存储或状态机。

## 验收要求

最低回归覆盖：逐 action 状态机、closed 终态、actor 缺失/暂停/租约过期、occurrence 幂等与冲突、并发同 revision、事务回滚、local/MySQL 共用合同、事件数据库不可变、稳定分页/篡改 continuation、1 MiB 正文、UTF-8 chunk、十万级 ref 有界投影、focus TTL/CAS、重启恢复，以及 health 不含内容。

## 旧快照的实际迁移形态

`streams.json` 只是一份旧系统当时状态的快照，不是 AttentionThread 事件账本。迁移层因此采用两套彼此隔离的数据：

- `attention_legacy_snapshots` 保存原文件完整字节、SHA-256、旧 schema/revision、状态计数与行哈希根；
- `attention_legacy_candidates` 按原顺序保存每行原字段的 canonical JSON 和行 SHA-256，只供审计与未来主体审阅；
- 两张表均禁止 UPDATE/DELETE，且 `import_mode` 固定为 `snapshot_only`、`generation_eligible=false`；
- `active/dormant/completed` 不映射为 `open/paused/closed`，`last_thought` 不写入 `public_statement`，导入前后 canonical event/head/focus 必须保持不变；
- 原文件先进入带 incomplete marker、逐字节副本和 manifest 的新归档目录；校验失败的目录永远不可消费，源文件绝不改写；
- 反向导出恢复的是原始 `streams.json` 字节及新的验证 manifest，不伪造旧事件历史。

MySQL 候选复制由 `scripts/migrate_life_attention_threads.py` 执行。它只接受总快照 manifest 唯一声明且物理 SHA-256/长度一致的 `life_engine_workspace/thoughts/streams.json`，使用 `CANDIDATE_COPY` fencing、同一 copy-authority run 和有界 MySQL 断线重试。业务启动继续使用 `initialize_schema=false`，迁移器不会改配置、激活 generation 或操作进程。

切换审计现在要求独立的 `attention_thread` copy run。旧快照本身永远不可激活；只有冻结快照、精确归档/导入/反向导出通过、数据库不可变触发器有效，并且新的 canonical Attention authority 从空 frontier/head/focus 开始时，canonical 域才可进入 generation。
