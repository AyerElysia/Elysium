# 统一机会运行时

状态：实施中。本文是用户已确认的设计和验收计划，不能作为尚未实现功能的交付证明。

## 目标与主体权利

机会让一件事在指定时间或有来源的事件发生后进入潜意识。爱莉决定是否处理、如何处理、修改安排、保持沉默或关闭。机会的到期、发布、看见分别是技术事实；均不代表接受、拒绝、完成或承诺。

爱莉拥有可选认知能力的安装、暂停、恢复、修改流程和卸载权。学习、回望叙事、记忆整理、文件整理、意向重逢等能力各自提供工程操作说明和可选 Skill；她可以选择、重写或替换自己的流程。时间、计数和工程状态可以决定何时展示事实，不能替她解释经历、判断重要性或选择行动。

主动心跳是一个周期唤醒机会：到时让潜意识查看近期事件，再由她决定做什么。初始配置只能标为 operator bootstrap，不能伪装成主体注册。她可以接管、调整、暂停或删除这个安排。普通入站消息与可靠持久化不依赖这个周期机会。

## 最小关系

1. 能力包：声明真实原子操作、依赖和生命周期，附工程 Manual 与可选默认 Skill。发现包不会自动安装，也不会覆盖主体流程。
2. 主体治理：不可变决定和当前 revision，记录启停、卸载、流程版本与安排。所有主体写入绑定活跃意识、来源和工具调用。
3. 机会运行时：到期生成稳定 occurrence，耐久发布到 Life Event，发出唤醒信号；完整模型送达后另记看见的证据。
4. 领域能力：继续拥有原有经历、候选、记忆、意向等权威。机会仅引用它们，不复制成另一套主体状态。

完整正文只存一次，投影视图有 UTF-8 预算、hash/ref 与继续读取路径。新机会经现有 Life Event → 潜意识近期/滚动上下文进入模型，不恢复每轮动态机会页。

## Skill 与执行

CAPABILITY.md 描述工程支持的操作和副作用。DEFAULT_SKILL.md 是可选的工程建议，不是爱莉已经选择的做事方式。她亲自提交的 workflow 以精确字节版本保存，保留 actor/source/occurrence/hash；修改流程不改变机器权限，也不把 Markdown 当脚本执行。

三个主体入口：nucleus_opportunity_query 查询；nucleus_opportunity_command 治理；nucleus_capability_call 调用当前安装、启用且 manifest 声明的操作。查询 protocol 可以逐个读取管理动作的真实参数。提交 workflow.replace 保存主体给出的精确字节，服务器计算 SHA-256；主体若提供校验值则必须一致。保存新版本不自动生效，必须显式 capability.bind_workflow 换绑；已有机会仍保留原先的固定 workflow，只有明确修改该机会才换成新版本。

对已有登记，`nucleus_opportunity_command` 的 `opportunity.schedule`／`opportunity.snooze`，以及 self_awaken 能力的 `opportunity.schedule`，复用同一 registration `CONFIGURE` 和精确 `expected_revision` CAS；改期不增加 HTTP 路由、参数或权限。`authority_committed` 与返回的登记 revision 只证明这次决定已耐久提交，不表示新时间已到期、机会已发布／看见或 workflow 已执行。省略的登记字段继续沿用原值，不由改期补造主体流程。

self_awaken 原生操作的 schema 与执行入口均要求正整数 expected_revision（不接受 bool、字符串或 0）。首次新建通过 nucleus_opportunity_command 的 opportunity.open，引用主体已选择的 provider／referent／workflow；schedule 不能当作自动 upsert，也不会静默恢复已关闭登记。

调用参数也必须可发现：查询 operation_schema，传入能力 ID 和 operation，读取目标工具的真实 schema；Learning 可再指定 action 披露内层参数。结果按 UTF-8 分块，提供整体 hash 和继续读取位置，不扩大执行权限。工程 Manual、可选 Skill 与参数 schema 各司其职，不能要求主体从说明书猜参数。主体明确提交空 workflow 也是有效版本；读取和重绑后均不得因空字符串而回退默认模板。

执行门继续校验当前意识的能力权限与原操作参数。专属旧入口在托管模式下必须从 capability_call 进入，不能绕过安装状态及在途执行管理；文件读写、事件查询、通用 Skill 等共享原语不会因卸载一个可选流程而消失。受控的 task-local 执行作用域不是模型参数，不扩大权限。

学习应能分别暴露反思、审计、整理和技能候选的操作。她决定调用次序；后台只维护可靠摄取和投影，不按固定顺序自行执行认知 LLM。通用技能和主体决定账本必须能独立于 LearningScheduler 存在。

## 卸载的效果

卸载决定提交后，立即阻止新机会和新操作；停止获取新工作，安全结束或取消已拥有任务，释放子系统自己的资源。再次启动仍保持卸载，只有新的明确安装决定可以恢复。重装也不自动消费旧积压。

暂停/卸载会取消该能力已经登记的在途调用和排队调用。超过有界取消期限仍未退出时，保持禁止新调用，health 报 degraded，不能谎报已停止；主体治理决定仍然保留。当前调用管理自身时，不等待或取消自己，其他旧调用照常取消。停止服务时先停止机会扫描和心跳消费者，再关闭能力，最后关闭共享资源；关闭失败保留诊断和可重试 owner。

已有事件、已采用技能、主体文档和卸载决定保留。保留历史不能被用作继续运行学习的理由。Life Event、身份、持久化、幂等与权限保护承担可靠性，不属于可选认知流程。

## 持久化与故障

只消费 LifeEngineService 已打开的同一 StorageBackendRuntime。当前托管模式要求 storage.enabled 的 selected local/MySQL；storage.disabled 的旧本地 Life Event 库与 proactive 库不是同一个权威，启用托管时明确拒绝，不用跨库确认冒充一致性。旧模式未切换时继续兼容运行，不迁移或搬动旧库。业务启动不修改正式 schema；独立迁移负责安装表及不可变约束。主体决定使用 occurrence 幂等和 revision CAS；同 identity 异内容显式冲突。调度者使用数据库时间与公开 singleton claim，不另建租约体系。

selected local 的就绪验证同样核对不可变 trigger 的完整名称、所属表及受控 SQL 定义，不只检查表存在。缺失、错表或错误定义均拒绝就绪；业务启动不偷偷补建或覆盖约束，必须经明确的 schema 准备/修复流程处理。MySQL 保持对应数据库触发器合同。

到期状态与发布 outbox 同事务提交。Life Event 使用稳定 occurrence 追加；发布成功后 ack 失败可幂等重放。入账不等于看见。看见只由最终成功模型 attempt 的精确回执及本批确实包含的事件身份证明。截断、未知、重复或缺失回执均不确认。

暂停/卸载必须阻止尚未发布的机会继续发布。取消不抹掉已经发生的事实。一个能力失败应保留工作并报告自己的健康状态，不能替其他能力作决定。

### 显式改期与旧发生的边界

登记 `CONFIGURE` 追加新的权威 revision，activation 是据此维护的可重建调度投影。旧 occurrence 仍 pending 时，清理过期投影不能同时将 `registration_revision` 伪装成已应用的新 revision 并清空 `next_due_at`；否则后续扫描无法识别新安排尚未接续。改期清理保留旧的已应用 revision，等待 `materialize_due` 在同一 scheduler owner、数据库时钟和事务边界内按新 `first_due_at` 安装新 revision。能力暂停时既有失效／恢复分支继续受能力状态门控制，不因这一修复自行恢复能力。

- 旧发生尚未发布：可以明确取消其 pending outbox 并释放旧 activation 占位，旧 occurrence 与登记历史仍保留；新时刻以前不产生新发生，到期只物化一次绑定新 revision／scheduled_for 的 occurrence，重复扫描不能重复。
- 旧发生已发布但未 seen：保留 publication 和实际 Life Event，不因改期伪造取消事实、seen 或完成；释放过期的调度占位，使新安排不被旧发生永久阻塞。旧发布是否作为再次唤醒来源仍受当前登记 revision／状态与能力状态门约束。
- 迟到的发布确认：只有实际 Life Event 身份、因果和正文 hash 核验一致时，才能补记已发生的发布事实；即使 outbox 曾在交错中取消，也不能否认已经落账的事件。但补记旧发布不能把旧 activation 重新装成新安排或覆盖当前 pending。
- 迟到的精确 seen 回执：继续按原 occurrence 与成功模型 attempt 验证、追加不可变事实；调度 reconcile 只处理与当前 pending 对应的发生。旧回执不能替新 occurrence 确认 seen，不能覆盖新 `first_due_at`、倒退 revision 或抹掉已发布历史。

上述均为时间、身份、并发和投递合同，不自动执行 workflow，不解释成接受、拒绝、完成或承诺。`at`／`interval`、暂停／关闭／能力停用、迟到回执及重开交错须分别验收；合同说明不等于这些分支已全部通过测试。

## 当前代码接入边界

新实现分为 `opportunity/catalog.py`（工程包发现）、`registry.py`（受控执行）、`runtime.py`（主体治理/有界披露/发布与看见）、`storage/opportunity_*`（同一 runtime 内的耐久合同）。`service/opportunity_runtime.py` 只绑定服务已拥有的 runtime，不创建第二数据库连接权威，也不关闭注入资源。

`opportunity.enabled` 是本轮迁移阶段的显式部署开关，默认 false；不能把“代码已写入”说成“正式实例已完成切换”。尚未完成旧安排迁移、卸载旁路验证和手动启动验收之前，不修改生产开关。打开后，机会调度只发布 availability Life Event；旧固定周期心跳改为等待机会唤醒，仍使用原有串行模型执行路径。初始 operator bootstrap 与旧安排迁移仍是未完成验收项，禁止用伪造 active actor 自动采纳模板。

共享 `SharedLearningProjectionRuntime` 保存 Insight/Skill 投影视图及主体决定账本；服务负责一次 initialize/close，LearningScheduler 借用并可请求 flush。无 projector claim 时允许读取已持久化视图，但同步 mutation 在改内存前拒绝。`nucleus_skill` 使用公开服务入口，显式主体写入绑定 actor/source/subject revision，并在 flush 完成后才返回成功。记忆复盘的权威依赖不再是 LearningScheduler；旧 Learning cadence 镜像不属于记忆复盘的事实权威。

机会发生冻结注册 revision、来源引用和 workflow hash。重复发布沿用同一 Life Event identity；最终模型回执记录真正 request/attempt identity 和成功完成时间。发布、看见、接受、完成不合并。已经发布但未被精确看见的机会，只有仍对应当前 open 登记 revision 且能力 enabled 时，才作为重启后再次唤醒的来源，不重新伪造一个发生；改期淘汰其调度资格不删除原发布事实。完整正文未进入本次精确文本时不推进其看见状态。

每种能力包都附工程手册、可选默认 Skill、真实参数披露和资产测试。目前已纳入目录的九类为 self_awaken、learning、memory_review、narrative_review、file_care、epistemic_explore、initiative_reencounter、todo_reminder、inner_return。安装不等于安排，安排不等于执行；除下述 initiative 来源桥外，这些包不会从旧计数/到期条件自动产生机会，而由主体显式登记 manual/at/interval 或当次调用。不能声称尚不存在的动态生产器已经运行。

## 迁移与旧入口

显式运维切换另有不可变的 opportunity_runtime_meta 标记。服务只读该标记，不在启动时创建或修改它；标记一旦存在，旧配置的 false 不再恢复旧自动链，健康检查报告 durable_cutover 来源。建表、写切换标记和主体安装能力是三个不同动作，均不得相互冒充。全新空目录不会自动安装默认能力，初次安排由主体经工具明确决定。

意向重逢桥接只读取主体已经明确设置的时间与原事件身份，引用类型为 initiative.reencounter_reference.v1；其 hash 校验引用清单，不冒充意向正文 hash。正文仍由原意向权威查询。已经关闭的机会不会因源记录仍然存在而重开；扫描以稳定身份轮转，避免旧关闭项占住第一页。旧意向账本的技术投递确认只在 availability 实际进入 Life Event 后记录，不当成主体已经看见。已承诺的外发/回声投递恢复继续属于可靠投递层，不借“机会”重新做一次语义决定。

托管模式明确退役旧独立生命定时器的创建/恢复/回调，以及旧机会页；历史登记不删除。聊天到达不再自行触发认识论候选 LLM。探索、叙事、学习等具体做法由主体通过安装能力和所选 workflow 调用，工程不将“新消息”自动解释为应该反思。

发布回执还必须在同一存储中核验 raw_life_events 的实际 occurrence、类型、来源、因果身份与正文 hash。先发布再被暂停时，真实发布仍然保留为历史；没有实际事件的确认必须拒绝。暂停不会抹掉事实，历史事实也不能使暂停的安排自动复活。

原意向账本的补记不夹在 Life Event 追加与机会发布确认之间。源扫描按稳定机会 ID 查询 latest_publication，使用已经落账的 Life Event identity 和稳定发布时间幂等补记。即使源补记失败或能力随后卸载，下次扫描只恢复这一历史事实，不另建机会，不把“已发布”说成“已看见”。

托管 Learning 初始化失败时，能力保持未就绪；旧服务启动分支不能再次构造 Learning 来绕过失败。关闭失败保留原 owner 供重试，不丢掉资源引用后假装卸载成功。无 Learning projector owner 的实例不启用可写 Learning 能力，但共享已持久化 Skill 的只读访问仍可保留。

准备与切换步骤见 [机会运行时切换与验收](../operations/opportunity-runtime-cutover.md)。准备工具的默认 dry-run 不连接数据库；verify/apply 使用 writer-capable runtime，绝不是可以在运行中随手执行的纯只读诊断。

本地显式维护模式 --activate-local-authority 与正式服务共用单实例入口锁，只激活已验证且当前无 active owner 的本地 generation。锁覆盖激活、schema 操作、撤销与关闭；失败／取消不得留下仍在后台取得写权限的操作后提前放锁。该模式不写能力、工作流或登记，不代替主体选择。

完整模型送达后，heartbeat 的后续 checkpoint 仍可能失败。看见的事实不能回滚或改写；后续成功 attempt 可以形成新的精确回执，不能因旧 occurrence 已看见就拒绝新的真实证明。服务恢复仍未完成的事件确认时使用现有串行消费者和有界退避，不新建并行 LLM 任务；重启也检查未确认的机会 Life Event，不只依赖首次看见的 outbox。

## 可检验的用户场景

- 她注册一个周期机会，重启后仍按同一安排出现；旧发生尚未发布或已发布未 seen 时明确改期，新安排按新时刻接续、不提前、不重复，旧发布与迟到回执不被删改或误用。
- 她读到机会并选择沉默，历史只记录已经看见，不产生拒绝或完成。
- 她改写学习流程，可改变调用次序和使用范围；协议和权限仍由原子能力执行。
- 她卸载 Learning，学习机会、后台认知调用、旧工具旁路均停止；记忆和通用 Skill 继续可用，重启不复活。
- 发布后进程中断，恢复只重放同一 occurrence；未真正送达的机会不被确认。
- 一个插件出错，其健康可诊断，其他机会仍可查询、治理和交付。

## 当前验证边界
