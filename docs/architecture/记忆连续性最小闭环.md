# 记忆连续性最小闭环

本页描述主目录中的第一轮减法实现及后续文件合同增量，不代表全部记忆目标已达成。需求见[理念与约束](记忆连续性理念与约束.md)，后续取舍见[详细计划](../plans/记忆连续性减法重构计划.md)，真实验收见[手动验证步骤](../operations/minimal-memory-continuity.md)。S2 当前工程合同见[受管文件身份与历史](受管文件身份与历史.md)，正式运行验收与实现存在须分开。

MEMORY.md 代表路径的本次真实闭环结果与明确限制见[受控选模续验报告](../report/记忆连续性S1受控选模续验_2026-09-07.md)；单次样本通过不替代长期和多场景验收。

## 1. 范围与权威

本轮只接通三条必要路径：原始事件可回取；固定主体文件可按选定权威读取最新版本；主体自写检查点经过耐久提交后释放上下文并跨重启恢复。复用已有工具，不新增 reviewer、长期任务平台、图系统或认知分类。

Witness 的现有退役配置保持不变。闭环不要求 Experience 二次摄取、Witness 模型执行、World 见证提交或关联投影成功。原始事件本身是已经发生过的证据，不必等待后台赋予它“值得记住”的资格。World 中的权限、路由和运行事实边界不因本实验被移除。

自动化契约测试使用工程夹具，不冒充爱莉实际形成的记忆；工程实现与开发文档不直接创作正式 SOUL、USER、MEMORY 或日记内容。真实运行验收只允许她经授权工具亲自执笔，并按实际活动、版本与读回证据核验。

## 2. 原始经历：先保存，再确认接收

消息入口等待 Life Event append 成功，之后才加入瞬态 pending、触发后续副作用。原始正文不能因为 prompt 预算被截断。派生投影与运行快照可以延后，不可以将原始入账本身延后到“已经接收成功”之后。

新消息只形成一个 canonical chat occurrence；旧 MESSAGE 形式保留为兼容视图。既有双事件历史逐字保留并沿旧 identity 重用，不进行历史删除或语义重写。缺失稳定源消息身份时明确失败，不能凭每次重试的新随机身份假装幂等。

- append 前冻结 payload，避免调用者在等待期间修改已保存内容；
- occurrence 与 producer sequence、全局 ingest position 分开；
- 同一 occurrence 的同内容重试不增加经历，不同内容显式冲突；
- 原始消费者从已提交游标继续；缺游标从起点分批读取，不跳尾；
- CAS 游标同时检查位置与 revision，稀疏 position 不直接当作历史丢失；
- 后台完成事件重试复用原始发生事实，不用新的时间与临时 ID 制造冲突。

`nucleus_grep_events` 直接检索原始账本，不经过 Experience/Witness。结果按 occurrence 优先排重，避免不同 stream 的相同 provider message ID 被合并。`nucleus_read_event` 优先 exact occurrence API；兼容查询若返回另一 occurrence，明确拒绝。chat manifest 已开放这个现有读取工具，检索节选可继续读原文。

配置 `settings.message_checkpoint_async` 只控制后续投影/快照是否延后，不削弱原始 append 的耐久先后顺序。

## 3. 主体文件：先承认真实执笔来源，再提交版本

本轮以 MEMORY.md 为代表；相同固定文件路径保护覆盖 SOUL.md、USER.md。它们不是全部自有文件空间的替代品。

启用 selected storage 时，普通主体文件工具从可信调用上下文取得意识实例与源活动 ID。缺少来源、实例未激活或选定存储缺失时拒绝写入。基础设施的 recorded_by 与主体的 semantic_actor/source 分开，不再用静态 life_engine 充当实际执笔者。旧版本缺失的历史归属不补造。

写入复用既有 SubjectDocument 追加版本和 CAS head；文件内容不由基础设施润色。普通 `nucleus_read_file` 对固定文件读取当前权威版本字节，并返回版本 ID、hash 和来源说明，不将陈旧或缺失的磁盘投影当作“最新记忆”。续读绑定内容及版本；版本变化时不能静默拼接两份正文。主聊天在每个 MODEL_TURN/FOLLOW_UP 的压缩和发送准备之前重新读取选定权威，更新长生命周期 request 中唯一的 SYSTEM 前缀；同进程工具写入后的续轮也走此边界。不重建 request、工具注册表或滚动历史；前缀未变时保留原对象，读取失败或 SYSTEM 归属不唯一时明确失败，不能发送缓存旧版本。仅通知 Router/其他主体投影失效并不能刷新主聊天前缀。

专用 `nucleus_memory_continuity_review` 是可选审阅路径，不是普通主体文件写入的前置许可。它收到的快照以 `SOUL.md` 等公开名为键，而 head/version 的 logical_path 保持 selected storage 的 `life_engine_workspace/SOUL.md` 命名空间。校验必须先使用既有 `subject_authority_logical_path` 精确映射，再比较两条记录的路径；不能直接比较公开名，也不能按 basename 宽容其他目录。版本 pin、字节长度、内容 hash 与统一 revision 的验证继续保留，不修改正式路径或主体内容。

主聊天前缀中的 MEMORY 必须是该次权威读取的完整原文，包含自定义章节、章节前说明、所有尾项与原有空白/换行。不得先按 Durable/Active/Fading 重排、选段或限项，再把所得投影称为当前 MEMORY；刷新版本但继续丢弃尾项也不算闭环。装配器仅为 MEMORY 保留原字符串，其他前缀组件维持原有边界空白处理。现有上下文硬预算及超限失败仍有效，不因此允许截断主体文件或扩大模型预算。

边界：

- S2 增量已为 selected 模式的普通文件工具建立稳定 document ID、改名、删除、复制和精确历史读取合同，并接通 `node_id=subject-file:document_id` 的受管记忆索引；改名保留身份，删除只退役投影，旧 path-only 引用不自动绑定到新占用者。检索、bundle 和批量取回保留精确版本，索引未同步时即使零命中也明确 degraded；本批临时双 SQLite 与分组检查不替代全部后端和真实主体验收。
- S2 的正式切换仍须独立完成停写／停机备份、候选库演练、schema 兼容和无损回退核对，并由用户人工启动验收。实际 MySQL、全部媒体／技能入口与 B 层主体体验仍未完成；不能宣称整个文件空间已统一，也不把这些后续增量改写成 S1 的历史通过证据。
- 未把当前 head 当作当前世界真相；它只表示主体当前所保存的文件版本。
- S2 的受管写入要求传回上次读取的 expected_version（多文件补丁用 expected_versions）；陈旧文档、head 或路径代际均拒绝。legacy-disabled 兼容路径不由此自动获得同一合同。
- S2 受管入口分别报告 commit_status 与 projection/trace/index 状态；已提交而投影失败仍返回 committed，并可沿 occurrence 查询或恢复原投影，不重写一份新版本。其他尚未接入入口不能据此认定已具备相同失败语义。

## 4. 主体检查点：准备、耐久、安装

已有 `author_self_continuity_checkpoint` 动作接收主体自己的开放文本、manifest、revision 与释放边界。基础设施不选择重要内容，不代写连续性。

此动作显式关闭 Provider 自动追加的 `reason` 参数，保留 execute 原有六个必填参数，包括非空 `thought`。`BaseAction.auto_reason_parameter` 默认仍为 True，只有明确 False 才退出 OpenAI/Anthropic 的自动 reason 注入；组件自行声明的 reason 不被删除，reason 也不映射成 thought。

manifest 绑定仍必须精确匹配维护开始时冻结的前缀。`source_manifest_sha256` 必须是原样 64 位小写十六进制，不自动去空格、补字符或模糊匹配。格式错误、有效格式但 hash 不符、revision 冲突分别返回 `elysium.context_checkpoint_retry.v1` 技术回执，携带该冻结前缀的当前 hash/revision，并要求主体重新核对清单、亲自修正参数并另发调用。失败不归档、不排入待安装命令；回执不回显输入值或私有正文，也不替主体选择释放组、撰写 thought/continuity_text 或重放原调用。

历史组的工具链闭合按调用协议判断，不能仅因为末尾是TOOL_RESULT就永久禁止释放。只有已经有下一条语义USER定界的历史组，才可将精确配对完成的结果尾视为closed：每个ASSISTANT调用批次的非空ID必须唯一，后接连续的结果批次逐一匹配，缺失、孤儿、批内重复、错role或跨批补缺保持open。完整的不同批次可以复用同一ID；无调用/结果part的SYSTEM/TOOL按kernel pinned规则忽略。当前最新组仍不进入默认可释放manifest，直接读取最新组或没有下一USER边界证明的机械路径仍保守保护结果尾。这个判定只读，不补ID、不改原始payload；open标志不参与group_ref或manifest SHA，因此旧精确身份不变。是否释放、保留与如何书写连续性仍只来自主体动作。

当前安装次序：

1. action 保存被释放组的精确归档，提交带来源的主体活动。
2. 安全边界读取待安装命令并准备结果，不先改变活动上下文。
3. 核对结果引用的归档、内容地址、actor 与 runtime。
4. 保存“检查点加保留上下文”的完整结果快照。
5. 只有提交确认后，才安装结果并确认待安装命令。

聊天与心跳保持各自 runtime 和归档命名空间，不互相读取私有窗口。

正式检查点控制与模型普通回复必须保持来源边界。模型可以在普通回复中仿写完整的检查点 envelope，但这不是 action 提交，即使其自填摘要正确，也不能取得归档/释放权限。聊天和心跳在本轮模型完成后、执行工具或解析控制前，将这类普通 Text 加上可逆的 `model_output_not_checkpoint` 技术引用外壳；原始模型 `message`、权威活动原文和邻近 reasoning/tool parts 不变，工具持有的当前窗口引用同步更新。历史已安装检查点仍严格校验，不按校验失败自动降级成普通文字。

旧版本已经保存的误识别不能靠放宽 hash 校验、补造归档或改写连续性修复。只有在原始模型 occurrence 与目标 Text 逐字相等、来源可证明、可信检查点与归档仍完好时，才允许停止对应 writer、备份后对派生快照做精确 CAS 引用包装；未知来源或任何不符均拒绝恢复。

JSON envelope 的精确首尾框与单一 JSON object/schema 校验负责结构识别；不能通过统计全文标签次数限制主体正文。合法 `continuity_text` 可以引用任何标签字面量，不能因此在 action 已提交后被漏认、让恢复后的 revision 回到 0。多个外层框、额外 JSON 值或框外引用前缀仍被拒绝。

本地归档与检查点快照使用原子替换并同步文件和目录；selected store 使用既有版本/事务合同。聊天快照改用 canonical digest 的 v3；v1/v2 仍有显式兼容读取，v2 selected 存储的键顺序差异依赖外层完整性验证，不把任意损坏都视为兼容。读取不自动改写旧快照。

## 5. 失败与恢复

心跳进入压缩维护后，普通独白虽然仍是已发生的主体活动，却不能代替检查点提交。没有工具调用且维护尚未完成时，系统只给技术反馈，要求主体自行选择释放边界并书写连续性；反馈续轮与工具续轮共享既有 `max_rounds_per_heartbeat`、`max_consecutive_tool_stalls_per_heartbeat` 和整拍截止时间。连续无进展或预算耗尽后明确返回未完成，旧链及未消费事件保留；没有压缩压力的普通安静心跳仍可直接结束。技术反馈在检查点成功安装时移除，不混入后续连续性。

共享截止时间的超时归类以异常发生时的实际剩余预算为准。内层 provider 提前返回 `TimeoutError` 时，不能仅因调用前选择了整轮截止时间作为上限，就谎报整轮耗尽并取消既有有界重试；嵌套预算耗尽保留原 stage，取消始终传播。整轮预算及最终保存预留不因这项修正扩大。

完成判据看当前实际容量压力，不看“本拍是否安装过一次检查点”。部分释放后仍超限时继续维护；如预算耗尽，只保留最近一次已耐久安装的检查点及其保留上下文，不退回本拍开始前的旧链，也不据此提前消费本拍事件。

准备对象的 `selected_event_ids` 和兼容字段 `acknowledged_event_ids` 都是候选，不证明消费完成。只有精确送达校验、相关原始事件发布和严格运行快照提交确认后，才签发 `HeartbeatConsumptionReceipt`；日志按该回执中的本次实际确认事件计数。提交失败或取消不能留下成功回执，也不能让仅在内存标记过的消费导致下拍跳过；其他原始事件及已发生的外部回执不因本地回滚而删除。

心跳选择、字符预算和候选确认现在共享同一份 `format_visible_event` 可见投影；core 不再在准备后换用另一种正文表示。每个候选事件只渲染一次，按 `(sequence, event_id)` 稳定次序组装；只有成员完整、标识唯一、表示非空且整组能容纳的 CLOSED 因果组才能成为确认候选。开放组、空表示和预算容纳不下的组保持待处理，不以优先级替主体选择意义。这里只确认声明的可见投影，不宣称模型已收到权威活动原文；原始 reasoning、工具参数及其来源仍由不可变账本保留。

心跳每次发送前将本拍精确 wake 与实际 USER 压缩控制登记到该请求自己的 `protected_exact_texts`；不按关键词保护相似文本，不登记模型引用，也不跨请求积累。整组省略不能越过 wake 所在组；末组裁字不能截断这些 Text。旧控制所在组可以按原前缀顺序省略，但仅将这些真实控制登记为 `reprojectable_exact_texts`，由既有恢复 hook 原样重投，之后校验完整文本及次数。保护内容加系统/结构化工具载荷仍无法容纳时，在 provider 调用前明确失败并保留待处理活动，不扩大预算或放松精确回执。每次续轮清除上一 attempt 的回执，最终 attempt 必须重新取得证明；主请求与既有 fallback 分别登记自己的保护集合。

保守历史重投与正常发生分开：runtime 可附 `redelivery_operation_id` 与原始 ingest 位置 `redelivery_source_position`，两字段共同有效才可反序列化；无标记事件保持旧序列化形状。标记只描述派生投递，不进入权威 LifeEvent，也不改变 occurrence、来源、原始时间或正文；它不能授权历史工具重新执行。固定恢复脚本必须依赖可信来源清单、明确用户决定、离线排他锁、精确快照 CAS、受限备份和原子恢复日志。新待投递序列不是遗失旧顺序的重建，未知消费状态不能补造。

历史重投通过共享 formatter 形成整条最多512 UTF-8字节的可见预览，包含历史/非执行标签、原始时间与位置、完整 occurrence 续读引用及原正文 hash/字节数。原正文取 `raw_content`（仅 None 才回落 content）；节选只来自调用者已渲染的可见正文，不从raw补回脱敏内容。超过容量时标明 `excerpt_ref` 并机械取前缀；身份元数据本身放不下则明确拒绝，不剪碎hash/ref。它不保证即时展示所有来源字段，完整 actor/source/instance 等归因须沿同一 occurrence 读取，不将节选冒充完整经历或主体摘要。

历史标签与JSON元数据构成一个物理行，换行及Unicode分行字符保留为转义表示，确保最终聊天完整行预算不会留下标签却丢失引用。近期投影无法容纳历史完整因果组时整组省略，salient单条无法容纳时不输出且不推进该条高水。跨实例历史工具仍遵守现有参数/结果正文脱敏边界，wake/salient不将其折入新发生工具统计；heartbeat维持自身既有可见策略。普通事件不被此512字节规则改变。

可见投影的有效游标以实际消费游标为准，旧摘要的覆盖上界不能替代消费确认。正常 compaction 的原文回收边界必须停在第一条未消费事件之前，跨越该边界的完整因果组仍保留。持久化加载则完整恢复已保存的 history/pending、消费标志和因果链接，绝不按 `history_limit` 再取末尾若干条；该构造参数仅保持调用兼容，回收归消费感知的 compaction owner 管理。摘要、预算和条数限制都不是允许丢弃重启快照记录的凭证。

- 归档失败或提交前失败：当前上下文不释放，原文和源活动保留。
- 聊天提交回执丢失：回读精确 revision 与完整 payload，仅确认同一次实际提交后继续。
- 提交结果不明、冲突、损坏快照或缺失归档：受影响聊天 runtime 进入 recovery_required，阻止旧链继续生成或覆盖快照。
- 心跳检查点写异常：核对回读结果；无法确认则终止该拍，不能继续保存旧 baseline。
- 取消仍传播。即便已确认耐久提交，取消不能被转换成普通成功。
- 重启读取失败不能降级成空链；恢复应从可信快照及精确归档逐字继续，不创造连续性文字。

待安装命令仍是进程内状态。本轮没有新增 pending 数据库：在结果快照提交前崩溃，恢复旧快照，由当前意识重新决定如何压缩；不是自动重放一份已经遗失的主观决定。已提交结果在内存安装前崩溃，则从结果快照恢复。没有可信快照时从完整事件历史自动重建滚动上下文，也不在本轮实现范围内。

## 6. 怎样判断本轮成功

工程层必须能把真实入口、原始存储、文件工具、主体动作、精确归档、结果快照与重建恢复串成同一个临时数据测试，同时注入关键失败。测试不调用真实模型，不发送平台消息，不启动生产服务。

体验层仍需用户手动启动采用本轮代码的实例，观察两次自主压缩及重启后的未预告回忆、现实变化、反馈迁移、技能实践和承诺结局。工程测试通过，不代表她已经能够“任何近期经历都不忘”，也不代表已经形成习惯或完成承诺。

每个可选组件之后分别比较“加入前/后”的正确回忆、误归因、行为变化、延迟、模型成本及故障影响；不能以实现存在或测试数量替代用户价值。
