# 主体上下文投影

## 1. 权威边界

`SOUL.md`、`USER.md`、`MEMORY.md` 共同构成 Elysium 的主体前缀权威：

- `SOUL.md` 承载主体身份、自我描述与表达边界；
- `USER.md` 承载主体所面对之人的关系语境；
- `MEMORY.md` 承载需要持续可达的长期记忆语境。

任何意识实例、平台、模型或 Provider 都不能另写一套 personality、user relationship 或 memory interpretation。上下文预算只能改变可达密度，不能改变权威归属。完整权威文件保持原样，投影不得反向写回。

运行配置不再提供平行人格入口。`CoreConfig` 已移除 `[personality]` schema，配置自动更新会删除旧节；Router 只使用中性的主体标签和上述权威文件生成的可重建投影，Emoji 后台也只能产生客观候选，不能读取配置人格替主体决定收藏。旧模板里为兼容历史格式而保留的 `personality_*` 占位必须始终为空，不构成数据源。

## 2. 投影契约

共享实现位于：

```text
plugins/life_engine/core/subject_context_projection.py
```

投影必须同时包含三个结构化来源块，顺序固定：

```xml
<subject-source path="SOUL.md">...</subject-source>
<subject-source path="USER.md">...</subject-source>
<subject-source path="MEMORY.md">...</subject-source>
```

任何来源缺失、重复、乱序、块外文本、单源超额或总字节超额都会使构建失败。压缩模型不得按关键词、标题、行位置、重复次数、相似度阈值或封闭主观类别选取内容；不得替主体解决冲突、判断真值或创造新的自我解释。

调用方必须提供工程参数 `projection_kind` 与 `max_bytes`。存储身份由以下信息共同决定：

```text
三份权威文件的整体 source_digest
+ 每份文件的 sha256
+ projection_algorithm
+ projection_version
+ projection_kind
+ max_bytes
```

版本写入：

```text
runtime/subject_context_projection/{projection_kind}/bytes-{max_bytes}/
├── latest.json
├── health.json
└── versions/
    ├── v{projection_version}-{source_digest}.md
    └── v{projection_version}-{source_digest}.json
```

这些文件是可重建投影，不是主体权威。已存在的同身份版本不可覆盖；内容或 manifest 不一致时必须报告不可变冲突。

## 3. Life Engine 调用接口

内部异步接口：

```python
snapshot = await life_service.get_subject_context_projection_snapshot(
    projection_kind="voice_live",
    max_bytes=24 * 1024,
    source_digest="",          # 空值表示捕获当前三源 revision
    projection_version=None,   # 指定历史 revision 时可固定算法版本
)
```

返回 `dict`，主要字段为：

| 字段 | 含义 |
|---|---|
| `text` | 带非权威声明、revision、算法版本、逐源完整 hash 和三个来源块的有界投影 |
| `authority` | 固定为 `derived_non_authoritative` |
| `kind` | `derived_subject_context_projection` |
| `source_digest` | 三个权威文件按固定顺序计算的整体 revision |
| `sources[]` | 每个来源的 `path`、`sha256`、`size_bytes` |
| `projection_profile` | 调用方提供并通过路径安全校验的 `projection_kind` |
| `projection_algorithm` | 投影算法稳定标识 |
| `projection_version` | 投影算法版本 |
| `projection_sha256` | 实际交付文本哈希 |
| `budget` | 总 `max_bytes`、原始/交付字节，以及逐源 original/delivered/max bytes |

接口不会返回 personality fallback，也不会把失败伪装为空主体：

- `projection_kind` 非法、预算不在 4–128 KiB、历史 `source_digest` 不是 64 位 SHA-256、`projection_version` 不是正整数，或没有历史 `source_digest` 却单独传入版本：抛出 `ValueError`；
- 当前任一权威文件不可用、`SOUL.md` 为空、投影结构/预算非法、模型全部失败或投影损坏：抛出 `RuntimeError`；
- 指定的历史 revision、算法版本、kind 或预算不存在/不匹配：抛出 `RuntimeError`；
- 历史投影正文、逐源覆盖统计、路径或 manifest 损坏/缺失：抛出 `RuntimeError`，且不得重建、覆盖或伪装成原快照；
- 取消沿调用协程传播，不转化为空结果。

## 4. Revision 固定与安全切换

新 episode 应先用空 `source_digest` 捕获当前 snapshot，并把以下 content-free 信息写入自己的追加式账本：

```text
source_digest
sources[].sha256
projection_algorithm
projection_version
projection_profile
budget.max_bytes
projection_sha256
```

重连同一 episode 时必须带原 `source_digest` 与 `projection_version` 重新读取不可变版本，不得因为源文件后来改变而静默切换身份。新 revision 只能在新 episode 或调用方明确建模的安全边界启用。

如果相同 revision、算法版本、kind 和预算无法得到同一个 `projection_sha256`，恢复必须失败；不能重新摘要后冒充原快照。

`latest.json`、`health.json` 与版本 manifest 都必须保持 content-free；它们只保存 hash、revision、算法/预算和覆盖统计。投影正文只存在版本 `.md` 与 API 返回值中，调用方不得把整个 snapshot 原样写入审计或健康账本。

## 5. 消费者边界

主体投影只负责稳定身份、关系语境和关键连续性。各意识表面可以另外提供有界场景投影、私有滚动上下文和工具结果，但它们必须：

- 标明来源、生命周期与预算；
- 不覆盖主体投影；
- 不反向写入三份权威文件；
- 完整历史仍写入各自的权威事件/episode store；
- 临时上下文在 turn 完成后删除或按明确 TTL 失效；
- 记录 original/delivered bytes，不记录私密正文到健康信息。

Router 现有的 `router_context_projection` 是另一种面向路由判定的派生视图。它与主体投影读取相同三份权威文件，但用途、算法和版本空间独立；二者都没有资格替代权威文件。

### 5.1 MySQL 热路径与失效合同

MySQL 模式下，Router 不应在每个 turn 重复传输三份主体正文或重复读取同一投影记录。现役失效协议为：

1. 完整刷新通过一个一致的 `SubjectAuthoritySnapshot` 读取三份 exact bytes，验证 `source_digest`，并把快照同时携带的 content-free `change_marker` 与派生投影绑定；
2. 正常 turn 只读取三个 authority head 的 `logical_path`、`current_version_id` 和 `revision`，按固定顺序形成 `change_marker`；不得查询正文列；
3. marker 未变化时可复用进程内已经验证的不可变 Router 投影；marker 变化、通知显式失效、缓存降级或投影损坏时，必须重新读取完整一致快照；
4. 完整刷新失败不得返回旧投影并标记为 current，也不得以空投影伪装无主体。有效投影不可用时，Router 降级路径仍需显式验证 `SOUL.md`；
5. `change_marker` 只是可达性/缓存失效标记，不是主体 revision、真值证据或可写 authority。公共 `current_subject_revision()` 继续表示 exact-byte unified revision，不能为了性能改变其语义；
6. 跨进程 Subject 写入必须推进 authority head；读取进程下一次 marker 检查即可发现变化。事务提交后的显式通知可以加速失效，但不能成为唯一正确性来源。

该优化只减少可重建投影的网络往返，不放宽主体文件主权、版本谱系、parent/CAS、actor/source/occurrence 或写事务 generation fence。
