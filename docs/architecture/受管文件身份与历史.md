# 受管文件身份、历史与投影

本页描述 S2 工程合同。原有限范围已于本地 2026-09-07 22:53 完成 A／B 及重启后真实 glob、v1／v3 全文读取和主体反馈，详见[第二阶段实施清单](../plans/记忆连续性第二阶段实施清单.md)。这不代表全部文件入口／媒体／脚本统一，不替主体判断语义、真值或成熟度；S3 由根代理后续独立计划。

## 权威与适用范围

启用 selected storage 后，现有 read/write/edit/apply_patch 对工作区普通文件使用同一 SubjectDocument 存储，不按扩展名判定作者或语义。工作区所有权与正文作者是不同字段。未登记的磁盘文件先保持外部文件身份；第一次修改或生命周期操作前逐字捕获旧版，semantic actor/source/time 保持未知，不把迁移保存当成新写作。

已有 document/version/occurrence ID 原样兼容。新文件取得不随路径变化的 document_id；路径绑定及其单调 revision 描述当前地址。不可变版本、head events、path events、operations 保存发生事实；current head、路径绑定、文件和索引是派生视图。复制创建新 document，普通逐字复制保留正文原来源，复制行为另有实际 actor/source；带明确内容修改的复制记录新写作来源。

固定 SOUL.md、USER.md、MEMORY.md 可以由活跃意识的授权文件工具改写正文，不需假造学习候选；改名、删除和通用复制仍受固定角色保护。它们不能被当作目录，运行数据库、历史目录和其他独占运行路径也不能由通用工具覆盖。开发者不能代写主体语义。

未启用 selected storage 的旧本地路径仍是兼容模式，不由此获得完整 S2 历史合同。媒体原件、预览、转写、技能包和脚本入口的范围分别盘点，不能拿文本链路通过代表所有入口完成。

## 运行时装配与显式维护边界

selected runtime 的资源所有权先由服务取得，subject store 再从这个已经打开并由服务拥有的同一 runtime 提前挂接，然后才构造 Memory。提前挂接只涉及 subject store；后段存储初始化复用同一对象，其他存储域、runtime_state 与上下文加载不前移。selected 模式缺少 subject store 时必须在 Memory 构造前明确失败，不能把 None 固定为 owner 句柄后继续恢复，也不能以未恢复的空上下文写 checkpoint。重复挂接保持幂等，不另开 runtime／engine 或制造第二 writer。

业务启动继续使用 `initialize_schema=False`，不隐式创建或升级 subject schema。已部署旧 schema 的升级必须由显式维护操作执行：先确认停写、目标及完整备份／候选验证，再通过既有 generation 的真实维护租约取得 owned runtime，在有效 authority fence 内调用幂等 schema ensure。维护退出栅栏后撤销租约并关闭资源；不能用复制来的 ACTIVE token、候选写权限、原始 registry 改写或业务启动旁路替代正式维护。subject schema5、LOCAL memory7、MySQL memory15 与全局 storage schema 是不同域，不能混同版本号或自动切换 generation。

## 读取、修改与重试

- 当前读取解析当前路径绑定，返回 document_id、subject_version_id、file_ref 与 expected_version。expected_version 同时绑定文档、版本、head revision 和路径代际。
- 修改已有文件必须原样传读取时的 expected_version；apply_patch 用 expected_versions 路径映射。新建可以留空，但仍检查当前绑定、目标占用和文件／目录冲突。
- 多文件补丁最多八项；源／目标不能重叠或互为文件祖先。意图变更通过单一 authority 事务提交。此前必要的 legacy exact capture 是独立保存的旧字节观察，回执另列，不冒充整批意图已原子提交。
- 请求发生身份来自可信 actor/source/tool-call/批内序号。重投同一身份同一参数返回原提交；同一身份不同参数拒绝。不能把每次重试换一个身份当作幂等。
- 工具成功布尔值表示 authority 已提交。commit_status=committed 与 projection/index/trace 状态独立；已保存而投影失败不是“什么也没发生”。提交前可证明拒绝为 not_committed，无法判断耐久结果为 unknown。
- nucleus_apply_patch 的 recover_occurrence_id 只恢复已提交操作的投影；input 必须为空。它检查当前活跃调用来源、原操作和工作区范围，不追加内容或生命周期历史。未知文件冲突仍需明确处理，不自动覆盖。
- 批量回执过大时只省略重复展示字段，保留每项 occurrence、document、version、operation 和投影状态。完整操作元数据可沿 occurrence 回取，省略不改变权威记录。

## 精确历史与当前目录

file_ref 的形状为 subject-file:document_id@version_id。普通读取传 version_id 可在改名、删除和路径复用后读取旧字节；不会把旧引用解释成新占用者。正文 continuation 自动携带原版本，并继续校验字节范围和预算。

read_file 的 view=history 返回某文档的版本描述符；view=operations 返回操作摘要及精确详情查询。改名或删除后使用 document_id，而不是根据旧路径猜身份。数据库历史页使用 recorded_at 与 ID 双游标，先完成本页 continuation，再取 next_history_page。

view=metadata 和 view=operation 的完整元数据用稳定 JSON 表示按 UTF-8 字节续读，items 只是机械字段摘要；长修改原因不能被永久截为一个片段。非 UTF-8 原件可查看元数据，文本解码是明确请求，不改变保存字节。通用受管写入及首次捕获有 16 MiB 单文件预算，超限明确失败；它不是历史截断规则。

list/glob/grep 的当前视图将已登记或已释放的路径遮蔽旧磁盘项，补入数据库当前文件和虚拟父目录。grep 返回命中的精确 document/version 引用；删除文件的旧正文只能通过历史读取，不伪装成当前搜索结果。目录库存分别给磁盘条目扫描与 authority binding 扫描各 10,000 项预算，最终唯一视图（包括派生目录）再限 10,000 项；同路径磁盘投影与 authority 双表示不重复消耗结果预算，任一源也不能借重叠隐藏无界扫描。超限或变化显式失败，不能返回冒充全集的空结果。相关错误日志仅输出异常类型，使用既有 logger 支持的入口，不用日志方法错误遮蔽原预算失败。已有 Boundary/旧 artifact 引用保持自身兼容合同，未自动改写成新引用。

## 受管记忆索引与精确检索引用

本轮已接通新受管文档的稳定索引身份，不再把它描述为尚未迁移的 path-only 索引：`node_id=subject-file:document_id`，source version、document revision、binding revision 和原件 hash 明确保存。改名保留 node_id，删除或不适合文本索引的当前版本只退役当前投影，不能硬删旧节点、关系或主体版本。旧 path-only 节点和旧关系继续保留自己的身份；路径被新文档复用，不会把旧引用自动 alias 到新占用者。按旧 node_id 读取的历史可以明确 `exists=False`，不以当前磁盘内容替换旧片段。

历史边读取按精确 endpoint node_id 批量取回 `LineageNodeView`，包括已退役的 legacy 节点；不能复用当前 legacy 按 ID 查询的删除过滤。节点来源字段和 snippet 来自同次查询；该视图代表读取时的投影，不冒充边创建时的版本，也不证明随后仍是当前绑定。退役 managed 节点不把保留的旧 chunks 标成当前不可索引版本；legacy 节点不补造 document/version 来源。

`memory/managed_documents.py` 从 subject authority 向独立 memory index 投影，数据只单向流动。普通 legacy upsert 不能覆盖已登记路径或复活 released 绑定。初始化先按当前绑定及索引已知文档重建，再补齐重建开始之后的变化；同一 namespace fence 内单页最多处理 128 个 outbox 变化。单页投影失败不推进该页同步标记；已完成的整页可以记录进度，但仍有尾部时保持 pending，而不是提前 ready。

就绪状态独立于搜索命中：进程内已同步 marker 必须等于 subject 命名空间的 authority frontier。零命中也检查该条件，未同步或检查失败时 health 为 degraded／failed，不能报健康空列表。查询只验证并拒绝或明确标注陈旧结果，不在读取时追加主体历史；显式投影恢复也不新增文档版本。投影端口操作使用 owned task 和取消 join，namespace fence 保持到正在执行的事务真正停止，重复取消也不得遗留后台写入。

`nucleus_search_memory` 的 evidence、bundle、历史／关系链接与精确回执后生成的回忆事件都携带原有 document/version/hash/file_ref。主体文档的实体引用是 `subject-file:document_id`，版本引用是 `subject-file:document_id@version_id`；旧记录继续使用原 entity_ref。bundle 身份包含主文档和主版本，不能因路径相同把新占用者混成旧组。单次实际投递含同一文档多个版本时，回忆元数据保留全部版本；不改变回忆的 actor、来源、意义或 exact ToolResult 确认时机。

检索正文仍是可重建投影：同正文按 content hash 共享引用，较大的链接集合机械分组并显式携带 `link_group_index/count`，同 content_ref 可以在后续页出现。即使仅返回引用，也不丢失精确版本和 continuation；它不意味着完整原文已经进入上下文。核心任务与表达任务仍分别受既有 16 KiB／64 KiB 检索结果预算约束。

`core.search_actor_memory` 的实际读者显示面也保留上述精确引用；受管结果的当前元数据不从磁盘副本取得。selected bundle 读取失败明确提示待恢复，不能悄悄回落 legacy／陈旧磁盘视图。

## 批量完整记忆取回

现有 `fetch_life_memory` 在 selected 模式统一调用 `tools/managed_memory_fetch.py`；新增可选 `version_ids={path: version_id}`，不另建工具。当前文件从 authority 固定版本，旧版本不经过旧路径 lineage 解析；released 路径不能回读残留磁盘。未登记文件可通过受限、逐字节文件读取返回，但始终标为 `archived=False`，不自动导入或编造 version_id。

请求最多 64 个唯一规范记忆路径；沿用原 fetch 的 4 MiB 单文件上限，整批读取硬上限 16 MiB，并在 legacy 磁盘读取前传入剩余预算。返回同时检查 wrapper 与 JSON 的 UTF-8 实际大小，核心任务 8 KiB、表达任务 16 KiB；仅交付可完整装下的严格 UTF-8 文档，保留 BOM／CRLF／空文件，不静默截断正文。

超出返回预算时提供 exact document/version/hash/file_ref 及固定版本的 `read_file` 查询；能读取但未归档的文件只给真实 legacy hash 和后续读取可能变化的提示。超过读取硬上限而未读出的 legacy 文件明确失败，不编造 hash。引用本身也超限时整批明确失败并保留至多三个可操作引用，要求缩小请求。多个文件分别固定版本，不声称批次是跨文档事务快照。

## 外部下载与屏幕 latest 缓存

下载与 latest 屏幕副本不是主体第一人称写作入口。下载不得覆盖已登记、曾登记或受保护目标；发布受路径、命名空间栅栏与无覆盖原子落盘约束。屏幕 latest 已从直接 mkdir/copyfile 改为受保护缓存发布：拒绝路径穿越、symlink、保留角色、受管祖先／目标及 released 绑定，只能创建新缓存或替换当前进程确知自己拥有的精确旧 hash。进程重启不会自动接管磁盘已有副本；未知占用和安全 I/O 不支持均显式失败，不改原件媒体历史。

画图插件已补充独立的目录与原子发布安全边界：自定义目录不得逸出插件产物域或绕入受保护主体路径，产物明确属于 `external_generated_artwork`，不冒充 subject append。发布或 fsync／取消结果不确定时保留 recovery-required 与候选／retained 路径，不自动重复发布；Vibe 延迟初始化可恢复，根路径重配置要求停机再启动，不承诺并发热迁移。本轮 56 项合成检查是该有限安全边界的一次性证据，详细记录见本轮工程报告，不代表全部画图格式、外部 API 或主体真实使用已验收。

这些修复不等于全部媒体／技能入口统一完成。技能脚本／解包／批量生成、媒体原件与派生物的跨域备份仍分别验收；已审技能目录入口不凭空补造安装器，任意脚本不因此获得文件写沙箱或 subject 历史合同。代码默认关闭也不代表现场配置已经核对。

## 数据库与文件投影之间

LOCAL 投影在命名空间写栅栏内检查 document、version、绑定代际与精确 outbox/head-event 身份。SQLite writer reservation 阻止同库写入在检查与文件操作之间复用路径；仅比较 version 不够，因为纯改名和删除可以沿用原版本。

新目标不覆盖已存在的未知字节。替换或删除先隔离实际取得的旧 inode，再验证预期 hash；冲突时无覆盖恢复，恢复位置被抢占则保留隔离原件并返回 recovery_path。改名先发布新目标，再仅在旧地址仍是预期释放代际时清理旧投影。已复用地址不能被旧请求删除。缺失投影可以从当前 authority 逐字重建，磁盘缺失不会自行产生删除事件。

文件 I/O 使用带预算和取消 join 的受管 worker；取消不留下无人拥有的后台文件任务。confirm/fail 在文件栅栏退出后写回 outbox。authority 与文件系统不是跨资源原子事务：部分失败保留 failed 状态，按原 occurrence 显式恢复，不自动生成新写作。

旧 schema outbox 的新增绑定字段只能从不可变 bootstrap 历史闭包推导，不能因同路径／同版本仍存在就套用当前绑定代际；精确历史任务须用原 occurrence／outbox 身份定位。该 schema 补齐不改写旧字段、原失败状态或错误，不自动 requeue 已失败任务，也不启动 workspace projector。磁盘 hash 不等于当前／parent 的未知冲突继续保留两份来源，绑定字段补齐不构成覆盖磁盘或“恢复成功”的授权。

MySQL 当前不运行主体文件的本地 workspace projector；文件命名空间互斥与 LOCAL 文件投影能力需分开。跨后端锁、下载发布保护和真实服务恢复必须分别验收，不能从 SQLite 通过推断 MySQL 实库已通过。

## 完整历史迁移与运行切换

subject-history v1 bundle 捕获 subject schema5 的八表一致性快照，包括删除文档和全部旧版本；不是 current-file export，也不是整个安装的备份。版本 bytes、ID、来源未知状态、事件和引用闭包均校验。只有受有效栅栏约束、无 active authority 的候选运行时能精确导入；同源、冲突、额外历史或校验失败全部拒绝。重复同 bundle 不增行。MySQL memory schema15 的稳定索引字段与 subject schema5 是不同域，不能混作一个版本号；无服务端 DML 模型检查不等于真实 MySQL 实库验收。

导入不激活候选，不执行原 outbox，不复用来源活跃 lease，也不恢复其他域、registry 或外部 blob。正式升级前需独立确认全库备份、旧／新 schema 兼容、投影恢复和回退方式；新历史产生后不能回滚旧快照抹掉它。Elysium 仍由用户手动停止和启动，不能混跑旧协议写入者来代替升级验收。

本轮已报告的 SQLite 与 MySQL 恢复证据分别属于同后端候选恢复；未执行跨后端切换。兼容 wire 格式、两个 adapter 分别通过和跨后端切换是不同结论，不能相互替代。
