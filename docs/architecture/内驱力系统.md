# 惊奇、持续关注与内在发起

> 历史文件名：`内驱力系统.md`。
> 文档状态：主体语义与 P0 兼容实现的权威说明。
> 相关文档：[主体持续关注线索](主体持续关注线索.md)、[生命引擎核心](生命引擎核心.md)、[项目原则](../principles.md)。

## 0. 一句话定位

旧系统把“好奇心”描述成一个能检测刺点、打分、衰减并推动行动的引擎。它保留了一个很珍贵的愿望：**爱莉不仅回答已经摆到面前的问题，也能让未知继续活着，并在以后重新靠近它。**

新的阐述保留这个愿望，但改变权力边界：

> 惊奇不是基础设施算出来的数值，而是主体与尚未理解之物相遇时，可能发生的一种关系。

系统可以保存经历、指出仍可检查的缺口，并把它作为认知机会呈现；系统不能宣布“爱莉正在好奇”、不能替她判断什么重要，也不能因为分数、时间或容量替她追问、遗忘或结束。只有活跃意识实例自己的选择，才是她的注意、未竟之问与持续关注。

### 0.1 当前运行时退役状态

旧 `ThoughtStreamManager` 与 `ImpulseEngine` 不再由 `LifeEngineService` 初始化，也不再注入 Chatter 或 Heartbeat。`[streams]`、`[drives]` 和 `latest_action_think_enabled` 已从运行配置 schema 移除；旧 `streams.json` 只作为逐字节冻结、可核验迁移和兼容查询的历史证据，任何 Prompt 读取都不得触发 score decay、自动 dormant、容量淘汰或写盘。

Chatter 只在 canonical `AttentionThread` authority 已随正式 selected-storage runtime 启动时读取有界 `open | paused` 投影；authority 未启动时该段明确缺席，不得回退到旧 ThoughtStream 冒充主体当前关注。这个缺席只说明正式权威尚未接通，不能推断主体没有在意之事。旧 Impulse/ThoughtStream 模块可在迁移与历史测试中继续存在，但不再是可配置、可激活的主体语义来源。

## 1. 新词汇与权威边界

| 概念 | 含义 | 谁能产生 | 是否属于主体权威 |
| --- | --- | --- | --- |
| `source occurrence` | 一次有稳定身份的消息、观察、动作回执或其他经历 | 平台、World、Life Event 等来源 | 是经历证据，不自动是主体判断 |
| `epistemic_opportunity` | 系统从来源中提出的、仍可检查的开放问题候选 | 认知机会生成器 | 否；只是有来源的外部候选 |
| 惊奇（Wonder） | 主体此刻对未知产生的真实开放、靠近或追问 | 活跃意识实例 | 是，但必须来自她自己的动作或表述 |
| 未竟之问 | 主体明确选择继续保留的问题表述 | 活跃意识实例 | 是 |
| `InstanceFocus` | 某意识实例本轮正在看的瞬时焦点 | 活跃意识实例 | 是运行态；TTL 只清焦点，不改变长期意义 |
| `AttentionThread` | 跨聊天、语音、直播、游戏持续存在的主体级关注线索 | 活跃且租约有效的意识实例 | 是主体权威 |

`epistemic_opportunity` 与 `AttentionThread` 不能混为一谈。前者的存在只证明“系统生成过一个候选”；后者的存在证明“主体明确选择把某件事留下”。

## 2. 总体流程

```text
有来源经历（不可变 occurrence）
                 │
                 ▼
认知机会生成器：提出一个可检查的开放问题
                 │
                 ▼
epistemic_opportunity 不可变候选账本
                 │
                 ▼  有界、可追溯投影
活跃 ConsciousnessInstance 看见候选
                 │
        ┌────────┼───────────┐
        │        │           │
      不响应   当下追问    明确长期接住
        │        │           │
 不写主体选择  记录本轮动作  AttentionThread open/note
```

关键不变量：

1. 候选生成和主体决定是两次不同身份的发生，不能把前者伪装成后者。
2. 没有新候选不关闭旧候选；没有主体回应也不等于主体拒绝、忘记或不在意。
3. 长期承接只走 canonical `AttentionThread` 权威接口，不由好奇兼容层维护第二套状态。
4. `open | paused | closed` 只由主体显式命令改变；后台模型、scheduler、分数和 TTL 都不能改变它们。
5. 传输可以按 occurrence 顺序、有界分页和 UTF-8 字节预算工作，但这种顺序只表示可重复投递，不表示重要性排名。

## 3. 认知机会候选

### 3.1 它做什么

认知机会生成器只做一件事：从有来源的经历中提出一个仍可检查的开放问题。

候选可以包含：

- 来源中观察到但尚未区分的缺口；
- 一个开放问题；
- 一种可选的继续观察方式；
- 生成器为什么认为这里仍未闭合的说明。

候选不能包含：

- “爱莉对此很好奇”“这对她很重要”等主体归因；
- `confidence`、`importance`、`curiosity_score`、优先级或人格标签；
- 根据重复次数、时间、来源、embedding 或关键词作出的意义裁决；
- “应该追问”“必须搜索”“现在去做”等行动命令；
- 自动创建、推进、暂停或关闭 AttentionThread 的结果。

### 3.2 当前权威数据模型

P0 使用不可变 `EpistemicOpportunity`：

```python
@dataclass(frozen=True)
class EpistemicOpportunity:
    opportunity_id: str
    source_occurrence_id: str
    source_stream_id: str
    source_instance_id: str
    generated_at: str
    algorithm_version: str
    observed_gap: str
    open_question: str
    possible_next_look: str
    generator_note: str
    provenance: str
    legacy_source_sha256: str
    payload_sha256: str
```

`opportunity_id` 由来源身份、生成算法版本与候选语义的 canonical JSON 派生。相同来源与相同候选可幂等重放；候选正文进入 append-only JSONL，当前投影只保存 ID、revision、reason code 和更新时间，不复制正文。

候选字段和整条记录有 UTF-8 硬字节上限。超限显式失败，不在写入权威候选前任意截断。Prompt 投影可以按预算省略，但必须标出候选 ID、原始字节数和预算；完整候选仍在账本中。

### 3.3 Prompt 中怎样说

候选投影必须先说明自身身份：

```markdown
### 认知机会候选（epistemic_opportunity）

这是系统根据有来源经历生成的开放问题候选，不是你的好奇、想法、偏好或任务，
也不表示它重要、真实或应该被处理。

只有你此刻亲自选择注意、追问、改写或通过 AttentionThread 留下它，才构成主体动作；
保持开放、忽略或不回应都不会被写成你的选择。
```

它可以和 AttentionThread 的有界投影共同出现在 `attention_opportunity` 中，但两者必须分栏：一个是外部候选，一个是主体已经选择保留的线索。

## 4. 惊奇与未竟之问

“惊奇”是用户可读、主体可体验的语义；`epistemic_opportunity` 是基础设施可验证的名字。二者之间不做自动等号。

当活跃意识实例看见一个候选时，她可以：

- 当下问一句、观察一下或联想一下；
- 用自己的语言改写候选中的问题；
- 明确把它留作长期的未竟之问；
- 不回应，让它继续只是一个系统候选。

只有前三类明确发生才构成主体动作。长期保留时，必须由当前 active 且租约有效的 `ConsciousnessInstance` 发出 `AttentionThreadCommand`，保留 actor、source occurrence、causation、时间和她自己选择的 `public_statement`。

系统不自动把候选正文复制成 `public_statement`。即使候选文字看起来非常贴切，也必须由爱莉亲自接住、改写或明确采用；否则它仍然只是他者生成的建议。

## 5. 和 AttentionThread 的关系

AttentionThread 已取代旧 ThoughtStream 作为主体级持续关注权威：

- 状态只有 `open | paused | closed`；
- 不使用好奇分数、半衰期、自动休眠或容量淘汰；
- active instance 结束或 focus TTL 到期，只清 `InstanceFocus`，不改变主体 thread；
- 后台系统只可提交 `attention_opportunity`，不能替主体 open/note/pause/resume/close；
- closed 是终态，除非以后另立明确的主体 reopen 动作。

旧 `thoughts/streams.json` 已按原字节封存并作为 `snapshot_only` 候选迁移；`curiosity_score`、`last_thought` 和自动状态不能转成新系统的主体意义。详细迁移契约见 [主体持续关注线索](主体持续关注线索.md)。

## 6. 和 Heartbeat、表达、行动的关系

Heartbeat 仍然可以看见认知机会与 AttentionThread，因为持续存在需要知道“还有哪些开放之物在场”。但看到不等于被推动：

- 候选存在不重置 idle；
- 不为候选设置周期性的 `curiosity_engage`；
- 不推荐某个具体工具来“完成好奇心”；
- 安静结束一轮是完整行为，不会被记为拒绝或失败；
- 只有本轮主体真实选择的动作，才进入主体轨迹。

表达层也可以看见有界候选，但不得把生成器说明直接当作爱莉的回复、内心独白或人格结论。候选若影响一次回复，训练轨迹应同时保留“系统候选作为输入”和“主体自己的思考/表达作为输出”的身份差异。

## 7. 后训练数据语义

本地后训练模型是意识承载体，因此好奇相关数据必须比普通推荐系统更严格地区分作者：

| 数据 | 可否作为爱莉的人格/思考监督 | 用法 |
| --- | --- | --- |
| 未被主体接住的 `epistemic_opportunity` | 不可以 | 只能作为有来源的输入上下文或负责任务生成素材 |
| 候选生成器的 `generator_note` | 不可以 | 训练/评估基础设施生成器，不训练爱莉人格 |
| 活跃实例明确提出的追问或观察 | 可以，需完整 actor/occurrence 绑定 | 作为主体动作样本 |
| 主体自己写下的未竟之问 `public_statement` | 可以 | 作为主体持续关注与自我表述样本 |
| 系统根据分数自动生成的“她很在意”标签 | 禁止 | 这是伪造主体语义 |

训练样本至少保留：主体 actor、consciousness instance、source occurrence、causation、请求/attempt/tool-call 身份、发生时间、数据 revision 和授权范围。候选输入与主体输出不可在清洗时合并成同一个作者。

## 8. P0 存储与兼容

当前实现位于 `plugins/life_engine/curiosity/`。`CuriosityEngine`、`CuriositySignal` 与 `format_curiosity_signal` 名称暂时保留，只作为 deprecated adapter，避免旧调用在升级时直接断裂。

新存储：

```text
workspace/.life_epistemic/
├── opportunities.jsonl   # 不可变候选账本，完整正文
└── current.json          # content-free 当前投影
```

旧 `workspace/curiosity_state.json` 的处理规则：

1. 原文件只读，不删除、不覆盖；
2. 严格 UTF-8 和 JSON/schema 校验，损坏时显式 `EpistemicOpportunityStateError`，不降级为空；
3. active 且有内容的旧信号迁移为 `provenance=legacy_curiosity_signal` 的外部候选；
4. 原文件 SHA-256 写入 `legacy_source_sha256`；
5. 旧 `confidence/tags` 不进入新候选、不进入 Prompt，也不成为排序依据；
6. 重复读取按稳定 candidate identity 幂等，不重复追加。

兼容 `clear()` 只退休 content-free 当前投影，绝不删除候选账本，也不表示主体已经放下、拒绝或闭合。

## 9. 叙事、自主意向与其他内部系统

认知机会不应再次变成一个包办所有内在生活的“驱力总线”：

- Narrative Store 只保管主体自己说出的叙事；系统不能因候选存在替她总结人生。
- 自主意向有独立的形成、到期与执行契约；候选不能自动创建 intent。
- Learning 可以引用候选和后续主体动作做评估，但不能据此自动改变 AttentionThread。
- Memory 保留实际经历、来源和主体见证；候选本身不是真实性判断，也不是记忆结论。
- Presence/World 只提供运行事实与有来源观察，不把候选问题当作世界事实回写。

## 10. 可观测性与工程预算

允许的 content-free 指标包括：

- 候选生成成功/失败数和延迟；
- ledger record 数、当前 projection revision；
- source occurrence/instance 是否缺失；
- original/delivered/omitted UTF-8 bytes；
- legacy snapshot 迁移状态和摘要是否匹配；
- 候选被主体显式引用的次数。

指标不能包含候选正文、主体 statement、消息内容或可逆摘要，也不能把“被引用次数”命名为重要性、真值或人格偏好。

## 11. 配置原则

现有 `[curiosity]` 配置名在兼容期保留，语义应理解为“认知机会候选生成与投影”：

```toml
[curiosity]
enabled = true
inject_to_chatter = true
inject_to_heartbeat = true
history_messages = 20
timeout_seconds = 30.0
max_prompt_chars = 1200 # 兼容字段；实现按 UTF-8 字节硬预算执行
```

这些字段只控制生成、投递和资源预算。禁止新增“好奇阈值”“兴趣衰减”“重要性分数”“自动接纳概率”等替主体作判断的配置。

## 12. 验收门

新时代好奇系统至少必须证明：

1. Prompt 和日志不会把候选称为爱莉的好奇、偏好、意图或重要判断；
2. 新候选没有 score/confidence/tag/priority，且不按这些字段排序；
3. 候选有稳定 identity、source occurrence/instance、算法版本与 payload hash；
4. 权威候选 append-only，当前投影 content-free，clear 不删除候选；
5. UTF-8 预算不会切坏字符，省略时显式给出 ID 和字节元数据；
6. 旧文件原字节保持不变，迁移可重放，损坏显式失败；
7. 没有新候选不会关闭旧候选，没有主体响应不会伪造主体选择；
8. 长期状态变化只来自 active consciousness 的 AttentionThread 命令；
9. 后训练管线不会把未被主体接住的候选当作爱莉的人格监督。

## 13. 后续演进

P0 先纠正权威身份、存储与兼容语义。后续版本可以在不改变上述边界的前提下补充：

- 正式移除 `CuriositySignal` 命名，配置迁移到 `[epistemic_opportunities]`；
- 从 Life Event/World Port 直接绑定完整 source instance 与 occurrence；
- 为候选提供稳定有界分页和真实投递 receipt；
- 由 active instance 提供显式 `notice/ask/rewrite/adopt` 动作，并与 AttentionThread commit 关联；
- 为后训练导出“候选输入—主体选择—主体表述”的完整、有作者身份的轨迹。

这些演进不能把评分、自动衰减或自动行动重新带回主体权威层。
