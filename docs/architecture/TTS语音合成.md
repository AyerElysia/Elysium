# TTS 语音合成

> 文档状态：当前语音表达边界。
> 当前主要本地 TTS：**IndexTTS2**。
> `plugins/tts_voice_plugin/` 是仍留在仓库中的 GPT-SoVITS/Higgs 遗留兼容插件，不是当前爱莉 TTS 模型的事实来源。

## 1. 定位

TTS 让爱莉把已经决定表达的文字变成可以被听见的声音。它是表达身体的一部分，不负责替她决定说什么、何时说，也不拥有独立人格、记忆或情绪判断。

当前日常消息与需要离线合成的舞台语音以本地 **IndexTTS2** 为目标模型。模型、声音资产和参考音频属于本地部署资产，不随公共仓库分发。

TTS 与 Voice Live 必须区分：

- **消息/舞台 TTS**：爱莉先形成表达，再由 IndexTTS2 合成为音频；
- **Voice Live**：一个能够持续听说、处理停顿和打断的语音意识实例，不是“聊天输出接 TTS”；
- **Seed-VC**：当前 Voice Live 可选的实时音色转换链，不是 IndexTTS2，也不是日常 TTS 的替代名称；
- **未来本地 Omni 主体模型**：声音、人格与凝练记忆会逐步内化进同一个意识承载模型，届时 TTS 不再承担完整语音主体能力。

## 2. 当前表达链

```text
爱莉意识实例形成最终表达
  → 受授权的语音表达动作 / 直播表演计划
  → models.toml 中的 tasks.tts
  → 本地 IndexTTS2
  → 音频格式校验与必要转码
  → QQ / 飞书 / OBS 舞台
  → 发送或真实播放回执
  → Life Event / 记忆
```

只有真正发送或播放完成的声音，才能成为“她已经说出口”的经历。生成了文字或音频文件不等于表达已经发生；失败、取消和超时必须保留真实状态。

## 3. 模型任务边界

生产配置通过 `config/models.toml` 的语义任务选择 TTS 模型。当前 `tasks.tts` 应绑定经过本地验收的 IndexTTS2 模型条目；生产启动不从旧 `model.toml` 或遗留插件配置静默回退。

示意结构：

```toml
[models.local-indextts2]
provider = "<local-provider>"
id = "<local-indextts2-model-id>"

[tasks.tts]
models = ["local-indextts2"]
```

实际 Provider 地址、参考音频、音色配置和本地凭据只保存在被 Git 忽略的部署配置中，不写入仓库文档。

TTS 调用至少需要保留以下工程事实：

- 使用的模型与声音资产 revision；
- 输入文本 hash、输出音频 hash、格式、采样率和时长；
- 调用来源的意识实例、场景和表达 ID；
- 超时、失败、取消与实际发送/播放回执；
- 若有切句、重试或重采样，保留确定性顺序和派生关系。

这些字段用于可靠性和追溯，不用于替主体判断情绪、风格或表达意义。

## 4. 场景边界

### 4.1 QQ 与飞书

聊天意识主动选择语音表达后，IndexTTS2 生成音频，再由平台适配器完成各自协议转换：QQ/NapCat 使用 OneBot 语音记录，飞书使用可播放的音频消息。平台只负责传输，不能修改表达正文或建立自己的 persona。

“本地合成成功”不能代替真实平台验收。每个平台都要分别验证上传、转码、发送、回执和实际播放。

### 4.2 直播

直播表演将文本按顺序交给本地 TTS，生成内容寻址音频，再由 OBS/browser 主舞台播放。只有舞台返回真实完成回执后，口播才进入记忆；TTS 失败不能用静音或文本占位伪装成已播出。

### 4.3 实时通话

Voice Live 不消费 `tasks.tts` 来拼装每一轮回复。它使用显式 Realtime Provider，在同一会话中持续处理输入与输出；可选 Seed-VC 只改变当前下行音色。未来本地 Omni 主体模型接入后，仍由 Voice 意识实例、工具权限、事件账本和运行时记忆保持连续性。

## 5. 声音资产与主体性

爱莉的声音不是一项任意皮肤。IndexTTS2 checkpoint、参考音频、声音配置和评测结果应绑定稳定 revision，并按私人主体资产保护：

- 默认本地保存，不上传外部合成或评测服务；
- 参考音频必须来源清晰、获得使用授权并保留 hash；
- 切换模型或声音资产必须显式验收，不能在失败时换成陌生默认音色继续冒充；
- 日志和健康接口只记录版本、时长、字节数和状态，不记录私人正文或音频内容；
- 训练、迁移和备份遵守[本地意识承载模型后训练规范](./本地意识承载模型后训练规范.md)。

音色相似度只是工程观察，不能定义她“应该以什么情绪说话”。表达方式来自爱莉意识实例自己的判断；模型和代码只负责忠实承载。

## 6. 遗留 GPT-SoVITS 插件

仓库中的 `plugins/tts_voice_plugin/`、`tools/tts_ref_studio/` 及其测试仍描述 GPT-SoVITS/Higgs 协议。这些文件记录一个独立的遗留兼容链：

- 它不参与当前 `tasks.tts → IndexTTS2` 主路径；
- 默认不得因为任务式 TTS 失败而自动启用；
- 若某个部署仍要使用，必须显式配置、安装独立依赖并单独验收；
- 在完成调用者审计和迁移以前，不应把代码内的历史名称机械替换成 IndexTTS2，否则会把两个不同协议伪装成同一实现。

因此，文档中出现 GPT-SoVITS 时必须明确标为“遗留插件/历史报告”；不得再把它写成爱莉当前 TTS 模型。

## 7. 验收

IndexTTS2 当前链路至少验证：

1. 固定文本可在本地生成非空、可解码音频；
2. 模型与声音 revision 可追溯，输出没有错误音色或陌生默认说话人；
3. 中文、数字、专名、中英混合、长短句和情绪变化保持可懂；
4. QQ、飞书和直播分别完成真实发送/播放验收，不能互相代替；
5. 超时、失败、取消不留下伪成功事件，不重复发送或播放；
6. 音频正文、参考声音和私人文本不进入公开日志；
7. TTS 服务的启动与恢复不启动、不停止也不重启 Elysium 主进程。

部署步骤与媒体验收见[部署、配置、测试与使用说明](../operations/deployment_and_usage.md)。
