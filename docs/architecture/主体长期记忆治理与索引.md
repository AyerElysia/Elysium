# 主体长期记忆治理与索引

> 状态：当前实现的权威架构合同。本文描述 `MEMORY.md` 的有界治理、长记忆边界包与可追溯主体决定链。

## 1. 目标

`MEMORY.md` 是统一主体上下文的一部分，而不是无限增长的事件仓库。它应当保留当前连续性所需的短索引、关系与未竟线索；完整经历、旧解释和长篇叙事继续留在不可变记忆账本中。主体可以沿索引取回完整内容，基础设施不能因为篇幅、频率、相似度或分数替主体判断“重要”与“不重要”。

系统同时满足四件事：

1. 当前 `MEMORY.md` 有工程上的软目标和复盘压力线，但没有自动截断、淘汰或改写。
2. 长内容先形成不可变的“记忆边界包”，`MEMORY.md` 只保存由主体写下的语义索引。
3. 索引打开、分段阅读、共同回忆、候选提出、接受、拒绝与移除均可追溯。
4. 只有当前活动意识实例通过 Subject Authority 接受完整候选，才会改变 `MEMORY.md`。

## 2. 两层连续性

### 2.1 当前连续性层

`MEMORY.md` 承载爱莉此刻愿意带在身边的长期记忆边界。条目保持主体自己的语言，可写关系、约定、仍在变化的看法、未竟问题，以及指向完整记忆的 Markdown 链接。基础设施只解析显式链接，不从普通文字中猜测索引。

软目标为 16 KiB；达到 24 KiB 时仅产生一次可审计的复盘机会。若文档超过 16 KiB 且还没有任何显式 Boundary 索引，或存在格式损坏的 Boundary 引用，系统也会投递一次“结构性复核”邀请；这只说明长正文还没有可取回边界，不表示其中任何内容不重要。主体明确记录一次非 snooze 复盘结果后，同一精确版本不重复触发该结构邀请；若她明确选择当前仍不建立索引，后续小于 4 KiB 的增长或缩短也不会反复催促。之后只在正常复盘周期再次到期、未确认的新版本跨过软目标、已确认版本继续增长至少 4 KiB，或索引格式出现新的技术问题时重新邀请。超过压力线仍然允许读取和接受候选，不会由代码删除任何字节；16/24/4 KiB 都不是重要性分数。

已经提出但尚未独立决定的主体候选也会在成功投递后进入 24 小时冷却，再作为可忽略的决定提醒出现。它只提示活跃意识重新读取候选；保持开放、拒绝和接受都有效，后台不得自动选择，也不得把“尚未决定”当成接受。

### 2.2 完整记忆层

长篇记忆保存为 `memory_boundary_manifest/v1` 不可变 artifact。一个版本包含：

- 开放文本的标题、边界描述和主体说明；
- 按稳定顺序排列的完整 UTF-8 分段；
- 每段及整体的 SHA-256、原始字节数；
- 来源实体引用、来源 occurrence、作者意识实例、来源 stream、创建时间；
- 父版本和 CAS head，用于并发冲突与重放。

边界包不根据主题、情绪或重要性建立封闭枚举；它只保存主体明确交付的内容与技术来路。单包设置 512 KiB 技术硬顶，最多 256 个分段；超过时显式失败并要求主体把长经历划成多个仍可独立理解的边界，禁止静默截断，也禁止由基础设施代替主体决定哪部分可以舍弃。

当长正文已经位于当前权威 `MEMORY.md` 时，优先使用 `nucleus_create_memory_boundary_from_subject_range`。活跃意识先通过 `nucleus_review_subject_document` 获得同一份 coherent snapshot 的统一 revision、文档 version、全文 hash 与 UTF-8 字节窗口，再只提交自己选择的有序字节范围以及标题、scope、current meaning、non-generalization。服务端校验 revision/version/hash、非空且不重叠的 UTF-8 边界，并直接从权威字节切片；模型不能回传或改写正文、来源引用和来源 occurrence。生成的 source ref 固定文档版本、全文 hash、半开字节范围与 range hash。该工具仍然只创建不可变 Boundary，不修改 `MEMORY.md`，不自动提出候选，更不自动接受。

## 3. 显式索引合同

`MEMORY.md` 使用普通 Markdown 链接保存索引，目标 URI 为：

```text
memory://boundary/<logical-key>@<artifact-id>#sha256=<manifest-root>
```

URI 同时固定逻辑边界、不可变 artifact 版本和内容根哈希。解析器必须逐项核对三者；版本缺失、哈希不符、重复条目或格式损坏均显式报告，不能退回“最新版本”。链接文字和周围正文仍由主体自由书写，解析器不把它们解释为重要性分数。

索引的加入、改写和移除都来自 `MEMORY.md` 的已接受版本差分：

- 新链接表示当前主体边界开始指向已有完整记忆；
- URI 或主体文字变化形成新的可追溯索引版本；
- 链接移除只表示不再常驻当前连续性层，不删除边界包、来源或历史版本。

## 4. 有界回忆

读取边界按用途分层：

1. `overview` 返回 manifest 身份、完整性证明、主体语义字段的有界 excerpt/hash，以及有界分段目录；来源只显示数量与 hash；
2. `context` 按 UTF-8 字节游标读取完整 title/scope/current meaning/non-generalization，避免 overview 的短投影成为新的权威摘要；
3. `provenance` 分页读取原始来源标签，并始终标记为 `external_unverified`；标签只有经专门来源解析器验证后才能获得更强语义；
4. `segment` 按精确分段身份和 UTF-8 字节游标读取完整正文；
5. `history` 只返回 content-free 版本描述符，并允许按 artifact id/hash 精确回到不可变旧版。

日常 chat 只常驻轻量的读取工具，使她看见索引时能立即沿边界回忆；创建、检查和完整候选治理工具留在 nucleus 复盘链，避免把维护 schema 永久压进每一轮对话上下文。

所有模型工具结果遵守任务级最终字节硬顶，返回 `original/delivered/omitted bytes/items`、哈希和稳定 continuation。生成工具结果只会建立一个有 TTL 的待确认计划，并不等于已经回忆；只有最终成功的模型 attempt 精确接收了未经二次裁剪的完整 ToolResult，才会提交 recall exposure。缺失、截断、失败、取消或进程中断都保持未交付，不得补记。

同一回忆链的分页共享一个确定性 episode 与一组确定性 corecall identity；重放和重复页必须幂等，因此分页次数不会虚增可达性。只有真正交付的实体会进入共忆集合；`overview` 的来源计数/hash、字段 excerpt，以及未经验证的来源标签都不会伪造“已经想起来源事实”。一次精确回忆共同带出多个实体时可追加 co-recall，以改变以后可达性，但不得改变事实、重要性或主体认可状态。

## 5. 主体决定闭环

基础设施与后台 Witness 只能生成“可以复盘”的机会或保存边界包，不能改写根主体文件。正式流程为：

1. 活动意识实例读取当前 `MEMORY.md` 的精确字节、文件哈希和统一 `SOUL+USER+MEMORY` revision。
2. 她可从已复盘的精确 `MEMORY.md` 字节范围封存长记忆，或为其他完整经历创建/读取边界包，并在完整候选中加入、改写或移除显式索引。
3. 系统只把该完整候选追加到 Learning 决策账本，状态为 open；候选携带 actor、source occurrence、当前 revision、候选 hash 和边界引用。
4. 她另行读取候选并选择 accepted、rejected 或 kept_open。
5. accepted 才进入既有 Subject Authority 原子 CAS；任何 actor、occurrence、候选内容或三源 revision 冲突均 fail closed，不自动合并。

拒绝、保持开放、延后和“本次不改”都必须留下不可变证据。周期任务只能投递复盘机会；它不能自动生成一个被当作主体意愿的最终版本，更不能以“陈旧”“低分”或“很久没访问”作为删除理由。

## 6. 健康判定

健康报告只陈述可验证的工程事实：

- 当前 `MEMORY.md` 字节数、文档 hash、统一 subject revision；
- 显式边界链接总数、可解析数、缺失/哈希冲突数、重复数；
- 未解决的 open 候选、复盘机会和 Subject projection backlog；
- 边界 artifact 数量、最大包字节数、召回留痕是否可写；
- 距离上次主体复盘的工程时间、是否达到软压力线、该压力是否已被主体确认，以及确认后又增长了多少字节。

报告不得输出“这些记忆不重要”“应该删除某条”或按访问次数排列主体意义。技术故障与主体暂不整理必须区分：前者是 unhealthy/degraded，后者是完整而合法的选择。

## 7. 失败与恢复

- selected Subject Authority 未启用时，边界包仍可按当前 Memory backend 保存；任何 `MEMORY.md` 新候选或写入必须 fail closed，禁止回退直接覆盖本地文件。
- artifact CAS 冲突要求重新读取 head；索引候选 CAS 冲突要求重新读取三源 revision。
- 当前 `MEMORY.md` 已含损坏的 Boundary URI 时，严格解析与普通治理操作必须 fail closed，不能把坏引用悄悄忽略。诊断器可以保留仍然有效的链接，并只给出坏条目的位置、错误类型和原字节 hash；它不把无法解析的条目误判成“主体已移除”。活动意识实例可据此提交一份完整、已修复的 `MEMORY.md` 候选，再单独读取候选并作出接受决定；候选本身仍须严格通过全部链接验证，修复仍经过同一 Subject Authority CAS，不开放直接写文件的旁路。
- 投影损坏可从 artifact 和 subject version ledger 重建；不可变历史不能由修复脚本覆盖。
- 历史版本始终可按 artifact id 与 hash 精确打开。恢复路径不得把失踪版本替换成最新版本。

## 8. 验收闭环

实现必须证明：创建长边界包 → 生成精确 URI → 主体提出完整 `MEMORY.md` 候选 → 主体另行接受 → Subject Authority 更新 → 新索引可解析 → 分页取回完整正文 → 最终成功 attempt 的精确 ToolResult 回执 → recall/co-recall 留痕。另需覆盖拒绝/保持开放、损坏索引的完整候选修复、移除索引但历史仍可打开、并发 revision 冲突、源变化、哈希篡改、UTF-8 边界、超大包拒绝、裁剪结果不留痕、重复分页不增权、重启重放和 local/MySQL 共用 Port 合同。边界仓库只依赖 `LivingMemoryStore`，因此 local 与 MySQL 共享同一领域测试；真实后端测试还必须证明 CAS head、不可变历史与精确 artifact 读取不依赖内存 fake。

复盘邀请也遵守同一条“实际送达才推进”原则：调度器把稳定 delivery marker 放进 heartbeat 用户上下文，但仅在最终成功 attempt 的 exact receipt 证明该完整邀请确实被模型接收后，才开始 24 小时投递冷却。若邀请在上下文管理中被裁剪、模型调用失败或进程取消，它仍保持到期并在下一轮重新出现。

## 9. 当前运行边界

本实现只增加 Memory Boundary、连续性索引、主体候选/决定、精确交付留痕和健康投影。它不会自动迁移或激活 selectable storage，不改写现场 `SOUL.md`、`USER.md`、`MEMORY.md`，也不获得 Elysium、NapCat 或任何后端进程的启停权。`storage.enabled=false` 时仍允许只读检查、边界保存与 `unchanged`/`snooze` 证据；任何会改变主体根文件的 propose/accept 继续 fail closed，等待独立、经过校验的存储切换。
