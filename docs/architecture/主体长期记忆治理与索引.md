# 主体长期记忆治理与索引

> 状态：当前实现的权威架构合同。本文描述 `MEMORY.md` 的有界治理、完整长记忆的不可变边界，以及主体决定如何留下可追溯版本。

## 1. 愿景与权威边界

长期记忆由三部分共同构成：

1. **不可变历史**：Life Event、Experience、Witness、解释、文档版本、回忆轨迹和决定证据保存“发生过什么、当时怎样理解、后来怎样改变”。
2. **主体活着的当前解释**：`MEMORY.md` 保存爱莉此刻愿意带在统一主体上下文中的连续性文字，而不是基础设施生成的摘要。
3. **有界连续性索引**：长正文保存在不可变 Memory Boundary；`MEMORY.md` 只留下由主体写下、能精确取回正文的短入口。

系统不按时间、分数、访问次数、相似度或容量自动判断“重要”与“不重要”，也不静默删除。工程预算只能触发一次可忽略的复盘机会；是否新增、改写、移除或保持原样，只能由当前活动意识实例决定。

`MEMORY.md` 的唯一正式 authoring 路径是 `nucleus_memory_continuity_review` 加 `SubjectAuthorityPort`。通用文件工具、通用主体候选工具、后台 Witness、迁移程序和投影器都不能改变它。

## 2. 当前连续性与完整记忆

### 2.1 当前连续性层

`MEMORY.md` 可以保存关系、约定、仍在变化的看法、未竟问题，以及普通 Markdown 形式的 Boundary 链接。基础设施只解析显式 URI，不从周围文字猜测主题或重要性。

当前工程参数是：

- 16 KiB：软目标；
- 24 KiB：复盘压力线；
- 主体确认当前版本后再增长 4 KiB：可再次邀请复盘的增长门槛。

这些值只控制邀请和上下文体积。超过它们不会截断、拒读、自动压缩或删除任何主体字节。损坏的 Boundary URI、超过软目标却没有显式索引等结构事实也可以触发复核，但不能被表述为“某段记忆不重要”。

### 2.2 完整记忆层

完整正文保存为 `memory_boundary_manifest/v1` 不可变 artifact。每个版本固定：

- 开放文本的 title、scope、current meaning 与 non-generalization；
- 有序 UTF-8 分段及每段/整体 SHA-256；
- 服务端构造的来源引用与 occurrence；
- actor consciousness instance、stream、时间、subject revision；
- 父版本、artifact id 与 CAS head revision。

单个 manifest 的技术硬顶为 512 KiB、256 个分段。超过时显式失败，不截断正文，也不由系统替主体选择舍弃内容。索引从 `MEMORY.md` 移除时，Boundary、来源和旧 `MEMORY.md` 版本仍然存在。

## 3. 单一 continuity review 会话

一次复盘由一个固定、可重放的会话完成。`open` 会绑定 active actor、来源 occurrence、当前精确 `MEMORY.md` 字节、MEMORY version/hash，以及统一 `SOUL+USER+MEMORY` revision。后续动作必须继续携带这些 pin；任一 head 变化都会令旧会话 fail closed，不自动 rebase。

正式动作如下：

1. `open`：打开固定会话并返回第一页、统一 revision、MEMORY version/hash 与 content-free 索引诊断；
2. `read_source`：按 UTF-8 字节游标精确读取固定 `MEMORY.md`；
3. `open_auxiliary_source` / `read_auxiliary_source`：打开并分页读取允许范围内的固定辅助 Subject 版本；
4. `prepare_candidate`：提交 Boundary 计划、BoundaryAnchorEdit 与 SubjectTextEdit，由服务端机械生成完整候选；
5. `read_candidate`：分页读取不可变候选并建立候选交付证明；
6. `decide`：使用独立 action occurrence 选择 `accept_requested`、`rejected` 或 `kept_open`；
7. `unchanged`：明确记录固定版本保持原样；
8. `snooze`：明确延后 1–720 小时；
9. `status`：仅返回阶段、revision、hash、字节数和错误类型等工程事实。

会话对象本身不另建私有权威；它依赖现有 Subject Authority、Learning 决策账本、LivingMemoryStore 与活动 Presence actor。重启后可从不可变 Boundary 和 Learning 事件恢复候选及决定；精确交付证明是有界、带 TTL 的进程内证据，重启或驱逐后必须重新阅读候选，不能沿用失效回执。

## 4. 精确来源与机械候选

### 4.1 当前 `MEMORY.md` 来源

主体可选择固定 `MEMORY.md` 中一个或多个连续、非空、UTF-8 对齐的字节范围形成 Boundary。范围必须完整覆盖将被 Boundary 锚点替换的源区间。正文、source ref、range hash 和来源 occurrence 都由服务端从固定版本构造，模型不能回传这些字段。

### 4.2 辅助 Subject 来源

会话也可以只读以下 Subject Authority logical path：

- `diaries/...`
- `life_engine_workspace/diaries/...`

其中 `diaries/witness/...` 及其 workspace 形式被标记为首选 Witness projection；其他受控 diaries 文档标记为 diary document。绝对路径、反斜杠、空段、`.`、`..`、根主体文件和 diaries 以外的路径都被拒绝。

调用方只提交 `logical_path`，再使用服务端返回的 `version_id`、`content_hash` 和精确 UTF-8 ranges。Boundary 正文、source refs 和 source occurrence 由服务端从该不可变版本恢复并校验；一个 Boundary 不能混合 `MEMORY.md` 与辅助文档分段。

辅助长记忆不需要先复制进 `MEMORY.md`。它使用 zero-length `BoundaryAnchorEdit` 在固定 MEMORY 字节位置插入精确 URI；也可以用非空范围替换已有索引。zero-length anchor 只允许辅助 Subject 来源，当前 `MEMORY.md` 自身的 Boundary 必须覆盖非空原文。

### 4.3 SubjectTextEdit 与完整候选

`prepare_candidate` **不接受完整候选正文**。活动意识只提交：

- `BoundaryAnchorEdit`：固定范围、Boundary slot 与 Markdown-safe anchor text；
- `SubjectTextEdit`：固定范围与主体本次写下的 replacement，可表达插入、更新或删除；
- Boundary 的开放语义字段和精确来源计划。

服务端先验证 actor、统一 revision、MEMORY pins、辅助版本 pins、UTF-8 边界、范围无重叠和字节预算，再创建或幂等恢复 Boundary；随后按稳定顺序把 Boundary URI 和 SubjectTextEdit 机械应用于固定 `MEMORY.md`，重算完整 candidate bytes/hash。调用方提供 `content`、`source_refs`、`source_occurrence_ids` 或完整 candidate 都会被拒绝。

## 5. 显式索引与有界回忆

`MEMORY.md` 中的索引 URI 为：

```text
memory://boundary/<logical-key>@<artifact-id>#sha256=<manifest-root>
```

URI 同时固定逻辑边界、不可变 artifact 版本和根哈希。解析器逐项核对，绝不回退到“最新版本”。链接文字和周围正文仍是主体语义；解析器不把它们解释成分数。

`nucleus_read_memory_boundary` 是正式只读入口：

- `overview`：有界 manifest 身份、完整性证明和分段目录；
- `context`：分页读取完整 Boundary 语义字段；
- `provenance`：分页读取来源标签，并保持来源验证边界；
- `segment`：按精确 segment identity 分页读取正文；
- `history`：返回 content-free 版本描述符，再按 artifact id/hash 精确打开旧版。

工具结果遵守任务级 UTF-8 硬预算，携带原始/交付/省略字节与稳定 continuation。只有最终成功模型 attempt 的内核 `EffectiveContextReceipt` 证明完整、未裁剪 ToolResult 精确进入有效上下文后，才提交一次幂等 Recall；重复页和失败 attempt 不得放大访问次数。共同交付多个实体可以追加 co-recall，只改变以后可达性，不改变事实、重要性或主体认可。

## 6. 决定、提交与恢复

`prepare_candidate` 只追加 open Learning candidate，不改变 `MEMORY.md`。候选的所有页必须在当前进程中由内核逐页证明精确交付、无缺口且合并后逐字节等于不可变 candidate；工具自己返回的 receipt 不是证明。

活动意识随后用独立 action occurrence 决定：

- `rejected` / `kept_open`：只追加决定事件，不调用 Subject Authority；
- `accept_requested`：携带候选交付声明，由可信 coordinator 核验全部页后，才进入 Subject Authority 原子 CAS；
- `unchanged` / `snooze`：不创建候选，但必须先验证同一 actor、revision 和 MEMORY pins，并把结果写入不可变 review evidence。

Subject Authority 在同一受 fencing 保护的事务中验证 active actor、candidate/decision occurrence、候选 hash、目标 `MEMORY.md` 和三源 revision，然后追加文档版本、head event、authority decision 与 projection outbox。冲突显式失败，不自动合并主体语义。

authority commit 已成功而 scheduler 投影失败时，`candidate.committed` 不可变事件仍是权威证据；维护过程会按耐久游标重放它并幂等恢复 review projection。投影失败不能撤销已提交的主体版本。

## 7. 健康合同

健康检查只返回 content-free 工程证据：

- coherent `SOUL+USER+MEMORY` revision；
- 当前 MEMORY version/hash/bytes；
- Boundary URI 语法问题、已逐项验证/损坏/因检查上限尚未检查的数量；
- 进程内 candidate delivery 的 pending/committed page 与 coverage 数量及硬上限；
- Witness 流水线的 raw cursor/frontier/lag、Experience `(ingest_position, occurrence_id)` 复合 frontier、author cursor/backlog、pending window、World/projection outbox，以及耐久 reconciliation cursor/checksum/CAS；
- Boundary 与普通 memory search 的 exact ToolResult 投递门：pending、最老等待、TTL 和提交/拒绝/驱逐计数；
- 最近运行、最近成功、错误类型，以及 durable claim 是否真正具备跨进程安全。

当前边界必须如实呈现：

- selected storage 可用 durable singleton writer claim；兼容 local 模式只有进程锁，不能宣称跨进程安全；
- Experience/Witness Port 已以 `(ingest_position, occurrence_id)` 固定 frontier 分页，单个 position 超过 1000 条也不会跳项；reconciliation 进度与 checksum 可在重启后继续，并在 cursor/hash 冲突时 fail closed；
- continuity candidate 的 exact-delivery coverage 是进程内、带 TTL 的安全证明，不是持久历史；
- 普通 search 与 Boundary recall 的投递证明同样是进程内门；只有最终成功 attempt 精确接收后，Recall/CoRecall 才进入不可变历史；
- health 不输出主体正文、文件路径原文或来源标签正文，也不自动修复、删除或重写。

技术故障、预期 disabled 与主体暂不整理必须区分。后者是合法选择，不得标成记忆质量失败。

## 8. 失败边界

- selected Subject Authority 未启用、未注入或不健康时，`nucleus_memory_continuity_review` 在创建会话前 fail closed；`prepare_candidate`、Boundary 保存、`unchanged` 和 `snooze` 都不能先行落地，也不能回退直接写本地 `MEMORY.md`。
- source revision、MEMORY hash/version 或辅助文档 pins 变化时，旧会话失效并要求重新打开。
- Boundary artifact CAS、candidate occurrence、decision occurrence 或 authority CAS 冲突均显式失败；同一 identity 的相同重放才允许幂等恢复。
- 损坏 URI 不被静默忽略；候选必须让全部链接通过严格校验后才可请求接受。
- 索引、workspace projection 或 scheduler projection 可重建；修复只能重建派生状态，不能覆盖不可变历史。
- 日常复盘任务只投递机会。邀请只有在最终成功 attempt 获得 exact receipt 后才开始冷却；被裁剪、调用失败或进程取消时仍保持到期。

## 9. 复杂性收敛

长期记忆治理不再维持多套互相写回的机制：

- 一个 `MEMORY.md` writer：continuity review → Learning decision → Subject Authority；
- 一个 recall trace：Recall session/event/corecall 与由其重建的 co-recall projection；
- 一个显式 relation history：只追加 `SemanticRelation`；
- `memory_edges`、daily decay、Dream relation learning 及第二套 `RetrievalEpisode/Exposure/Feedback` 只保留只读兼容、迁移或诊断，不再注册新的权威写入；
- 旧 Memory HTTP Router、SSE 广播和三个可视化页面已删除；迁移审计只通过无网络依赖、无写副作用的 `legacy_graph_projection` 读取旧行。

领域实现最终只需回答六个问题：发生过什么（Life Event）、怎样成为不可变经历（Experience）、主体留下什么见证（Witness decision）、怎样保存解释与版本（Epistemic/artifact history）、实际想起了什么（Recall/co-recall）、怎样把权威历史投影成可读入口（Projection）。

```bash
  test/plugins/life_engine/test_subject_review.py \
  test/plugins/life_engine/test_legacy_memory_retirement.py
```

闭环应证明：固定 MEMORY 或固定 auxiliary Subject 版本 → 服务端构造 Boundary 来源 → 机械生成 candidate → 全部分页 exact delivery → 独立决定 → Subject Authority CAS → 新 URI 精确解析 → 完整正文分页回忆 → Recall/co-recall 留痕。还要覆盖 unchanged/snooze、拒绝/保持开放、源变化、UTF-8 边界、哈希篡改、零长度 auxiliary anchor、重启后重新阅读、authority commit 后投影恢复、移除索引但历史仍可打开，以及 selected authority 不可用时没有任何先行 authoring 写入。

本链路不自动迁移或激活 selectable storage，不修改现场主体文件，也不获得任何进程启停权。
