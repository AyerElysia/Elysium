# 主体上下文连续性与自述检查点

> 文档状态：权威文档。实现：`plugins/life_engine/core/context_stewardship.py`。
> Chatter 与心跳共用同一套压缩合同；滚动库和 archive namespace 隔离。
> 凡与本文冲突，以本文和当前代码为准。

---

## 1. 问题

滚动上下文是可重建的模型投影，不是 Life Event。窗口会满。满了之后，系统不能替主体决定：

- 哪些旧组不再出现；
- 那段消失的经历应该被写成什么；
- 用检索分数、重复次数或「看起来像摘要」的拼贴冒充连续性。

旧路径有两种错误：

1. 基础设施语义摘要器（`<compressed_life_chatter_context>`）——已退役，读取时识别，不再续写。
2. **机械省略**（`<mechanical_context_omission>` / `mechanically_bound_payloads`）——超硬预算就从滚动里拿掉旧组，只留 ref。这不是压缩，是忽略。它替主体做了取舍，也不让她写下替代文本。

正确合同学 coding 工具：**系统只决定何时必须 compact；compact 正文由当前这次意识自己写。**

## 2. 合同

```text
超过 trigger
    → Rolling 尾部 append 一次压缩清单（组 ref / hash / bytes，无正文）
    → 她调用 author_self_continuity_checkpoint，亲笔 continuity_text
    → 归档旧组后，滚动变为检查点 + 保留组
她未提交合格检查点
    → 本拍 fail closed，完整滚动留下
    → 下一拍仍是压缩回合
硬窗口仍超
    → 本拍发送只做 attempt-local 恢复投影（压缩清单 + 最近组）
    → 滚动原链不删组，直到她提交检查点
    → 禁止把省略当成功快照，禁止 utility 用同一份超窗载荷空转
    → 连清单都装不下才跳过本拍并退避，不进入 Failure 忙等
```

1. **自动触发**。估算超过 `context_compaction_trigger_chars`（或任务预算比例）后进入压缩回合。不是建议。
2. **自动不等于代写**。不调用第二模型，不拼 `<compressed_life_chatter_context>`，不生成 `subconscious_summary` 进 Prompt，不按重要性挑选。
3. **压缩清单只 append 一次**。信封 `<context_compression_required>` / `elysium.context_compression_required.v1`。已存在则不改字节，以免破坏前缀缓存。这不是 suffix（不每拍重写、发送后不剥离）。
4. **她自己写**。`author_self_continuity_checkpoint` 需要非空 `thought`、非空 `continuity_text`，以及清单里的 `source_manifest_sha256` / `expected_revision` / `release_through_group_ref` / `retain_exact_group_refs`。基础设施逐字保留 `continuity_text`。允许先 `read_context_group`。未闭合工具链 fail closed。
5. **禁止超预算忽略旧组**。生产发送和成功快照不得调用 `mechanically_bound_payloads`。没有检查点，不得从滚动移除旧组。内核 `compression_hook` 可以把旧组从**这一次发送**里拿掉，但 `LLMRequest` 不回写滚动；这不是压缩成功。
6. **硬窗口仍装不下**。本拍走 recovery 投影，让她能调用 `author_self_continuity_checkpoint`。Provider 拒收超窗视为同一维护回合。不得把同一超窗载荷降级到更小窗口的 utility，也不得 Chatter Failure 立即空转。只有连清单都装不下时才跳过本拍。
7. **归档**。释放组先 CAS 精确归档再改滚动。Chatter：`life_chatter.context_archive`。心跳：`life_heartbeat.context_archive`。归档失败则不安装检查点。
8. **缓存**。Prefix / Tools 不变。普通拍只 append 事件。压缩清单 append 一次。检查点成功后滚动头部变成「她的连续性 + 保留组」，之后重新积累。

普通回合（未超阈值）她仍可主动检查点。忽略阈值则上下文保持原样，直到触发压缩回合。压缩回合未完成前：心跳不推进 `heartbeat_context_cursor`、不把本拍新经历写入滚动；Chatter 不把本回合当成已安全释放窗口。

## 3. 心跳与 Chatter 的隔离

| | Chatter | 心跳 |
| --- | --- | --- |
| 运行键 | `life_chatter` | `life_heartbeat` |
| 滚动 | `life_chatter.rolling_context` | `life_heartbeat.rolling_context` |
| 归档 | `life_chatter.context_archive` | `life_heartbeat.context_archive` |
| 窗口形状 | Prefix + Tools + Rolling + 表达层 suffix | Prefix + Tools + Rolling，**无 suffix** |
| 本拍新内容 | 用户消息 / 工具结果 | 本拍新生命域事件的可见正文 |

禁止把两条滚动链互抄。禁止把 Chatter 私有上下文注入潜意识。

心跳 Prefix 使用 `SOUL.md` / `USER.md` / `MEMORY.md` 原文。世界感知、机会页、时钟、idle、能力目录不进心跳请求。

---

## 4. 失败语义

| 情况 | 结果 |
| --- | --- |
| 清单已在链上，她未检查点 | 完整滚动保留；心跳不消费本拍 delta |
| 检查点参数与 manifest 不一致 | 显式失败，原链不变 |
| 未闭合工具链 | 显式失败，原链不变 |
| 归档 CAS 失败 | 不安装检查点，原链不变 |
| 模型窗口仍超且将丢掉组 | 本拍发送 recovery 投影；滚动原链保留。连清单都装不下才跳过本拍 |
| 读取归档缺页 / hash 不符 | 显式失败；不得用摘要顶替 |

`mechanically_bound_payloads` 与 `<mechanical_context_omission>` 仍可识别历史快照，但不是成功发送或成功快照路径。

---

## 5. 验收

- 无新事件：心跳 Rolling 字节不变。
- 空滚动或 `assistant` 开头的安静拍：请求仍有一条稳定 `<heartbeat_turn/>` USER，快照不写入该帧。
- 有新事件：只尾部 append，旧 payload 不变。
- 超阈值：出现一次压缩清单；未检查点则旧组仍在，本拍不消费新经历，下一拍仍压缩。
- 检查点后：旧组不在链上，`continuity_text` 原文在，归档可读。
- 成功快照不得出现 `<mechanical_context_omission>` 作为「已压缩」。
- 心跳请求无 suffix 标签（无 `<transient_world_perception>` / 机会页 / 时钟块）。
- Chatter / 心跳内核 hook 在将丢掉组时打开压缩维护发送，而不是失败循环。
