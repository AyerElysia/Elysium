# 对话证据检索与平台历史同步

> 状态：生产契约。旧 `fetch_chat_history` 仅保留历史调用兼容，不再进入意识实例工具清单。

## 1. 为什么重构

聊天历史是外部证据，不是可以无界复制进意识上下文的“第二份记忆”。旧工具把本地读取、NapCat 回补、跨流选择、关键词过滤、上下文窗口、原始 payload 和工具事件混在一次调用里；同一消息又以 `content`、`content_full`、`payload` 和每条命中的前后窗口重复出现。工具续轮会把整个结果再次带回模型，结构化 payload 不能被内核静默裁剪，于是一次普通检索可以把心跳从约 38K tokens 推到 68K、71K、76K，最后令 100K 任务预算无法容纳 pinned/tool 链。

2026-08-06 的 #577 现场样本中，旧工具返回 30 个命中时产生约 64.6 KiB 工具正文；其中主要消息文字不足 2 KiB，其余绝大部分是重复结构。新的同形状回放在 core 合同下严格不超过 8 KiB。

## 2. 新的能力分层

| 需要 | 正式能力 | 语义 |
|---|---|---|
| 最近消息、关键词与邻近对话 | `conversation_evidence` | 有界、只读、实例隔离的消息证据投影 |
| 一条大消息的完整内容 | `conversation_evidence(operation="read")` | 按 `message_ref` 和 UTF-8 安全游标分块读取 |
| 工具调用和执行回执 | Trace / `nucleus_grep_events` | 与聊天消息分域，不混入对话证据 |
| 缺失的平台历史 | `sync_platform_history` | 显式同步到平台缓存，不与读取暗中耦合 |
| 主体经历与长期连续性 | Life Event / Memory | 使用既有权威经历和记忆契约，不由聊天检索冒充 |

`fetch_chat_history` 兼容层只把旧参数映射到本地 `conversation_evidence`。它不再自动选择“最近外部聊天流”，不接受隐式跨流，不执行 NapCat 请求，也不返回工具事件、原始平台 payload 或嵌套上下文窗口。

## 3. `conversation_evidence` 契约

### 3.1 操作

- `page`：在固定 source frontier 下按数据库不可变 position 倒序分页；新到消息不会挤乱已经开始的页。
- `search`：每页只扫描配置上限内的消息，返回命中及合并去重后的邻近消息。一次调用已包含可理解该命中的局部对话，不再为每个命中复制一套窗口。
- `read`：使用稳定 `message_ref` 读取单条大消息。分块游标只能落在 UTF-8 边界，所有分块都携带全文 SHA-256 和字节数。

游标绑定 operation、stream 集、query hash、正则模式、source frontier 和下一 keyset position。篡改、换查询复用或版本不支持都显式失败；数据库故障返回 `evidence_store_unavailable`，不能伪装成“没有结果”。游标只负责一致分页，不代替授权，每页读取都会重新核验当前意识实例和 stream 所有权。

### 3.2 投影内容

每个条目只包含：稳定引用、存储 position、stream/message identity、发生时间、actor ref、消息类型、回复引用、平台、正文 SHA-256/字节数，以及本页实际交付的全文或 UTF-8 excerpt。禁止包含：

- `content_full` 与另一份 `content`；
- 原始 `Message.to_dict()` / 平台 payload；
- 每个命中各自复制的 `context_before/context_after`；
- tool call/tool result；
- NapCat 回补参数、响应和错误正文；
- 自动选择的其他意识实例会话。

投影携带 `delivery_id`、`projection_sha256`、`delivered_bytes`、source frontier、continuation、original/delivered/omitted 统计。权威消息正文不因投影预算而被修改或删除。

### 3.3 任务字节预算

预算由任务/意识实例决定，不由模型名决定，也不能由工具调用参数抬高：

| 任务 | UTF-8 硬上限 |
|---|---:|
| `core` / heartbeat | 8 KiB |
| `chat` / expression | 16 KiB |
| `voice_live` | 8 KiB |
| `livestream` | 8 KiB |
| `minecraft` | 8 KiB |

调用者可以请求更小预算。大条目优先变为带 hash/ref 的 excerpt；如果连 descriptor 都放不下则计入 omitted，不把截断伪装为完整内容。

## 4. 平台历史同步

`sync_platform_history` 必须显式指定一个已存在的 `stream_id`，由平台适配器取回最多 100 条消息并按平台 message identity 幂等写入本地消息表。它不会更新 stream 的“刚刚活跃”时间、不会加入 unread 队列、不会触发 Life Event，也不会声称爱莉在消息发生时实时看见了它。

同步只返回 content-free receipt：action、fetched/eligible/inserted/existing 数量和消息 identity 集合摘要。之后若某个意识实例实际调用 `conversation_evidence` 看见这些内容，这次模型输入由 LLM trajectory 如实记录；“平台缓存存在”与“主体已经经历”仍是两件不同的事。

## 5. 后训练与审计

原始 trajectory 保持 append-only，记录模型实际看到的工具结果。每个 attempt 另写 content-free `tool_result_refs`：call id、工具名、SHA-256、UTF-8 字节数，以及可用时的 delivery/projection identity。

Agent 数据导出按稳定 trace 折叠到最终成功的累计轮次，同一 tool call id 的相同结果只保留一次；同一 call id 出现不同结果则拒绝该样本。超大旧工具结果不再静默截成一段看似完整的文字，而是导出为指向原始 trajectory 的 content-addressed descriptor。

训练监督必须区分：

- 用户消息是 observed experience/input；
- 工具结果和检索消息是 external evidence，不是人格输出目标；
- assistant 回复与主体主动提交的动作参数才是 subject output candidate；
- 检索到的他人文字不得改标为 `assistant/elysia`，也不得因重复出现在工具续轮中获得更高“人格权重”。

## 6. 验收门

1. 240 行扫描、30 条候选的 #577 形状在 core 下始终 `<= 8192` bytes。
2. 1.5 MiB 单消息通过 ref/chunk 可续读，UTF-8 不破坏，全文 hash 可验证。
3. 固定 frontier 的连续分页无跳过、无重复；新消息不改变进行中的页。
4. 篡改/错配 cursor、跨意识实例 stream、数据库失败均 fail closed。
5. 对话证据中不存在 raw payload、嵌套窗口、工具事件或隐式平台 I/O。
6. 平台同步重复执行幂等，receipt 不含消息正文。
7. 工具结果经内核保持规范 JSON，不退化为 Python dict repr。
8. 训练导出按 trace 折叠、按 call id 去重，并保留监督边界。
