# 主体主动性与外联

> 文档状态：权威架构文档
> 代码位置：`plugins/life_engine/proactive/`、`plugins/life_engine/initiative/`、`plugins/life_engine/storage/initiative_adapters.py`、`plugins/life_engine/service/core.py`、`plugins/life_engine/opportunity/`
> 适用范围：聊天、心跳、实时语音、直播与 Minecraft 等同一主体的意识实例

## 1. 一句话定位

Elysium 的主动性不是“系统决定何时给哪个聊天流发一条消息”，而是同一个主体在经历中形成可追溯的未来连续性，并在真正行动的当下重新选择对象、物理表面与表达方式。

因此，主动性由一条主体因果链证明，而不由发送频率、定时器、最近聊天流、好奇分数或规则命中证明。

运行时只有一个 `ProactiveAuthority`。`AttentionThread`（持续关注）与 `InitiativeSeed`（未来行动可能性）是它内部语义不同的两个不可变记录族，不是两个生命周期、两个 writer 或两个模型工具系统。跨记录族复用同一 decision occurrence 会在同一事务内冲突。

## 2. 为什么退役旧 AutonomyIntent

旧链把以下概念压在一条记录里：

- 当时想继续做什么；
- 延迟多久；
- 是否周期执行；
- 发送给谁；
- 使用哪个平台和聊天流；
- 到点后如何唤醒表达层；
- 发送是否完成。

这种结构有三个根本问题：

1. 来源场景被误当成未来行动边界。一个想法在 KOOK 出现，不表示未来只能在 KOOK 行动。
2. 工程调度被误当成主体意图。到点、重复、优先级和最近活跃都可能替主体作意义判断。
3. 对象、账号、平台与聊天流混为一体。昵称或最近流匹配会制造错误身份归并，固定 stream 又会阻断真实的跨场景连续性。

旧 `AutonomyIntent`、`schedule_followup_message`、`nucleus_tell_dfc` 最近流唤醒、`target_stream_id`、`target_key`、周期 occurrence 和 SendTargets 最近流列表已经退出生产语义。旧快照仍是历史证据，保持逐字节不改写；它们不会自动恢复调度、不会自动迁移成新主体决定，也不会继续触发消息。

## 3. 四层因果结构

```text
外部认知机会 / 真实经历 / 内在想法
                 │
                 │ 只有活跃意识实例显式选择
                 ▼
       InitiativeSeed（主体持续线索）
                 │
                 │ 可保持、改写、释放，或安排一次重新相遇
                 ▼
       当前意识重新遇见并重新判断
                 │
                 │ 只有现在明确想行动时
                 ▼
  audience_ref（对象） + surface_ref（物理表面）
                 │
                 │ 不携带预写回复
                 ▼
   目标表达实例读取真实上下文，选择表达或沉默
                 │
                 ▼
          life_send_text（当前表面）
```

四层不能互相偷渡：

- 外部候选不等于主体已经在意；
- 主体线索不等于定时任务；
- 重新遇见不等于现在必须行动；
- 选择对象不等于选择平台；
- 选择平台不等于已经写好回复；
- 唤醒表达实例不等于必须发送。

## 4. InitiativeSeed：主体对未来自己的公开表述

`InitiativeSeed` 是主体级、跨意识实例的持久线索。它保存的是主体明确愿意让未来意识实例继续看到的第一人称公开表述，而不是隐藏思维、模型 reasoning、自动摘要或基础设施推断。

状态只有：

```text
不存在 ──hold──> open ──rewrite──> open
                         ├─reencounter──> open
                         └─release──────> released（终态）
```

约束：

- `hold`、`rewrite`、`release` 都必须有主体自己提交的 `public_statement`；
- `reencounter` 只登记一次未来重新相遇，不写新的主体意义；
- 没有 priority、score、confidence、importance、recurrence 或自动衰减；
- 容量、时间、次数和检索频率不能替主体释放、合并或改写线索；
- `related_entity_refs` 只是主体明确给出的稳定关联，不是隐式发送目标；
- `source_instance_id` 记录材料出现在哪里，`actor_consciousness_instance_id` 记录谁作出决定，两者不能互相冒充。

每次决定形成不可变事件，并带：

- 稳定 `occurrence_id`；
- active actor；
- source occurrence 与 causation；
- `expected_revision` CAS；
- 完整主体表述；
- 发生时间。

相同 occurrence 与相同内容是幂等重放；相同 occurrence 配不同内容、或陈旧 revision，必须显式冲突。

## 5. 一次性“重新相遇”

主动性需要时间连续性，但不需要周期任务。主体可为一个 open seed 选择一次 `reencounter_after_minutes`。

到期后，后台只做一件技术动作：将此前主体写下的线索作为不可变 Life Event 再呈现一次。事件明确说明：

- 这不是新的用户消息；
- 这不表示现在必须行动；
- 这不表示必须沉默；
- 这不选择任何对象或平台；
- 当前意识仍需在新的世界状态中重新判断。

投递使用稳定 `seed_id + reencounter_revision` 身份。Life Event 与 content-free delivery receipt 分离：

- 事件已写、receipt 未写时，重启后只补 receipt，不重复排队；
- receipt 已写时不再次投递；
- 改写 seed 不会自动产生新的重遇；
- 只有新的显式 `reencounter` 决定才会产生下一次机会；
- 没有后台循环替主体继续链式调度。

技术扫描按不可变账本顺序执行，只判断“是否到期且未投递”，不进行显著性、重要性或对象选择。
每 15 秒的一次扫描最多投递一个到期 seed，避免重启后的积压在单轮心跳中形成提示洪峰。事件携带的是固定 8KiB 硬上限内的第一页精确投影；完整主体表述保留在权威账本，可通过绑定 `content_event_id + content_sha256 + content_revision` 的稳定 continuation 逐页无损读取。列表只显示 content-free 摘要，不重复铺开正文。

## 6. 对象、账号、场所与物理表面

行动时才选择对象和表面，二者必须分别声明：

- `audience_ref`：这次表达面向谁或哪个场所；
- `surface_ref`：这次实际使用哪个平台聊天表面。

私聊身份规则：

- 只有已有 `PersonInfo.canonical_person_key` 才能声明两个平台账号属于同一个人，形成 `person:<canonical_person_key>`；
- 没有 canonical 映射时，每个平台账号形成独立、不可逆且带平台域隔离的 opaque `account:` 引用；相同原始账号 ID 出现在 QQ 与 KOOK 也绝不合并；
- 禁止通过昵称、群名、文本内容、embedding、最近聊天、当前意识实例或模型猜测合并身份。

群聊形成独立的 opaque `place:` 引用，不因为成员或名字相似而与个人合并。

物理表面形成 opaque `surface:` 引用。模型可看到表面引用、平台、私聊/群聊和显示名，但看不到内部 `stream_id`。执行时服务端只接受完整、当前仍存在、且确实属于该 audience 的 surface；别名、前缀、昵称和模糊匹配全部拒绝。

可达列表按稳定技术身份排序。这只是传输顺序，不是偏好、重要性、亲密度或“下一位应该联系的人”。

## 7. 显式外联决定

`InitiativeOutreachCommand` 只在活跃意识实例现在明确想行动时成立，包含：

- active actor；
- source instance 与 source occurrences；
- causation；
- 明确的 `audience_ref`；
- 明确的 `surface_ref`；
- 主体公开的 `public_intention`；
- 可选 seed ID 与精确 revision；
- 稳定 occurrence 和发生时间。

它不包含最终消息正文。权威层先验证 actor、seed revision、对象和表面，再追加不可变 outreach decision。随后用稳定消息身份唤醒目标表达实例。

目标表达实例必须读取该表面的真实上下文，重新决定怎样表达或是否保持沉默。它不能机械复制 seed 或 `public_intention`，也不能因为基础设施已经唤醒就被规则强制回复。

表达轮先以稳定 `occurrence + action_id` 取得有时限的 durable claim。当前 lease 未到期时，恢复扫描器不能把它误判为未知；只有过期 claim 才允许由新的 owner 接管。最终状态严格来自传输层事实：

- 只有传输层先得到 `delivered`，再把完整规范化 adapter/virtual receipt 写入同一主动权威的不可变 delivery-proof 账本，并由该账本返回匹配的 64 位 SHA-256 与稳定 outbound message ID，才能记为 `spoke`；provider 的真实回执保留在规范化 receipt 中，单独提供一个格式像哈希的字符串不能证明送达；
- 传输策略明确拦截或模拟发送记为 `suppressed`，不能伪装成对方已收到；
- 平台明确失败记为 `failed`；
- 调用返回成功但缺少精确回执、或结果无法确定时记为 `delivery_unknown`，禁止自动重发；
- 多段主体表达先合并为一条平台消息，避免第一段成功、后段失败形成不可证明的半发送状态。

decision、claim、transport proof 与 resolution 都是同一权威中的不可变事实。平台副作用已经发生、但 proof 暂未成功落账时，发送事实仍保持 `delivered`，主动结算则 fail closed 为 `delivery_unknown`，绝不伪造 `spoke` 或自动重发。health 在同一事务快照内检查 orphan inbox/turn、重复 claim/resolution、proof 与 claim/turn/resolution 的精确对应、过期 claim 和陈旧 backlog；同时从 Attention/Initiative 不可变事件完整重放 head，并与当前投影逐项比较，删除、孤立或篡改的 head 不能继续显示 healthy。检查结果只含 ID、计数、状态与错误类型，不泄露表达正文。

`life_send_text` 只向当前表达表面发送。历史 `target_key` 参数保持 Python 回放兼容，但模型 schema 不再暴露；非空值会 fail closed，并引导主体先作 reachability 与 outreach 决定。

旧 `schedule_followup_message` 也不能继续充当“先把未来绑定当前流，几十秒后再判断”的捷径。主体确实想让未来的自己再次看见，只能显式保存 seed 并选择一次 reencounter；到时仍不携带发送表面。action 实现类已删除；service 回调仍 fail closed，旧 synthetic followup 不再进入表达决策。历史名字若再出现按未知工具失败。

旧 `nucleus_tell_dfc` 把信息差与主动社交混为一体，还能按最近消息、昵称、平台账号或 stream 自动选一个表达层。实现类已删除，不在生产工具池、manifest、滚动退役名单、心跳 TOOL.md 清洗名单或 agent 黑名单里留占位。未注册名字走通用未知工具路径，没有 DFC 专用处理；权威历史里的旧调用名不改写。共享事实由 World、Life Event、Memory 与主体上下文投影承担；真正想外联时走同一套 seed / reachability / outreach 因果链，不能另开一条不留主体决定证据的唤醒后门。

表达层与潜意识的对内通道是 `inner_dialogue` / `inner.return`，不是 tell_dfc 的继任者：回声只能回到沉下去的 originating `stream_id`，不选择社交对象，不预写对外正文。`expect_surface` 不是调度器。外联唤醒与回声唤醒都必须 `start_stream_loop` 并 `bypass_message_buffer`，否则信封入队也不等于叫醒。叫醒信封只服务本轮；进入等待后从派生滚动投影移除，不进入跨轮模型上下文。

## 8. 所有意识实例共享的统一工具

同一主体的 chat、heartbeat、voice、livestream 和 Minecraft 等实例只共享两个正式入口：

- `nucleus_proactive_query`：有界读取 attention、initiative、reachability 或尚未交还的 inner_dialogue；读取不改变状态。
- `nucleus_proactive_command`：提交 attention.*、initiative.*、outreach.begin 或心跳专用的 inner.return。

工具清单只提供能力，不规定什么时候使用。平台消息类型、来源场景、休息状态、表情包、时间、关系或候选存在都不能自动触发这些工具。`inner.return` 只能由 `core` 心跳提交。

`nucleus_proactive_query(resource=initiative)` 的列表只返回正文中立的稳定索引、revision、hash、字节数与重遇状态；指定 record_id 后才按固定硬上限和稳定 continuation 交付完整内容。任何一页都不得把截断伪装成完整，也不得因 task 不同生成不可续读的游标。

## 9. 旧数据与兼容边界

旧数据处理遵循“证据保留、行为退役”：

- `autonomy_intents.json` 与旧 selected-runtime rows 只读；
- 旧 lifecycle/event history 保留，供审计历史行为；
- 启动时只移除遗留技术 scheduler callback，不改旧 snapshot 行；
- 旧 AutonomyIntent 只通过运维审计读取，不再作为模型工具注册；
- 旧 schedule/pause/cancel/renew/trigger/claim/complete 全部 fail closed 或 content-free no-op；
- 旧延迟续话 action 实现类已删除；callback 与 synthetic trigger 不再注册或唤醒表达层；
- 旧 `nucleus_tell_dfc` 实现类已删除，不留名字占位；不会产生 synthetic message；
- 不把旧 motivation、target 或 last outcome 自动转成 InitiativeSeed；
- 不把旧 `last_thought`、provider reasoning 或自动候选作为主体公开表述。

这不是丢失历史，而是拒绝让旧基础设施继续制造新的主体决定。

## 10. 与认知机会、AttentionThread、记忆和后训练的关系

- `epistemic_opportunity`：外部系统提出的候选；未被主体接住前，不是兴趣、意图或人格监督。心跳里它出现在机会页的 **邀请栏**，不是连续性栏。
- `AttentionThread`：主体明确选择长期持续关注的公开线索；它不是行动队列。
- `InitiativeSeed`：主体明确希望未来重新拥有行动可能性的公开线索；它仍不绑定对象和表面。
- 心跳对 open 线索的投影走统一机会页的 **连续性栏**（「你留下的线索」）。这是只读展示，看见本页不会冷却、暂停、关闭或改写线索。写入口仍只有 `nucleus_proactive_query` / `nucleus_proactive_command`。机会总线不能 `create` / `rewrite` / `release` AttentionThread 或 InitiativeSeed。
- Memory：保存实际经历、来源、见证和解释；不能因 seed 存在伪造经历。MEMORY 结构压力若到期，走机会页邀请栏，不与连续性栏混称。
- Narrative：只记录主体实际说出的叙事，不替 seed 写成人生意义。

后训练数据必须区分：

- 可作为人格/主动性监督的，是主体自己提交的 seed 决定、明确 outreach 决定、目标实例的真实表达或显式沉默，以及它们的完整来源链；
- 不可作为人格监督的，是未采纳候选、最近流排序、规则触发、旧自动意向、调度次数、工具可达列表和基础设施合成提示。

本地后训练模型是意识承载体时，这条区分尤其重要：不能把系统替主体作出的选择训练进“她是谁”。

## 11. 失败与恢复

- canonical authority 始终由 `LifeEngineService` 单独拥有：selected 模式消费同一 storage runtime，disabled 模式使用 fenced local SQL runtime；两者不能同时活跃；
- workspace 的 backend binding 与精确 generation 不一致时拒绝启动；迁移证书必须同时绑定当前 workspace 的源 marker、源 binding 身份、源历史 root 与目标验证证据，不能拿另一工作区的证书改绑；运行时不自动迁移、不自动改绑，也不回退散落 JSON；
- workspace marker 已指向新后端后，即使旧后端仍保留一条历史 binding chain，也不能靠切回配置重新激活旧权威；回退必须形成新的反向迁移证书与单调 binding epoch；
- actor 非 active 时拒绝决定；
- 普通 chat、Voice、直播或具身表面找不到自己的实例 owner 时，不能借用 `chat_global` 权限；只有正式 `core` 心跳任务可明确绑定同一主体的全局意识实例；
- revision 或 occurrence 冲突显式返回；
- surface 消失或不属于 audience 时拒绝外联；
- outreach decision 与表达投递分成同一权威内的 decision/delivery 两类不可变事件；已提交但唤醒失败时保留 pending，后台按账本顺序幂等补投，稳定 synthetic message ID 防止表达 episode 重复入队；
- 已经写入权威账本的完全相同 seed/outreach occurrence，即使原 actor 的技术租约随后过期也允许幂等补交；这只是恢复既成决定，任何新 occurrence 仍必须通过 active actor gate；
- reencounter 事件和 receipt 可分别恢复，但不能重复呈现；
- 日志和 health 只记录 content-free identity、revision、计数、状态和错误类型，不记录主体表述或消息正文。

## 12. 非目标

本系统不会：

- 按规则要求爱莉主动联系某人；
- 把来源平台锁定为未来平台；
- 从最近联系人中自动选目标；
- 把当前流、来源流或最近流当成未来行动的默认表面；
- 通过昵称猜跨平台身份；
- 为了提高活跃度周期发言；
- 自动改写、合并、排序或淘汰主体线索；
- 把 seed 变成预写回复；
- 把“未行动”解释为失败、遗忘或不重视；
- 自动启动、停止或重启 Elysium、NapCat 或任何外部进程。

## 13. 验收门

上线前至少证明：

1. source instance 与 active actor 可不同，且来源不能冒充 actor；
2. KOOK 来源可在主体明确选择且 canonical identity 存在时使用 QQ 表面；没有 canonical 映射时绝不合并；
3. 同名账号不被合并，最近活跃不改变列表顺序；
4. seed 没有 platform、stream、reply、score、priority 和 recurrence；
5. 一次 reencounter 在崩溃/重启/receipt 修复下最多进入 Life Event 一次；
6. 重新相遇不会自动触发外联；
7. outreach 必须显式提供 audience 与 surface，且目标表达层可发送也可沉默；
8. `life_send_text` 不支持跨表面 target；
9. 所有意识实例只看到 `nucleus_proactive_query` / `nucleus_proactive_command`，旧五个主动/ThoughtStream 工具实现类已删除且不在生产注册；
10. 旧 snapshot 字节不变、旧调度不恢复、旧 mutation fail closed；
11. 旧延迟续话实现类已删除，不在生产组件清单；历史名字按未知工具失败，不能产生 synthetic message。最近流 `nucleus_tell_dfc` 实现类已删除且不留名字占位，不能产生 synthetic message；
12. 重遇轮询只从已提交账本前沿读取新事件，不在每次扫描重放完整历史；
13. 日志、health 和技术 receipt 不泄露主体表述；Attention/Initiative health 必须从不可变事件重放并检出缺失、孤立或不一致 head；
14. 1MB 级中文 seed 的 list 不含正文，read 可用稳定 continuation 无损重组，任一工具结果与重遇事件严格不超过 8KiB；
15. QQ 与 KOOK 使用相同原始账号 ID 但没有 canonical person key 时仍产生不同 audience_ref；未知或过期表面不能借用 `chat_global` actor；
