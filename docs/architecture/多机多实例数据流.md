# 多机多实例数据流架构（Elysium Multi-Node Data Flow）

> 文档状态：权威文档，2026-08-13 梳理。
> 适用：MySQL 共享后端模式（`config/elysium.toml` → `backend = "mysql"`），
> 多个合法 Elysium 节点共享同一个 selected verified generation。
> 配套阅读：`docs/architecture/多后端共享数据库-runtime_context字段审计.md`、
> `docs/operations/unstable_errors_handoff.md`（故障记录）、

## 1. 物理拓扑

```
┌─────────────────────────────────────────────────────────────────────┐
│ 节点 A（Windows / WSL / Linux）                                  │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │ Elysium：用户手工执行平台部署入口的 doctor / run，保持前台 │  │
│  │ 选配平台适配器：独立端口、账号与授权边界                    │  │
│  │ 本地 New API：由独立生命周期 owner 自动启动            │  │
│  └───────────────────────────────────────────────────────────────┘  │
│ 网络代理与直连例外由本机运维配置，不属于共享架构数据       │
└─────────────────────────────────────────────────────────────────────┘
        │  受控网络 / TLS / 隧道（端点和凭据仅存本机配置）
        ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 节点 B 与共享存储区                                                │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │ Elysium：用户手工执行平台部署入口的 doctor / run，竞争认领作业 │  │
│  └───────────────────────────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │ MySQL selected verified generation：共享耐久运行权威     │  │
│  └───────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
```

`selected verified generation` 是该部署的耐久运行权威：它决定运行时字节、
事件、版本和消费进度应在哪里持久化，不裁决爱莉应如何理解、相信或选择。
“共享权威”也不允许基础设施、迁移脚本或其他节点冒充主体执笔；主体文档只能通过
明确授权的爱莉意识实例行动链追加新版本，并保留 actor、source、occurrence 和时间。

## 2. 共享存储层（MySQL selected verified generation）

| 表族 | 内容 | 写入仲裁 |
|---|---|---|
| `storage_authority_registry` | 全局写权威（generation/epoch/owner/lease） | join/activate + 租约 |
| `storage_backend_generations` | 已注册 generation（含 verified 状态） | 启动校验 |
| `runtime_singleton_writer_claims` | 需独占的领域 writer claim | acquire/renew + 配置化租约 |
| `heartbeat_operations` | 心跳按 sequence 认领（每轮仅一实例执行） | claim + lease |
| `runtime_states` | 滚动上下文、投影、presence 快照、共享状态 | CAS revision + writer_claim |
| `raw_life_events` | 不可变生命事件账本 | append-only |
| `memory_*`（experiences/chunks/nodes/witnesses/index_jobs…） | 生命记忆 + 索引 | 不可变触发器 + 索引 worker |
| `subject_*`（documents/versions/authority/outbox） | 主体文档（SOUL/USER/MEMORY） | 版本链 + outbox |
| `learning_*`（events/projections） | 三环自学习 | 单写者投影 |
| `messages` / `chat_streams` / `person_info` | Core 聊天数据 | 同一 generation 中的事务写入 |

## 3. 多写者协调机制

```
每轮 heartbeat（周期由当前配置约束，sequence 单调递增）：
  两个实例各自发起 claim(sequence=N)
      ├─ 一方成功 → 执行：注入事件 → LLM 决策 → 写记忆/发消息 → commit
      └─ 另一方失败 → 日志 "已被其他实例认领，跳过本轮"（不重复驱动）

写共享状态（rolling_context / 记忆 / 见证）：
  需独占作者的领域在写前 acquire_singleton_writer（租约与续租周期以当前配置为准）
      ├─ 拿到 → 持租约重读最新 revision → 写入 → release
      └─ 拿不到 → 跳过本轮保存，同步 revision 缓存

租约后台续期（renew_authority，周期以当前配置为准）：
  runtime 明确返回 "singleton writer is not managed locally"
      → 丢弃旧的本地 claim 引用 → 重新 acquire
  普通 DB/网络失败
      → 保留本地 claim 并向上抛出 → 由后续有界流程重试，不自行抢占
```

### 3.1 关键时序（heartbeat 交替）

```
sequence=N    节点 A 认领并执行，节点 B 跳过
sequence=N+1  节点 B 认领并执行，节点 A 跳过
sequence=N+2  任一健康节点按原子 claim 结果执行
```

### 3.2 启动接管

```
用户手工执行平台部署入口的 doctor → 只读确认配置、端口和已有 owner
  → 用户手工执行同一入口的 run，保持前台并观察启动日志
  → _acquire_writer_claim 依据数据库时间串行、有界重试 acquire
  → 旧租约未过期则等待或显式失败，不越权抢占
  → 租约经数据库时间确认过期后，原子接管并递增 lease_epoch
```

`doctor` 和 `run` 不清理 lease，`scripts/cleanup_leases.sh` 已永久退役并会 fail-closed。
禁止通过 `start.bat`、人工 `DELETE` 或仅凭 PID 存活状态删除 writer claim；这些证据不足以
证明 owner token、epoch、fencing token 与数据库时间边界。

## 4. 数据流全景（一次"对话+记忆"的完整路径）

```
消息入站（KOOK / NapCat / Ayla / N.E.K.O / 飞书）
   ▼
message_receiver → EventBus（on_message_received）
   ▼
life_chatter（意识决策，双实例竞争驱动）
   ├─ 路由器（轻量 LLM，只读纯文本）：要不要进入主模型
   └─ 主模型（Life Chatter）：带 SOUL/USER/MEMORY 上下文决策
        ├─ 回复 → 出站 transport → 对应平台
        └─ 内心活动 → 记录（monologue）
   ▼
life_engine 心跳（每 30s，sequence 认领）
   ▼
记忆沉淀：想法碎片 → 内在状态池 → memory_experiences
   ▼
memory_witness（每 5 分钟，单写者租约）
   ├─ 收集经历（读 EventBus 账本）
   ├─ 决策窗口（_decide_window，读 subject 投影）
   ├─ 生成见证（LLM 写作）→ memory_witnesses（不可变）
   └─ 写日记 / 投影
   ▼
学习系统（三环：审计 / 压缩 / 指标，单写者投影）
   ▼
后训练数据：LLM 轨迹 → training_data_lake/raw/*.jsonl（本地）
```

## 5. 关键风险点与对应修复（2026-08 记录）

| 风险 | 机制 | 修复 |
|---|---|---|
| 双实例 CAS 竞争（rolling_context / presence） | CAS revision | 单写者租约仲裁（chatter.py / presence_store 导入统一） |
| frp 隧道瞬断（2013） | 连接池复用死连接 | pool_recycle 120s < wait_timeout 180s |
| 旧 owner 异常退出后的接管延迟 | 数据库时间租约 + fencing | 保留 claim，由原子 acquire 在自然过期后接管；禁止启动脚本清租约 |
| claim 被明确 invalidate 后 renew 失败 | runtime 返回 `singleton writer is not managed locally` | memory_witness 仅在该结构化状态下丢弃旧 claim 并 reacquire；普通 DB/网络失败保留 claim、向上抛出并后续重试 |
| schema 对齐中途断连 | 长事务无重试 | bot.py schema_sync 3 次重试 |
| 投影 manifest 不匹配 | profile 校验 | 只显式重建可重建投影，保留权威历史和操作审计 |
| KOOK 域名被 Clash fake-ip 劫持 | TUN 劫持 | DIRECT + fake-ip-filter |

## 6. 两种部署模式对比

| 维度 | selected local 单实例 | mysql 双实例共享 |
|---|---|---|
| 意识驱动 | 单实例，无竞争 | 双实例竞争（heartbeat 仲裁） |
| 存储 | selected local backend 是本节点耐久运行权威 | selected verified MySQL generation 是共享耐久运行权威 |
| 同步 | 当前 legacy `shared_sync` 明确禁用；远端同步等待 selected export-outbox 的 fenced bridge，操作者只能执行有审计的一次性迁移/导出 | 合法节点直接访问同一 generation |
| 风险 | 无分布式 writer 竞态；仍有 SQLite 单 writer 锁竞争与单机故障域 | 租约/CAS/认领竞态（frp 放大） |
| 适用 | 个人使用 / 离线 / 低并发 | 多机高可用 / 多实例意识 |

### 6.1 节点与外部服务生命周期

- 每个 Elysium 节点都必须由用户在可观察终端中手工执行 `./deploy.sh doctor`、
  `./deploy.sh run`（Linux/WSL），或 `.\deploy.ps1 doctor`、`.\deploy.ps1 run`
  （Windows PowerShell）；禁止为 Elysium 创建 systemd、cron、计划任务、登录启动项
  或 restart loop。
- 本地 New API 是模型基础设施，必须由它自己的独立生命周期 owner 自动启动、检查唯一
  PID/端口并维持健康；Elysium 只会显式报告 Provider 故障，不拉起、停止或重启 New API。
- NapCat/QQNT 属于独立适配器运行时，可由另一个明确 owner 自动启动与有界恢复；
  恢复前必须以 PID、父进程、运行目录、监听端口和现存实例组成复合证据，不得制造重复实例。
- 不同 Elysium 节点必须使用不冲突的 HTTP 端口和外部适配器会话。同一 MySQL
  generation 可共享耐久历史，不会让两个进程同时拥有同一独占端口或平台账号。

## 7. 后训练数据流

```
LLMRequest.send() → record_attempt() → TrajectoryCollector（后台线程+队列）
   ▼ append-only JSONL（媒体 redact）
data/training_data_lake/raw/YYYY-MM-DD.jsonl
   ▼ 保留 3 天 → gzip 归档
data/training_data_lake/archive/*.jsonl.gz（永久保留）
   ▼ 离线导出
data/training_data_lake/export/（SFT / Agent 格式）
```

具体记录数、字节量、日期和节点分布属于部署私有运行状态，只在脱敏、限权的健康或
审计输出中查看，不固化到公共架构文档。
