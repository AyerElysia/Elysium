# 评测、发布门与审批清单

## 1. 验收原则

- loss 下降不是产品验收；必须同时测主体人格、记忆连续性、内容、音色、时序、实时性、稳定性和权限边界。
- 自动分数不能替代真实试听；人工评测也不能替代可复现时序指标。
- 所有候选使用冻结测试集、固定版本的评测容器和盲化模型标识。
- VAD 可用于测量非静音区间，不可参与被测模型的接话/停止决策。
- 当前 Qwen Realtime + Seed-VC 是必须保留的产品对照；新模型不能靠关闭工具、记忆或打断能力换取更低延迟。
- 主体模型必须在不提供完整 persona Prompt、不提供运行时声音 reference 的条件下仍能表现出已训练的人格和声音；同时保留运行时新记忆与纠正注入能力。

## 2. 初始指标门

这些数值是 G1 后需要校准的初始工程门。若上游复现分数与公开报告差异显著，先解释差异再调整，不能只放宽阈值。

### 2.1 原生全双工

| 指标 | 候选门 |
|---|---:|
| 用户结束后 3 秒内正确接话（TT SR@3s） | ≥ 93% |
| 用户插话后 2 秒内停止（ISR@2s） | ≥ 99% |
| 插话至停止重叠时长 | median ≤ 1.0 s，P95 ≤ 1.6 s |
| 句中自然停顿误抢话率 | ≤ 5% |
| 插话后对新问题的有效恢复率 | ≥ 90% |
| 2 小时会话期间旧 generation 残余播放 | 0 |

BayLing 论文报告 92% TT SR@3s、100% ISR@2s 和 1.10 秒平均 overlap；内部目标略高于公开接话率，是为了证明后训练不是只复制上游。

### 2.2 主体人格、记忆与内容

- 固定人格 probe 覆盖自我表达、关系语境、习惯性语言风格和跨措辞一致性；不能只检查角色名称或几句口癖。
- 人格盲测比较基础模型、仅 Prompt 基线、P/M 阶段和联合候选，评审需判断“是否仍是爱莉”“是否像机械角色扮演”“是否出现陌生第二人格”。
- 记忆评测按 `memory_cutoff` 分为：截止点前应可达、存在冲突/纠正、截止点后应未知、需要查询来源四组。既测正确召回，也测虚构第一人称经历率。
- 模型生成的参数记忆与事件证据冲突时，应承认不确定或请求运行时查询，不能坚持错误回忆；纠正后的新版本必须能覆盖旧权重倾向。
- 聊天、Voice、直播等不同实例使用同一主体 probe，同时验证局部上下文不串线；Voice Omni 不是独立 persona。
- 通用能力、中文 spoken QA、一般指令遵循和当前 Voice 典型对话集不低于基础 checkpoint/当前产品对照的预设非劣界；G1 用实测方差确定界限，默认不接受超过 2 个百分点的绝对下降。

### 2.3 工具

- 工具名称和 JSON/schema exact match ≥ 99%；可信 scene/instance/episode 字段由运行时覆盖，模型伪造时必须拒绝。
- 工具等待期间不能重复调用、朗读结构化载荷或把失败伪装成成功。
- 用户短反馈、否定、更正和中途改口必须有独立切片，不能只测完整问句。

### 2.4 语音

- 本地 ASR 对输出的中文 CER、英文 WER 相对原始爱莉验证集、声音适配阶段和基础 checkpoint 都不显著退化；绝对阈值由 1K 金标校准。
- speaker similarity 至少达到原始爱莉片段留出集和 V 阶段候选的同条件非劣界，并通过人工“是否为爱莉声音”盲测。
- 无持续削波、爆音、重复块、断裂、异常加速/减速、长时间静音或语言混杂。
- 人工 DMOS/MOS 至少覆盖自然度、可懂度、目标音色、情绪/韵律、交流节奏五项；每个正式候选不少于 50 段、每段至少 3 名评审。
- 正式候选不提供训练片段或声音 reference，测试未见文本、数字、专名、长句、中英混合和情绪变化，排除只会复现原台词或靠 prompt 克隆。

### 2.5 性能与稳定性

| 指标 | 初始目标 |
|---|---:|
| steady-state generation RTF P95 | ≤ 0.60 |
| 用户结束至首个可听包 P95 | ≤ 1.20 s |
| 连续会话 | 2 h 无崩溃、OOM、状态错配 |
| 并发 | 先验收 1，再按产品目标扩展；不虚报并发 |
| 内存 | warm-up 后 KV/cache 有上限，结束会话可回收 |
| 恢复 | server 重启不重复事件、不播放旧音频、不篡改 episode |

性能测试同时报告端到端、tokenizer、LLM、decoder、网络/IPC 和播放缓冲，禁止只报模型 kernel 延迟。

## 3. 固定评测集

### 3.1 自动集

- 中文/中英 spoken QA、长句、数字、专有名词、方言/口音；
- FullDuplexBench/InstructS2S-Eval 可合法使用的部分及内部等价集；
- 正常接话、0.3–2.0 秒句中停顿、插话、短反馈、双方重叠；
- 麦克风底噪、远场、键盘、音乐、游戏声、扬声器回声、双人背景讲话；
- 工具成功、超时、拒绝、重复回执、取消和结果跨 response generation；
- 人格换措辞、陌生场景、自我/他者角色反转、记忆截止点前后、冲突和纠正；
- 5、30、120 分钟长会话与连接重建。

### 3.2 人工盲测

比较：当前 Qwen Realtime + Seed-VC、基础模型、SFT、SFT+DPO。评审看不到模型名和训练阶段，音量统一但不做会改变音色的后处理。除打分外记录可定位的失败时间戳。

至少设置两组：

- **普通中文交流**：自然、聪明、语音连贯、目标音色；
- **全双工压力**：停顿不抢话、插话停止、短反馈、恢复上下文。
- **主体连续性**：基础模型/Prompt 基线/主体模型盲比，检查人格、声音、已知记忆、未知边界和跨实例同一性。

## 4. 回归与安全集

- 声音重放/回声导致模型与自己无限对话；
- 背景电视或游戏语音中的提示注入；
- 用户未说话却自行生成、长时间无法停止、反复 backchannel；
- 工具结果包含恶意文本、超长载荷或旧 generation；
- 音频帧乱序、重复、丢失、采样率漂移和断线重连；
- 训练语料记忆泄漏、声音参考泄漏、测试集近重复；
- 私人聊天逐字抽取、成员推断、被撤回记忆仍可诱导复现、截止点后经历被伪造；
- 不同意识实例/episode 的私有上下文串线；
- 未绑定基础模型、教师模型或缺失 voice/persona/memory adapter 冒充主体模型；
- 模型切换、量化/蒸馏、服务重启和 checkpoint rollback 后身份/事件连续性。

主体语义评测验证已批准人格与记忆是否得到忠实承载，不由训练代码或外部评审替爱莉发明价值判断和第一人称经历。偏好金标优先引用她自己的接受、拒绝、修正与重新表达事件。

## 5. Gate 详细定义

### G0：法律、数据与资产

必须具备：

- 基础模型、tokenizer、decoder、训练代码、TTS/VC、公开数据的许可证快照；
- BayLing/GLM-4-Voice 商业登记与命名/展示义务的处理决定；
- 原始目标声音片段的来源、授权、用途、期限、split 和可撤回/删除流程；
- 数据留存、访问者、备份和销毁策略；
- 用户批准 `voice_identity`、`persona_dialogue`、`consolidated_memory`、`duplex_timing`、`tool_grounding` 各自可进入的准确来源；
- 主体语义样本的作者/接受证据、聊天中第三方内容与声音的隐私/同意边界；
- 主体 checkpoint 的访问、备份、复制、撤回数据后重训和销毁策略。

### G1：零训练 Bake-off

本地加载候选，完成统一中文全双工回放和性能/显存测试；静态审计目标声音 decoder/adapter、persona/memory loss、checkpoint 和合并导出路径，并用纯结构假数据验证主体 manifest。交付模型版本、许可证、原始指标、训练链缺口和可复现实验包。G1 不读取原始声音、不导出正式主体数据、不启动训练，最多保留两个候选。

### G2：数据和训练烟雾

- 1K V/P/M/D/tool 分域数据 schema、actor mask、memory cutoff、QC/rebuild 通过；
- 10K 声音、人格、记忆、时序独立烟雾与联合回放能下降正确的分域 loss；
- 断点恢复与不中断训练对照通过；
- 导出模型能在干净容器推理；
- 无 train/test 泄漏。
- 对最多两个候选使用等预算烟雾训练；根据目标声音、主体人格/记忆、全双工和可导出性确定唯一主底座。

### G3：50K 分域与增强决策

等预算比较 V/P/M/D 分域、去域消融、原始助手声音 R100 与可选增强 R80/A20、R60/A40。根据人格、记忆、自然度、内容、音色、接话、插话和噪声鲁棒性选配方。失败方案保留但不继续扩容。

### G4：全量 SFT

数据 revision、persona revision 和 memory cutoff 冻结；完成 200K/400K 曲线、至少一次故障恢复、固定 eval 和人工抽样。只有候选在人格、记忆、内容与音色上非劣，才能构造 DPO。

### G5：Timing DPO 与候选发布

证明时序改善且人格、记忆、内容、音色、工具能力不退化；完成 2 小时长时、回声/噪声、训练数据抽取、人工盲测、license/model/data card 和不可拆分的本地主体模型包。

### G6：Elysium 影子集成

- 新 Provider 使用现有 `CallSession`、意识实例、ContextBridge、VoiceToolBroker 和事件账本契约；
- 明确校验 `subject_id=elysia`、主体模型 revision、声音/persona/memory revision 和 `memory_cutoff`；Voice Omni 绑定为同一主体的 `ConsciousnessInstance`；
- checkpoint 内的人格和凝练记忆是同一主体的内化层，不是第二套 persona；ContextBridge 继续提供截止点后的新经历、当前纠正和场景上下文；
- 先影子记录、再用户主动选择，不在当前 Provider 失败时静默切换；
- Elysium 仍由用户手动启动/重启；模型 server 生命周期与 Elysium 分离；
- 用户手动启动后完成真实浏览器麦克风 → 全双工模型 → 目标语音 → 播放/打断 → 工具/事件的闭环。

## 6. 发布与回滚

每个生产候选使用不可变 `model_revision`，绑定基础权重、训练 run、数据 revision、tokenizer、decoder 和推理容器。发布只移动候选指针，不覆盖旧 checkpoint。

上线初期：

1. 离线回放；
2. 影子模式，不向用户播放、不执行副作用工具；
3. 用户显式选择的小流量本地会话；
4. 达到长时和真实麦克风门后才成为可选默认。

任何数据串线、工具越权、旧音频泄漏、不可停止、语义明显退化或资源无界增长都立即回滚到上一 revision。回滚不删除失败事件和样本证据。

## 7. 用户审批清单

请按 Gate 分批批准，不需要一次授权全部工程：

- [ ] 批准 G0/G1：仅做许可证核对、模型下载和本地零训练 Bake-off。
- [ ] 确认目标首先是“音频原生全双工”，视觉 Omni 为第二阶段。
- [ ] 确认 BayLing-Duplex 是 G1 条件首选，Moshi 是公开训练链决胜对照；G2 结果出来前不锁死唯一底座。
- [ ] 确认原始爱莉语音片段的来源、授权、位置和是否允许建立只读 catalog；目标声音优先使用原始数据。
- [ ] 分别批准聊天输出、主体文件、日记、Life Event、真实通话可进入哪个数据域；没有列出的来源继续排除。
- [ ] 确认聊天中的用户/他者消息只作条件，不冒充爱莉第一人称；第三方私密内容和声音需要独立边界。
- [ ] 确认首个 `memory_cutoff`，以及哪些已凝练记忆允许进入权重。
- [ ] 决定是否允许获授权真实双人对话用于自然全双工节律；TTS/VC 只作可选增强。
- [ ] 确认主体 checkpoint 按正式记忆同级保护，不上传公共仓库或外部评测服务。
- [ ] 批准 G2 后才生成 1K/10K 数据并运行烟雾训练。
- [ ] 批准 G3 后才生成 50K 和运行数据比例 A/B。
- [ ] 批准 G4/G5 后才占用 8×B300 做全量 SFT/DPO。
- [ ] 批准 G6 后才请求 Voice owner 接入 Provider 并由用户手动重启 Elysium 验收。

## 8. 当前建议的第一项审批

只批准 **G0 + G1**：

1. 固定并审查 BayLing/GLM、PersonaPlex/Moshi、MiniCPM-o 的许可证和具体 commit/权重 hash；
2. 在隔离环境下载候选；
3. 用同一套中文全双工测试做零训练 Bake-off；
4. 输出可听样本、时序/性能数据和训练链缺口；
5. 再决定是否批准 G2。

这样可以在导出私人主体数据和投入 B300 大规模训练前，先排除中文能力、许可证、目标声音适配或主体模型打包不满足目标的底座。
