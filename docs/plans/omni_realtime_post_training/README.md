# 本地 Omni 实时全双工模型后训练计划

> 状态：待用户审批的技术方案，不代表已经授权下载模型、生成训练数据、占用 8×B300、启动训练或接入 Elysium。
> 调研基线：2026-08-04。模型、许可证和上游训练支持在开工前必须重新核对并固定版本。

## 1. 结论

本计划建议把目标拆成两个可验收阶段，而不是一次性训练一个同时承担中文理解、音视频感知、全双工时序、工具调用和固定音色的模型：

1. **第一阶段：音频原生全双工。** 模型在同一生成循环中持续听取用户语音并生成自己的文本/语音，自己决定何时保持沉默、开始说话、停止、处理插话和恢复回答。前置 VAD 可以用于降噪、保护和评测，但不能替模型做轮次决策。
2. **第二阶段：Omni 扩展。** 在第一阶段稳定后再加入视觉或其他感知条件。Elysium 现有的 Perception/World State 仍是权威运行时边界；不得为了“全模态”把私有场景上下文、身份或长期记忆直接固化进模型权重。

首选研究底座是 **BayLing-Duplex / GLM-4-Voice 9B**，前提是先通过许可证、中文实机能力和可复现训练三个门。它的多通道交错序列直接建模“用户语音 + 助手内在文本 + 助手语音”，公开论文用 400K 全双工样本进行 SFT，再用只改变时序的 DPO 偏好对优化轮次和打断。它比把流式响应包装成“全双工”更接近本项目目标。

同时保留两条对照线：

- **PersonaPlex 7B / Moshi**：真正的双音频流、成熟的实时服务和公开后训练经验，尤其适合验证“本地 TTS 合成数据 + 真实对话节律”的数据方案；主要缺点是公开底座以英语为主。
- **Qwen3-Omni-30B-A3B-Instruct**：作为本地语义教师、音频理解基准和离线评审模型，不作为第一阶段全双工学生底座。它具有低延迟流式 Thinker–Talker，但公开技术报告没有原生同时听说或打断时序的双通道训练定义。

MiniCPM-o 4.5 可作为未来音视频 Omni 的短期可行性实验，但不应在验证其全双工训练链和中文稳定性前直接承担主线。

## 2. 为什么本地 TTS 数据可行，但不能单独使用

本地 TTS 很适合提供：

- 助手目标音色的一致语音；
- 可控的文本、情绪、语速、停顿和重音；
- 大规模、可追溯、无需上传隐私数据的合成；
- 正例和仅改变时序的 DPO 负例。

但单一 TTS 会把合成器的韵律、停顿、呼吸和缺陷一起蒸馏给学生，也无法自然覆盖抢话、犹豫、回声、短反馈和双方重叠。PersonaPlex 的公开结果同样显示：合成数据更擅长提供角色与任务遵循，真实双人对话更擅长提供自然的交流节律。因此计划要求保留可审计的真实/自然对话数据混合实验，不允许未经对照就把 100% 单音色合成数据扩到最终规模。

## 3. 目标架构

```mermaid
flowchart LR
    A["批准的对话文本与时序模板"] --> B["本地 TTS 数据工厂"]
    B --> C["用户轨与助手轨对齐"]
    D["有授权的真实双人对话"] --> C
    C --> E["质量检查与不可变数据版本"]
    E --> F["冻结语音 tokenizer 预编码"]
    F --> G["8×B300：SFT"]
    G --> H["时序偏好对：DPO + SFT 保持项"]
    H --> I["离线全双工评测与人工盲测"]
    I --> J["本地推理候选包"]
    J --> K["Elysium Voice Provider 适配"]
```

训练模型只负责语音理解、回复内容、交流时序和语音 token 生成。Elysium 继续负责可信意识实例、主体上下文投影、工具权限、事件账本、长期记忆和进程生命周期。后训练不得创造第二套人格或把运行时记忆焊进 checkpoint。

## 4. 8×B300 定位

如果设备是 DGX/HGX B300，官方规格为 8×288 GB HBM3e（合计约 2.3 TB）、NVSwitch 全互连；DGX B300 还提供 8×3.84 TB 本地 NVMe。对 9B 级全双工模型，显存不是首要风险，数据质量、音频预处理吞吐、长序列负载均衡、恢复能力和评测可信度更重要。

建议：

- 第一个可复现基线使用 BF16；只有 BF16 与 FP8 在固定样本上达到损失、梯度和输出等价门后才启用 Transformer Engine FP8。
- 10K 样本烟雾训练可以用 LoRA 验证数据与时序；生产候选应比较 LoRA 与冻结 tokenizer/decoder、全量微调 9B LLM 的差异。
- 全量训练使用 8 卡单节点 `torchrun`，优先 FSDP2 或 DeepSpeed ZeRO-2/3；不把单卡能放下模型误当成可恢复、可扩展的工业训练方案。
- 不承诺训练耗时。先跑 1% burn-in，依据真实 samples/s、codec 预处理速度和 checkpoint 时间计算成本。

## 5. 里程碑与审批点

| Gate | 交付物 | 用户审批后才能做的下一步 |
|---|---|---|
| G0 | 模型权重、代码、TTS、语料许可证与声音授权清单 | 下载受限权重、登记商业用途、生成数据 |
| G1 | BayLing、PersonaPlex/Moshi、MiniCPM-o 的本地中文实机报告 | 确定唯一主底座 |
| G2 | 1K 数据契约与 10K LoRA 烟雾训练 | 扩到 50K 数据混合实验 |
| G3 | 50K 的合成/真实数据比例、音色和全双工 A/B | 扩到 200K/400K SFT |
| G4 | 可恢复的全量 SFT、固定离线评测集 | 构造并运行时序 DPO |
| G5 | DPO 候选、盲测、长时稳定和安全评测 | 导出本地推理候选 |
| G6 | 与现有 Voice Provider 契约的影子接入 | 用户手动启动 Elysium 做真实链路验收 |

任何 Gate 未通过都保留数据、配置、日志和 checkpoint，不用“继续堆数据/算力”掩盖失败。
