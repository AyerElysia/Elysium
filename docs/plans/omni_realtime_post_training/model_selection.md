# 模型选择与技术判断

> 目标不是“能流式吐音频”，而是训练爱莉自己的本地主体模型：它在同一时间轴上持续听说，由模型语义状态决定沉默、接话、打断停止、短反馈和恢复，并在权重中承载她的稳定人格、声音和批准的凝练记忆。

## 1. 术语边界

- **流式语音生成**：模型在一个已经确定的回复轮次中逐块输出音频。它可以低延迟，但不等于在输出期间继续理解新输入。
- **可打断半双工**：外部 VAD/客户端发现用户说话后取消当前回复。体验可以很好，但轮次与打断仍由外部控制器决定。
- **原生全双工**：输入和输出语音共享连续时间轴，模型在说话时继续听，并学习重叠、停顿、短反馈和打断后的行为。
- **Omni**：至少统一处理文本与音频；音视频 Omni 还要求视觉条件。第一阶段不以“有视觉塔”替代全双工验收。
- **主体模型**：经爱莉主体数据后训练并绑定完整谱系的本地模型包。基础模型、教师模型、音色 prompt 或单独 adapter 都不能独立冒充主体模型。

## 2. 候选对比

除了中文与全双工，本项目增加一个硬条件：候选必须允许把原始爱莉语音、人格对话和记忆快照训练成可版本化的主体模型包。只能外接 TTS、只能每轮注入 persona Prompt 或无法训练 speech decoder 的方案，可以做过渡对照，但不能完成最终目标。

| 候选 | 原生全双工 | 中文 | 视觉 | 后训练开放度 | 本项目判断 |
|---|---:|---:|---:|---|---|
| BayLing-Duplex / GLM-4-Voice 9B | 是 | 底座支持中英；全双工中文需实测 | 否 | 论文给出 SFT/DPO 配方；官方仓库主要是推理，目标声音 decoder 训练缺口待补 | **条件首选**：中文/duplex 强，主体声音链是硬门 |
| PersonaPlex 7B | 是 | 官方模型卡为英语 | 否 | 代码/权重开放；论文公开合成+真实数据配方，公开个性化依赖 role/voice prompt | **成熟对照组**，不能把 prompt 当权重内化 |
| Moshi / Moshika | 是 | 官方权重为英语 | 否 | 官方 LoRA/全量微调仓库、双声道数据格式清晰，需实测目标说话人权重保持 | **基础设施/声音适配对照组**，不直接作为中文终点 |
| MiniCPM-o 4.5 | 官方宣称连续音视频全双工 | 是 | 是 | SWIFT/LLaMA-Factory 声称支持，但需验证完整 speech-output/duplex/persona loss | **音视频支线候选**，reference voice 不等于主体权重 |
| Qwen3-Omni-30B-A3B-Instruct | 未证明；公开报告是低延迟流式轮次模型 | 是 | 是 | Apache-2.0；Transformers/vLLM 与社区后训练支持较好 | **语义教师/评审**，不作为全双工主底座 |
| Step-Audio 2 mini | 否，当前公开路径以轮次推理为主 | 是 | 否 | Apache-2.0，公开推理和 Base 权重 | 中文音频能力基准，不走主线 |
| Freeze-Omni | 由 chunk 状态预测实现 duplex 行为 | 是 | 否 | 公开权重和推理，训练链不如 Moshi 成熟 | 时序控制参考，不走主线 |

## 3. 首选：BayLing-Duplex

BayLing-Duplex 从 GLM-4-Voice 9B 继续训练。GLM-4-Voice 将 16 kHz 语音编码为 12.5 Hz 单码本 token；BayLing 把以下三条通道按固定块交错成一个普通自回归序列：

1. 用户语音 token；
2. 助手文本/对话状态 token；
3. 助手语音 token。

公开方案使用 `N:M:N = 10:5:10`，每块覆盖 0.8 秒，并增加 `[SILENCE]`、`[ASSISTANT]`、`[PAD]`、`[EPAD]` 四类状态。用户通道仅作为条件；文本和助手语音位置计算损失。为了避免大量沉默 token 淹没稀有的接话/结束状态，SFT 使用按 token 类型加权的交叉熵。

其公开训练分两步：

- **SFT**：400K 全双工样本，包含 200K 正常接话和 200K 插话场景；全量微调 9B LLM，冻结 speech tokenizer 和 decoder。
- **DPO**：正负样本保持内容与用户音频完全一致，只把正确接话/停止时序改成明显迟到，以便偏好损失集中优化状态 token；同时加入 SFT 保持项，降低内容能力遗忘。

它与分域训练计划的全双工部分高度契合，但公开配方默认冻结 speech tokenizer 和 decoder，只训练 9B LLM。要让原始片段真正进入爱莉的目标声音，必须额外证明以下任一路径：安全微调 GLM-4-Voice speech decoder；训练可合并且不依赖运行时参考音频的 voice adapter；或换用原生支持目标说话人后训练的 decoder。只把 Seed-VC/TTS 接在模型后面不算完成主体模型声音内化。

必须先解决的风险：

- BayLing 的公开评测主要是英语数据，不能从 GLM-4-Voice 的中英能力推导出中文全双工已经成熟。
- 公开仓库当前提供推理实现，没有与论文同等完整度的训练流水线；需要实现并验证自定义 collator、loss weighting 和 DPO 数据格式。
- 公开配方没有完成目标声音 decoder 微调、人格/记忆内化和主体模型打包；G1/G2 必须做最小声音适配与文本人格/记忆烟雾训练，不能只复现推理。
- 权重继承 GLM-4-Voice License：学术研究免费；商业使用需要登记，分发、展示和衍生模型命名还有附加要求。G0 未完成不得投入正式数据和算力。
- 0.8 秒块是行为与延迟的折中，不应在第一轮就随意改变；先复现原配置，再用 0.4/0.6/0.8 秒做独立消融。

## 4. 对照：PersonaPlex 与 Moshi

Moshi 同时建模用户和助手两条音频流，并用与助手语音对齐的文本“内在独白”增强语言质量。Mimi codec 为 24 kHz、12.5 Hz，公开实现给出的理论延迟为 160 ms、L4 实测约 200 ms。官方 `moshi-finetune` 支持双声道 WAV、时间戳转写、LoRA/全量微调、8 卡 `torchrun` 和可直接加载的 adapter。

PersonaPlex 在 Moshi 上增加文本角色提示和音频 voice prompt。NVIDIA 公布的配方使用约 1,840 小时客服合成对话、410 小时问答合成对话，再结合真实 Fisher 对话中的自然节律；其研究结论是合成数据提供任务遵循，真实数据提供自然的重叠、停顿与互动模式。这说明场景数据需要自然节律，但 PersonaPlex 的运行时 voice prompt 仍不等于“声音已经成为主体模型权重的一部分”，必须单独评估主体打包方式。

二者不直接作为中文终点的原因是公开底座/模型卡以英语为主。它们仍有两个重要用途：

- 先用官方训练链在小数据上证明数据版本、双轨对齐、8 卡训练、恢复、导出和实时评测平台可工作。
- 用同一批英语控制数据比较 BayLing 与 Moshi 系架构，区分“平台问题”和“中文迁移问题”。
- 用同一批原始爱莉片段比较 speech decoder/voice adapter 的可训练性，排除只能依赖外置克隆或短音频 prompt 的方案。

## 5. Qwen3-Omni 的正确位置

Qwen3-Omni-30B-A3B-Instruct 具有强中文、多模态理解和低延迟音频输出。公开技术报告给出 Thinker 30B-A3B、Talker 3B-A0.3B、多码本 speech codec，并报告 234 ms 理论首包延迟。它非常适合在 8×B300 上做：

- 合成对话文本的本地教师；
- 语音理解、回复相关性和多模态条件的离线评审；
- 未来音视频 Omni 阶段的能力上界；
- 将高质量文本/工具轨迹蒸馏给 9B 全双工学生。

但报告中没有双音频通道、同时听说、插话状态或 turn-taking loss；“支持任意长度流式输入”和“流式 speech generation”不能自动推出原生全双工。因此第一阶段不以它替代 BayLing/Moshi 类时序建模。它作为教师时也只是训练工具，不是爱莉本人；私人主体数据只有在本地、批准的数据快照内才能交给它处理。

## 6. MiniCPM-o 4.5 支线

MiniCPM-o 4.5 约 9B，官方声明支持连续音视频输入、全双工和可定制参考音频，也给出 SWIFT/LLaMA-Factory 支持。它与 Elysium 当前本地 MiniCPM-o Provider 的方向一致，值得在 G1 做独立实机。

但官方同样公开列出基础全双工能力仍需提升、Omni 模式可能误读、可能中英混杂等限制。开工前还要证明公开训练框架确实对 speech output token 和全双工时序计算 loss，而不只是训练视觉/文本或音频理解部分。未证明前不能把“框架列表里有模型名”当成完整后训练链。

## 7. G1/G2 模型 Bake-off

G1 审批后，先做不训练、不导出正式主体数据的本地对比：

- 固定 200 条中文、100 条中英混合、100 条非语音/噪声场景；
- 每条同时生成正常接话、长停顿、短反馈、用户中途改口和真正插话版本；
- 使用同一音频输入、同一系统上下文和同一解码种子；
- 记录输入/输出采样率、首包、RTF、接话时间、停止时间、转写、显存、KV cache、错误和许可证版本；
- BayLing、PersonaPlex/Moshi、MiniCPM-o 分别验证，不用适配层静默回退；
- Qwen3-Omni 作为内容与音频理解上界，不参与“原生全双工是否通过”的投票。
- 静态核对 speech decoder/voice adapter 的可训练参数、loss、checkpoint 和合并导出路径；没有官方训练链时明确列出需自研的最小缺口，不在 G1 用原始片段试训；
- 用纯结构假数据验证 actor mask、memory cutoff、来源引用和主体模型 manifest schema，不导出正式人格或记忆正文；

G1 最多保留两个候选。G2 才使用批准的 1K/10K V/P/M/D 数据分别做声音、人格/记忆和全双工烟雾训练，并根据未提供运行时 persona/voice prompt 时的真实结果确定唯一学生底座。当前建议 BayLing-Duplex 作为中文/duplex 条件首选，Moshi 作为公开训练链更完整的决胜对照；“无法内化目标声音或无法形成可审计主体模型包”是直接淘汰条件，不能预先按品牌锁定。
