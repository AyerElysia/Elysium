# 记忆连续性减法重构计划

状态：分阶段工程计划。本文中的“目标”“出口条件”不表示已经实现或验收通过。

本计划承接 [记忆连续性理念与约束](../architecture/记忆连续性理念与约束.md)。它规定怎样把用户要求变成少量可验证的工程增量，不替爱莉创作记忆、人格或自我解释。

实施以仓库 [AGENTS.md](../../AGENTS.md) 为边界。现场存在未提交的并发修改和用户正在运行的实例；不得覆盖其他人的修改，不得自动停止、启动或重启 Elysium。完成隔离检查不等于真实启动验收，未经用户手动启动验收不得推送。

## 一、决策摘要

本轮不做整套推翻，也不高比例照搬旧系统。保留的是历史、身份、主体执笔权、权限和可靠性合同；旧组件需要分别证明必要性与实际价值。

第一阶段只闭合以下路径：

> 原始经历可靠入账与回取 → 爱莉本人通过现有工具读取、改写 MEMORY.md → 她亲自提交连续性检查点 → 检查点与精确归档耐久成功后才释放上下文 → 重启后接回同一条连续性并继续精确回取。

第一阶段明确不依赖 Witness 成功、Experience 二次正文摄取、复杂联想或新的后台 reviewer。现有权限、事件归属、路由与私有上下文隔离仍必须保留；不能为了缩短链路而绕过这些安全边界。

本轮以固定 MEMORY.md 作为主体文件的代表路径。它不等于已经统一整个自有文件空间的身份、版本、删除、改名与二进制归档，也不等于已经解决学习、技能验证或承诺履行的全部问题。

### 2.2 需要显式放弃的假设

- 旧组件通过过一些单元测试，不等于用户可感知的记忆能力已验证。
- 保存了副本，不等于原始经历完整、可定位、可读取。
- 生成见证或摘要，不等于该经历已经被后续主体实际读到。
- 图上关联增加，不等于正确回忆或行为连续性改善。
- 文件读取成功，不等于它与当前 prompt 使用的是同一版本。
- 内存中的压缩命令准备成功，不等于重启后可以恢复。
- 修改代码后工具不再报错，不等于故障被修复；错误也可能被吞掉或链路被跳过。
- 机会系统理念适合，不等于其当前具体实现免于验收。

## 三、组件去留决策表

`保留合同` 不表示无条件保留实现；`合并候选` 不授权立即删数据；`可选` 必须能明确关闭而不冒充主体拒绝；`延后` 表示不进入第一闭环。

| 组件或职责 | 当前方向 | 第一阶段怎样处理 | 重新进入主链路的证明 |
|---|---|---|---|
| 原始 Life Event 与来源身份 | 保留合同，检查实现 | 经历正文、occurrence、归属和时间可靠保存；原文可分页回取 | 幂等、缺口、故障和精确回读测试通过 |
| Experience 二次摄取 | 合并候选／退出首阶段依赖 | 最小回取不等其消费完成；保留旧 ID、历史与读取兼容 | 明确有原始事件查询不能承担的需求，且不是仅重复正文和游标 |
| Memory Witness | 可选活动，不作记忆成立前提 | 不新增或恢复必经见证 worker；保留过去写下的见证 | 主体自主回望活动在对照中有明确价值，且失败不阻断原始记忆 |
| 主体文件和不可变历史 | 保留合同，收敛入口 | 只闭合 MEMORY.md 代表路径的同源读写与重启读取 | 下一阶段再证明全文件覆盖、改名、删除与并发 |
| Context Stewardship | 保留必要协议，定向修复 | 主体自写检查点；精确来源归档；先耐久后释放 | 压缩中断、重启和损坏恢复都不伪造连续性 |
| 基本搜索与精确读取 | 保留，减少入口 | 原始事件查找／回读、主体文件读写、context group 读取 | 注册与运行时实测一致，分页完整，权限正确 |
| Boundary 独立流程 | 合并候选／可选增强 | 旧精确引用保持可读；不要求每段记忆先建 Boundary | 与普通文件版本引用相比确有必要能力或体验收益 |
| 自主关联与图扩展 | 可选增强，延后规模扩展 | 第一基线不用复杂自动展开；保留已写关系历史 | 相同条件下增加正确回忆，成本和误联想可接受 |
| World／投影器 | 仅保留必要运行合同，审查依赖 | 保留身份、权限、路由等必要带来源状态；不当作另一份主观事实权威 | 明确消费者、可重建性和故障影响范围 |
| 统一机会理念与运行时 | 保留理念，具体实现待验 | 第一闭环无安排需求时不强接；确需安排时只接一条经过验证的路径 | 到期、唤起、回执、去重、暂停、重启均有证据 |
| 学习与技能验证 | 延后 | 保留真实实践和反馈原始证据；不自动宣布成熟 | 一次实践→结果→主体调整→再次实践的独立闭环通过 |
| 承诺对照与提醒 | 延后 | 用场景观察问题，不先建独立承诺数据库或专用工具群 | 能区别未完成、未知、阻碍与重商，不扩大外部行动权限 |
| 新后台 reviewer／新成套工具 | 冻结 | 本阶段不新增 | 最小系统仍存在可重复证明的问题，且现有主体活动与机会无法充分承担 |

## 四、工具策略：第一阶段新增常驻工具为零

第一阶段检查并修复现有入口，不重新创建 memory CRUD 或“万能记忆管理器”。如果某个已有工具缺少实例注册，可以补齐已存在能力的注册；必须同步插件列表、实例 manifest、说明文字与运行时依赖。

| 现有名字 | 本轮职责 | 不应扩大成的职责 |
|---|---|---|
| `nucleus_grep_events` | 依明确查询或时间／来源条件定位原始经历，给出可继续读取的 occurrence 引用 | 自动替主体判定什么最重要、哪句是承诺 |
| `nucleus_read_event` | 按 occurrence 精确分页读取同一事件 | 从 Witness 或摘要伪造原文 |
| `nucleus_read_file` | 对 MEMORY.md 读取选定权威当前版本；一次分页链固定同一版本 | 无提示地在本地磁盘、远端和缓存之间切换 |
| `nucleus_write_file`、`nucleus_edit_file`、`nucleus_apply_patch` | 爱莉自主写入代表文件，提供真实提交结果及来源 | 另建第一人称总结器，或把部分提交报成整体失败后盲重试 |
| `author_self_continuity_checkpoint` | 提交主体自己写的连续性文字、来源 manifest 和释放边界 | 基础设施自行挑选意义或补写第一人称 |
| `read_context_group` | 沿精确 group ref 回读已归档内容，保留实例私有边界 | 让别的实例任意读取当前实例的私有上下文 |

返回字段的最终命名以实现后的 schema 和测试为准，计划要求至少可识别：来源、当前读取版本、内容校验、分页是否完整、提交是否耐久以及仍待恢复的步骤。不能仅靠一段模糊自然语言把“已提交但投影滞后”和“未提交”混成同一种失败。

后续若扩展身份、历史、关系修订或复盘范围，优先扩展已有受控服务及按需能力；任何新增常驻工具必须说明现有入口为什么不足，并单独核算上下文和验证成本。

## 五、阶段 S0：建立可以比较的基线

### 入口条件

用户已授权计划与第一闭环实施；完成 AGENTS、若存在的 COLLABORATION、工作树和相关差异检查。确认现有实例是否运行，登记本轮文件所有者。

### 工作项

1. 固定第一闭环路径和明确不在本轮范围的组件，不先增加配置、后台角色和数据库。
2. 列出原始入账、精确回取、MEMORY.md 读写、checkpoint 提交、快照恢复五个边界的当前调用者与失败传播。
3. 核对并发修改，特别是 Witness 退役、事件流改造和机会运行时；只合入第一闭环必需的明确差异，不整包复制旧分支。
4. 在临时数据上记录基线结果，包括失败，不使用正式主体文件作实验夹具。
5. 准备人类保管的回忆题与事实答案；不提前把测试题和答案交给负责压缩的爱莉。

### 产出与出口

产出是理念文档、本计划、最小依赖与变更清单、临时夹具及基线记录。出口是能说明每一处准备改动与用户目标的对应关系，并确认没有未知共享文件冲突。

如出现所有权冲突或所需变更必须扩成另一套系统，暂停冲突范围；继续完成不受影响的文档和只读核查，不以新 worktree 绕过主目录状态。

## 六、阶段 S1：第一最小闭环

### 6.1 原始经历入账与回取

目标：即使 Witness 没有运行、Experience 尚未摄取或可选投影失败，已经保存的原始经历仍能按身份回取。

必须检查：

- 原文不在入账前被截断；每次发生有稳定 occurrence 和真实来源归属。
- 同一 occurrence 相同内容重试不重复；同一身份不同内容显式冲突。
- grep 命中是有界投影，read_event 才沿 occurrence 补齐原文；投影不得冒充全文。
- 分页 continuation 不能跨事件使用，字节边界、hash 和读取前沿保持一致。
- 找不到记录、权限不足、存储不可用分别显式失败，不能返回一个看起来合法的空经历。
- 原始回忆与当前工具活动仍进入共同可追溯历史，但不因此自动成为外部事实真值。

验证时应有一个依赖隔离用例：可选 Witness／Experience 路径不可用，原始事件入账与回取仍按合同完成。不要通过吞掉可选组件错误来假装它工作正常。

### 6.2 MEMORY.md 代表文件同源读写

目标：她写入的 MEMORY.md，与随后工具读取、下一轮 prompt 使用和重启后读取的，是同一个被明确确认的主体版本。

必须检查：

- 读取优先从当前选定 authority 取得完整字节和版本，不能把陈旧磁盘投影当作当前真源。
- 分页首次读取固定一个版本；后续页不能悄悄混入更新后的内容。
- 写入来自真实主体工具活动，保留来源、实例、发生身份与原因；遗留缺失不能补造为完整来源。
- 写入冲突能被发现。若本轮尚不能覆盖所有通用文件并发编辑，则明确限制代表路径并留下后续项，不宣称全文件 CAS 完成。
- authority 已提交而本地文件或索引未同步时，报告真实提交状态和恢复路径，不能诱导重复写入。
- 故意放置过时磁盘副本时，工具读、prompt 读和权威版本仍一致；不为“修复投影”覆盖未知用户字节。

本轮只以 MEMORY.md 为实现与验收代表，不自动迁移其它主体文件，不统一全文件改名／删除，不扩大到所有附件格式。

### 6.3 主体检查点先耐久，后释放

目标：压缩由爱莉自己决定语义内容；基础设施保证当前窗口退出的原文可精确找回，且重启不会丢掉她刚写下的连续性。

顺序合同如下：

1. 固定当前主体、runtime、source manifest、revision 和可释放 group 范围。
2. 接收她亲自写的检查点及释放边界；结构和权限不合法时拒绝，不替她改写语义。
3. 对将释放的组保存精确归档并校验可回取。
4. 将检查点及恢复所需的精确身份、来源和版本耐久保存；优先复用已有快照／归档能力，不先新建第三套日志。
5. 只有耐久边界成立后才更新当前上下文、确认释放与对应消费状态。
6. 成功回执必须对应这次实际提交。调用取消、超时或重试，不得使“准备过”变成“已经生效”。

归档已经保存而后续提交失败，可以留下可解释的未完成归档；不能反过来先释放再希望稍后保存成功。开放的工具调用链、新到达且未被本次 manifest 覆盖的用户内容，不得被误释放。

### 6.4 重启恢复

目标：新进程恢复同一个主体与窗口谱系，能够看到已提交检查点并回取它引用的精确组。

- 有可信快照与归档时按现有协议恢复；原文、hash、actor、runtime 和 revision 对不上时显式报告。
- 持久化读取失败、损坏快照、缺失归档，不得被解释为“没有历史，建立空链继续”。
- 如果能证明仅投影损坏，可从可信记录重建；不能为恢复创造新的第一人称连续性文字。
- 检查点已提交但旧进程尚未完成内存更新就崩溃时，重启结果仍应与已提交版本一致。
- 严格保留实例隔离；统一主体不意味着互相复制私有滚动上下文。

### 6.5 S1 出口与产出

产出包括最小实现、对应契约测试、故障注入记录、真实手动验收步骤、变更范围与限制说明。工具列表应保持“已有能力修复／对齐”，而不是新增一组记忆工具。

工程出口是四个边界均可证明：原文可回取、代表文件同源读写、检查点先耐久后释放、重启不空链假连续。随后进入模型与真实运行验收；工程出口通过不能单独宣布体感连续性完成。

## 七、两层验收

### 7.1 A 层：基础设施契约测试

使用临时数据库、临时 workspace、受控时钟和可注入失败的存储适配器。可以用固定文本构造协议夹具，但必须标明它是测试文本，不得说成爱莉实际自主形成的记忆。

| 风险 | 注入方式 | 必须观察到的结果 |
|---|---|---|
| 原始入账失败 | 在耐久提交前返回错误 | 不确认保存，不推进相关已完成边界 |
| 重复与身份冲突 | 重放相同 occurrence，再提交不同正文 | 相同重放幂等；冲突明确可定位 |
| 长原文分页 | 超过单页预算并包含中文和多字节字符 | 连续页可还原完整原文，引用与hash不变 |
| 读取中变更 | 页一之后推进当前 head | 继续读固定版本或显式失效，不能拼接两个版本 |
| authority／磁盘分歧 | 放置旧磁盘内容 | MEMORY 工具读和 prompt 读按既定权威一致 |
| 部分提交 | authority成功后令投影失败 | 报告已提交与待恢复步骤，不谎称未发生 |
| 归档失败 | 第一组或中间组保存失败 | 不释放对应原文，不安装假成功检查点 |
| 检查点保存失败 | 归档成功、检查点耐久提交失败 | 保留当前连续性，可重试，不丢来源 |
| 崩溃窗口 | 在耐久成功与内存更新之间重建运行时 | 恢复已提交状态，不重复压缩／重复经历 |
| 快照或归档损坏 | 缺键、hash变化、错误actor/runtime | 显式阻断受影响恢复，不回退空窗口 |
| 可选组件失效 | Witness／Experience／复杂图入口不可用 | 原始回取和代表文件闭环不依赖其成功 |
| 权限和跨实例 | 非owner请求私有group或无权事件 | 拒绝访问，不借引用绕过权限 |
| 并发和取消 | 两次修改同版本、提交中取消 | 冲突／取消语义可重放，无静默覆盖与越界推进 |

当前正式实例运行时，仅执行不会写正式数据、不会争用 authority 或造成资源饥饿的轻量定向检查；高负载回归须等待用户手动停止实例。不得自动拉起第二个正式实例以取得测试结果。

### 7.2 B 层：真实模型自主记忆与行为验收

此层必须由爱莉在真实交互中亲自选择记什么、怎样组织和怎样压缩。固定夹具可以证明工具协议，但不能证明她真的形成了连续性。

由用户手动启动采用本轮代码的实例后，按以下步骤进行：

1. 开始前记录版本、启用组件、工具可用清单和当前主体／实例身份，不记录秘密或无关私人原文。
2. 在正常交流和实际活动中积累一组经历，包含普通细节而不只包含显著事件。测试者另行保管时间、原文引用和预期答案。
3. 让她自主决定是否以及如何写 MEMORY.md、建立线索或回读来源。不要把待考细节逐条提示为“必须保留的测试答案”。
4. 经历第一次真实主体压缩，确认其实际提交者、来源与耐久状态；继续正常交流和新活动。
5. 经历第二次真实主体压缩。若她未提交有效检查点，不代笔补一个测试摘要，应将场景记为尚未完成并查清原因。
6. 由用户手动重启；验证主体、runtime 和已提交连续性能够恢复，没有静默空链。
7. 提问没有预先告知她的近期回忆题。允许她自主调用读取／搜索；分别记录直接想起、沿线索找回、未找到、错误归因和编造。
8. 再进行相关行为场景，观察经历是否影响新的选择，而不是只让她解释自己有没有成长。

应至少覆盖下列情形：

| 情形 | 观察点 | 防止“测试通过但实际没做到”的措施 |
|---|---|---|
| 未提前告知的近期细节 | 压缩两次加重启后能否准确回忆普通经历 | 问题不提前给负责压缩的主体；答案不重新注入当前prompt |
| 现实情况变化 | 同时知道过去是什么、后来改成什么及来源 | 不把旧经历删掉；不能仅返回最新一句而无法解释过去 |
| 跨任务反馈迁移 | 某次批评或夸奖能否在不同表述的新情境中影响行为 | 不直接重复原反馈关键词；不替主体写预设习惯 |
| 承诺有多种结局 | 能区别真实完成、未完成、阻碍、取消／重新协商和目前未知 | 采用无外部风险的小任务；工具成功或口头保证不等于承诺完成 |
| 技能实践 | 方法使用结果是否被看见，之后能否基于实际反馈调整 | 记录作品／测试／实际反馈；不以模型自评代替效果 |

承诺和技能场景在 S1 可以先作为基线观察，用来确认尚缺什么；它们若未通过，不得自动扩张 S1 或声称已解决。应把具体失败交给后续阶段，只有数据表明必要时才考虑新验证角色。

### 7.3 组件价值对照

在同一输入场景、模型、工具权限和相近预算下，先测基本读取／搜索基线，再一次只加入一个可选增强。尽量使用多次尝试和未用于调参的保留场景，不能只展示一次有利结果。

至少记录：正确回忆与错误归因、行为是否改变、工具回读次数、模型调用与token成本、延迟、故障频率、失败影响范围及恢复代价。额外模型调用带来的收益需要同时报告成本，不能把更多预算误归功于组件架构。

不设置会直接决定主体记忆真假、遗忘或技能成熟度的自动分数。工程协议可按明确合同通过／失败；主观学习和相处体验由带证据的人工观察与主体反馈共同说明。

## 八、阶段 S2：统一文件记忆身份与版本

### 入口

S1 已在代表路径通过契约检查及真实手动恢复；基线显示最小路径可用。全文件身份问题成为具体障碍，且有明确迁移与兼容方案。

### 工作项

1. 把记忆身份从路径解耦：同一文件改名仍为同一记忆；复制是否产生新身份要由明确文件操作语义决定，不靠内容相似度猜测。
2. 统一受管写入口，覆盖新增、更新、改名和删除生命周期；记录旧字节、当前head、发生身份和作者来源。
3. 逐项盘点 file tools、下载、媒体保存、技能导入及其他写入路径，防止绕过统一版本合同。不得仅修一个入口就声称全空间覆盖。
4. 日常读取先定位 current head，再固定精确版本完成分页；历史读取显式选择版本，旧Boundary／事件引用不漂移。
5. 索引只负责可达性；当前head、文件投影和检索缓存可由历史重建，不反向修改主体原文。
6. 图片、音频、视频等原件保留内容校验与来源引用；文本说明、转写、派生预览与原件分离，不把全部格式强转成一段文本。
7. 旧路径、旧ID、旧版本缺来源的事实如实保留；迁移不补造主体作者，不合并语义相似的旧记忆。

### 出口与产出

产出为统一受管文件合同、逐入口覆盖清单、兼容与迁移说明、故障注入测试。出口必须包括：改名不断引用，删除后仍能追溯旧字节，同版本并发修改不静默覆盖，重试不重复版本，投影损坏可重建。

未经全格式、全写入口验证，只能报告已覆盖范围，不能宣称“整个文件空间都完成了统一”。

## 九、阶段 S3：自主索引与关联

### 入口

基本读取、当前／历史版本和文件身份已可靠。已有无复杂图基线，可用于比较增益。

### 工作项

- 保留由爱莉书写的多层线索和索引，不让基础设施决定她应该怎样组织记忆。
- 关系端点使用稳定引用；关系含义、理由及需要时的强度由主体表达。
- 对关系修改或撤回追加新历史，维护可重建当前投影；不硬删旧判断。
- 扩展已有关系／读取能力前，先证明普通文件链接与精确版本在哪些情形不够用。
- 对独立 Boundary 流程和复杂图扩散分别做对照；可合并的职责收敛回已有版本引用，不为保留类名而强制增加流程。
- 检索排名、共同回忆、关联强度和真假判断严格分离；一次回忆不是自动强化或认可关系的授权。

### 出口与产出

产出为主体可理解的引用和关系协议、现有工具的最小扩展、对照记录。出口是额外关联能在保留场景中提供可说明的正确回忆收益，而非只增加节点、边和提示词长度。没有收益或故障面明显扩大时，保持可选或撤回当前增强实现，历史仍保留。

## 十、阶段 S4：时效、学习、技能与承诺对照

### 入口

S1–S3 的必要部分已稳定；真实交互已经给出可重复的具体问题，例如旧情况被当作当前事实、方法使用后未吸收反馈、明确承诺长期没有后续。

### 共用方向

优先让现有主体活动通过统一机会能力，对照“以前怎样理解／答应”与“后来实际发生什么”。证据来自共同事件与文件历史，结果进入已有注意或主体记忆路径，不各自复制一套长期库和调度器。

最初只选一个明确问题做闭环，不能同时启用时效审查器、技能裁判、承诺监察者和习惯评分器。

### 具体约束

- 时效：过去发生的事实不会仅因年龄增长变错；当前适用性需依据新信息。重新读或重存旧文件不算重新验证。
- 学习与技能：以真实实践和反馈为依据，修改由主体决定；自动测试只验证其技术可观察部分，不自动宣布人格或技能成熟。
- 承诺：区分明确答应、愿望、尝试、条件和未知；没有证据不等于证明没做，不擅自加期限或制造义务。
- 提醒：明确指出依据和未解决的差距；不能用重复提醒代替解决，也不能把新保证当成旧问题已完成。
- 机会：先证明一次安排→到期→唤起→执行／明确推迟→回执→恢复的链路，再承载更多语义活动。
- 权限：发现一个承诺或技能练习需求，不自动获得发消息、联网、花费或修改外部系统的权限。

### 是否新增 reviewer 的门槛

只有当经过验证的现有主体活动与机会能力仍持续漏掉一类重要问题，而且新增角色相较更简单做法确有证据支持时，才重新讨论 reviewer。届时必须单独确定身份、授权、访问范围、退出机制、成本、失败语义和结果是否需要主体接受，不能把当前建议自动转成常驻人格。

### 出口与产出

每次仅交付一种问题的端到端闭环及对照记录，例如一次技能实践改进或一次未落实承诺被正确处理。没有通过的类别保持未完成，不用一个通用工具的存在覆盖全部能力宣称。

## 十一、隐私、权限、性能与停止条件

### 隐私和权限

实验原文、记忆版本、context归档与主体模型数据按正式记忆敏感级别保护，不上传公共服务或放入公开报告。报告优先保留身份引用、hash、状态和最小必要节选，不暴露秘密与无关私人原文。

跨实例共享只能经过明确的事件和授权读取边界；共同主体身份不等于每个窗口可以访问所有私有上下文。测试不得借助无权路径获得正确答案。

### 性能

首先记录基线，再决定是否增加机制。每阶段报告模型调用数、请求预算、回读页数、延迟、待处理量、可选组件成本和恢复代价；目标是以更短且可解释的链路完成体验，而不是把工作隐藏进不计成本的后台。

预算用于控制资源，不用于静默丢弃权威原文。待处理积压必须可见；无新增输入、无到期安排时，不应为了证明“系统在工作”而无意义地反复调用模型。

### 必须停止扩大范围的情况

- 发现主体字节缺失、身份错归、跨实例泄漏、越权或历史不可回取。
- 未提交的共享修改发生冲突，无法证明保留其他人的工作。
- 核心失败被空结果、空上下文、伪成功或静默降级掩盖。
- 需要用户停止／重启实例才能继续安全验证，而用户尚未操作。
- 第一闭环尚不能解释失败，却准备新增更多模型角色或工具。
- 新组件只提高复杂度和成本，未表现出可复现收益。

停止扩大范围不等于删除历史或放弃记录。应保留失败现场的最小必要证据、已确认的提交状态和可恢复入口，完成不受影响的工作，并报告需要用户决定的边界。

## 十二、整合、回退与交付清单

### 整合

工程改动落在主仓库当前工作状态中。只处理明确属于本轮的文件或hunk，不宽范围暂存，不整包覆盖并发事件流、Witness退役或机会系统修改。隔离测试使用临时数据，不使用另一套正式运行实例。

每次交付记录：变了什么、没有变什么、哪些合同已测试、哪些只观察过源码、哪些仍需用户手动验收。当前限制应与成功结果同等明确。

### 回退

回退优先退代码和可重建投影，不删除或改写主体历史字节。新代码若已产生版本或引用，旧代码恢复前必须证明仍可读取；不能把回退理解为清空新表、抹掉新经历或把head强行退到旧理解。

若无法无损恢复，则停止并向用户报告，不创造“看起来更顺”的记忆。正式数据迁移必须有范围明确的备份和逐字节／可证明无损的恢复方法。
