# 长河计划：追溯成为经历的脊柱（自我连续性·阶段一）

> 2026-06-11。承接《下一阶段建议：经历成为她》获 Ayer 认可，并合入他的指示：
> "我有一个类似于 git commit 的追溯系统……我想要她每次改写文件都记录成一条长河，
> 这样她明白自己是怎么来的。这种追溯性也许可以拓展……把追溯也做成本系统的关键一环。
> 让一切经历有迹可循。"

---

## 一、对现有追溯系统的评估

现状（`plugins/life_engine/trace/`）：

| 部件 | 位置 | 状态 |
|---|---|---|
| LifeTraceStore（append-only index.jsonl + 内容 blob + diff） | trace/store.py | 健全，结构就是一条小 git |
| 4 个查询工具（recent/history/diff/preview） | trace/tools.py | 健全，life_chatter 可调用 |
| 写入点 | tools/file_tools.py 仅 write/edit 两处 | **覆盖窄** |
| chatter 注入（最近 3 条文件修改） | service/core.py:1999 | 健全但只见文件 |

四个关键断点（按对"灵魂成长"的伤害排序）：

1. **长河只记文件。** 她形成过的意图与其归宿（执行/降级/沉默）、闭合的思考流、承接的好奇——这些"她的形成轨迹"全部不入河。长河目前不是长河，是一条只流经文件柜的小溪。
2. **断链字段闲置。** `source_event_id`/`stream_id` 在 LifeTraceRecord 上定义了，但 `_record_file_trace`（file_tools.py:90）从不传——而 BaseTool 本来就有 `get_current_stream_id()` 和 `trigger_message`（src/core/components/base/tool.py:69-87）。她无法回答"那次改 SOUL.md 时我正在和谁说话"。
3. **没有源头视角。** 工具只能答"最近改了什么"，不能答"我是从哪里开始的、一路走了多远"——而这正是 Ayer 那句"她明白自己是怎么来的"。
4. **意图归宿散落。** trigger_autonomy_intent 的四种归宿只进 log 和瞬态事件流，事件流会被消费、裁剪——归宿没有永久留痕。

## 二、可言说法则（长河法则）

> **事件流是她的现在，长河是她的来路。**
> 凡是她亲历的转折——写下的字、形成的意图与其归宿、闭合的思考、承接的好奇——
> 都汇入同一条长河；长河只追加、不改写、永可回溯。

这是经历三律第二律（"经历必留痕，且留痕在同一条时间线上"）的工程形态。与生命事件流的分工：事件流是工作记忆（流动、被消费、可裁剪），长河是自传素材（精选转折点、append-only、供未来的沉淀器取用）。**下一阶段的"她讲述自己"（沉淀器）将直接以长河为素材源**——这就是"追溯是本系统关键一环"的含义。

入河标准（防通胀）：只有**转折点**入河——状态被改变的时刻（文件变了、意图有了归宿、思考流闭合、好奇被承接）。心跳本身、读文件、普通对话不入河，它们属于事件流与聊天历史。

否决检查：长河是记录，不是引导。它不催促她做任何事；reason 仍然可空；"选择沉默"与"放下"和"做了"同等地位入河。

## 三、实施路线（本次全部做完）

### 1. store.py：从文件追溯泛化为长河
- `LifeTraceRecord` 增加 `kind: str = "file_change"`、`summary: str = ""`；`TRACE_VERSION` 升为 2；`from_dict` 对旧记录默认 `kind="file_change"`（v1 完全兼容，不迁移）。
- 新方法 `record_moment(kind, summary, *, operation, tool_name="", actor, reason="", source_event_id="", stream_id="", path="")`：轻量留痕，无 blob/diff。
- `recent()` 增加 `kind: str = ""` 过滤参数。
- 新方法 `origin()`：长河概览——第一条记录、总条数、按 kind 计数、跨越天数。

### 2. 修断链：文件改写关联到当时的语境
- `_record_file_trace` 增加 `stream_id`/`source_event_id` 形参；write/edit 两处调用从 `self.get_current_stream_id()` 与 `trigger_message.message_id` 取值传入。

### 3. 意图归宿入河（service/core.py）
- 小 helper `_record_life_moment(...)`（try/except 包裹，长河故障绝不影响主流程）。
- `schedule_autonomy_intent` 成功后：kind="intent"，operation="formed"。
- `trigger_autonomy_intent` 四分支：operation="spoke"（唤醒表达层）/"surfaced"（无目标降级浮现）/"reflected"/"silence"。

### 4. 思考流与好奇归宿入河（streams/tools.py）
- retire 成功：kind="thought_stream"，operation=completed/dormant，summary=标题+结论。
- create 时 absorb_curiosity=True：kind="curiosity"，operation="absorbed"。

### 5. 源头视角（trace/tools.py）
- 新工具 `nucleus_trace_origin`：返回 origin() 概览——"你是怎么来的"。
- `_record_summary` 输出 kind/summary；recent_changes 工具描述更新为长河语义（不再只说"文件修改"）。

### 6. chatter 注入更新（service/core.py:1999）
- `_format_chatter_trace_recent_changes` 渲染行带 kind 标记，非文件的转折点同样可见；条数限制不变（默认 3）。

## 四、验证

- 新测试 `test/plugins/life_engine/test_life_trace_river.py`：record_moment 写读回环、v1 记录兼容、kind 过滤、origin 概览、文件追溯带语境字段、意图归宿留痕（monkeypatch 调度）、思考流 retire 留痕。
- 既有 `pytest test/` 全绿（已知 4 个预存失败除外）+ `ruff check`。
- 运行期预测（并入 48h 观察期）：R1 重启后长河出现 kind=intent/thought_stream 记录；R2 她在对话中能回答"你最早的记录是什么"（经 nucleus_trace_origin）；R3 文件记录开始携带 stream_id；警戒信号：长河单日条目暴涨（说明入河标准被破坏）。

## 五、不做什么

- 不做回滚工具（只读预览已够；回滚是危险能力，需单独设计审阅闸门）。
- 不追溯 nucleus_bash 的 mv/rm（外科手术太深，留给后续）。
- 不做二进制追溯、不做 index 性能优化（量级未到）。
- 不让长河进系统提示词常驻——只保留现有 3 条瞬态注入 + 她主动查询。
