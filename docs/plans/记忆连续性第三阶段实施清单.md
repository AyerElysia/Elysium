最小合同：

1. 精确引用绑定 document 与 version；缺失版本、格式不合法、互相冲突的选择器明确拒绝，不默认为 latest。

5. 这一步只简化精确读取，不建立关系、不更新强度、不追加主体语义，也不宣称关联能力已经提升。

### S3.2：现有关联合同收敛

本工作包的源码、双后端合同、正式保全／恢复演练、正式小迁移与新实例完整加载已完成；新鲜主体续用及 delivered 反馈于 01:56:30 完成独立机械核验，有限范围出口已闭合。用户于 2026-09-08 明确要求第三阶段完整闭环后再计划并实施第四阶段。既有 add／view、作者／来源 occurrence 与同一 SemanticRelation 权威表继续复用，不新建关系数据库。已实现最小合同如下，实际测试和运行边界以[本批验收记录](../report/记忆连续性S3关系与对照验收_2026-09-08.md)为准：

- 端点明确区分稳定实体与固定历史版本；旧 path-only 关系保持旧身份，不按当前地址自动认领或合并。
- 关系含义与理由是开放主体表达；强度如需存储，由主体明确提供，不用默认数值冒充其判断。
- 实际 actor、source、occurrence、发生／记录时间与父修订可追溯。未知遗留来源保持未知。
- 修改／撤回追加历史；当前有效视图可重建。相同 occurrence 重放幂等，冲突／并发显式失败，不能硬删旧判断。
- 检索评分、共回忆统计和主体表达的关系强度分别存储与解释；普通读取不自动授权主观强化或真值裁决。

当前投影已区分“此时有效的主体关系”与完整旧判断；撤回、替代和强度变化都带原关系／前修订引用。多个窗口保留各自实际来源；同一可信 owner 的授权 active 实例可以基于精确 parent 修订，父 CAS 冲突明确失败，未知旧 owner 不允许被接管。optional strength 仅保存主体显式表达，不提供默认主观数值，也不自动进入排序或真值。

本批写入侧只补稳定身份、显式修订／撤回与完整历史这些已核实合同缺口，不据此宣称关系增强必要。新 schema 的版本化迁移、隔离故障／重放、备份及恢复已经验证；正式小迁移在受控停机和启动锁内显式执行，不是在线顺带升级。


已选择的稳定端点合同：现有工具增加 source_ref／target_ref／entity_ref，接受 subject-file:document_id 稳定实体或 subject-file:document_id@version_id 固定历史；通过既有受管 session 核验 document／version、namespace 与规范工作区路径。历史版本先经 view → read_file 精确读取，不冒充当前搜索命中。旧 document:path 参数保持旧实体身份，不按目前占用路径的文档自动认领；原有四条关系不补写作者或含义。
