## 3. 有序工作包

### S3.0：建立普通文件与精确引用基线

- 核对 file_ref、当前实体引用、固定版本引用、旧 Boundary 引用到真实读取工具的路径，说明需要几步、哪里依赖可变化路径。
- 用临时资料覆盖：索引指向旧版本、更新后仍回读旧版、改名／删除／路径复用后不串档、只有一个精确引用时的可达性、错误和无权限引用的显式失败。
- 分别记录协议成功、实际读回字节、工具调用／页数、额外依赖与错误；不以测试次数或无意义节点数代替收益。
- 普通检索基线须同时覆盖模型工具与 search_actor_memory：断言 legacy 扩散、canonical 显式关系和共同回忆扩散均未被额外调用。是否关闭必须进入实验记录，不能仅凭传入一个旧开关推断；本轮规划不改变正式默认配置。
- 若普通文件链接已足够，保留它作为默认能力，不为保留独立组件而增加步骤。

### S3.1：只补已经证明的引用消费缺口

第一项为纠正已经静态确认的 exact_read_hint 冲突，并验证生成的调用指引能被真实工具执行。随后让已有读取工具直接消费它自己返回的完整精确引用：当前未发现普通文件现成入口，实施前先用合成测试复现并固定旧 path＋version_id 基线，复用 existing session／descriptor 归属校验和 continuation，不建立平行存储或常驻工具。Boundary 已具备原生 exact_uri 路径，不重复实现。

最小合同：

1. 精确引用绑定 document 与 version；缺失版本、格式不合法、互相冲突的选择器明确拒绝，不默认为 latest。
2. 继续通过同一 selected authority、工作区与权限边界读取。引用不是权限凭证，不允许借 document ID 读取其它 namespace 或私有上下文。
3. 验证版本确属该 document，按权威保留的路径与字节读取；改名、删除和地址复用不将旧引用解释成新占用者。
4. 延续原分页、hash、continuation、二进制解码和返回预算合同；不中断旧 path＋version／Boundary 调用的兼容路径。
5. 这一步只简化精确读取，不建立关系、不更新强度、不追加主体语义，也不宣称关联能力已经提升。

首批用例：提示生成的精确调用实际可执行；只保留输出 file_ref 时经历更新／改名／删除／原路径复用后仍读同一旧版；非法引用、错配、跨 namespace 和冲突选择器拒绝；分页期间变更仍固定原版本且篡改 continuation 拒绝；原 path＋version 与 Boundary URI 的兼容及 hash 失败语义不退化。只有修复这些合同与基线后，才进入关系写入侧。

### S3.2：现有关联合同收敛

已有 add／view 及作者／来源幂等继续复用；先解决稳定端点与检索种子不一致，再补已确认缺失的修订／撤回合同。实现选择既有服务或主体文件版本机制的最小扩展，不预先指定新的关系数据库：

- 端点明确区分稳定实体与固定历史版本；旧 path-only 关系保持旧身份，不按当前地址自动认领或合并。
- 关系含义与理由是开放主体表达；强度如需存储，由主体明确提供，不用默认数值冒充其判断。
- 实际 actor、source、occurrence、发生／记录时间与父修订可追溯。未知遗留来源保持未知。
- 修改／撤回追加历史；当前有效视图可重建。相同 occurrence 重放幂等，冲突／并发显式失败，不能硬删旧判断。
- 检索评分、共回忆统计和主体表达的关系强度分别存储与解释；普通读取不自动授权主观强化或真值裁决。

当前投影必须能区分“此时有效的主体关系”与完整旧判断；撤回、替代和强度变化都须带原关系／前修订引用。多个窗口意见冲突保留各自来源，不能用最后写入抹去冲突。是否允许不同来源修订同一关系，以及 optional strength 的表示，需在本工作包的合同设计中明确；不得以一个默认数值替主体作答。

只有在 S3.0 基线上有明确能力缺口、且上述安全合同可满足时，才进入写入侧改动。若需要新 schema，必须另有版本化迁移、隔离往返、失败回退及保全方案，不能顺带在线升级正式库。

### S3.3：对照额外关联与独立 Boundary 的价值

一次只改变一个因素：A 为普通主体索引＋精确版本读取；B 只加入主体明确写下的关系；C 单独观察共同回忆／可达性扩散；Boundary 的独立流程另做对照，不混入同一变量。分支从同一初始资料和隔离实验状态开始，不能把前一分支的新回忆／缓存带到后一分支造成假收益；不回滚正式历史来重置实验。不同时改变模型、提示词、多个工具或预算。

对照记录至少包括：资料／问题集版本、允许读取的来源、模型与工具集合、上下文与调用预算、实际调用／页数、正确回忆、未找到、错误归因、是否有原文支持、延迟、token／模型调用成本、失败影响范围和恢复代价。合成协议评测与主体真实表现分开保存。

开发集用于完善协议；保留集不参与调参，正确答案不得重新注入负责形成线索或压缩的主体上下文。先规划至少三类不同的保留场景：多层线索、过去／当前变化、共享线索下的相似但不同来源；每个条件重复观察，不只展示一次有利结果。具体真实材料由主体在授权活动中选择，工程不代笔建立测试关系。

对结果的计数只是测量，不用于自动判定记忆真假、成熟、遗忘或人格。没有额外正确回忆收益，或成本与故障面明显增加时，保持增强可选或退出当前增强路径，已经写下的历史仍完整可读。

### S3.4：分批运行验收与交付

每个小增量先合成定向测试，再按风险补集成、重启／重放、权限与取消验证。运行中只允许不触碰正式数据、不竞争 authority 的轻量检查；较重测试在受控停机窗口串行执行。需要正式停启时复核唯一 PID、父进程、启动身份、目录和端口；本次用户的特批不允许自启循环，也不允许覆盖主体历史。

正式验收只加载一个经过验证的增量，不改模型配置来掩盖工具缺陷；分别记录代码已实现、是否已加载与是否已由主体实际使用。未验证的增强不默认接入检索，不推送未经真实启动确认的运行变更。

## 4. 本阶段不做

- 不新增 Witness、独立 reviewer、定时语义整理器、技能／承诺评分器或第二套长期记忆。
- 不自动替主体从关键词、相似度、共同出现或时间推断关系含义、强度和真假。
- 不批量重写旧索引／关系，不以路径相同合并身份，不清空历史来重建投影。
- 不把 S2 保留的 outbox 360 未知冲突变成覆盖磁盘的授权；不扩大到任意媒体域、技能脚本或跨后端切换。
- 不承诺本轮开始 S3 就代表整个 S3 或长期连续性目标已经完成。
