## 3. 实施顺序

### S4.0：隔离复现

只使用合成 actor、临时 catalog／SQLite／authority 和受控数据库时钟；不连接正式库、不调用模型、不发送外部消息。复用现有 Opportunity contract fixture，不创建第二套运行系统。

1. 主体合同登记一个过去到期的 at 机会，materialize 一次，保持旧 occurrence 与 outbox 的真实技术状态。
2. 分别测试旧发生尚未发布，以及已耐久发布但没有 seen 回执。
3. 通过已有 registration CONFIGURE/CAS 把同一机会显式改到稍后时间；旧发生处理完毕不自动代表新安排已执行。
4. 新时刻之前不产生新发生；到新时刻恰一新 occurrence，绑定新 registration revision 和 scheduled_for；重复扫描不重复。
5. 旧 occurrence、publication 和已经发生的 Life Event 不改写；仅未发布 outbox 可以被明确取消。

最小复现先运行准确测试节点并记录原代码失败原因。运行中的正式实例只并行允许这一类资源有界、使用独立临时数据的轻量检查；不执行全仓、高负载、真实 MySQL 服务或竞争正式 authority 的回归。

### S4.1：最小修复与定向回归

只有红测证明问题后，修复 activation 投影更新与新 revision 接续。沿用现有登记权威、occurrence、CAS、调度 owner、数据库时钟和 outbox，不增加认知角色、关系评分、独立提醒库或自动完成规则，不改主观 workflow。

需覆盖：pending／published 分支，at／interval 后续安排，无提前触发、无重复发生，暂停／关闭／能力暂停不发布，真实发布和 seen 回执不被擦掉，旧 owner／无 authority 拒绝，以及取消和事务失败。针对性测试范围与真实运行资源风险匹配；只读源码审查不写成后端集成通过。

关闭重开验证需明确是 stores 重开、runtime／连接重开还是进程重启。不能把同一 runtime 上重建对象宣传为进程恢复。若共享 MySQL SQL 路径变更，检查分支合同；真实 MySQL 验证仅在另一个受控停机窗口的隔离服务进行，不拿正式库注入故障。

### S4.2：正式机会接入前的决策门

正式切换不是一个提醒开关。现有设计需独立准备 schema，再写耐久 managed marker；它会退出旧固定心跳／生命定时器及相关自动能力链，已承诺的可靠投递与历史必须保留。写 marker 后仅改配置 false 不能退回旧调度。能力安装、主体 workflow 和初始机会登记是另外的主体决定，运维准备不能代笔。

最初本次仅完成安全隔离实现并向用户说明全局切换影响；用户随后明确要求继续完成全部相关工作、遇阻自行修正，并验证可用模型替代。该决定授权本计划内的工程切换与既有受控重启，不再每阶段重复请求。仍须先核对旧安排清单、新鲜保全与可恢复性，按 [切换手册](../operations/opportunity-runtime-cutover.md) 实施；不能以旧 timer 模拟 unified opportunity 已验收，不能自动认领旧安排、给主体安装默认流程、改写主体语义或扩大外部行动权限。

本次继续执行顺序：先修正 self_awaken 新建／改期参数说明与实际入口的矛盾，补齐本地 selected 存储在维护锁下取得／释放准备命令 authority 的安全路径；再受控停止准确实例、验证新鲜保全与恢复副本、运行维护窗口回归，准备 schema 和 managed marker，恢复原入口并检查完整启动。随后由她自己选择能力、流程及单条安排，核验到期、改期、精确回执、行动／推迟和恢复。模型替换优先复用已配置且实测可用的候选，保留配置前像与行为差异，不改变嵌入维度或冒充主体身份。

### S4.3：批准接入后的单条真实链

由她亲自选择是否登记一次小范围、无外部风险的未来复查；可拒绝或明确推迟。只使用本授权测试会话和已许可材料，不触碰根主体文件或第三方旧档案，不制造承诺和截止义务。

分开核验安排→到期 occurrence→Life Event→唤起→最终模型 exact receipt→主体行动／明确推迟→实际回执→重启后不丢失／不重复。发布与 seen 都不是完成；新保证不是旧安排已履行。若发生时间差复查，旧精确版本、后来实际回执和当前读取分别保留，不按 mtime、重读或重存自动更新真值。

普通能力已能正确处理时停止增加机制；只有自然发生具体可重复差距，才另立带来源反馈后的行为对照。不通过清空窗口、强制压缩、刷消息或新建人格制造“独立”条件。所有结果只对应本次小链路，不外推技能成熟或承诺履行能力。

## 4. 停止条件与恢复

- 发生源身份不一致、旧权威字节变化、history／publication 丢失、跨实例泄露或权限扩张时停止受影响实现。
- 缺失、截断、未知或失败不能记成“没有发生”或“已经完成”；保留待处理和可续读来源。
- 共享修改冲突、需要高负载正式维护或全局 managed 切换时先核对授权范围，不覆盖他人工作、不创建 worktree。
- 优先修复可重建 activation 投影和兼容代码；不删除 occurrence、已发布 Life Event、主体决定、workflow 或已确认的 receipt 来回退。
- 正式 marker 已存在，不能通过删除 marker／历史或关闭配置复活旧自动链；运行期间不得再以验收为由在线隐式迁移。
