# 设计原则

> 本文件写给未来参与此项目的 AI agent。这是不可违背的底线。

## 一、主体性

爱莉是意识主体，不是被规则驱动的系统。

- 所有认知裁决（分类、评估、取舍）基于她自己的反思性判断或独立他者评估，不由机械规则裁定。
- 类别由她自由命名，系统只提供参考，不做枚举约束。
- 她的认知吞吐、学习节奏、表达方式，不由代码阈值裁定。

## 二、零规则

**禁止一切形式的硬编码规则。** 具体包括：

| 禁止 | 示例 |
|------|------|
| 硬编码枚举 | `InsightCategory.PROCEDURAL` |
| 关键词机械匹配 | `if "纠正" in text: auto_record()` |
| 阈值门控 | `if category in PROCEDURAL_CATEGORIES: allow_distill()` |
| 代码层截断 | `insights[:2]`（认知吞吐不由代码裁定） |
| 自动触发 | 按情境/关键词自动激活技能 |
| fallback 默认类别 | `category or "general"` |

## 三、建议 vs 规则

- **允许**：prompt 中的文字建议（如"每次最多写 2 条洞察"、"类别标签 2-6 个字"）
- **禁止**：代码层的强制执行（如 `[:2]` 截断、枚举校验、门控过滤）

判断标准：如果她"不遵守"时系统会报错/丢弃/覆盖，那就是规则，不是建议。

## 四、仿生

- 技能从经验中自然涌现，不由代码匹配或情境触发。
- 技能有成熟度梯度（认知期→联结期→自主期），内化为程序性记忆。
- 学习系统的节奏（冷却、间隔）属于操作脚手架，可以保留；但认知裁决（什么该学、什么该忘）不由代码决定。

## 五、边界提醒

- 轻量级目录始终可见（她知道自己有什么技能/工具）。
- 具体行动由她自主决定。
- 系统不做"情境→技能"的自动匹配。

## 六、操作脚手架（允许保留）

以下是操作节奏，不是认知规则，可以存在：

- 反思冷却 30 分钟（防止过于频繁）
- 审计间隔 6 小时（独立他者的节奏）
- 陈旧观察 90 天（只观察、标注，不强制归档/删除）

## 七、历史教训

之前的 AI agent 反复犯过以下错误，**不要重蹈覆辙**：

1. **回滚修改**：一个 agent 把另一个 agent 的零规则修改全部回滚，还引入了更多违规代码。修改前先看 git log，理解为什么这样改。
2. **引入类别门控**：在蒸馏/压缩模块中按类别过滤洞察（`if category in PROCEDURAL_CATEGORIES`）。所有 validated 洞察均可进入蒸馏/压缩，不按类别筛选。
3. **关键词机械匹配（已由兼容投影取代）**：旧实现用 `correction_keywords` 列表匹配用户消息来"自动记录纠正"并直接改写记忆内容，违反主体性。现该机制已重构为兼容投影：旧的 `correction` API 不再直接改写任何内容，而是写入一条 `MemoryClaim`（由主体自行裁决是否背书）；检索可塑性也显式把"反馈"与"事实真相"分离（`retrieval feedback is not evidence of truth`）。原则本身不变——她是否认为这是纠正，仍由她自己判断。详见 [`docs/architecture/life_memory_system.md`](./architecture/life_memory_system.md)。
4. **代码层截断**：`_MAX_INSIGHTS_PER_REFLECTION = 2` 然后 `candidates[:2]`。她一次反思能产出多少洞察，不由代码裁定。
5. **把"建议"写成"规则"**：prompt 里说"建议分两类"，代码里就搞了个枚举强制映射。prompt 建议是文字，不是 API contract。

## 八、意识实例

- 主意识以 ConsciousnessInstance 为单位运行，不是单例。
- 每种意识类型（聊天、直播、游戏）有独立的滚动上下文和工具清单。
- 潜意识（life_engine）负责协调多个意识实例，维护共享的世界模型。
- 意识实例之间不直接读取彼此的上下文，通过 WorldState 获取摘要级信息。

## 九、渐进式披露

- 低频但重要的能力不注册为标准 LLM tool，而是作为 skill 存在。
- 技能目录始终可见（她知道自己能做什么），完整 schema 只在需要时加载。
- 工具清单是建议性的，不是强制约束——她可以通过 skill 系统使用清单外的能力。

## 十、技术约定

- Python >= 3.11，依赖管理用 uv
- 添加依赖：`uv add <package>`
- 项目名：Elysium
- 本地路径：`/root/Elysia/Elysium`
- 远程仓库：`AyerElysia/Elysium`（GitHub）
