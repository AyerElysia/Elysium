# 心跳潜意识上下文污染分析（2026-09-03）

> 类型：诊断 + 结论更正。
> 代码落地：2026-09-04，潜意识滚动 + 主体亲笔压缩。
> 权威行为以 [生命引擎核心](../architecture/生命引擎核心.md) §2.3 / §5.2 和 [主体上下文连续性与自述检查点](../architecture/主体上下文连续性与自述检查点.md) 为准。

---

## 1. 当时看见的污染

心跳当时每拍重建 `SYSTEM + TOOL + 一条 USER`。USER 里叠了指令头、`<transient_world_perception>`、`SubconsciousContextManager.prepare()` 的事件块（含协议信封）、机会页、时钟/idle 和能力目录。

同时 `_get_nucleus_tools()` 曾把约 49 份完整 schema 钉进每次请求。

结果是：

- 安静拍几乎只剩世界协议快照，看不到近期生命域事件；
- 有 delta 时内联 `raw_content` 信封，而不是可见正文；
- 每拍重绘 suffix，Prefix 缓存被破坏；
- 工具 schema 占用大量窗口，和「轻量目录、按需展开」相反。

权威 Life Event 账本本身不是污染源。应收缩的是 Prompt 投影和 schema 披露。

工具白名单收缩（约 19 个常驻，后增检查点与读组）已经先做完。本文不再把「49 份 schema」写成当前事实。

---

## 2. 曾经错误的修复方向

中间一度考虑过：

- 把事件块收成更好看的规范摘要；
- 给心跳加 suffix（机会页 / 世界感知仍每拍重写）；
- 超预算走 Chatter 当时的 `mechanically_bound_payloads`：丢掉旧组，换成 `<mechanical_context_omission>` 只有 ref。

这些都不能成立。

规范摘要是基础设施语义摘要器。机械省略替主体决定哪些组从窗口消失，也不让她写下替代文本。给心跳加每拍变化的 suffix，会继续打掉 Prefix 缓存，并把瞬态世界/机会页误当成潜意识经历。

**更正（2026-09-04）**：成功路径不是「更好的投影」或「机械省略」。心跳改成稳定 Prefix + 固定 Tools + 只 append 的 Rolling，没有 suffix。超阈值进入压缩回合，只有爱莉调用 `author_self_continuity_checkpoint` 亲笔 `continuity_text` 才能释放旧组。硬窗口仍超则 fail closed，完整滚动留下。

Chatter 同期取消把机械省略当作成功发送/成功快照。内核 hook 若将丢掉对话组，抛错而不是省略。

## 3. 当前窗口（验收用）

| 项 | 当前行为 |
| --- | --- |
| Prefix | `SOUL` / `USER` / `MEMORY` 原文 + EXISTENCE + 过滤 `TOOL.md` + 稳定身份头 |
| Tools | `HEARTBEAT_TOOL_NAMES`（含检查点与 `read_context_group`） |
| Rolling | `life_heartbeat.rolling_context`；每拍只 append 可见生命域事件 |
| 无新事件 | 链不动；空滚动时请求补稳定 `<heartbeat_turn/>`，不写入快照 |
| 压缩 | 清单 append 一次；她亲笔检查点；归档 `life_heartbeat.context_archive` |
| 不进请求 | 世界感知、机会页、时钟、idle、能力目录、机械省略 |
| 消费游标 | 成功 attempt 对本拍声明投影给出 exact receipt，且压缩回合已完成 |

机会总线和 World Projection 仍存在，只是不再注入心跳模型窗口。

## 4. 运行中发现（2026-09-04）

空滚动且无新事件时，心跳请求只有 SYSTEM+TOOL。模型返回后内核追加 assistant，失败为 `对话不能以 assistant 开始; roles=['assistant']`。已改为：仅在对话链为空或以 assistant 开头时，请求补一条稳定 `<heartbeat_turn/>` USER；无新事件仍不把该帧或本拍回复写入滚动快照。

涉及心跳的改动必须由用户手动启动 Elysium。本文只记录代码合同；启动成功与关键链路日志是运行验收，不在 agent 自动启动范围内。
