# 心跳潜意识上下文污染分析（2026-09-03）

## 结论

当时心跳变脏，不是爱莉自己把内心写乱了，而是 **Prompt 投影把账本协议、世界快照和全量工具 schema 一齐灌进了潜意识窗口**。工具变多是其中一层：诊断时心跳没有清单，每次把约 **49 个工具的完整 JSON Schema（约 57 KiB）** 作为不可裁剪的 `ROLE.TOOL` 钉死在请求里。

**工具 schema 这一层已经由问题 2 改掉。** 当前心跳走 `HEARTBEAT_TOOL_NAMES`（约 19 个常驻 schema）+ 能力目录 + `nucleus_learn` 跟随 learning skill。下文 1.1 的分组表是收缩前的快照，不是当前行为。当前清单见 [心跳工具清单_2026-09-03](./心跳工具清单_2026-09-03.md)。事件投影与世界感知的污染观察（第 2、3 节）当时仍然成立，不因工具白名单自动消失。

本报告原来只做只读诊断。问题 2 落地后，第 1 节的「当前实现」结论已过时，以架构文档和心跳工具清单为准。

## 证据来源

- 代码：`plugins/life_engine/service/core.py` 的 `_get_nucleus_tools` / `_run_heartbeat_model` / `_prepare_heartbeat_context` / `_build_prompt_header`；`plugins/life_engine/service/subconscious_context.py` 的 `_render_event`；`plugins/life_engine/service/perception_gateway.py`；`src/kernel/llm/context.py`（`ROLE.TOOL` 固定钉住）。
- 运行日志：`data/logs.db` 近 7 天 `wake_context_injected`，只读 `content_chars` / `selected` / `drained` / `history`，不读取事件正文。
- 工具体积：对当前心跳工具池调用 `to_schema()`，统计 UTF-8 字节，不打印描述原文。
- 近 7 天 `authority token lease` / `StaleAuthorityToken` 日志命中 1939 次，与 2026-09-02 文件权威租约问题同谱系；会让未确认 delta 反复重放，把脏投影放大。

未使用：`llm_usage` 表当前为空，没有心跳 prompt token 的独立计量。

## 1. 工具污染（本次补充）

### 1.1 心跳没有工具清单

`tool_manifests.py` 写明：意识实例按 kind 过滤 schema，**中枢心跳不受这些清单约束**，走 `life_engine_internal` 自己的注册。

`LifeEngineService._get_nucleus_tools()` 每次心跳拼接：

| 分组 | 数量 | schema 约计 |
| --- | --- | --- |
| 文件 / bash / 屏幕 / 平台 / 叙事 / 休息 / 子代理 / 会话证据等 `ALL_TOOLS` | 15 | 19.4 KiB |
| 学习系统 `LEARNING_TOOLS` | **16** | **12.5 KiB** |
| 记忆检索 / 边界 / 连续性复盘 | 5 | 9.1 KiB |
| grep 文件 + Life Event 读写 | 3 | 6.7 KiB |
| 联网、主动系统、技能、日程、TODO、表情收藏 | 10 | 9.1 KiB |
| **合计** | **49** | **57.7 KiB** |

最大单项：`nucleus_memory_continuity_review`（4.0 KiB）、`nucleus_grep_file`（3.6 KiB）、`nucleus_run_agent`（2.6 KiB）、`nucleus_grep_events`（2.3 KiB）、`nucleus_search_memory`（2.3 KiB）。

这些 schema 经 `request.add_payload(LLMPayload(ROLE.TOOL, tools))` 进入请求。内核把 `ROLE.TOOL` 与 `ROLE.SYSTEM` 一样视为 pinned：上下文超预算时先砍用户侧事件流，**不会先拿掉工具表**。

### 1.2 和原则的偏差

`docs/principles.md` 第七条：她应能看到轻量能力目录，低频复杂能力按需要加载完整 schema。当前心跳是反向实现：学习候选、连续性复盘、屏幕、bash、联网、子代理、平台动作、表情收藏，无论本轮是否有对应工作，完整参数表都在。

指令头 `_build_prompt_header()` 又用大段「你可以 / 不要」复述 TODO、主动系统、技能、休息、子代理、bash、联网、看屏。工作区 `TOOL.md` 再注入一次（仅做了执行器口吻过滤）。模型同时看到三份工具说明书：schema、心跳手册、工作区文档。

命名也不干净：心跳实际注册的是 `nucleus_todo`，指令头仍写 `nucleus_manage_todo`；聊天清单仍列着 `nucleus_list_todos` / `nucleus_manage_todo`。这不是认知裁决问题，是协议身份漂移。

### 1.3 为什么「最近」更明显

不是偶然观感。最近几周心跳工具池明显变厚，而且多数只服务低频维护：

- 学习侧从「看洞察」扩成 16 个独立工具（反思、质疑、主体文档候选、技能候选、验证实验等），全部常驻心跳。
- 08-31 完整意识活动链补上 `nucleus_grep_events` / `nucleus_read_event`，schema 本身不小；真正变脏的是它们让模型更常去翻协议事件，返回值再以 `raw_content` JSON 写回下一轮。
- 连续性复盘、记忆边界、统一主动 query/command、表情收藏三件套都进了中枢池。
- 指令头同时禁止心跳用 bash / 看屏 / 联网替用户办事，但这些 schema 仍在。禁止写在散文里，能力却完整暴露，既占预算，也诱使模型把潜意识当成万能执行器。

Minecraft 的 `nucleus_minecraft` **没有**进 `_get_nucleus_tools()`；它在聊天 / 场景清单里。心跳脏的主因不是 Minecraft 工具 schema。

聊天也变多了（chat manifest 约 40 项，含文件、bash、联网、Minecraft），但至少有清单，且没有把 16 个学习工具和表情收藏工具强行灌进每一轮表达。心跳是「中枢应能做运维」被实现成「每次独白带上全部运维面板」。

## 2. 事件流投影污染（前序发现，仍成立）

08-31 修复保证了账本完整，这是对的。Prompt 投影没有同步改成「第一人称可读」。

`SubconsciousContextManager._render_event()` 对 `CONSCIOUS_ACTIVITY` 使用 `raw_content or content`。模型轮的 compact `content` 只是 `{phase, has_provider_reasoning, has_assistant_message, tool_call_count}`，实际注入的是整份 `life.conscious_activity.model_turn.v1`，含 `provider_reasoning_content`、transport id、schema 名。单项 ≤ 4 KiB 就全文内联。

工具调用在 Prompt 里再 dump 一遍参数 JSON；工具结果同样走 `raw_content` 协议信封。心跳自己的模型轮也会落账，下一拍 `prepare()` 再把这份 CoT JSON 当作「最近事件」读回来。

默认在**有未消费 delta** 时还会拼最近 5 个已确认因果组。游标追上、本拍没有新事件时，`prepare()` 直接返回空 `content`，这 5 组不会出现在 Prompt 里。近 7 天 773 次 `selected=0` 就是这种空事件投影。

游标只在成功模型 attempt 给出整份 wake Text 的 exact receipt 后前进。09-02 租约过期导致持久化失败时，同一份脏 delta 会连拍重放；日志里近 7 天权威租约失败命中与此相符。代码侧租约/keepalive 修复尚未随用户手动重启生效。

## 3. 世界感知在 16k 预算之外

`_prepare_heartbeat_context()` 先按 16k 裁事件，再把 `prepare_perception("life_engine_subconscious")` 的 `<transient_world_perception>` 整段前置。感知默认硬顶 32 KiB，含 Presence 窗口、assertion 行（`assertion_id/domain/predicate/value=.../occurrence_id/...`）和 change 行。内联值上限 512 字节/条，行本身仍是协议键值。

近 7 天 2350 次 wake：

- `selected=0`（无新事件）773 次，`content_chars` 高度集中在 **12013 / 12306 / 12151**。空闲心跳仍固定带约 12k 字符的世界协议快照。
- 有事件时平均约 16k，最高 33653，与「12k 感知 + 16k 事件」相加一致。
- 空闲基线反复出现，说明脏感不完全取决于她刚做过什么；即使安静，潜意识窗口也先被世界投影填一层。

这与 `docs/architecture/LLM内核.md` 记录的历史超窗（感知未共享总预算）是同一结构，只是现在有 100k token 任务帽，所以更多表现为脏，而不是必炸窗。

## 4. 心跳用户消息实际长什么样

一次 `life_engine_heartbeat` 的 user 侧大致是：

1. 固定指令头（身份、内在动作、TODO、主动系统、技能、工具边界、输出格式、工作区文件树）
2. `<transient_world_perception>`（预算外，常驻 ~12k）
3. 事件投影：仅当有未消费 delta 时才出现（16k 内：摘要 + 近 5 组 + delta；内容偏 schema JSON / CoT）。游标追上则为空。
4. 状态行、注意线索、日记普查、文件收拾邀请、回望长河、学习观察、技能目录、学习进度、主体复盘邀请
5. 可选 MEMORY 维护提示

system 侧另有完整 `SOUL.md`、`USER.md` 摘要、`TOOL.md` 过滤稿。工具 schema 不在上述字符预算里。

所以「潜意识上下文」在检视器里看起来会同时像：运维手册、世界状态 API dump、意识活动 JSON、以及一份她来不及读完的工具目录。

## 5. 不是什么

- 不是要把账本改回摘要快照。权威 Life Event 仍须完整、可追溯；脏的是 Prompt 投影。
- 不是要用关键词筛掉她的想法。工程上只能改信封、预算和披露层级。
- 不是 Minecraft 工具进了心跳。具身工具在聊天/场景清单。
- 不能把「系统没授权某工具」说成「她不想用」。心跳若收缩 schema，必须另给可见目录，并保留她主动展开的路径。

## 6. 滚动上下文、生命域感知与 platform 式工具（2026-09-03 续）

用户希望：潜意识滚动上下文 = 整个生命域的近期事件，超出预算再压缩；工具参考 `platform_action`（目录/机会常驻，读到 skill 后再执行）。对照现状：

### 6.1 现在不是「全生命域近期事件 + 超预算压缩」

- 权威账本是统一生命域：聊天、心跳、Witness、Voice、直播、Minecraft、子代理的模型轮/工具都会 `record_conscious_*` 进同一 Life Event，并进入 pending → `_event_history`。
- Prompt 用的不是账本近期窗口，而是运行时折叠缓冲。`compact_history()` 把已确认前缀收进规范摘要，内存里只留摘要 + 最近 5 个因果组 + 未消费工作。
- 摘要几乎只保留高价值 MESSAGE 和 AGENT_RESULT；`CONSCIOUS_ACTIVITY` / `HEARTBEAT` / 普通 TOOL 只进计数器，不进摘要正文。折叠后等于从滚动视图里消失。
- `prepare()` 在 **没有未消费 delta 时返回空 content**。安静心跳看不到那 5 个近期组。
- 「压缩」不是 Chatter 那种 LLM 上下文压缩（`context_compaction.py`）。超预算时是按因果组塞进 16k：塞不下就丢组、大项改 excerpt_ref。没有把旧事件语义压缩成可续读的近期长河。

因此：账本覆盖生命域，滚动 Prompt 不是。

### 6.2 潜意识能不能感知整个生命域

能感知「正在发生、尚未确认」的跨实例活动，以及世界投影里的 Presence/assertion；不能默认看见整条生命域近期故事。

| 通道 | 范围 | 默认是否进心跳 Prompt |
| --- | --- | --- |
| Life Event 账本 | 所有已注册意识表面的活动 | 否；需 `nucleus_grep_events` / `nucleus_read_event` |
| pending / `_event_history` | 同上，但已折叠 | 仅未消费 delta（外加有 delta 时的近 5 组） |
| World Perception | 所有 active 窗口 + assertion/change 页 | 是，每拍约 12k 协议行，预算外 |
| 各实例私有滚动上下文 | Chatter/Voice 自己的对话窗 | 否，且禁止互抄 |

`inner_query` 可以再问世界投影。私有聊天原文不进潜意识，这是实例隔离，不是缺陷。

目标态应为：每拍都投递「有界的生命域近期事件投影」（含各表面），超预算把更早部分标成压缩摘要并保留 occurrence ref；账本仍完整。不得用关键词决定哪些表面「重要」才留下。

### 6.3 海量工具：按 platform 模式收，而不是再加 16 张 schema

`platform_action` 已经是正确模板：一个 dispatcher；`action=help` 或读 `skills/qq_actions/SKILL.md` 才展开能力；不把 200+ 飞书 API 注册成独立工具。学习侧其实已有机会段落（技能目录、学习进度、主体复盘邀请），却仍然把 16 个学习工具的完整 schema 每拍钉进 `ROLE.TOOL`。

应对齐为：

1. 心跳常驻：观察/沉淀真正常用的少量入口（休息、工作区文件、记忆检索、事件续读、主动系统、`nucleus_skill`、一个学习 dispatcher、已有的 `platform_action`）。
2. 机会段落继续只报事实（有候选、有复盘窗口），不报「你应该调用某工具」，也不按情境自动 `get_skill`。
3. 她看见机会后自己 `nucleus_skill detail` / `get_skill` / dispatcher `help`，再执行。这是渐进式披露，不是情境→技能匹配。
4. 学习 16 工具收成一个多 action dispatcher，SKILL.md 放操作说明，与 QQ/飞书清单同构。

未改事件投影与世界感知。工具收编已落地（见文首与 [心跳工具清单_2026-09-03](./心跳工具清单_2026-09-03.md)）。滚动上下文改成「每拍近期生命域窗口 + 标示压缩」仍未做，需要独立交付和契约测试；涉及心跳的运行验收仍须用户手动重启。

## 7. 滚动 / 工具 / 后缀三块（2026-09-03 晚）

心跳**不用** Chatter 的 Prefix / Rolling / Suffix 装配器。每拍是全新三条 payload：`ROLE.SYSTEM` + `ROLE.TOOL` + 一条 `ROLE.USER`。没有跨拍滚动 payload 链；上一拍独白只经 Life Event，再视游标决定是否进本拍投影。

对照检视器里常说的三块：

| 块 | 心跳里实际是什么 | 是否健康 |
| --- | --- | --- |
| 滚动 | `prepare()` 的事件投影，贴在 USER「最近事件流」里；世界感知被前置进同一段 | **否。** 无 delta 时空段；有 delta 才带摘要 + 近 5 组 + 本拍工作。折叠后 `CONSCIOUS_ACTIVITY` 只进计数。单项 ≤4KiB 内联协议/`raw_content`。16k 是塞组，不是生命域近期窗口的可续读压缩。 |
| 工具 | `HEARTBEAT_TOOL_NAMES` 约 19 个 schema，pinned；另有能力目录和过滤后的 `TOOL.md` | **代码侧已收干净。** 不再每拍钉 49 张学习/bash/看屏 schema。未手动重启则运行中仍可能是旧池。三份说明书（schema / 指令头 / TOOL.md）仍重叠。 |
| 后缀 | 心跳没有发送后剥离的 suffix。USER 后半是状态、机会页、TODO、能力目录、学习短状态、时段建议；世界感知其实在事件流前面 | **半健康。** 机会页/能力目录契约是对的。世界感知仍在 16k 外、空闲也约 12k 协议行。指令头和时段建议仍有「信息差」口吻。这些每拍重建，不会像聊天滚动那样把旧脏块攒下去。 |

目标态（滚动每拍都有有界生命域近期窗、超预算标压缩并留 occurrence ref）仍未落地。权威账本完整，脏的是 Prompt 投影。
