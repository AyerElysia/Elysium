## 方法与隔离边界

诊断脚本：`scripts/probe_configured_relay_models.py`。请求显式声明是 synthetic infrastructure diagnostic，不是爱莉或其他主体，不载入 SOUL、USER、MEMORY、历史、检查点或任何真实聊天内容。

每个候选进行两步 OpenAI-compatible `chat/completions` 合成往返：

1. 使用 `tool_choice=auto` 请求原生无操作工具 `diagnostic-noop`，要求随机 marker 与整数 count=7；验证恰有一个 function call、工具名、严格 JSON 参数、随机 marker/count 与非空 call ID 均匹配。
2. 不执行任何真实工具，只在请求中续接绑定同一 call ID 的合成 tool result；要求返回其 marker。验证 HTTP 200、非空短文本包含正确 marker，且没有额外工具调用。

保留被测模型已配置的 reasoning/thinking 参数及 stream 设置。每 HTTP 阶段总时限 45 秒、连接时限 5 秒、最多 1,024 输出 token；最大并发 2、无重试、无重定向、不使用环境代理。仅输出白名单元数据与成功布尔值；凭据、异常正文、响应正文、原始 headers 与 URL query 均不输出或保存。

## 建议与验收限制

仅就短合成测试而言，`gpt-5.6-terra` 在原配置 `reasoning_effort=high`、`stream=true` 条件下通过完整工具往返；Gemini 与 Astra 也有本时点成功证据。但主协调者随后转述真实 notice 长窗口链的独立观察：terra 两次 `LLMEmptyResponseError`、Gemini 多次返回成功但未调工具、MiMo 先两次 429 后发送成功。因此不能把本次短合成通过当作 terra 在真实长窗口稳定的证据，也不再据此建议直接沿 terra 验收。主协调者拟结合 Astra 本次双阶段 200 与此前真实工具链证据，另行决定正式测试选型；此诊断子任务没有自行验证上述长窗口记录，也没有修改正式路由或进行重启。旧记录中 Gemini 没有调用工具的现象同样不能用于断言它完全不具备原生工具能力。

这次只证明短合成输入下原生工具调用与工具结果续接可用，不证明百万 token 长上下文、大工具清单、真实表达工具投递、主体记忆文件写入或 S1 连续性闭环已完成；这些仍须在正式授权链中验收。服务可用性是本时点观察，不是长期稳定性保证。
