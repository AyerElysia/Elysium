# 潜意识与表达层交互（对内回声 + 稳定叫醒）

> 日期：2026-09-03
> 状态：代码已落地；运行中的 Elysium 需用户手动重启后才会吃到唤醒修复。

## 范围

补齐同一主体两条门，不复活 `nucleus_tell_dfc`：

1. **对内回声**：表达层 `inner_dialogue` 结构化落账；心跳 `nucleus_proactive_command(action=inner.return)` 把第一人称回声交还给 originating `stream_id`，并真正拉起该流的 `StreamLoop`。
2. **对外叫醒**：现有 `outreach.begin` 在合成未读信封后补上 `start_stream_loop` 与 `bypass_message_buffer`。心跳工具名对 `tool-` 前缀与裸名双向容错。

## 不做

- 不复活 `nucleus_tell_dfc`；其实现类已删除
- 不按最近聊天流、昵称或账号自动选表达层
- 不把 inner.return 写入 outreach claim / `spoke` / `passed`
- 不在看到 `inner_dialogue` 事件后自动叫醒
- 不给心跳增加 `life_send_*`

## 权威与投影

- sink / return / delivery 都是只追加的 Life Event；`raw_content` 是结构化 JSON，不靠解析 header 散文。
- open set 是可重建投影，心跳 cursor 推进后仍可通过 `nucleus_proactive_query(resource=inner_dialogue)` 看见。
- `expect_surface=false` 不进入 open set。缺 `stream_id` 的 sink 保留念头，但 return fail closed（`missing_stream`）。
- open 上限 32；满时新的 `expect_surface=true` 显式拒绝。

## 验收

定向测试：`test/plugins/life_engine/test_inner_dialogue_return.py`、`test_initiative_delivery.py` 唤醒断言、`test_heartbeat_tools.py` 前缀解析。

真机：用户手动重启 Elysium 后，一次 `inner_dialogue` → 心跳 `inner.return` 应叫醒原窗口且不强制发送；一次 `outreach.begin` 应拉起目标流驱动器。
