# 后台认知任务模型时限审计（2026-08-10）

## 结论

本轮故障不是“后台模型普遍不可用”，而是前台与后台共享了同一个 Provider 级 120 秒 attempt 上限，且 Learning 复用了 Heartbeat 的 `core` 路由。后台领域自己的总 deadline 又不足以容纳首选模型超时后的完整故障转移，导致高质量推理在固定边界被反复切断。

治理原则调整为：

- 前台交互兼顾质量与用户可感知速度；
- 后台认知以质量和完整性优先，使用更充足但仍有限、可取消的总 deadline；
- 单候选 attempt 上限按任务配置，不再通过放大全局 Provider 值连带拖慢前台；
- 领域总 deadline 与单候选 attempt 是两层不同合同，不能互相冒充；
- 超时、取消和关停不得伪装成功，不得推进 cursor、commit 未精确交付的投影或丢弃耐久待办。

## 现场证据

审计只统计 content-free 轨迹元数据与日志事件，没有读取或记录 prompt、响应正文、工具参数、凭据和用户消息内容。

2026-08-09 08:30 至 2026-08-10 的轨迹切片显示：

| 请求 | 首选模型结果 | 后备模型结果 | 观察 |
| --- | --- | --- | --- |
| `life_engine_heartbeat` | 442/442 成功 | 未成为常态依赖 | p99 约 63 秒，最大约 95 秒；现有 300 秒总硬顶基本合理 |
| `life_learning_reflection` | DeepSeek 30 次中 7 次成功、23 次在约 120 秒超时 | Luna 21/21 成功，p90 约 53 秒 | 180 秒总 deadline 在首选超时后只剩约 60 秒 |
| `life_learning_audit` | DeepSeek 5 次中 1 次成功、4 次在约 120 秒超时 | Luna 5/5 成功，约 18–43 秒 | 审计最终完成，但每条候选先消耗固定失败前缀 |
| `life_memory_witness` | 32/32 成功 | — | 最大约 74 秒；当前实现仍只约束 send，response 消费边界不完整 |
| `life_epistemic_opportunity` | 日志中出现 23 次 45 秒 typed timeout | — | 45 秒明显不适合后台候选生成 |

Learning 的真实旧预算关系为：

```text
DeepSeek 单 attempt 120s
→ 剩余约 60s
→ Luna fallback
→ 整个逻辑请求总 deadline 180s
```

因此日志中的 TimeoutError 主要是预算层次错误，不等同于 Learning 数据丢失。本次 audit 最终完成了候选处理；Reflection 的工作先进入耐久队列，失败后保留并退避。

## 根因

1. `config/models.toml` 的 `providers.<name>.timeout` 被装配到每一个模型候选。
2. 任务配置此前没有 attempt timeout 覆盖字段，前台和后台只能共享 120 秒。
3. Learning 由 `LifeEngineService` 注入 Heartbeat 的 `core` task name，没有独立路由身份。
4. Audit、Reflection、Knowledge 与 Skill 的逻辑请求总 deadline 均为 180 秒，无法稳定容纳“120 秒首选超时 + 完整后备响应”。
5. Memory Witness 只给 `request.send()` 设置外层上限，最终 response 消费没有共享同一个 monotonic deadline。
6. Epistemic Opportunity 虽已有正确的单一 deadline 和 single-flight，但总时限只有 45 秒。
7. `force_stream_mode` 的非流式兼容路径曾分别给 `client.create()` 和流预收集各一份完整 timeout，使一个名义上的单候选 attempt 最坏接近 `2 × timeout`。

## 实施合同

### 平台模型路由

新增可选 `tasks.<name>.attempt_timeout_seconds`：

- 仅接受正有限 `int | float`；
- 对该 task 的全部候选覆盖现有内部 `entry["timeout"]`；
- 未配置时继续继承 Provider timeout；
- 不进入 `extra_params`，不发送给上游；
- 纳入 secret-free route digest；
- canonical task 与兼容 alias 使用同一已解析值。
- 每个候选在调用前只建立一个 monotonic deadline；强制流的 create 与非流式预收集共享它，后者只取得剩余预算。显式 `stream=True` 的后续消费不继承该 attempt deadline。

任务策略：

| task | 单候选 attempt 上限 | 领域总 deadline |
| --- | ---: | ---: |
| `core` | 180 秒 | Heartbeat 保持最多 300 秒 |
| `learning` | 300 秒 | 每个 Learning 逻辑请求 900 秒 |
| `witness` | 300 秒 | Witness 600 秒 |
| `utility` | 180 秒 | Epistemic Opportunity 300 秒 |
| `agent` | 300 秒 | 既有 worker/mission 总预算保持 |
| 前台 expression/router/live/vision | 不放大 | 保持既有用户体验边界 |

### 领域消费者

- Learning 使用独立 canonical task `learning`，并把统一 900 秒 monotonic deadline 注入 Audit、Reflection、Knowledge、Skill Distillation 及各自 gate。
- Memory Witness 用同一个 600 秒 monotonic deadline 覆盖 send 与 response 消费；外部取消原样传播。
- Epistemic Opportunity 使用 300 秒总 deadline；现有 single-flight、候选保存语义和主体权限不变。
- Heartbeat 保持最多 300 秒共享总预算，不因后台其他任务延长而变成无界循环。

## 并发与可靠性

延长后台时限不等于全局串行：Heartbeat、Witness、Learning worker、Epistemic Opportunity 和其他意识实例仍可按既有独立 owner 并发。领域内继续保留 single-flight、串行维护阶段或耐久队列，禁止同一工作因超时配置而复制执行。

取消、服务关闭、模型故障转移和 deadline 到期必须保持可传播、可观测且 content-free。超时不得自动生成主体决定；后台候选也不得被当成人格权威或后训练监督。

## 验收门

- 同一 Provider 在前台任务继续使用原默认 attempt，上述后台 task 使用各自覆盖值；
- 仅修改 task attempt 时 route digest 必须变化；
- 非数值、布尔值、零、负数、NaN/Inf 启动时 fail closed；
- Learning 明确解析到 `learning`，不再隐式复用 `core`；
- 发送成功但 response 卡住时，Witness 在同一总 deadline 到期；
- 超时或取消不推进 Witness cursor、不 commit 未精确交付的 perception；
- Curiosity 300 秒配置可通过 schema，超时仍不保存伪候选；
- 前台路由、表达、实时任务的 attempt 时限不随本轮放大；
- 强制流 create 消耗部分预算后，预收集只获得剩余时间；超时会取消并收净当前流，再沿既有策略故障转移，且不会重复 attempt/trajectory 身份；
- 定向测试、风险回归、静态检查与 diff-check 全部通过。
