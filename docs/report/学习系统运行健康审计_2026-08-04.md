## 1. 结论

学习系统已经从 2026-08-01 审计的 **D（核心闭环断裂）** 恢复到 **B（工程闭环合规，正式运行切换仍待人工边界验收）**。

## 3. 已恢复的主体性边界

与 08-01 审计相比，以下高风险路径已经实质修正：

1. `auditor.py` 不再以“正面证据达到 N 条、跨 M 天”为代码级真值门槛；证据只交给独立审计阅读。
2. 反思层只有在模型明确给出 `reinforces` 时才强化旧洞察；文本相似或 topic 相同不再由代码替主体认定为同一认识。
3. Skill 蒸馏要求模型明确选择稳定 `skill_id` 或明确提出新 Skill；未知 ID、缺少主体选定名称均 fail closed。
4. Skill gate 请求失败或解析失败时不再默认接受。
5. 知识压缩与 Skill 更新均保留来源、版本和独立门控结果。

这些变化使“系统组织证据”和“主体形成认识”重新分开，是本次健康等级提升的主要原因。

## 4. 已完成修复与剩余边界

### 已修复：维护阶段级联饥饿

`LearningScheduler.on_heartbeat()` 现在按 reflection、epistemic backfill、audit、compression、distillation、metrics、staleness 七个阶段独立执行。每个 due 阶段先写 started 证据，完成后写 succeeded；失败写 failed 并继续后续阶段。若开始证据本身无法持久化，该阶段 fail closed，不执行无法审计的工作。

08-01 的压缩异常曾证明共享异常边界会连带饿死 Skill 蒸馏。本轮合同测试覆盖压缩失败后蒸馏、指标和陈旧检查仍继续，以及多个阶段同时失败时各自留下独立健康证据。

正式运行状态中的 `last_staleness_check_at` 曾停在 08-03 08:12，这是旧运行代码留下的风险证据。新调度器已修复结构原因，但本次没有重启进程，不能把隔离测试冒充正式长周期观察。

### 已修复：快环 Skill 可见性

`ReflectionEngine._build_skill_section()` 已直接消费真实 `SkillPattern`，并有合同测试证明 Skill 名称进入 `<your_skills>`。目录和正文被明确标为“程序性学习账本（可质疑，非主体权威）”，代码不根据名称或关键词自动激活技能。

### 已修复：逐阶段健康与隐私

新的 append-only 维护记录包含 run/phase、开始结束时间、耗时、pending count、结果、异常类型和只由异常模块/类型生成的 fingerprint。日志、health 和迁移失败记录不再复制异常消息，避免模型响应、私密提示或凭据通过异常文本外泄。

### 已修复：主体权威旁路

legacy `knowledge/vN.md` 与 Skill 目录不再以“自我认知/我的做事方式”身份注入。它们是有界、带 projection kind/hash/bytes 的派生学习观察。压缩成功只产生 `LearningCandidate`；接受必须来自活动 `ConsciousnessInstance`，携带精确 candidate revision/hash 与统一 `SOUL+USER+MEMORY` revision，并由 canonical `SubjectAuthorityPort` 在一个 fenced UoW 中提交。后台 scheduler、auditor 和 gate 没有主体执笔权。

### 剩余边界：正式运行和 legacy 原子性

- 旧 JSON 快照、JSONL 审计和 Markdown 版本不能跨文件原子提交；读取损坏已 fail closed，但彻底事务一致性需要未来经批准切换 selectable storage。
- 本次只实现并验证了迁移/反向导出工具，没有迁移正式 `.life_learning`，没有激活 MySQL 或 local selectable generation。
- 新代码尚未在用户手动重启后的完整 24 小时正式窗口中观察，当前不能把隔离测试替代线上时序证据。

## 5. 后续运行验收门

实现层重构已经完成。后续不是继续让后台“更聪明地自动决定”，而是验证新边界在正式环境长期成立：

1. 用户手动重启 Elysium 后观察至少一个完整 24 小时窗口，验证七个维护阶段不再互相饥饿，反思失败任务能够重试并在成功后清除。
2. 用真实活动意识实例完成一次“列出候选 → 分页读取完整候选 → 明确拒绝/保持开放”的无主体写入闭环。
3. 再完成一次“读取统一 revision → 明确接受或重写 → SubjectAuthority 提交 → outbox 投影 → 新 revision 生效”的闭环，并验证 stale revision 显式冲突。
4. selectable storage 切换前必须先产生冻结快照、执行 Learning 精确字节候选复制与反向恢复、通过隔离 MySQL 合同，并由用户另行批准；不得自动激活。
