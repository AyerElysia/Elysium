## 审计结论（修复前）

1. **反思环健康**：队列 675 入队 / 822 完成，连续失败 0；08-23 凌晨 3 小时出生
   7 条新洞察，证据累积真实（最多一条 49 条证据）。
2. **独立审计环真实但产能不足**：历史 168 次偏见检测；存在完整的
   "needs_more_evidence → 跨情境证据到达 → validated（仍保留意见）" 轨迹。
   但 `audit_interval_hours=6.0` × `audit_batch_size=3` 的名义产能约 12 条/天，
   而洞察流入已达 25-55 条/天（08-19~08-22 实测 35/39/25/55），积压 184 条候选，
   验证率 19.8%。
3. **慢环压缩空转（本次修复的根因）**：`should_compress()` 中触发数检查
   （`len(promotable) >= trigger_count` → `return True`）先于且绕过间隔检查。
   validated 洞察只在主体接受后才离开可压缩列表，而接受链自 08-03 起从未走通，
   30 条 validated 长期高于触发数 5，导致压缩在每个维护周期触发（实测约每 9 分钟
   一份），且每次都从同一份 v3 base 重写——1625 份版本是平行重写而非累积演化，
   `compress_interval_hours=48` 成为死代码。
4. **LLM 路由不稳放大一切**：`ox-alpha-free` 排在 core/learning 等全部任务链首位，
   08-22 全天空回复失败 302 次，覆盖心跳、学习、见证全部请求类型；每个请求先付
   一次失败往返，并造成心跳工具循环停滞（08-23 白天 8 次
   `consecutive_tool_stalls`）。多步工具会话（如 MEMORY.md 复盘的
   open→分页读→prepare_candidate→读候选→decide）无法在单次心跳内完成。
5. **主体复盘机制完好但从未被走完**：邀请按 24h 冷却正常投递
   （`last_offered_at` 每日更新，最近 08-22 12:00），工具已注册
   （`nucleus_review_subject_document`、`nucleus_memory_continuity_review`），
   会话为跨心跳无状态状态机；无一条 `last_reviewed_at` 记录。
   卡点是工具循环被 LLM 失败打断，以及主体自身尚未选择回应（后者属于主体自由）。
6. **早前审计报告的一处误报更正**：08-23 晨间检查曾报告"技能快照
   usage_observations 全为 0，与审计流 356 条不符"。复核确认这是检查脚本
   用错了字段名（实际字段为 `use_observations`）；快照与审计流逐技能一致
   （如 skl_541aca5a28 均为 141 条）。技能子系统无此 bug。

## 遗留事实：接受链与存储后端

学习链"最后一公里"（LearningCandidate → 主体接受 → SOUL/MEMORY）需要
selectable storage；当前架构下它由 `config/core.toml [storage].backend = "mysql"`
全局决定（`settings_from_life_engine_config`：`enabled = backend == MYSQL`），
legacy local 模式按设计 fail-closed，无法接受任何候选。

08-23 只读盘点远程 MySQL（frp-one.com:65429，registry `life-domain`）确认：

- generation `life-mysql-multi-writer-20260808-v1` 曾被 `elysium-windows-primary`
  于 08-08 激活，registry epoch=66，租约早已过期（lease_until=2020-01-01）；
- 远程 `raw_life_events` 128,547 条，本地 221,545 条且实时更新（最新事件
  08-23 03:45）——远程是停滞的旧副本；
- 本机 `backend_generation` 预配置恰好指向该 generation。**若在未重迁移的情况下
  把 backend 切为 mysql，她的权威数据将回跳到三周前的状态，属于主体连续性事故。**

因此本次不执行切换。正式打通接受链需要按
`docs/operations/life_storage_backend_runbook.md` 完整执行：
停止 → 冻结快照 → 五域候选复制（含 `migrate_life_learning.py` 对当前
`.life_learning` 的全量迁移，含 1629 份知识版本）→ `upgrade-runtime-state` /
`upgrade-learning` schema 升级 → `audit_life_storage_cutover.py` 签署新 verified
generation → 更新 `[storage].backend` 与 `backend_generation` → 手动启动并按
runbook §7 完成十一条验收。切换与验收窗口归属：用户。
