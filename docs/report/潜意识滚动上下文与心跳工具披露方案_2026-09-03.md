# 潜意识滚动上下文与心跳工具披露方案（2026-09-03）

> **已收口**：当前执行方案改为 [潜意识三问题方案_2026-09-03](./潜意识三问题方案_2026-09-03.md)。本文仍可作投影层备忘；**不要按本文「先改投影」的顺序施工。**
>
> 状态：被取代的旧草案。对应诊断 [心跳潜意识上下文污染分析_2026-09-03](./心跳潜意识上下文污染分析_2026-09-03.md)。
> 约束：不替主体做认知裁决；不抄写各实例私有滚动上下文；不自动按情境打开 skill；权威账本只追加；Prompt 投影必须标明摘要/节选身份。

两个问题分开交付，但共享同一验收窗口（用户手动重启 Elysium）。建议顺序：先滚动上下文，再工具披露——先让她每拍看见生命域近期事件，再拿掉 49 张常驻 schema。两次都可以在一次重启里合并验收。

---

## 共同不变量

1. Life Event 账本仍是全生命域权威；本方案只改心跳 Prompt 投影和工具 schema 披露。
2. Chatter / Voice 私有滚动上下文不得复制进潜意识。跨实例只走事件、Presence、World、Perception Gateway。
3. 机会段落只陈述可观察事实（有候选、有复盘窗口），不写「应该调用某工具」，也不在注入机会时自动 `get_skill`。
4. 收缩 schema ≠ 她没有该能力。目录和 skill 必须仍能让她知道能力存在，并由她决定是否展开。
5. exact receipt 只证明声明过的投影已送达。节选必须标 `excerpt`；压缩段必须标压缩身份和续读 ref。
6. 涉及心跳的改动不得由 agent 启动 Elysium；测试先本地跑，启动验收等用户。

## 问题一：滚动上下文 = 生命域近期事件，超预算再压缩

### 现状（不是目标）

- `prepare()` 在没有未消费 delta 时返回空 content；安静心跳看不到近期事件。
- `_event_history` 经 `compact_history()` 折叠后，模型轮/心跳/普通工具不进摘要正文。
- 超 16k 是丢组或 excerpt，不是「把更早生命域事件收成可续读压缩层」。
- 有 delta 时内联 `raw_content` 协议 JSON，把 16k 填满。
- 世界感知在 16k 之外每拍约 12k。

### 目标

每拍心跳 user 侧都有一层**生命域近期事件投影**：

```text
【压缩前缀】已确认、超出窗口的旧事件
  - 标明 compressed / 覆盖序列 / folded_stats
  - 条目保留 surface、instance、类型、时间、occurrence ref
  - 不生成假第一人称叙事；不把折叠当成「她刚才想了什么」的权威正文
【近期完整组】最近 N 个已关闭因果组（默认仍 5，按序列，含所有表面）
【本拍 delta】未消费新事件；完整投递才能推进游标
```

预算内先保证 delta 完整可确认；余量给近期组；再给压缩前缀。塞不下的近期组不得假确认。世界感知与事件流共享一个 wake 总预算（建议 24–32k 字符量级：感知有变化才展开 assertion/change，无变化只保留 Presence + 上一拍 delivery hash）。

### 做法

**A. 空闲也要有近期窗口**

改 `SubconsciousContextManager.prepare()`：`delta` 为空时仍渲染 summary + recent_closed，而不是 `content=""`。

- `acknowledged_event_ids` 仍只含本拍完整投递的 **新** delta（空闲为 `[]`）。
- 近期组是连续性背景，每拍重投影，不靠「消费」前进。
- 现有测试 `test_consumed_events_are_not_replayed_and_do_not_advance_delta` 要改成：不推进游标、不把已消费事件当 delta；但允许它们出现在 recent/summary 投影里。

**B. 折叠必须留下活动痕迹**

`_summary_entry_for_event()` 目前对 `CONSCIOUS_ACTIVITY` / `HEARTBEAT` / 普通 TOOL 返回 `None`。改为写入**内容无关或短身份行**，例如：

- `conscious_activity`：`surface=life_chatter instance=chat_global phase=generated tools=1 ref=life-event-occurrence:…`
- 不把 `provider_reasoning_content` 写进摘要。
- 继续用 stats 计数。kind 白名单扩展为开放身份标签，不是主观分类穷尽。

压缩前缀必须能从账本按 occurrence 重建；禁止用 LLM 替她总结潜意识。

**C. Prompt 渲染去协议信封**

`_render_event()` 对心跳消费者改用投影，而不是 `raw_content or content`：

| 类型 | Prompt 投影 |
| --- | --- |
| 模型轮 | 表面 + instance + 是否有 reasoning/独白 + ref；正文节选 ≤ 预算，标 excerpt |
| 工具选择 | 工具名 + 主体提交的业务字段（如 send_text 的 thought/content）；去掉 schema/transport 信封 |
| 工具结果 | 成功/失败 + 短结果或 ref |
| 消息 | 发送者 + 正文（已有） |

账本 `raw_content` 不变。`nucleus_read_event` 仍读权威原文。Witness 继续 `redacted-tools-v1`。

现有测试 `test_conscious_expression_activity_keeps_complete_arguments_and_outcome` 断言 Prompt 含五字段：心跳投影仍应能看到 `life_send_text` 的 thought/decision/mood/content，只是不要整份 v1 JSON。

**D. 窗口来源**

第一期仍用 `_event_history`（本来就是各表面 `record_conscious_*` 的汇合），修 prepare/summary/render 即可覆盖「整个生命域的近期」。

第二期若运行时折叠把窗口截得太短：心跳按序列从 Life Event 账本再取一页近期组，与内存 recent 对齐；缺口 fail closed，禁止把游标跳到尾部。第一期不做账本重扫，除非测试证明 5 组不够表达跨表面连续性。

**E. 世界感知**

与事件共享 wake 总预算。无新 change 时只投递 Presence + `world-perception:{id}` 未变化声明；有新 change 再展开 assertion/change 页。idle 不再每拍重贴 12k 协议行。

### 定向测试

- 已消费、无 delta：content 非空，含 recent 或 summary；`acknowledged_event_ids` 为空；cursor 不前进。
- 聊天 + 心跳 + 另一表面（可用 fixture 标 `source_instance_id`）同窗出现。
- 超预算：压缩前缀有标记和 ref；被截断组不在 acknowledged 中。
- 模型轮投影不含 `life.conscious_activity.model_turn.v1` 整包，但 ref 可续读。
- 重放同一 occurrence 不重复；缺口不跳游标。

## 问题二：海量工具按 platform 模式披露

### 现状

心跳不走 `CONSCIOUSNESS_TOOL_MANIFESTS`，`_get_nucleus_tools()` 每次钉约 49 个完整 schema（约 57 KiB），`ROLE.TOOL` 不可裁剪。学习已有机会段落（技能目录、学习进度、主体复盘），却同时常驻 16 张学习 schema。

`platform_action` 模板：一个 dispatcher；`action=help` 读 `skills/{platform}_actions/SKILL.md`；不把平台 API 注册成独立工具。

### 目标

```text
心跳常驻 schema     = 少量观察/沉淀入口 + 各域一个 dispatcher
机会段落             = 事实（有候选 / 有复盘窗口），不是命令
展开                 = 她读 skill 或 dispatcher help 之后自己调用
禁止                 = 代码按情境自动 get_skill / 自动选学习工具
```

### 心跳常驻清单（第一期）

保留（单工具或已是 dispatcher）：

- `nucleus_rest_heartbeat`
- 工作区文件：`nucleus_read_file` / `write` / `edit` / `list` / `mkdir` / `grep_file`（第一期不合并，避免改聊天契约）
- 记忆与账本：`nucleus_search_memory`、`nucleus_read_memory_boundary`、`nucleus_grep_events`、`nucleus_read_event`
- 主动系统：`nucleus_proactive_query`、`nucleus_proactive_command`
- 已是 dispatcher：`nucleus_skill`、`nucleus_todo`、`nucleus_schedule`、`platform_action`
- **新** `nucleus_learn`（见下）
- `nucleus_memory_continuity_review` 暂留（已是单工具多 action）；说明迁到 skill 后可再降描述体积

移出心跳常驻 schema（能力仍在目录/skill 里，由她展开后走原工具或并入 dispatcher）：

- 16 个独立 `LEARNING_TOOLS`（由 `nucleus_learn` 取代注册）
- `nucleus_browse_memes` / `collect_meme` / `dismiss_meme`
- `nucleus_run_agent`、`nucleus_view_screen`、`nucleus_bash`、`nucleus_web_search`、`nucleus_browser_fetch`
- `conversation_evidence`、`sync_platform_history`、`fetch_life_memory`、`nucleus_trace`、`nucleus_write_narrative`
- `nucleus_relations`、`nucleus_memory_stats`

移出不是删除实现：类仍注册给插件/聊天（若清单需要）。心跳只是不把它们的 schema 每拍送进 core。指令头里「不要在心跳里看屏/bash 替用户办事」与「schema 仍在」的矛盾一并消失。

若她在心跳里仍要 bash 做工作区诊断：第二期把 bash/web 收进 `nucleus_workspace` dispatcher + skill，而不是再加回 5 张独立表。第一期允许心跳用文件工具覆盖绝大多数沉淀需求。

### `nucleus_learn`（platform 同构）

一个工具，`action` + 其余参数。内部委托现有 16 个 Tool 类的 `execute`，不重写学习语义。

建议 action 与现名对齐，便于她从机会段落对上号：

`help` / `reflect_now` / `list_insights` / `challenge_insight` / `reconsider_insight` / `view_knowledge` / `knowledge_candidates` / `review_subject_document` / `list_subject_candidates` / `read_subject_candidate` / `decide_subject_candidate` / `list_skill_candidates` / `read_skill_candidate` / `decide_skill_candidate` / `observe_stale_insights` / `list_validation_experiments` / `complete_validation_experiment`

- `action=help`：读取工作区 `skills/learning/SKILL.md`（工程能力清单，不是 SOUL/USER/MEMORY；禁止生成第一人称自我叙事）。若文件不存在，fail closed 并提示路径，不得编造能力表。
- 机会段落改成事实 + 披露指针，例如「有待决定的主体文档候选；操作说明在 `skills/learning/SKILL.md`，用 `nucleus_learn(action='help')` 读取」。不写「请现在调用 decide」。
- 旧类保留供测试与内部委托；不再进入 `_get_nucleus_tools()`。
- 不在聊天清单里新增 16 个学习工具（聊天本来就没有）。

`skills/learning/SKILL.md` 由工程写入工作区 skills 目录，与 `qq_actions` 同类。若工作区已有该路径且含主体笔迹，不得覆盖；只新增缺失文件或把模板放在 `plugins/` 由她/运维自行放置。

### 心跳工具清单代码位置

新增明确清单，例如 `HEARTBEAT_TOOL_NAMES` 或 `CONSCIOUSNESS_TOOL_MANIFESTS["life_engine_internal"]`，`_get_nucleus_tools()` 按名字过滤。`tool_manifests.py` 里「中枢不受清单约束」那句改成：中枢有**自己的**清单，不是聊天清单，也不是「全部已注册工具」。

`test_heartbeat_nucleus_pool_exposes_only_unified_proactive_tools` 扩展为：学习 16 名不在池中；`nucleus_learn` 在池中；主动系统两工具仍在。

### 指令头

删掉与 schema 重复的长工具手册。TODO 名称与 `nucleus_todo` 对齐。保留非强制建议和安全边界（主体文件不能用通用 file 改）。

## 交付顺序与风险

| 阶段 | 内容 | 风险 |
| --- | --- | --- |
| 1 | prepare 空闲也渲染近期窗；摘要保留活动身份行；事件投影去信封；世界感知共享预算 | 游标/receipt 回归；Prompt 变长但应比 JSON 更可读 |
| 2 | 心跳清单 + `nucleus_learn` + learning SKILL.md + 机会段落指针 + 指令头去重 | 她暂时不能在心跳直接 bash/看屏，除非读 skill；这是预期 |

不要用 LLM 压缩潜意识。不要按关键词挑选「重要」表面。不要在机会注入时自动加载 skill。
