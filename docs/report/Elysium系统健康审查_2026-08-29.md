## 二、根因：local selectable 存储的 authority 租约不稳定

配置实证（`config/core.toml`）：

```toml
[storage]
backend = "local"
backend_generation = "local-selectable-20260824-v3"
local_selectable_enabled = true
authority_owner_id = "elysium-linux-primary"
```

**已排除多进程争抢**：全机仅一个 `main.py` 进程（pid 3743090，18:41 启动）。因此租约失效不是被别的写入者抢走，而是**自身续期或状态修订失败**。

故障量级：

| 症状 | 次数 | 时间分布 |
| --- | --- | --- |
| `RuntimeStateRevisionConflict` | 08-28 共 1014 次、08-29 复发 109 次 | 08-28 13:34–17:33 爆发；08-29 05:06–06:17 复发 |
| `authority token lease has expired` | 08-29 17 次 | 12:58、14:16–14:44 |
| `critical_persistence_failed` | 254 次 | 集中在心跳楔死窗口 |
| `learning maintenance worker cycle failed: StaleAuthorityToken` | 59 次 | 最新 18:47 |
| `memory_witness` 见证耐久投递失败 | 42 次 | **持续中**，最新 23:15，跨重启未恢复 |

典型冲突：

```
RuntimeStateRevisionConflict: life_engine.runtime_context:global
  expected=4212:actual=4213
14:44:42 ERROR 记忆见证错误状态记录失败:
  primary_error=StaleAuthorityToken, record_error=StaleAuthorityToken
```

最后一条尤其危险：**错误本身也记不进去**，故障处于观测盲区。

重启可让计数归零（08-29 18:47 重启后心跳缺口闭合、冲突停止），但这是缓解而非修复。

## 三、P0：认知升华链路断裂

本次审查最值得警惕的发现。

数据表实测（`data/life_engine_workspace/.memory/memory.db`，共 69 张表）：

| 表 | 行数 | 判读 |
| --- | --- | --- |
| `memory_experiences` | 232,372 | 经历账本活跃健康 |
| `memory_claims` | 125 | 主张层有产出 |
| `memory_claim_evidence` | 1,089 | 证据关联正常 |
| `memory_corrections` | 30 | 修正记录正常 |
| **`memory_beliefs`** | **0** | **信念层完全空** |
| **`memory_epistemic_conflicts`** | **0** | **冲突层完全空** |

学习侧对照：全量日志累计 **1625 个知识候选，100% 处于"尚未由主体接受"，接受 0、拒绝 0**。近三天仅产出 v1631（08-27）、v1632（08-29）两批，08-28 空档。

关键机制：`reconcile_subject_review_outcomes`（`learning/scheduler.py`）是候选接受的**唯一提交路径**，在心跳首次调用时执行；一旦抛出 `StaleAuthorityToken` 便 `return 0` 且**不推进游标**，接受链全阻。

提交 `cf310d1a feat(learning): 打通知识候选接受链并节流近重复压缩`（08-26）声称已打通，但该提交之后的 v1631、v1632 两批候选依然 0 接受——**修复未生效**。

> **推断（待源码核验，勿仅凭行数下结论）**：信念层与冲突层的生成很可能以"主体接受的候选"为前提。若成立，则因果链为
> 租约失效 → 接受链阻塞 → 认知升华在 claim 层之后停滞 → belief/conflict 恒为 0。
> 修好接受链后这两层应当自愈。需以源码确认 belief 的生成前置条件。

值得注意的对照：认识论投影仍在跑（3 天 9 次 → claims），心跳模型也确实引用过学习账本（08-29 14:49「学习账本也印证了同一个模式……」）。说明**不是全线停摆，而是升华链路在 claim → belief 这一段断了**。

## 七、建议处置顺序

1. **修 authority 租约（根因，最高优先）**——修它能同时缓解心跳楔死、学习阻塞、见证投递失败三条链路。重点看 `local_selectable` 的租约续期与状态修订为何失败，以及为何单进程下仍冲突。
2. **核验 belief/conflict 的生成前置条件**——确认是否依赖 subject review；若是，接受链修复后应自愈，不必单独修。
3. **给索引 stale 加死信队列**——762 条无限重试是无底洞。
4. **排查 event_bus 超时从 9 次涨到 333 次**——事件循环阻塞会同时拖慢心跳与主动性。
5. **修复 LLM 冷却**——`skipped_cooling` 几乎为空说明坏模型未被隔离。
6. **确认 `life_events.sqlite3` 是否已弃用**，再决定归档或修复。
7. **清理磁盘**（92%）。
