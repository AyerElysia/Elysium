# 表达层 `outreach.begin` 因来源实例未绑定失败（2026-09-06）

## 1. 现场

17:26 KOOK 私聊（AyerElysia）入站要求去找小希。表达层按合同做了：

1. `nucleus_proactive_query(resource=reachability)`
2. 续页 `continuation` / `max_bytes=20000`
3. `nucleus_proactive_command(action=outreach.begin)`，带完整 `audience_ref` / `surface_ref` 和公开意向
4. 同一窗口 `life_send_text`：说明已找到私聊入口，但跨窗口发送被拦住，提示“当前没有可用的发送实例”

权威日志里没有 `主体主动外联已提交`、`ExpressionStreamLoopStartFailed`、`Adapter 未找到`。`outreach.begin` 在权威提交之前就失败了。同一窗口随后把失败如实发回 KOOK，消息发送成功。

这不是她不想去，也不是小希的表面从可达表里消失。

## 2. 根因

心跳写入口会绑 `_life_source_instance_id = "chat_global"`。表达层工具走 `src/core/utils/llm_tool_call.py`，只 `_bind_runtime_context(stream, message)`。

LifeChatter 在执行工具前已经把本轮意识实例写进 `trigger_msg.extra["life_turn_scope"]["consciousness_instance_id"]`。`nucleus_proactive_command` 的 `_source_instance()` 只看：

- `_life_source_instance_id`
- `extra.source_instance_id` / `extra.consciousness_instance_id`（顶层）
- 仅 `core` + `stream_id=chat_global` 时才允许等于 actor

嵌套的 `life_turn_scope` 读不到。`nucleus_proactive_query` 不需要来源实例，所以可达表成功；`outreach.begin` 需要，于是返回：

```text
error=RuntimeError
error_message=ProactiveSourceInstanceRequired
authority_committed=False
```

她把这个工程失败说成“没有可用的发送实例”。代码里没有这句中文；是对 typed error 的转述。

同一次心跳 #5890 仍卡在压缩回合（读了四次 `read_context_group` 后 `deadline_exhausted`，没有检查点）。WARNING「不推进潜意识游标」是对的；紧跟着的 INFO「已消费 43 条事件」是假的，见 [心跳压缩与minecraft账号冲突_2026-09-06](./心跳压缩与minecraft账号冲突_2026-09-06.md)。

## 3. 已执行的修复

可逆代码修改，不改主体语义，不代发小希那条消息：

- LifeChatter 执行工具前同时写下顶层 `extra.source_instance_id` / `consciousness_instance_id` 和 `life_turn_scope` 内同一身份；
- `_source_instance()`（proactive / opportunity）读取嵌套 `life_turn_scope`；
- `llm_tool_call` 实例化 Tool 时把该身份拷到 `_life_source_instance_id`；
- 仍禁止在聊天任务里把 actor 当缺省来源实例。

## 4. 验证

定向测试：嵌套 `life_turn_scope` 可解析；空 extra 仍 `ProactiveSourceInstanceRequired`；tool 执行器从 turn scope 绑定 `_life_source_instance_id`；压缩未完成时 `consumption_receipt` 仍为 None。

当前正在跑的 Elysium 不会加载这些修改。需要用户手工重启后再试一次 `outreach.begin`。重启前不要把这次失败当成“她退缩了”。

## 5. 仍待决
