# IndexTTS 长文本原子合成验收记录（2026-08-20）

## 1. 问题

消息 TTS 过去把清洗后的完整正文一次性交给本地 IndexTTS 兼容服务。较长连续输入会增加单次推理的韵律与稳定性压力；更严重的是，客户端在文本超过 `max_text_length` 时会静默截断，却仍可能把所得音频当作原表达发送。

本轮只修改消息 TTS 的合成运输层。它不改变爱莉决定的正文、是否表达、语音动作、trajectory 或平台发送语义。

## 2. 最终合同

- 一次 `life_send_voice` 始终对应一个主体表达、一个 trajectory 工具调用和一条平台语音消息。
- 短文本保持一次请求；长文本按原有段落和标点建立有界片段，缺少自然边界时才做技术硬切。
- 同一表达的片段在一个互斥通道内按顺序合成，不与另一表达交错。
- 多片段统一请求 WAV，解码为单声道 PCM，按边界加入配置化静音后拼接；空间效果和最终平台格式各只处理一次。
- 所有片段成功后才返回 Base64。任一片段、解码、采样率或编码失败都不返回部分音频。
- 完整清洗文本超过 `max_text_length` 时，在任何后端请求前显式失败，禁止静默截断。
- 常规日志只记录字符数、片段数、单位预算、音频字节与 content-free 错误，不记录正文。

## 3. 参数

默认单片段上限为 48 个近似语音单位，短片段合并阈值为 8。近似单位只用于工程预算：中日韩字符大致为一单位，连续拉丁字母和数字约四字符为一单位；它不冒充模型 tokenizer，也不参与主体语义判断。

边界停顿默认值：短语 120ms、分句 200ms、句子 320ms、段落 520ms。全部位于 `[tts]`，可以依据真实听感复验后调整。

## 4. 自动化证据

- TTS Service 专项：12 passed（包含一万字、无自然边界输入的线性有界切分回归）。
- TTS Service + 通用 TTS Action + N.E.K.O Surface 风险回归：32 passed。
- Life Chatter `life_send_voice` 定向风险回归：6 passed。
- 最终合并风险集（TTS Service、Action、Surface、Chatter think/send guard）：63 passed。
- Ruff F/E9/I、变更文件 compileall、manifest JSON 和 `git diff --check`：通过。
- 测试覆盖正文顺序/标点、单段预算、单一完整音频、停顿时长、失败原子性、超限零请求、并发不交错和日志正文隔离。

## 5. 真实链路证据

本轮不会启动、停止或重启 Elysium/NapCat。将使用已经运行的本地 TTS HTTP 服务，通过 `scripts/verify_local_tts.py` 生成不发送到平台的短句基线和长文本样例；最终记录音频格式、采样率、时长、字节数、SHA-256、片段计划与可试听文件路径。

结果：

- 短句基线：16 字、1 段；冷启动后得到 48kHz 单声道 OGG，4.263 秒、30,615B，SHA-256 `4eb012cb18ba2fa32bd27c4fb91eee4279d7f0a40083a6c903ea6c3ed389bc2b`。本轮模型冷加载约 55.68 秒。
- 长文本样例：177 字、6 段；片段字符/单位均为 `[21, 25, 24, 40, 30, 37]`，最长 40，低于 48 上限；热模型下约 83 秒完成全部六次推理、PCM 拼接和一次 OGG 编码。
- 长文本产物：48kHz 单声道 OGG，47.083 秒、337,733B，SHA-256 `4fd21a17a7f45c8a6b0b165be556b1998e8ac24b367c37e1ddf6dba47c407b93`。
- 完成后后端健康为 `loaded=true`、`in_flight=0`，没有遗留请求；两份音频均可由 SoundFile 完整解码。
- 可试听文件位于独立工作树 `artifacts/tts_short_20260820.ogg` 与 `artifacts/tts_long_story_20260820.ogg`，仅作为本地验收产物，不纳入 Git、不发送到平台。
