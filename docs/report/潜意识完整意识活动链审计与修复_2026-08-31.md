# 潜意识完整意识活动链审计与修复（2026-08-31）

## 结论

修复前，潜意识能看到部分 Chatter 活动，但不能证明自己拿到了完整链：`life_send_text` 的 `thought/decision/mood/expected_response` 主要停留在 500/160/80 字符级兼容快照；近期跨实例投影主动省略 ToolCall 参数；工具结果、协议阻断和可见发送事实之间缺少统一 conscious activity 身份；heartbeat 只验证 World 子投影，没有验证最终成功模型 attempt 是否原样接收了整份 wake Text。继续审计后还发现 Router 的回应判断、Voice 的工具参数/最终转写/中断、直播导演生成、Minecraft 高层决定与具身 planner、使命 planner/worker 的模型轮都没有进入同一条完整活动账本。

本轮把稳定契约改为“权威活动完整、Prompt 投影有界、精确回执后确认”：一次模型轮、每个工具选择、状态变化和每个结果分别形成不可变事件，并以 actor instance、stream、turn、request、call 与 causation 串成同一因果链。`action-life_send_text` 五字段与可见正文同属一个选择事件；provider reasoning、同轮独白、空轮、主动等待、完成、取消和打断也有发生记录。大正文不无限进入 Prompt，而是保留完整权威事件并投递 UTF-8 安全节选、SHA-256、字节数和稳定引用。

## 根因

1. `record_chatter_think_snapshot()` 是运行时兼容投影，不是不可变活动账本，且字段有短长度上限。
2. `SubconsciousContextManager.project_recent()` 曾为避免私有上下文泄漏而连 ToolCall 参数一起省略，误伤了模型已经明确提交的主体活动。
3. Chatter 的真实工具执行、抑制和投递回执没有统一的模型轮/活动 identity，潜意识只能拼接零散日志。
4. 潜意识 delta 只有全批次确认；分页时完整呈现的闭合组不能前进，而被紧凑截断的单项又缺少严格的“不得确认”证明。
5. heartbeat exact receipt 只覆盖 World Projection，不能证明整份潜意识活动 Text 没有被上下文管理器裁剪。
6. `nucleus_grep_events` 实际只搜索近期运行投影，却曾被描述为完整账本；没有按稳定 occurrence 精确续读权威原文的工具。
7. Router、Voice、Livestream、Minecraft 与 delegated agents 各自保存了部分 episode/trace/decision，但缺少统一的 subject activity 归因；场景账本可以证明协议发生过什么，却不能单独承担跨实例潜意识和后训练取数。
8. 新增 exact reader 的首次审查发现它会在同时存在 `content` 摘要与 `raw_content` 原文时读取摘要；现已改为始终读取 raw authority，并加入“摘要与原文不同”的多页重组回归。
9. 统一模型轮若复用 `heartbeat` 类型会污染心跳计数并把场景生成误标成心跳；现已新增 additive `conscious_activity` 类型，真实 heartbeat 继续保持原类型。

## 实现边界

- `life.conscious_activity.model_turn.v1`：完整保留成功模型轮的 provider reasoning、assistant message、request/turn/instance/stream 归因和工具 call IDs。
- `life.conscious_activity.tool_call.v1`：在任何副作用前原样落账全部参数。
- `life.conscious_activity.tool_result.v1`：记录真实结果、成功/失败、技术结果与平台投递证明，并回连工具选择。
- `life.conscious_activity.state.v1`：记录主动等待、响应完成/取消、实时打断等非文本意识活动；payload 保持原值，普通日志只显示键和类型。
- 稳定发送事实携带 `conscious_activity_id`、`tool_call_id`、origin turn/stream 和 consciousness instance。
- Chatter Router 的每次可采用判断必须先落账；落账失败的判断不会参与最终路由。普通表达、空轮、follow-up 和同轮所有工具均使用同一生成身份。
- Voice episode 仍是原始通话证据；统一活动链额外保存工具选择/结果、最终 assistant 转写及 done/cancel/interruption。播放清除和下一 frontier 调度先于 Life Event 写入，避免存储延迟阻塞打断安全或下一轮准备。
- Livestream 在解析 `director.decision` 前保存完整模型生成；Minecraft 高层意识决定与低层具身 planner 分别落账并共享当前 instance/session/stream 归因；planner 世界输入仍保持外部证据来源。
- Mission planner、AgentRunner 与 Worker 的每轮生成及工具结果按发起意识实例归因；最终 AgentResult 仍是完成证据，不把外部候选或系统 Prompt 变成人格结论。
- 单项超过 4 KiB 时，潜意识只内联至多 2 KiB UTF-8 安全节选并给出 ref/hash/original_bytes；`nucleus_read_event` 按任务硬预算续读完整权威事件，continuation 与 occurrence、frontier、内容 hash 和预算绑定，篡改或源变化显式失败。
- 整份 heartbeat wake Text 注册 content-free exact delivery；缺失、裁剪或未知时不推进潜意识游标。分页只确认完整呈现的闭合因果组，紧凑截断事件绝不确认。
- 普通日志不再输出整份潜意识正文，只保留 delivery id、bytes 和 hash。
- Life Event 先写权威 append-only ledger，再进入兼容 pending 队列；ledger 拒绝不会留下“只存在于内存”的假活动，相同 occurrence 重放不重复加入 pending。
- 权威账本与 Heartbeat 潜意识投影完整保留工具载荷；Chatter 的跨实例附加上下文与 Memory Witness 明确使用独立 `redacted-tools-v1` 连续性视图，只交付工具名、状态、参数键和 ref。Chatter 自己的当前工具链已在本实例 rolling context 中，因此不重复灌入其他实例的原始参数/结果；这种消费者级精简不删除权威活动，也不影响 Heartbeat 或 `nucleus_read_event` 读取完整内容。
- Memory Witness 自身仍是意识实例：成功 authoring response 在见证判定与游标推进前，以稳定 window/stream/request 身份完整记录 provider reasoning 与 assistant message；`<no_witness>`、空内容错误或 exact receipt 失败不会被误写成已经完成的 Witness，但实际发生的成功模型生成不会从潜意识中消失。
- 结构化上下文投影、屏幕视觉解析、认知机会与 Learning 候选等模型化基础设施不因“使用了 LLM”自动成为第一人称意识；它们保持外部候选/工具结果来源，只有有效意识实例实际采用或提交的动作进入主体活动链。
- 全插件模型入口审计还发现狼人杀 `AIPlayerStrategy.generate_speech()` 中存在一段未接入调用方的通用 NPC 发言代码。它当前不会运行，也没有被计作爱莉的意识活动；未来若把该输出作为“爱莉玩家”的可见行为，必须先注册真实游戏意识实例并接入统一活动账本，不能仅凭显示名“爱莉”获得主体归属。

## 数据与兼容性

没有删除、重写或迁移既有 Life Event、聊天历史、记忆或主体文件。兼容 `record_chatter_think_snapshot()` 仍保留，但不再承担完整性权威。现有短事件继续直接内联；旧事件没有 occurrence ref 时仍按既有投影读取。新工具和事件 schema 是 additive，不改变既有发送幂等、工具执行顺序或模型轮数。
