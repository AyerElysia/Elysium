## 已完成

- 新增连接脚本，安装至 `~/.local/bin/elysia-attach`，支持 main、heartbeat、status；原实例与服务实例同时存在则拒绝模糊选择，不偷偷启动。
- 新增手工服务定义、一次性前台进程管理和安装器。服务 `Restart=no`、无 `[Install]` 段、停止使用 SIGINT，不故障重拉。
- 前台管理进程用 pidfd 传递停止信号，单次启动主入口，等待原始退出回执后退出。PTY EOF 不等于已获得退出码，必须等待 status/signal 明确。
- 安装器保留既有不同文件，拒绝盲覆盖；只注册单元，不改变运行进程。AGENTS 和运维说明同步记录 Spark 的手工 systemd 特例。

所有测试只用临时目录、唯一命名的临时服务和独立 tmux socket，未使用正式数据库、应用监听端口或 authority；测试服务已停止并清理其状态。本次没有停止或重启本体 PID 632287，没有修改 New API。

## 尚需操作者完成

系统级安装被 sudo 认证阻断，服务尚未安装或接管正式实例。操作者在 Spark 运行：

```bash
sudo bash /home/ayerelysia/Elysia/Elysium/scripts/install_spark_controls.sh
```

安装不停止旧实例。首次接管时，用 `elysia-attach` 进入旧控制台，Ctrl+C，等待关闭后，再 `sudo systemctl restart elysium`。此后 root 可直接 `systemctl restart elysium`，普通用户按系统认证要求使用 sudo。服务首次正式接管后的启动验收仍待执行，不能由临时服务测试代替。

移除本次入口可在停止受管实例后删除精确单元 `/etc/systemd/system/elysium.service` 和两个已核对目标的 elysia-attach 符号链接，再 daemon-reload；仓库工程文件仍保留，可以重新安装。不触碰运行数据库和主体历史。
