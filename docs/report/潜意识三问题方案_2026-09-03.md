# 潜意识三问题方案（2026-09-03）

> 状态：问题 1、2、3 均已落地（代码）。心跳链路须用户手动重启 Elysium 后验收。
> 取代：`潜意识滚动上下文与心跳工具披露方案_2026-09-03.md` 里「先改投影」的顺序；机会细节仍以 `统一机会暴露方案_2026-09-03.md` 为准；心跳清单以 `心跳工具清单_2026-09-03.md` 为准。
> 本轮不做：把协议 JSON 改成好看投影、LLM 压缩独白、按情境自动 get_skill。

现在要解决的是三件不同的事。不要混成一次「把心跳变干净」。

| # | 问题 | 成功标准 |
| --- | --- | --- |
| 1 | 潜意识能否**接到**全部生命域事件 | 心跳消费链是账本的具名消费者；缺口失败；不靠平行 pending 碰运气 |
| 2 | 海量工具 | 心跳常驻少量 dispatcher；学习一份 skill；看见机会后再读说明书 |
| 3 | 机会暴露重复 | 一条 Offer 总线 + 一个机会页；不排序、不代决定 |

顺序：**1 → 3 → 2**。先保证事件进得去，再把邀请收成一条管道，最后才收 schema。2 依赖 3 的「有候选就给机会、读 skill 再动手」。涉及心跳的验收一律等用户手动重启。

## 问题 1：潜意识接到全部生命域事件

### 已落地（2026-09-03）

心跳是账本具名消费者 `life_engine_subconscious_ingest:v1`。`_pending_events` 是派生缓冲。`_prepare_heartbeat_context` 在 drain 前 catch-up；启动 `_load_runtime_context` 后也会追赶。缺口 fail closed。

- 进入工作集：`metadata.legacy_event_type` 活动/消息，以及无 legacy 对偶的 `chat.message.delivery_failed` / `delivery_unknown`。
- 只推进 ingest：`send_requested`、已确认投递、重复 received chat fact、provider notice。
- 双游标：ingest 用账本 position；ack 仍用 `heartbeat_context_cursor`（LifeEngineEvent.sequence）。
- 已有运行历史且 consumer 尚未创建时 seed 到 frontier，不把旧账本当新经历。
- agent/mission 先账本后入队，persist 失败 restore；心跳收集失败不再 skip。
- `record_message` 同步路径先账本；异步路径可先 pending，后台写账本失败有界重试。
- `nucleus_grep_events` 搜账本，可选时间/窗口/人/工具/因果过滤；节选 + `nucleus_read_event` 续读。

实现锚点：`plugins/life_engine/service/subconscious_ingest.py`，`LifeEventStorePort.scan_window`。验收须用户手动重启 Elysium。

### 落地前缺口（已关闭）

权威 Life Event 账本是全生命域的。落地前心跳**不是**这个账本的消费者，只吃 `_pending_events` / `_event_history`。下列缺口已按上节关闭，不再作为当前行为：

- 投递失败只写账本不进 pending
- `record_message` 先 pending 再账本且无 catch-up
- agent/mission 收集失败 skip
- 账本已写、checkpoint 未写时无法追赶
- `nucleus_grep_events` 只搜运行时投影

「接到」≠ 每拍把全文再塞进 Prompt。私有 Chatter 滚动上下文本来就不该进潜意识。

### 目标

`life_engine_subconscious_ingest:v1` 成为 Life Event 账本上的具名消费者（ingest 游标用账本 position；ack 仍用 `heartbeat_context_cursor`）：

```text
账本 frontier
    → 心跳 consumer cursor（只在本拍声明过的事件被成功心跳 attempt 确认后前进）
    → 未确认的进入 pending/本拍工作集
缺口、重复 occurrence、内容冲突：fail closed，禁止把游标拨到尾部
```

启动和每拍 prepare 之前：从 cursor 追赶到 frontier，幂等入队。pending 变成账本的派生缓冲，不再是第二份权威。

### 第一期范围

纳入消费：

- 所有 `conscious_activity`（模型轮、工具选择/结果、状态）
- 入站/出站 `MESSAGE` 兼容事件
- agent/mission 完成事件（收集失败必须保留待处理，禁止 skip）

第一期仍可后置（继续只在账本、不强制进心跳工作集）：纯 World assertion 细节（另有 Perception）、`send_requested` 若已有配对 `tool_result`。若没有配对结果，投递失败必须能作为活动被心跳看见。

### 做法

1. 登记 consumer `life_engine_subconscious_ingest:v1`。ingest 用账本 position；`heartbeat_context_cursor` 仍用 `LifeEngineEvent.sequence`。已有运行历史且 consumer 尚未创建时 seed 到 frontier（`bootstrap=high_water`），禁止把全部历史重放为「新经历」。
2. `_prepare_heartbeat_context` 开头 catch-up；与 drain 合并为一次有序工作集。
3. `record_message` 改为与 `record_conscious_*` 相同：先账本，再队列，occurrence 幂等。
4. `_collect_background_agent_results` 失败保留 coordinator 结果，不得 skip。
5. 启动加载 runtime 后立刻 catch-up，补上 checkpoint 落后于账本的事件。
6. 定向测试：只写账本不写 pending → 下一次 prepare 仍能接到；缺口报错；重复 occurrence 不双份；消息与意识活动同序。

本阶段不改 `_render_event`，不改空闲时空 content。接到了就可以在测试里断言工作集含该 occurrence。

## 问题 3：统一机会暴露

### 已落地（2026-09-03）

一条 Offer 总线、一个心跳机会页。机会只是建议。忽略 ≠ 拒绝。不打分、不排「现在最该做的」。

页分两栏：连续性栏是 open AttentionThread / InitiativeSeed 只读投影；邀请栏是到期工程事实（学习复盘、MEMORY、file_care、river、epistemic）。总线不能创建或改写线索。冷却只针对邀请栏，且必须等本页 exact receipt；render 不再写冷却。TODO 提醒仍走生命事件，不进本页。`nucleus_learn` / learning skill 仍属问题 2。

实现锚点：`plugins/life_engine/opportunity/`。细节见 [统一机会暴露方案_2026-09-03](./统一机会暴露方案_2026-09-03.md) 与 [机会总线_2026-09-03](./机会总线_2026-09-03.md)。

### 落地前缺口（已关闭）

主动、学习、记忆、叙事、文件收拾、认知候选都在「给机会、不代决定」，但各写邀请、各做冷却、各抢心跳字数。`HeartbeatSectionProvider` 只统一了往 prompt 塞字。file_care / river / MEMORY 在 **render 时** 写入冷却，裁剪或失败也会被当成已经看见。

### 目标

一条 **Offer 总线**。机会只是建议。忽略 ≠ 拒绝。不能打分、不能排「现在最该做的」。

```text
offer_id / kind / domain / producer / facts / disclosure_ref / delivery / cooldown
```

`disclosure_ref` 指向 skill 或已有 dispatcher help，不指向「请调用 decide」。

两类分开：她已留下的 AttentionThread / InitiativeSeed 是主体连续性，只读投影，不是系统新建议。总线管基础设施邀请：复盘到期、MEMORY 过大、长河到期、file_care、epistemic 候选。

一个心跳机会页，共享预算（约 2–4k），exact receipt 后才冷却邀请。裁剪或失败则机会仍到期。

主动系统的 command/query 仍是唯一写入口。机会总线不能创建线索。

## 问题 2：工具（机会 + skill 或常驻工具）

### 已落地（2026-09-03）

对心跳来说，学习、文件收拾、长河、MEMORY 复盘是同一类邀请：机会页只给到期事实；动手说明书要么是一份工程 skill，要么是已经常驻的工具。

| 要写的 | 数量 |
| --- | --- |
| 机会总线 | 0 份 skill |
| `skills/learning/SKILL.md` | **1 份**（工程说明书，禁止第一人称自我叙事；工作区已有则不覆盖） |
| QQ / 飞书 | 0 份新的（已有） |
| 文件收拾 / 长河 / TODO / MEMORY | 0 份；`disclosure_ref` 指向常驻工具 |

`nucleus_learn` 是跟随 learning skill 的薄执行门（`action` + `arguments` 对象），内部委托现有 16 个学习 Tool 类。`action=help` 读那份 skill。不是 16 张学习 schema 的平铺。

心跳常驻见 `HEARTBEAT_TOOL_NAMES`：休息、工作区文件、记忆检索与 MEMORY 执笔链、事件 grep/read、主动 query/command、`nucleus_skill`、`nucleus_todo`、`nucleus_schedule`、`nucleus_learn`、`nucleus_write_narrative`。`nucleus_write_narrative` **留下**，否则长河邀请是死路。`platform_action` **移出**心跳：外联写入口是 `outreach.begin` → 表达层。

移出心跳注册（类还在，聊天清单本阶段不动）：16 个独立学习工具、表情三件套、run_agent、view_screen、bash、web、conversation_evidence、sync_platform_history、fetch_life_memory、trace、relations、memory_stats、`platform_action`。

`life_engine_internal` 现在是这份白名单，不再等于全部已注册工具。能力目录指出未注入本拍的能力仍在其它意识窗口。机会页学习邀请 `disclosure_ref` 为 `nucleus_learn` / `skills/learning`。禁止到期自动注入 skill 正文。

细节：[心跳工具清单_2026-09-03](./心跳工具清单_2026-09-03.md)。
