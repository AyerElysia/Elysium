# N.E.K.O 与 DFC 清理

> 日期：2026-09-03
> 状态：生产代码已删除相关实现。未改主体文件、未启动 Elysium。
> 范围：`plugins/neko_surface`、Neko Surface API/TTS/Chatter 特判、`DFCIntegration` 与 DFC 入站。

## 结论

N.E.K.O 展示面和 DFC 入站都已从生产路径拿掉。控制台不用 Surface；没有生产调用方再写 `enqueue_dfc_message`。历史 Life Event 没有改写：旧 `content_type=dfc_message` 仍按普通消息读取，不再贴「📮 DFC」或「信息差」标签。`nucleus_tell_dfc` 实现类已删除，也不在滚动退役名单、心跳 TOOL.md 清洗名单或 agent 黑名单里留占位；未注册名字走通用未知工具路径，没有 DFC 专用处理。

## N.E.K.O

已删除：

- `plugins/neko_surface/` 整棵插件与 `test/plugins/neko_surface/`
- 部署模板 `config/plugins/neko_surface/config.toml`、`.gitignore` 例外、schema 检查
- Chatter 的 `neko.surface` 低延迟特判、实时 guidance、请求覆盖、自动 TTS 抑制
- TTS Action 对 `neko.surface` 的双发抑制
- `/api/v1/surfaces*`、`surface:*` scope、能力目录 `surface.presentation`、foundation 模块映射、inventory 合同、旧 `/api/neko-surface` 兼容路由

保留：`surface_ref` 仍是聊天可达性引用，与 Neko 插件无关。Minecraft 文档里对外引的 Project-N-E-K-O 公开插件经验也保留，那不是本仓库插件。

直播桥接的 TTS 屏蔽仍然只针对 `platform == "live"`。

## DFC

已删除：

- `DFCIntegration` 及 `LifeEngineService` 上的 `enqueue_dfc_message` / `enqueue_outer_message` / `get_state_digest_for_dfc` / `query_actor_context` 包装
- `build_dfc_message_event`
- `LifeEngineState.last_tell_dfc_at` / `tell_dfc_count` 的读写（旧 checkpoint 键加载时忽略）

保留：

- 历史 `dfc_message` 事件可读、可进入 salient / 潜意识投影，当作普通消息
- `scripts/migrate_training_data.py` 仍把历史 `dfc_message` 当成用户轮
- `test_tell_dfc_tool.py`：证明实现类与注册名已不存在，不是名字占位

`search_actor_memory` 仍是通用记忆检索，关联扩展的 `context_key` 改为 `life_engine/memory`。

## 验收

定向测试：Chatter、TTS、life_engine 入站、部署 schema、P3-12/13/14 API 共 326 项通过后，修正记忆检索 `context_key` 断言再跑 1 项通过。随后去掉 `nucleus_tell_dfc` 在滚动退役名单、心跳 TOOL.md 清洗名单和 agent 黑名单里的占位，再跑 tell_dfc / manifest / heartbeat prompt 定向测试。Ruff 变更文件无新增 F/E9。OpenAPI 已重生（129 个 HTTP 操作，无 `/surfaces`）。未启动 Elysium；生产进程需用户手动重启后才会丢掉旧插件。
