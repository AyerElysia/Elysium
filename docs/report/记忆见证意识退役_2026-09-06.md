# 记忆见证意识退役（2026-09-06）

> 操作者要求先停掉持续报错的记忆见证循环。这是工程退役，不是主体选择不见证，也不是对 oversized occurrence 的语义处理。

## 1. 时间线与证据

| 时间 | 来源 | 事实 |
|---|---|---|
| 2026-09-06 00:05:37（UTC+8） | 运行日志 `life_engine.memory_witness` | `记忆见证意识运行失败`，栈在 `MemoryWitnessCoordinator.loop` → `run_once` → `_next_authoring_window` → `_list_plannable_occurrences` → `_plan_window` |
| 同条 traceback | 异常正文 | `MemoryWitnessOccurrenceWindowTooLarge:position=194204:occurrences=1:utf8_bytes=1530215:count_limit=40:byte_limit=65536` |

该 ERROR 会按见证间隔反复出现，因为窗口规划 fail-closed：首个完整 ingest position 已经超过 UTF-8 硬预算，系统保持 author cursor，不截断、不跳过。下一轮仍从同一位置规划，于是同一异常循环。

## 2. 根因

Experience position `194204` 是一个完整 position，只含 1 条 occurrence，渲染后约 1,530,215 UTF-8 字节。见证窗口硬上限是 40 条或 65,536 字节。规划器在 `selected` 仍为空时遇到超限组，写入 `_oversized_window` 并抛出 `MemoryWitnessWindowTooLarge`。

这是完整性保护，不是实现偶然失败。缺的是 oversized occurrence 的显式、可审计策略；在策略出现以前，继续跑循环只会刷 ERROR。

## 3. 已执行操作

1. `LifeEngineConfig.MemoryWitnessSection.enabled` 默认改为 `false`。缺省不再启动 `life_engine_memory_witness`。
2. 本机 `config/plugins/life_engine/config.toml` 的 `[memory_witness] enabled` 改为 `false`。该文件被 Git 忽略，只影响本机运行配置。
3. 启动路径与 `loop()` 的 `enabled` 缺省回退改为 `false`，避免缺字段时把退役开关当成开启。
4. health：coordinator 未创建且 `enabled=false` 时报告 `status=disabled`、`reason=memory_witness_retired`。不把退役标成 `failed`。
5. 架构、运维与本报告同步为“当前默认退役”。

## 4. 副作用与可逆性

`enabled=false` 停的是整个 memory_witness worker，不只是 LLM 写作。因此 Stage A（Life Event → Experience 摄取）和 Stage C（已有决定的 World/Markdown 投递与 reconciliation）也会暂停。Life Event 权威账本继续追加；Experience 与 Witness 历史、author cursor 留在原位。

回滚方式：在 oversized occurrence 有显式策略之后，把 `[memory_witness] enabled` 设回 `true`，由用户手工重启 Elysium。禁止用把 author cursor 跳到当前尾部来“清零积压”。
