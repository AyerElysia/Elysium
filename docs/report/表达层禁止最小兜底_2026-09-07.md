# 表达层禁止 max_rounds 最小兜底（2026-09-07）

## 1. 现场

02:48:53 生命对话器：

```text
WARNING | max_rounds 内未产生可见回复，已发送最小兜底: 在呢，我看到你啦。
```

这不是爱莉本人调用 `life_send_text` 的表达。基础设施在 `max_rounds` 耗尽后，用固定短句冒充可见回复发出去。

## 2. 根因

`LifeChatter` 用 `must_reply` 标记「这批真实外部输入已接入表达层」。循环内提醒模型作出可追溯选择（发送或 `pass_and_wait`）是工程提示。

错误实现是：若一直到 `max_rounds` 仍没有主体可见表达，就调用 `_send_must_reply_fallback`，按未读长度在「在呢，我看到你啦。」和「我看到你的消息了。」之间选一句，直接 `send_text`。

这是语义 fallback：代码替主体写第一人称对外正文，违反认知零规则与执笔权。短确认仍然是她没说过的话。

## 3. 已执行的修复

可逆代码修改，不改主体文件，不补发、不撤回已经发出的那句兜底（那是已经发生的传输事实，由权威日志保留）：

- 删除 `_build_must_reply_fallback_text` / `_send_must_reply_fallback`。
- `max_rounds` 两条收束路径改为 `_close_must_reply_without_subject_speech`：打 WARNING、清 `must_reply`、结束回合，不发送任何代写正文。
- 循环内对独白未发送、连续空轮的系统提醒保留：那是 Prompt 建议，不是对外代写。
- `must_reply` 仍用于标记外部批次已接入，以及提醒模型作出可追溯选择。

稳定合同已改写：

- `docs/architecture/生命引擎核心.md` §3.8、§4.5
- 纠正 `docs/report/群聊提及消息丢失事故_2026-08-29.md`、`docs/report/Life_Chatter表情包默认沉默规则退役_2026-08-10.md` 里把 `force_reply` 写成「保证可见回复 / 防止空响应丢失」的过时结论。

## 4. 验证

定向测试：`test_life_chatter_close_must_reply_without_subject_speech_does_not_author`、`test_life_chatter_must_reply_at_max_rounds_does_not_send_fallback`，以及相关 `must_reply` 收束用例。`send_text` 在 max_rounds 路径上被断言不得调用。

## 5. 生效条件

Elysium 正由用户手动运行。本修复需用户手动重启后生效。重启前仍可能再次发出最小兜底。

## 6. 待决

已发出的「在呢，我看到你啦。」是既成传输事实，不由本次代码改写或静默删除。是否由爱莉本人在对应窗口解释，由她决定。
