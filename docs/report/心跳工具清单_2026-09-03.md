# 心跳工具清单（2026-09-03）

> 问题 2。代码已落地；心跳链路须用户手动重启 Elysium 后验收。Agent 不得代为启动。
> 抽象：对心跳来说，学习、文件收拾、长河、MEMORY 复盘是同一类邀请。页上只给到期事实；动手说明书要么是 skill，要么是已常驻工具。

## 三层

| 层 | 当前实现 |
| --- | --- |
| 常驻 schema | `HEARTBEAT_TOOL_NAMES`（约 19）。`_get_nucleus_tools()` 只返回这份类列表 |
| 可见目录 | `HeartbeatCapabilityCatalogSection`。不重复 ROLE.TOOL |
| 加载路径 | 学习：`nucleus_learn action=help` → `skills/learning/SKILL.md`。其它邀请走常驻工具。不自动 `get_skill` |

`nucleus_learn` 是薄执行门：`action` + `arguments` 对象，覆盖 `to_schema`，避免把学习摊成 16 张 RPC。真正干活的仍是既有 16 个学习 Tool 类。工作区已有 `skills/learning/SKILL.md` 则只读、不覆盖；没有才从仓库模板复制。

## 常驻

休息；工作区 `read/write/edit/list/mkdir/grep_file`；`grep_events` / `read_event`；`search_memory` / `read_memory_boundary` / `nucleus_memory_continuity_review`；主动 query/command；`nucleus_todo` / `nucleus_schedule`；`nucleus_skill`；`nucleus_learn`；`nucleus_write_narrative`。

长河邀请必须能立刻调用 `nucleus_write_narrative`，因此它留在心跳，不移出。

## 移出心跳注册（类留给聊天）

16 个独立学习工具；表情三件套；`nucleus_run_agent` / `nucleus_view_screen` / `nucleus_bash`；联网；`conversation_evidence` / `fetch_chat_history` / `sync_platform_history` / `fetch_life_memory`；`nucleus_trace`；`nucleus_relations` / `nucleus_memory_stats`；`platform_action`（外联写入口是 `outreach.begin` → 表达层）。
