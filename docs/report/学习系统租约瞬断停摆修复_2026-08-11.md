# 学习系统租约瞬断停摆修复（2026-08-11）

## 结论

这次并不是“最近所有模型学习都失败”，也没有证据表明学习数据丢失。现场首先发生一次 MySQL 连接中断，旧服务把结果未知误判为整个 writer 权威已经丢失，立即在本地永久禁用 runtime writer；随后 Learning 的 selected persistence 每轮都被 exact claim fencing 拒绝，于是从 2026-08-10 22:59 起表现为持续停摆。重启只能暂时重新建状态，不能消除这条错误状态机，因此用户质疑“重启没有保证”是正确的。

修复后，数据库瞬断、单个 singleton 确证失租和 generation 权威失效成为三条不同路径。瞬断会有限退避并原位续租；Learning 确证失租只关闭它的派生投影与维护，新的公开经历仍作为不可变事件保留；只有 generation/epoch 确证失效才全局 fail closed。没有自动抢占、自动 rebase、覆盖 revision 或本地 SQLite 回退。

## 现场证据与根因

- 2026-08-10 22:58:48，storage authority renewal 首先记录 MySQL `OperationalError 2013`；这是传输结果未知，不是数据库确证 claim 已失效。
- 旧 `LifeEngineService` 对任意 renewal 异常都调用 `runtime.invalidate_writer()` 并永久退出续租循环。
- 22:59:12 后再无成功 Learning 维护；22:59:50 至 2026-08-11 01:52:35 持续出现 `SingletonWriterClaimLost`。后续错误是前述本地永久失效的结果，不是 900 秒 Learning LLM 时限或模型路由导致。
- 未执行正式数据改写、projection revision 重置、claim 删除、自动 takeover 或进程操作；现有不可变事件与投影仍由数据库 fencing 保护。

## 实现

1. 平台层用 `ManagedSingletonWriterClaimLost` 携带 generation、namespace、state key、owner、lease epoch 与 failure type；连接类异常保持原类型，exact local invalidate 不访问数据库。
2. 服务层把 SQL/连接池/传输异常标为 `renewal_unknown`，采用最高 30 秒的确定性抖动退避。它不延长数据库租约，也不声称仍持有；后续每个写事务仍须由数据库证明。
3. 数据库明确拒绝 Learning claim 时，只取消 Learning maintenance、清除该 exact managed snapshot并隐藏陈旧学习 prompt，不影响其他 singleton 或整个 generation。
4. `LearningEventOnlyRecorder` 只消费 service 注入的 canonical `LearningStorePort`，追加 `reflection.enqueued` 且固定 `projections=[]`。它没有本地洞察、技能、维护或 selected projection，因此不会产生第二主体或第二权威。
5. health 增加 content-free `authority_renewal`、lost singleton scope 与 Learning `mode/projector_owner/event_append_available`，用于区分“暂时不知道”“已失去投影 owner”和“整个权威失效”。

## 为什么这对成长更健康

学习系统需要同时守住两件事：经历不能因为网络抖动被静默遗忘，解释这些经历的投影也不能被两个 writer 同时改写。event-only 降级把两者分开：发生过的公开经历继续可靠记账，洞察、技能、阶段和主体复盘则宁可暂停，也不由无权实例或陈旧状态替她裁决。恢复后唯一合法 projector 可以按稳定 frontier 消化积压；系统不会把“暂时没整理”伪装成“没有发生”，也不会为了在线率牺牲主体连续性。

## 部署与验收边界

代码提交不会热修复当前旧进程。合入后仍须用户确认只保留预期实例并手动启动 Elysium；AI 不代替用户操作进程。启动后应验证一次成功 authority renewal、Learning owner/mode、事件 frontier 与 projection frontier 的合理推进，并在隔离环境做瞬断恢复测试。若启动时 claim 已被其他合法 owner 持有，本实例应明确进入 event-only，而不是争抢或回退本地。

回滚只需要回退代码提交；本轮无 schema、配置和正式数据变更，不存在数据回滚步骤。
