## 2. 工程根因及最小改动

`LifeEngineReadFileTool.execute` 原来只在 `end_idx < total_lines` 时设置 `source_selection_truncated=True`，遗漏了 `start_idx > 0` 且已到文件末尾的情况。传输投影的 `truncated=False` 本身没有错，但不足以说明所选行覆盖全文。

修复沿用已有字段，明确赋值为 `start_idx > 0 or end_idx < total_lines`；工具说明区分行选择和字节分页。没有新增工具、数据库字段、自动认知判定或专用学习系统。原来的行选择函数、正文、精确版本引用、分页身份、预算和权限路径均保持不变。产品源码消费者检查未发现依赖该字段“键存在即表示 True”的额外调用方。

开发中曾误认为 `limit=0` 保留 offset，导致新增测试和一行新增说明错误。既有 `select_read_line_window` 明确规定此时选整份文件；已纠正说明和测试，分页尾部用例改用 `offset=41, limit=60`。没有为了让错误测试通过而更改既有读取语义。

这是 G01/G04/G06/G10/G11 的有限实践验收，不声称是长期习惯或独立回忆测验。以下为工程评估条件，不是要注入主体的回答模板。在反馈尚未发送时先登记，不在看到表现后改判据；素材只能使用不含私人内容的工程测试材料，不建立第二套正式记忆。

| 保留情形 | 可核验边界 |
|---|---|
| 同一版本、完整行范围、单页 | 可称该版本全文读回 |
| 同一版本、尾部片段、已传完 | 不能凭传输完成称全文读回 |
| 同一版本、完整行选择、传输缺页 | 尚缺精确字节覆盖；成功取齐后才能改称完整 |
| 多个版本的片段混合 | 不能冒充某一精确版本全文；若可证明重建，须明确依据 |
| 旧版全文加本人提交差量 | 与“新版完整读回”分开记录，不将有效差量推理判成无知 |
| 正文或版本不可取得 | 明确未知、受阻或选择停止，不把承诺、调用选择或失败当作已完成 |
