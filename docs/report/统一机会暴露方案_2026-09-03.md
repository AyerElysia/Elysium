# 统一机会暴露（2026-09-03）

> 状态：问题 3 已落地（代码）。问题 2 的学习 skill 门也已落地，见 [心跳工具清单_2026-09-03](./心跳工具清单_2026-09-03.md)。心跳链路须用户手动重启 Elysium 后验收。
> 原则：模型可能不会自发做出某种行为，所以给机会；不能替她决定，所以机会只是建议，不是任务、不是自动执行。

## 当前行为

心跳只渲染 **一个机会页**（`OpportunitySection` → `plugins/life_engine/opportunity/`）。登记、有界展示、页级 exact receipt、邀请冷却都走这条总线。意义仍不统一：不排序「哪个更重要」，不合并成「你现在最该做的事」，不按情境自动 `get_skill`。

页分两栏，语义不得混：

1. **连续性栏**：open 的 `AttentionThread` / `InitiativeSeed`。这是主动权威的只读投影，标签是「你留下的线索」，不是系统新建议。看见本页不会冷却、暂停、关闭或改写线索。写入口仍是 `nucleus_proactive_query` / `nucleus_proactive_command`。
2. **邀请栏**：基础设施到期事实（主体文档复盘、MEMORY 结构压力、file_care、长河、epistemic 候选）。

生命域事件是否进入潜意识，仍是账本/pending 管道（问题 1），不塞进机会系统。TODO / `enqueue_proactive_opportunity` 已能进账本工作集，不迁进机会页，避免双份。学习邀请的说明书是 `nucleus_learn` + `skills/learning/SKILL.md`；到期不自动 `get_skill`。

聊天滚动上下文的 Attention 投影（`_format_chatter_attention_threads`）不是心跳机会页。

## 契约

```text
offer_id / kind / domain / producer / observed_at / facts / disclosure_ref
kind                continuity | invitation
domain              attention | initiative | learning | memory | narrative | file_care | epistemic
```

禁止字段：importance、priority、score、「建议现在做 X」、自动 tool_name 选择。

稳定展示顺序只用技术键：`kind` + `domain` + `offer_id`。连续性栏固定在邀请栏之前。分页是预算（约 2–4 KiB UTF-8），不是重要性。先给每一条一行身份，余量再展开 facts；放不下标 `omitted` + offer id，禁止静默丢。

整页一个 `delivery_id`。只有最终成功心跳 attempt 对本页声明投影给出 content-free exact receipt，才冷却 **邀请栏** 中未 omitted 的 offer。裁剪、失败、取消 = 机会仍到期。忽略、安静结束、不调用工具，不写「她拒绝」。

`disclosure_ref` 指向 skill 或已有常驻工具，不自动打开 skill：

| domain | disclosure_ref |
| --- | --- |
| continuity | `nucleus_proactive_query` / `nucleus_proactive_command` |
| learning | `nucleus_learn` / `skills/learning` |
| memory | `nucleus_memory_continuity_review` |
| narrative | `nucleus_write_narrative` |
| file_care | `nucleus_mkdir` / `nucleus_read_file` |
| epistemic | 只读候选；不自动打开 skill |

Health 只读：due/omitted ids、kind、domain、last delivery、error_type。不泄露 facts 正文或第一人称线索正文。
