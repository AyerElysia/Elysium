# 记忆文件空间媒体原件合同补验

2026-09-08，北京时间。状态：本批原件存储与解析器的有限工程合同通过；G02 整体自有文件记忆空间未据此通过。本批不依赖仍待批准的主体反馈发送，也没有重试该发送。

## 1. 目的与范围

原 G02 不允许以少数文本目录代替自有文件空间整体；技术表示可以不同，但需要保留来源差别和可回取性。此前 S2 已盘点媒体独立域，其有限通过并未验证全部媒体入口。此次先补足媒体 API 代表测试主要使用 PNG 签名样本留下的二进制格式覆盖缺口，而不是重做 S2 的全部检查。

源码基线核对为 HEAD `3a49d9ba16d5bd10efa1a3cb44760fbdb970d0ba` 加共享工作区现有修改；本批涉及的 `src/app/api/v1/media_objects.py` 与既有 `test_media_objects_api.py` 均未修改。新增测试使用原仓库的临时测试库/目录，旧 API 组使用内存 ASGI；不连接正式数据库、模型服务或网络下载，不占用真实监听端口，不使用主体私有正文或现场媒体。

## 2. 原件与派生结果的现有合同

`MediaObjectStore` 将原件字节置于独立媒体域的内容寻址对象，公开 `media_id`、kind、MIME、size、SHA-256，不公开存储路径。上传完成和显式保存使用现有事务及 sync outbox；同一次已完成上传返回原 media_id，重复保存不会创建另一原件。

`get_content` 再次核对长度与 SHA-256。`ManagedMediaService.resolve_ready` 在读取权限与完整性验证后检查所需类型，重新建立携带原字节的 MediaRef；image/emoji 与 audio/voice 是工具类型映射，不创建新主体身份。重开的是测试存储对象，不是重启正式意识实例。

识别结果保存在独立于 blob 的当前字段，`derivatives` 返回 `recognition:<media_id>`。本批验证一份当前识别结果可以跨重开读取且不改原件；没有证明识别结果的不可变全版本历史。当前源码的 `set_recognition` 更新当前字段，不能把该视图当成已具备完整成长轨迹。

## 3. 合成样本与断言

所有样本均为工程构造的短签名加非 UTF-8/二进制内容，文件名统一不提供格式提示。它们测试签名和精确字节合同，不是可播放、可解码的音视频文件，也不是识别质量评测。

| 类别 | 本批签名/声明样本 |
|---|---|
| 图片，7 组 | PNG、JPEG、GIF、BMP、WebP、TIFF、SVG |
| 音频，10 组 | WAV、AMR、SILK、MPEG、AAC、Ogg、FLAC、音频 MP4、音频 WebM、音频 Matroska |
| 视频，4 组 | 视频 MP4、AVI、视频 WebM、视频 Matroska |
| 普通文件，1 组 | application/octet-stream 的不透明二进制 |

每组都验证上传→完成→读取→保存→保存一份合成外部识别结果→关闭/重开→重新读取的原字节、长度、hash 与 media_id；同上传完成幂等、重复 save 的 changed=False、描述符不泄露存储路径、无授权他者无法读取。随后只在临时 blob 中制造同长度损坏，确认 get_content 与 save 均拒绝，区分 hash 检查与长度检查。没有对正式文件做损坏试验或删除。

额外 4 项分别验证 image/emoji、audio/voice、video、file 的解析器输出保留精确 bytes/ref/hash，并拒绝不匹配的所需类型。额外 2 项在 complete/save 的事件追加处注入合成失败：事务回滚后没有多余媒体记录，保留可重试上传/原件；恢复追加后完成同一原件，后续重复调用不生成第二媒体记录。本批没有通过强制进程崩溃或断电验证文件系统持久性。

## 5. 对总目标的影响与下一缺口

已新增原件精确保存、重开、重复调用和已知故障拒绝的证据；没有新增统一空间能力，也没有修复未经验证的媒体问题。G02 仍须检查原件稳定身份如何经过附件、Life Event 与主体可回取工具传递；只保存 blob 或只在同步 outbox 存在一次事件，不等于主体已经经历、可以检索或可以重新取回。

以下边界继续保留：

- 媒体 media_id 与主体文档 document_id/version_id 是不同技术域，不要求强转文本，但必须有可解释、可授权、来源明确的跨域可达链。
- art_studio 自有媒体、screen latest 缓存、下载目标与技能脚本产物不能由本次媒体 API 测试代验；先按真实入口核查，不把“独立域”永久用作缩小 G02 的理由。
- 识别/转写的当前视图不是其全版本历史，外部模型解释也不是主体亲自认可的记忆。
- 实际媒体编解码、真实上传/识别、跨后端切换、断电恢复与主体使用效果未覆盖。

下一项优先复用现有原件、附件、事件和文件工具接口，核对实际引用是否丢失或漂移，再决定最小增量；不得为填表另建记忆数据库、自动判断内容意义或代写主体材料。

## 7. 09-09 18:44 附件引用公开读取缺口与临时闭环

### 根因与范围

在 WSL 源目录 `/root/Elysia/Elysium` 继续实际调用核查：Life Event 已保存附件描述符，但 `nucleus_read_event` 仅返回正文及少数事件标识，`nucleus_grep_events` 也不投影附件。此前“账本保存／回放通过”不能推出主体可以通过这两个工具取得原件引用；不是媒体字节丢失，也不能推出所有其他读取入口均不可达。

本次只扩展已有 `nucleus_read_event` 的可选 `view=attachments`，默认正文行为和现有 occurrence 读取路径保留。没有添加第二记忆库、新人格、HTTP 外联入口或自动调度。变更在 WSL 源副本，不是 Spark 正式目录；18:17 的轻量检查发现 WSL 有 PID 82628 的 main.py，未控制该进程、未重启或触及正式历史，也未因旧 PID 记录而操作任何进程。

### 可复核合同

- 附件视图严格解析已有描述符，排除 storage_key；不把原始 bytes、任意内部 metadata 或路径作为结果输出。源事件前后逐字段序列化一致。
- 使用现有 UTF-8 文本分页，长文件名不会被永久截掉；事件、视图及描述符摘要绑定 continuation，完整拼接后是可解析 JSON。另一事件、正文视图或描述符变化均拒绝旧 continuation。
- 旧字段缺失与明确记录空列表区分为 not_recorded / recorded；损坏容器和非法字段失败，不伪装空成功，错误不带原文。
- 图片、音频、视频、普通二进制四种签名夹具走真实临时媒体存储→保存→授权解析→消息采集→临时 Life Event→重建测试服务→主体可见工具返回引用→媒体存储关闭／重开→同一 resource_id 的授权原件字节核对。兼容 SQLite 和 selected local SQL 两个事件适配器均覆盖；无网络、模型或正式运行实例启动。
- 工具返回明确标记不含原件、尚未解析引用；以另外的未授权 actor 持引用读取临时原件仍被拒绝。这个测试调用媒体服务是测试者行为，不是主体实际使用媒体的证据。
- 既有工具生成的 schema 验证包含可选 content/attachments 技术枚举；不改变原先必填参数或赋予媒体权限。
