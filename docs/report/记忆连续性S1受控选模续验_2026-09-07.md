## 4. 为什么收窄候选需要受控重启

权威模型配置是 `config/models.toml`，不是旧 `config/model.toml` 或其他配置 fallback：

- `src/kernel/config/models_loader.py` 的 `get_models_config()` 返回进程内已加载的不可变注册表快照；保存磁盘文件不会自动重新加载它。生产启动由 `src/app/runtime/bot.py` 调用 `init_models_config()`。
- Chatter 长期持有 `_GLOBAL_RUNTIME.response`；`LLMResponse.send()` 继续继承原来的 `model_set`。即使显式替换注册表，旧 Chatter 链也不会自动换候选。
- 新 SYSTEM 刷新 helper 只重新读取当前主体权威并替换唯一 SYSTEM 槽；它不替换模型候选、工具 schema、滚动历史或上下文管理器。
- Heartbeat 每拍创建新请求、重新读取注册表和 SYSTEM；同拍续轮沿用原请求链。当前 core 与 utility 的配置没有改变。
- 保存 Python 文件或仅清理模块缓存，不足以证明已存在的 Chatter 实例和活动生成器已经换成新代码；不能把插件重载宣称为已验证的无缝热更。

所以，本轮后续重启的具体理由是：**将 expression 收窄为 Astra，并让已缓存模型链采用新路由快照**。不是“04:10:48 外部新进程尚未加载前述两个修复”。
