# 表达层纯文本不调工具（2026-09-07）

## 1. 结论

她「一直发纯文本」不是在给用户发消息，也不是 `life_send_text` 校验把工具打回去。模型返回了**助手正文、空 `call_list`**。LifeChatter 按合同把这记成内心独白并继续 loop；用户窗口看不到。

今晚 22 次 `记录纯文本独白`，推断全部来自 **`gemini-3.7-flash`**。同一晚真正发出去的 18 次 `life_send_text`，几乎都是 **`gpt-6-astra`**（少数像是 mimo 冷却结束后打出工具）。gemini 成功时 0 次可确认的工具发送。

09-06 对照：独白 0，`life_send_text` 161。昨天表达层几乎总能打出工具。

## 2. 合同（不是 bug）

`plugins/life_engine/core/chatter.py`：空 `call_list` 且有正文 → `_record_plain_text_inner_monologue`，然后 follow-up。对外说话必须 `life_send_text`；等待必须 `action-life_pass_and_wait`。Prompt 已经写明「assistant 纯文本不会发给用户」。

这不是认知裁决，是协议：没有工具调用就没有平台副作用。

## 3. 今晚为什么反复发生

expression 链（snapshot `c64152faddf71a94`）：

`mimo-v2.5` → `gemini-3.7-flash` → `gpt-6-astra` → `claude-opus-5`

- mimo：今晚 `life_chatter` 约 20 次 429，经常被跳过冷却。
- gemini：HTTP 成功，但只吐对用户说话的散文，不带 tool_calls。重试链把「成功」当完成，**不会**再交给 gpt-6。
- 下一轮 follow-up 仍选 gemini（mimo 还在冷却）→ 再独白。循环最多 5 轮。
- gpt-6：会调 `life_send_text`；今晚 4 次 504。只有 gemini 自己 400「上游不可用」时才会落到它（例如 03:03:51 那次真正发出）。
- claude：额度不足，链尾打穿。

不是 `thought 必须是非空`（日志 0），也不是短时重复发送拦截（0）。

典型簇：

- 02:46–02:48：五轮 gemini 独白 → max_rounds → 当时仍发了最小兜底。
- 03:48–03:50、03:52–03:54：同样五轮 gemini 独白 → 已禁止兜底 → 对外完全沉默。

系统提醒「独白用户没收到，请调 life_send_text」会注入 follow-up；gemini 下一轮继续写散文，提醒无效。

## 4. 工程洞

重试只在模型请求失败时前进。gemini **协议成功、工具空** 会占满 `max_rounds`，把会调工具的 gpt-6 挡在后面。这是路由/降级语义问题，不是她选择不调工具。

心跳 `model_reply` 本来就是纯文本通道，不要和表达层独白混为一谈；心跳草稿不会送到 KOOK。
