# TODO 系统重构（2026-09-03）

> 代码已落地；心跳/聊天工具清单须用户手动重启 Elysium 后生效。Agent 不得代为启动。

## 为什么改

旧 TODO 是「承诺行动」微操作集：create/start/log_progress/review/complete、priority、逾期排序、创建即挂日程提醒。这既不像 Codex `update_plan` / Claude `TodoWrite` 那种整板写入，也违反认知零规则（用紧急度替她排序、用提醒诗催她行动）。

## 当前行为

- 唯一 LLM 工具：`nucleus_todo`（`write` / `list` / `get`）。
- 写入合同：`todos: [{id, content, status}]` + `merge`。status 只有 `pending | in_progress | completed | cancelled`。同时最多一条 `in_progress`。禁止 importance / priority / score。
- `merge=true`：按 id 补丁。`merge=false`：本次列表是开放板，未出现的开放项取消；已结束项保留。
- 持久化仍在 `workspace/todos.json`（version 3）。她是连续存在，板不是会话一次性 scratchpad。
- 心跳 `TodoBoardSection` 注入约 1 KiB 当前开放板，按 status+id，不是机会、不催办。不进机会页。
- 不再自动创建「请判断是否推进」的 schedule 提醒。v2 遗留 `schedule_record_id` 记在 `legacy_schedule_ids`，首次 `nucleus_todo` 调用时删除对应日程。
- 周期任务完成不会由系统再排下一次；要继续就再 write 一条。
- Health：`todo_board` 只有 counts / open_count / error_type，无正文。
- 管理端仍只读。

v2 迁移：`title` + `next_action` → `content`；`blocked`→`pending`，`archived`→`cancelled`；丢弃 priority。v1 数组仍归档为 `todos_legacy_*.json`。
