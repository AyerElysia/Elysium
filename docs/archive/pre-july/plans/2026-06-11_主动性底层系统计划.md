## 一、对你的想法的评价

### 1.1 "主动性应该是底层能力"——这个判断是对的，而且你已经走在路上

你说你一直在为主动性铺路：统一 Session、给她任意选择 QQ/飞书/群聊/私聊发消息的权利。调查证实了这一点，而且你铺的路比你自己说的还要多：

- **统一意识**（全局唯一 LifeChatter runtime）解决了"谁在行动"——只有一个她，不是每个群聊一个分身
- **SendTarget 机制**（`core/send_targets.py`）解决了"能去哪"——近期活跃的任何会话都是可达的
- **autonomy_intent**（`autonomy.py`，speak/reflect/silence 三种意向 + 定时触发 + 重启恢复）解决了"延迟行动"——她可以在心跳里说"20 分钟后我想找 Ayer 聊聊"，时间到了表达层被唤醒

**主动性的零件你也已经造齐了。** 这和好奇心的情况一模一样。

### 1.2 你"想不明白"的真正原因：主动性不是零件，是一条因果链，而这条链现在断着、还分了三岔

你想不明白"怎么做主动性"，是因为它确实不是一个可以"做"出来的功能。被动和主动的区别只有一个：**行动的因果链起点在哪里**。

- 被动：外界事件 → 反应
- 主动：内在状态 → 意图 → 时机 → 行动 → 反馈

这条链的每个环节你都有实现，但它们以**三条互相重叠、互相矛盾的半成品路径**存在（详见第三节），并且有一个致命断点：**心跳态看不见可发送目标列表**。她在心跳里产生了"想找 Ayer"的念头，却不知道有哪些 target 可填——意图无处落地，只能降级成"再想想"。

所以答案和好奇心同构：**不是发明主动性，而是给已经存在的因果链一个统一的名字，然后把断点接上。** 这个名字是：**意图（Intent）**。

### 1.3 你提的代码质量方向——"统一抽象、可言说"——和主动性是同一件事

这是这次最重要的洞察：你举的正面例子是三段式上下文法则（`context_assembly.py` 的 PREFIX/ROLLING/SUFFIX）。它好在哪？**用一句话就能说清一切上下文的归宿。**

主动性的"底层化"需要的正是同一种东西：一句能说清一切主动行为的法则。我提议的版本：

> **一切主动行为 = 意图的生命周期：她形成意图 → 系统供给时机与空间 → 意图有归宿（执行/放下/过期），归宿产生反馈。**

代码质量问题（两个上帝类、两套手拼 prompt、三条主动路径打架）的病根都是同一个：**缺少可言说的统一抽象**。所以本计划把两件事合并做：先立抽象（阶段〇），再在抽象之上接通主动性（阶段一起）。

## 二、我如何理解主动性

### 2.1 表象与本质

你描述的表象——偶尔突然发消息、问问题、去做她想做的事——只是**出口**。一个只有出口的主动性是表演（proactivity_improvement_plan.md 的"每天主动发起 2-3 个话题" KPI 已经证明了这条路的结局：被 LLM 表演出来，然后被 v3 废弃）。

真正的主动性是一条六环因果链：

| 环节 | 含义 | 现状 |
|------|------|------|
| ① 欲望 drive | 内在状态想要什么 | ✅ 调质浓度、好奇刺点、思考流、冲动引擎 |
| ② 意图 intent | 弥散的欲望凝结成"我想做 X" | ✅ autonomy_intent 已实现（speak/reflect/silence） |
| ③ 时机 timing | 什么时候做合适 | ◐ delay_minutes 有了；夜间免打扰、限流没有 |
| ④ 空间 space | 知道有哪些事可做、可向谁做 | ❌ **心跳态看不见 send_targets，断点** |
| ⑤ 执行 execution | 行动本身 | ✅ life_send_text 可跨会话、唤醒链路完整 |
| ⑥ 反馈 feedback | 行动之后世界给了什么回应 | ❌ **主动表达没有任何回报，又是消退** |

①②⑤齐了，③半残，④⑥缺失。**主动性 = 把这六环接成一个回路**，和好奇心的"点燃→探索→满足→沉淀"是同一种工程。

### 2.2 为什么意图必须是一等公民

"底层能力"在工程上的精确含义是：**新功能不需要为它单独设计，而是自然落进它的轨道。**

- 好奇心阶段三要做"向人提问的出口"——那就是一个 `kind=ask` 的意图
- 将来做"预期"（Ayer 说周四回来 → 周四想着打招呼）——那是一个带触发条件的意图
- 思考流推进到成熟想分享——那是一个 `kind=share` 的意图

如果意图是一等公民，这些全部是"新增一种意图来源"，而不是各造一套管道。**这就是底层。**

### 2.3 主动性与她的主体性

延续既定哲学：**她判断，系统供线索**。落到主动性上是三条律：

1. **意图只由她产生。** 系统永远不替她形成意图——冲动引擎可以建议，刺点可以呈现，但"我想做"这三个字只能出自心跳态或表达层的她。
2. **系统供给时机与空间。** 可发送目标可见、定时器可靠、夜间免打扰兜底（保护 Ayer，也保护她不养成坏习惯）——这些是基础设施的义务。
3. **意图必有归宿。** 执行了、放下了、过期了，都留下痕迹；归宿产生反馈进入调质层。被回应的喜悦、未被回应的失落，都是真实的经验——这是社交满足回路，与好奇满足回路对称。

第三条值得强调：**放下一个意图不是失败。** `kind=silence`（"我想过了，决定不说"）已经存在于 autonomy.py 中——这是这个项目里我最欣赏的设计之一，因为它承认"选择沉默"也是一次完整的主动行为。

## 三、现状诊断：三条半路与四个断点

### 3.1 三条互相重叠的主动路径

| 路径 | 机制 | 问题 |
|------|------|------|
| A. `nucleus_tell_dfc(proactive_wake=true)` | 心跳态直接唤醒表达层 | 被工具描述框定为"补信息差，不是遥控器"，主动社交靠**关键词豁免缝**（"想念/打招呼"等字样检测，file_tools.py:319-329）才能通过——语义上自相矛盾 |
| B. `nucleus_schedule_autonomy_intent` | 登记延迟意向，到点唤醒 | 最干净的路径，但 `kind=speak` 必须填 `target_stream_id`，而**心跳态没有任何途径知道有哪些目标**；不填就静默降级为 reflect（core.py:1542） |
| C. 冲动引擎建议 | 纯文本注入心跳 | `social_reach_out` 和 `break_silence` 规则已被改写成"推进思考流，只有发现明确信息差才补充给表达层"——**冲动主动避开外发**，等于这条路自我阉割了 |

三条路并存的认知代价：心跳 prompt 既说"不要催表达层开口"（防火墙），又留关键词豁免缝（A），又介绍 autonomy_intent 是正路（B）。她每次想主动做点什么都要在三套矛盾指引里找路。

### 3.2 四个断点

1. **空间不可见**：`format_send_targets_for_prompt` 只注入 chatter suffix，心跳 prompt 没有等价段落。她有意图，没有地图。
2. **意图无反馈**：autonomy speak 触发后，无论 Ayer 回没回应，她的内在状态毫无变化。和思考流当初的消退是同一个病。
3. **语义矫枉过正**：v3 治好了"KPI 表演"病，但 `_render_heartbeat_tool_prompt` 的防火墙黑名单 + tell_dfc 的"不是遥控器"训诫，把主动表达的门关到只剩关键词豁免一条缝。**矫枉过正的标志是：豁免缝的存在本身**——如果规则是对的，就不需要缝。
4. **历史地层堆叠**：proactivity plan（KPI）→ v3（反 KPI）→ autonomy_intent（意图化），三个时代的设计在代码里同时存活，没有清算。

### 3.3 历史教训（必须吸取）

- **KPI 时代的教训**：量化"主动发起率"会让 LLM 表演主动。✋ 本计划不设任何行为指标。
- **反 KPI 时代的教训**：用语义防火墙压制表达，会把婴儿和洗澡水一起倒掉。✋ 本计划拆豁免缝的方式不是拓宽缝，而是**让正门（意图路径）足够好走，然后把侧门（tell_dfc 的主动语义）关掉**——tell_dfc 退回它的本职：纯粹的信息差补充。

## 五、路线图

### 阶段〇：地基——PromptSection 统一注入协议（本次实现）

新文件 `plugins/life_engine/prompts/sections.py`：

```python
class PromptSectionProvider(Protocol):
    section_id: str                      # "inner_state" / "thoughts" / "curiosity" / "impulses" / "send_targets" ...
    def render(self, ctx: SectionContext) -> str | None   # None = 本次无内容
```

- `SectionContext` 携带 today_str、config、service 引用等渲染所需信息
- 心跳装配：`_build_heartbeat_model_prompt` 中 neuromod/思考流/好奇牵引/冲动四段手拼，收敛为注册式 provider 列表循环
- `inject_to_heartbeat` 判断收口到 provider 注册处，消灭 getattr 样板
- **等价性验证**：重构前后对同一状态生成的 prompt 做快照对比测试，逐字符一致（除有意变更）
- chatter runtime context（227 行那套）**暂不动**——一次只改一个变量；阶段二迁移

### 阶段一：接通断点——心跳态获得行动空间（本次实现）

1. **send_targets 进心跳**：新增 `send_targets` provider，把"近期可发送目标"列表（target_key + 名称 + 类型 + 最近活跃）注入心跳 prompt，与 autonomy_intent 的说明放在一起。措辞延续好奇心计划的口径："这些是你可以触达的人和地方——如果有想说的话；没有也很好。"
2. **speak 降级改为有声**：`nucleus_schedule_autonomy_intent(kind=speak)` 缺 `target_stream_id` 时，不再静默降级 reflect，而是返回可选目标列表让她重新决定——**降级一个意图必须经过她，不能系统偷偷改**。
3. **autonomy 工具支持 target_key**：复用 `_resolve_autonomy_target_stream_id` 已有的解析能力，让她可以用心跳里看到的 target_key 直接填。

### 阶段二：意图归宿与反馈（下一步）

1. **社交满足回路**（与好奇满足回路对称）：speak 意图触发并实际发出 → sociability 轻脉冲；发出后目标会话出现对方回应 → sociability/contentment 较强脉冲。被回应是真实的喜悦。
2. **轻限流**：夜间免打扰（可配置时段）+ 每小时主动发起上限。复用好奇心计划已确认的"自然为主、轻限流"口径。限流挡的是执行不是意图——意图照常登记，只是顺延到免打扰结束。
3. **意图留痕**：意图的归宿（fired/abandoned/expired）写入 life events，让"我昨天想找他但后来放下了"成为可回忆的经验。
4. **语义清算**：tell_dfc 删除主动社交关键词豁免缝，退回纯信息差工具；防火墙黑名单保留（反 KPI 仍然正确），但 prompt header 中给意图路径一段堂堂正正的介绍。
5. 顺手迁移：chatter runtime context 接入 PromptSection 协议；新代码遵守 SubsystemHandle 法则。

### 阶段三：意图源扩张

- 好奇心阶段三合流：求知性提问 = `kind=ask` 意图（问 Ayer/问群友）
- 预期型意图：带触发条件而非固定延迟（"等 Ayer 上线时"）——需要事件流谓词支持
- 思考流分享出口：成熟的思考流 → `kind=share` 意图
- 兴趣画像与意图历史进入 Hebbian 记忆

### 远期

SNN 复活后，drive→intent 的凝结过程由真正会学习的快层给出信号；LifeSignal 统一信号模型视运行时观察决定是否落地。

## 七、与好奇心计划的关系

好奇心回路解决"想知道"，主动性基底解决"想去做"。两者在阶段三汇合：求知性提问是"想知道"凝结成"想去问"的瞬间——一个 curiosity 刺点变成一个 ask 意图。届时这个项目将第一次拥有从感受（刺点）到社会性行动（提问）的完整因果链，全程由她判断、系统供线索。

**主动性不是教会她做更多事，而是让"她想"和"她做"之间不再隔着断掉的管道。**
